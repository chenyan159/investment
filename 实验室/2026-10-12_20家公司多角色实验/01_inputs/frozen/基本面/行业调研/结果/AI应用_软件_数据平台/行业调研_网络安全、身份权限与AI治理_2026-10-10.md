# 网络安全、身份权限与AI治理行业调研：控制执行权、预算重分配与利润兑现

研究截止日期：**2026年10月10日，美国太平洋时间**。金额除另有注明外均为美元；模型表使用“十亿美元”（1十亿美元＝10亿美元）。年度规模是自然年期间的外部支出流量；公司数据保留原财政期，ARR、RPO及期末客户数不折算为当年收入。研究观察与模型主要覆盖2026—2028年，较长期技术方向用于解释条件，不延伸成没有约束的2030年精确预测。

证据标记：**F＝披露事实，E＝外部机构预测，M＝管理层目标或公司自述，C＝直接计算，I＝本报告推断/假设，U＝尚不能识别**。公司声明的产品上线是F，产品效果、客户回报及未经审计的私营公司经营数字通常仍为M。所有情景和概率均为I，条件范围不是统计置信区间。

本次独立联网研究。项目内仅使用“基本面/产业背景/结果/”中的全局图谱、Token经济和瓶颈反证资料作为口径线索，未使用其他公司或行业研究结论作为输入；金额、技术进展和法规时间表均追至外部资料。未获得的付费市场明细、实际成交价及厂商未拆分收入不作为已验证事实。

## 一、核心判断及其成立条件

**行业需求仍有增长基础，但“风险增加—代理增加—安全收入增加—利润增加”不是一条自动成立的链。** 可收费的经济单位是持续保护的企业部署、员工或客户访问、受治理权限、完成并验收的服务以及承担责任的控制能力。大量临时代理身份、认证请求、检测结果和治理清单可以增长，客户的独立账单却不增长。身份与AI安全是整体安全池的子集，不能与整体支出相加。

最值得关注的价值迁移，是从“识别风险、显示告警”转向“能够约束动作、完成修复，并留下责任证据”。这一迁移会同时产生三种结果：掌握身份、执行入口和客户合同的平台增加附加销售；基础认证、文本过滤及一般政策目录被平台或开源内化；复杂跨系统权限、修复流程和监管证据仍需要专门能力。技术重要性并不保证独立收费。

决定判断的证据及模型含义集中如下，详细事实、期间和出处在后文交付一次。

| 观察 | 性质与关键数值口径 | 经济含义及不能推出的结论 |
|---|---|---|
| 整体安全市场已有较大现实基数 | E：Gartner 2026年2月公开预测全球2026年信息安全支出约2440亿美元；这不是2026年实际结算额 | AI安全可以快速增长而对总池贡献仍有限；不能用少数高增长厂商代表全行业 |
| AI安全尚是小池、分类仍在变动 | E：Gartner 2026年8月预测Securing AI支出2026年28.35亿美元、2027年47.83亿美元、2028年接近77亿美元 | 本报告基准模型为2027年47.43亿美元、2028年71.03亿美元，已受到外部预测校准，不能称为独立的第二份验证 |
| Agent SSO和云端身份原语出现包内收费 | F：Okta将Agent SSO纳入原有SSO；AWS经Runtime或Gateway使用AgentCore Identity不另收费 | 原始机器身份数量不能直接乘人类席位价格；收费向治理、特权、责任和部署复杂度迁移 |
| AI治理的市场数字发生版本冲突 | E：Gartner 2月给出2026年4.92亿美元，8月较新分类给出2.75亿美元；公开材料没有桥接 | 保留两个原值，不取均值、不解释成行业收入骤降；狭义基准采用较新2.75亿美元 |
| AI已形成真实漏洞修复案例 | F：Mozilla 2026年4月21日披露Firefox 150修复了初步评估中AI识别的271个漏洞 | 发现能力已超出纯演示；有限案例仍不能证明全球软件已安全，或修复、回归测试、部署成本一并消失 |
| 预算和实施能力并非无限 | F：英国调查企业攻击/泄露识别比例连续两版均为43%；ENISA样本安全预算占IT约9%，76%报告招聘困难 | 威胁强度、识别能力和预算不同步；增加产品不等于能实施、验收和兑现 |
| 收入、调整后利润与股东经济收益有差距 | F/C：Palo Alto FY2026 GAAP经营利润率约6.1%，调整后约29.2%；Zscaler最新季度FCF率7% | 再投资、股权报酬、并购与基础设施会吸收增量收益，高软件毛利不等于高资本回报 |

**当前最有依据的基准路径**是：2027—2028年普通安全和身份需求温和至较快增长，AI专用安全从小基数扩大；软件交付数量增长快于净价，身份治理与复杂权限的收费优于基础认证；平台较容易形成规模收入，独立AI安全供应商的利润兑现更晚。选择这一基准来自既有安全池、真实付费厂商、已上线的包内功能和实施约束，未取乐观与悲观的算术平均。

| 全球年度支出模型 | 2026校准点 | 2027：悲观 / 基准 / 乐观 | 2028：悲观 / 基准 / 乐观 |
|---|---:|---:|---:|
| 整体信息安全 | 244.000 | 243.237 / 275.273 / 308.168 | 226.264 / 305.716 / 385.996 |
| 其中：身份权限 | 34.000 | 33.115 / 39.241 / 47.245 | 30.574 / 45.715 / 63.455 |
| 其中：狭义Securing AI | 2.835 | 2.780 / 4.743 / 7.196 | 2.549 / 7.103 / 13.882 |

以上全部为I，除AI校准点来自明确标注的E。它们是可复算的代表参数点，保留三位小数只是方便审查算术，经济判断不具有相应精度。整体2026年校准范围为235—265十亿美元；身份权限分项合计22—47十亿美元；AI分项合计1.81—4.40十亿美元。这些是有口径误差的条件范围，不能把所有上界相加。附录给出各分项的当前范围、每条路径的需求、履约能力、净价、成本、经营模型及2027/2028范围。

**最强反面解释**是：AI防御和平台整合显著降低每单位保护的成本，客户以相近或更低预算完成更多工作，独立产品被替代，服务人员减少，整个行业支出可能收缩。已有包内收费、开源授权和真实自动化能力支持这一路径。反对它的证据是传统与新增攻击面持续共存，治理与权限供应商仍形成真实付费增长，组织修复能力不能即时自动化。现有证据不足以排除总池收缩，因此悲观情景明确保留2028年低于2026年的收入结果。

真正影响结论的未解决问题有四个：套餐实际分摊后的净价；生产环境中具写权限代理的规模与控制覆盖率；AI安全收入中“其他”类别的产品组成；自动化节省最终成为客户现金节约、增加覆盖还是供应商利润的比例。当前没有可靠全行业观测值。

## 二、客户究竟购买什么：责任边界与不能相加的预算

### 2.1 产品边界与经济单位

| 支付任务 | 客户购买及验收对象 | 常用经济单位 | 采购/预算负责人及失败成本 |
|---|---|---|---|
| 端点、网络、云及应用安全 | 资产可见性、攻击阻断、检测、修复与恢复能力 | 受保护端点、受保护吞吐、应用/云部署年、检测与修复服务 | CISO、IT及云平台团队；业务中断、数据损失和合同责任 |
| 员工身份访问 | 登录、设备与会话条件、加入/转岗/离职的访问控制 | 持续受保护员工年及应用连接复杂度 | IT、IAM与HR；账号失控、离职权限未撤销 |
| 客户身份CIAM | 对消费者/客户的认证、账户恢复、欺诈防护及授权 | 付费应用部署年、活跃用户/认证量阶梯 | 产品/开发团队及安全；交易流失、欺诈、恢复失败 |
| 特权访问PAM | 高权限凭据、短期授权、会话审计与紧急访问 | 特权账户/系统、受管理企业合同年 | 安全与运维；高权限动作及横向扩散 |
| 身份治理IGA | 权限盘点、职责分离、访问审批/复核、合规证据 | 受治理身份/权限组合、企业治理部署年 | IAM、内审、合规和应用所有者；错误授权、审计失效 |
| 机器身份、秘密与非人类身份 | 密钥/证书/服务身份生命周期、拥有者与授权 | 持续受治理工作负载/秘密集；认证请求是另一单位 | 云/开发平台与安全；凭据泄露、无人负责的访问 |
| AI应用安全 | AI开发链、模型接口和运行时攻击面的测试与防护 | 生产AI应用部署年、风险级别、持续评估量 | 应用、AI平台和安全；越权、外泄、错误动作 |
| AI使用控制 | 对员工使用外部/内部AI的访问、数据和活动控制 | 被保护员工/应用覆盖年 | CISO、IT与数据保护；敏感数据外发 |
| AI网关 | 模型/工具入口的策略执行、路由、记录与控制 | 企业网关部署年、请求量及保护强度 | AI/开发平台与安全；控制绕过或阻断业务 |
| AI治理平台 | 用例/模型台账、风险分类、评估、责任、变更审批和审计证据 | 具有实际责任流程的企业部署年 | 法务、风险、业务和AI治理委员会；无法证明合规与问责 |

一般的数据目录、主数据质量、分析血缘和数据仓库归相邻“数据治理/数据平台”专题；只有为访问安全、AI风险责任或审计所购买的增量功能归本专题。模型训练/推理、一般AI观测和应用开发成本也不因产品自称“治理”而全部归入安全收入。安全AI用于SOC属于既有安全产品升级；保护AI系统的专用控制才进入本报告狭义Securing AI池。

鉴权、授权、治理不能互相替代：鉴权回答“谁”；授权回答“能执行什么”；治理回答“由谁负责、依据什么批准、如何持续复核”。一个代理继承用户身份，仍可能不应继承该用户的全部可执行权限；只有目录记录而没有执行控制，也不能防止错误动作。

### 2.2 总池、可加子池及相邻不可加池

本报告总池是最终客户为外部安全产品和服务支付的年度金额，包含企业/政府主池，并沿用整体市场锚点中未能完全剥离的消费者安全等尾部。内部安全人员工资、保险赔付、网络犯罪损失、云通用计算、一般数据治理和AI应用业务收入不加入总池。内部工资是ROI及替代关系的重要参照，另行讨论。

为模型建立互斥的五层：**其他安全软件＋身份权限软件＋狭义AI专用安全软件＋外部安全服务＋网络安全设备及不可分的平台功能**。在现实账单中按主责功能分摊；跨主题套餐只分一次。分类是研究分摊，不声称与任何机构逐行一一对应。

例如，客户给MDR供应商支付100万美元，其中供应商采购20万美元安全软件：研究终端池时保留100万美元，或拆成软件20万＋净服务80万；不能将客户100万与上游20万相加成120万。研究供应商收入可分别观察两层，但其收入合计不是终端需求。渠道折扣、转售总额与净佣金也需用同一处理方式。

Microsoft E5/E7包含身份、终端和安全AI能力，客户的整套办公订阅不是安全收入。无法观察到的套餐内部安全分摊属于U。Palo Alto包含收购业务，Zscaler包含Red Canary，不能把被收购公司收入再加一遍；可观测性收入也不能全部视为安全。机器身份上的通用PAM/IGA功能归身份池，只有额外购买的AI专项保护归AI池。Gartner“Other Securing AI”没有足够明细，模型使用残余池并保留覆盖不确定性。

预算可能来自新增安全拨款，也可能来自取代旧单点工具、减少外部咨询、转移应用开发预算或减少内部人工。新AI预算仅在客户实际增加外部付款时扩总池；账单内部搬家改变价值分配，不能自动计为新增需求。

## 三、技术前沿与采用：为什么执行边界比代理数量重要

### 3.1 从代理身份到动作授权

成熟SSO/MFA、PAM和IGA已具备规模付费基础；“所有机器身份都按员工席位收费”仍是商业假说。Okta于2026年8月24日宣布Agent SSO正式可用并纳入核心SSO，不另加费用；扩展发现、生命周期和治理则属于其AI代理产品路径。前者证明产品交付，不能证明后者已形成可单独识别的大额收入。[Okta Agent SSO公告，2026-08-24](https://www.okta.com/newsroom/press-releases/okta-brings-first-class-identity-to-ai-agents-with-agent-sso/)

AWS当前价目表同样将经AgentCore Runtime/Gateway使用的Identity列为无额外收费，其他场景为每千次非AWS OAuth令牌/API密钥请求0.010美元；Gateway标准调用每千次0.005美元，Policy授权检查每次0.000025美元。页面未给统一发布日期，本报告于截止日核验，适用公开标价而非企业合同净价。**C：一亿次请求若分别触发一次上述调用，身份、基础Gateway和Policy检查的标价合计约4000美元，其中Identity约1000美元；包内身份情形还会减少这一金额。** 不包含模型推理、高级护栏、日志、网络、托管、客户集成及其他调用。这只能约束“请求增长等于大量身份许可收入”的说法，不能代表完整AI安全成本。[AWS AgentCore定价，核验2026-10-10](https://aws.amazon.com/bedrock/agentcore/pricing/)

微软Entra Agent ID在2026年5月公开文档中进入正式可用阶段；Agent 365与E7的组合提供平台分发入口。正式可用与有偿渗透分别判断，微软并未公开足以单独复算的代理治理收入。[Entra Agent ID更新，2026-05-01](https://learn.microsoft.com/en-us/entra/agent-id/whats-new-agent-id)，[微软端到端代理安全说明，2026-03-20](https://www.microsoft.com/en-us/security/blog/2026/03/20/secure-agentic-ai-end-to-end/)

**本报告推断：机器身份价值的计价分母会从原始“身份个数”转向持续受管理的应用、拥有者、特权边界和风险责任。** 相同工作负载可以创建成百上千临时身份，但只形成一份持续治理合同；相反，一个高度特权的跨系统代理即使调用较少，也可能需要昂贵的接入、审批和审计。这解释了机器覆盖加速与单位收费下降可以共存。

### 3.2 模型输出不能成为自己的权限证明

MCP 2026-07-28版本的原始安全文档要求令牌受众校验、避免令牌透传、按客户端获得同意，并采用最小权限及渐进授权。它是协议/实施规范，不是“所有接入者已经安全”的认证。[MCP安全最佳实践，版本2026-07-28](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices)

可行控制链如下，模型在受限制能力内提出动作，执行侧独立验证：

~~~mermaid
flowchart LR
  U[用户与任务责任人] --> ID[身份与委托范围]
  ID --> A[代理提出工具动作]
  A --> P[确定性策略与权限检查]
  P --> G[受控网关或执行器]
  G --> T[应用与数据]
  P --> H[高风险人工批准]
  H --> G
  G --> L[日志、复核、撤销与责任证据]
~~~

“确定性”指规则判定及强制执行，不意味着政策永远正确。LLM识别恶意文本可以作一层检测，但不宜让不可信内容自行扩大网络、文件或付款权限。授权检查必须放在实际执行点；目录和策略建议若不能影响执行，经济价值主要是可见性和审计。

Open Policy Agent及OpenFGA已经提供开源政策/细粒度授权基础设施。它们压低通用策略原语的许可溢价，但客户仍需配置业务对象、维护身份绑定、处理策略变更、运行服务和承担故障。开放标准使跨平台控制更容易，也给客户自研和集成商替代单点软件创造条件。[OPA原始文档，截止日版本](https://www.openpolicyagent.org/docs)，[OpenFGA项目说明，截止日版本](https://openfga.dev/project)

前沿商业机会因此集中于：跨系统最小权限能否真实执行；谁维护授权对象及责任人；撤销与回滚是否及时；能否向业务与审计证明全过程。仅增加一个“agent目录”较容易被平台吸收。

### 3.3 AI检测与修复：从发现瓶颈转向修复瓶颈

Mozilla在2026年4月21日披露，Firefox 150包含对初步Mythos Preview评估中识别的271个漏洞的修复。这是客户/软件维护方公开的真实修复证据，强于仅由模型厂商报告一个检测分数；它仍是高能力团队与特定代码库案例。[Mozilla原始文章，2026-04-21，对应Firefox 150发布](https://blog.mozilla.org/en/firefox/privacy-security/ai-security-zero-day-vulnerabilities/)

Anthropic在5月22日Glasswing阶段更新中给出约23019个候选漏洞、其中6202个估计高危/严重的规模，并根据验证样本估算约3900个真实阳性；数字具有分类与抽样外推限定，不能写成“6202个已经确认且修复的零日”。4月7日项目宣布的1亿美元是使用额度承诺，不是最终客户已支付的安全收入。[Glasswing初步更新，2026-05-22](https://www.anthropic.com/research/glasswing-initial-update)，[项目公告，2026-04-07](https://www.anthropic.com/glasswing)

经济链条是：发现更多候选问题→去重和确认→定位责任团队→代码修改→回归及兼容测试→客户部署→减少可利用暴露时间。第一步降价和放量，后续步骤可能增加短期工作。若修复积压增长，客户未必持续购买更多扫描量，反而可能限制扫描或要求闭环产品；若发现和修复均自动化，传统按扫描/人工小时计费的收入可能减少。

最强替代假说是“模型能力由云/开发平台直接提供，单独AppSec工具被削弱”。支持证据是维护方已直接获得模型能力、通用策略工具开放；反对证据是业务资产关系、修复验收和组织责任并非模型权重中的通用知识。是否持续缩短已确认漏洞到实际部署的中位时长，比候选漏洞数更能判断商业价值。

### 3.4 人工批准不等于安全责任已经履行

Anthropic 2026年5月25日工程材料披露，其内部用户约93%的权限提示被批准。该比例是厂商特定内部场景，不能外推全球用户；它表明高频批准可能变成低信息决策，不能把“有人点了允许”当成有效风险缓释。同一材料讨论隔离及网络边界，支持将模型检测与运行时约束组合的路径。[Anthropic containment工程材料，2026-05-25](https://www.anthropic.com/engineering/how-we-contain-claude)

本报告推断：高价值控制将减少需要用户逐项判断的低风险动作，将人工资源留给少数有金额、敏感性或不可逆责任的操作。成功标准应同时包含任务完成率、授权内动作比例、漏阻断、误阻断、可回滚率及人工分钟数。单一“攻击检测率”或红队排行榜不足以推断客户ROI。

### 3.5 采用阶段与商业兑现

| 方向 | 截止日阶段判断 | 下一阶段需要什么 | 收入/现金的额外条件 |
|---|---|---|---|
| 基础SSO、MFA、PAM、IGA | 已规模商业化，F有上市公司收入/ARR | 扩大连接、治理对象和复杂权限 | 净留存、增购、实施验收；并非每新增身份多收费 |

| AI网关、使用控制 | 已有商业产品，但全行业付费拆分U | 生产流量经过控制且不被绕过 | 净价覆盖推理/检测/日志成本，包内替代可控 |

| AI治理证据平台 | 商业化与咨询并存，分类U | 台账接入实际采购、变更和审计流程 | 多部门责任归属、非重复预算、法规验收 |
| 大范围自主SOC/修复 | 部分任务可工程验证；全闭环行业规模尚未证明 | 接受有写权限的自动动作且失误成本可控 | 可度量人力/外包节约，而非仅增加被审查工作 |



## 四、需求侧：安全责任持续，预算扩张需要具体桥梁

### 4.1 风险观测与预算观测分别处理

英国政府2025/2026版调查于2026年4月30日发布，企业访谈在2025年8—12月进行，问的是之前12个月。样本为2112家企业，企业识别到攻击/泄露的比例43%，与前一版相同；不包括无IT企业和个体经营者。它不能证明全球攻击没有增加，也不能证明预算需要按攻击叙事同比增长。检测能力、样本结构和行为报告影响观测值。[英国政府调查，2026-04-30，对应回溯调查期](https://www.gov.uk/government/statistics/cyber-security-breaches-survey-20252026/cyber-security-breaches-survey-20252026)

Verizon于2026年5月19日发布的DBIR案例资料将漏洞利用列为31%的初始进入方式，并指出第三方参与48%的泄露。这是报告收录案件的结构，不是所有企业的年度泄露概率；公开新闻页不足以完整重建每一来源案件的时间边界，本报告不把其当成截至10月的实时全量测量。[Verizon 2026 DBIR原始公告，2026-05-19](https://www.verizon.com/about/news/breach-industry-wide-dbir-finds)

ENISA 2025投资研究于2025年12月发布，覆盖欧盟关键部门1080名专业人员，83%样本为大型组织。样本安全预算占IT预算约9%、中位数约150万欧元，预算占比基本维持前期；76%报告招聘困难、71%报告留人困难。主要限定是关键部门和大企业偏重，不能外推所有企业的安全预算率，也不能把“招聘难”转换成同额未满足的软件采购。[ENISA研究，2025-12-08](https://www.enisa.europa.eu/publications/nis-investments-2025)，[ENISA研究摘要及样本说明，2025-12](https://www.enisa.europa.eu/news/whats-driving-cybersecurity-investments-and-where-lie-the-challenges)

上述证据支持三种不同需求：持续保护存量业务；接入新增云、软件供应链和代理；解决实施与人员不足。第一种稳定预算，第二种扩保护数量，第三种可能买外包/自动化，也可能延迟项目。三者不应一律当成净新增许可。

### 4.2 身份需求的可兑现桥梁

微软2026年1月28日FY2026 Q2电话会披露，Microsoft 365商业付费席位超过4.5亿，同比增长6%；经济期间为2025年10—12月。它提供大规模企业员工数字接入的锚，但这些席位不是全部另付费Entra席位，也不是全球不重复员工人数。[微软原始电话会，2026-01-28](https://www.microsoft.com/en-us/investor/events/fy-2026/earnings-fy-2026-q2)

本报告员工访问基准的覆盖量2028年为2026年的115%，包含员工数、连接与实际保护采用；低于按代理原始数量指数增长的推法。净价指数96意味着更多高级覆盖抵消部分包内降价。IGA和PAM的基准覆盖量分别153、140，原因是治理对象和应用连接增加，而非单纯员工增长。此增长路径有付费治理供应商现实基础，仍须通过访问复核质量、续费和部署速度兑现。

CIAM需求更依赖应用用户、业务采用和账户风险。按免费MAU/流量扩张不能自动推出收入；被动低活跃账户、缓存认证和低价开源替代可能降低每次访问成本。模型采用付费应用部署等价量而非把全球消费者加总成收费身份。

机器身份的基准覆盖量2028年185、净价90，悲观覆盖量135但净价60。相同客户拥有更多机器身份和更低每身份支出可以同时发生；能够维护权限拥有者、撤销秘密与处置高风险访问的厂商，才有条件抵抗原语降价。

### 4.3 AI治理监管对预算的时滞

欧盟官方时间表截至截止日已反映2026年7月27日生效的AI Omnibus修改：一般规则在2026年8月2日适用，Annex III所涉高风险用例义务延期至**2027年12月2日**，嵌入受监管产品的相关高风险规则至**2028年8月2日**。不再采用旧版“所有高风险义务均在2026年落地”的需求时钟。[欧委会当前AI Act时间表，核验2026-10-10；对应2026-07-27修订](https://digital-strategy.ec.europa.eu/en/policies/regulatory-framework-ai)

法规需求涉及风险评估、数据质量、记录、责任、监督和上市后监测；一部分可由已有GRC、内审和工程流程完成。法规并未等同于必须采购独立AI治理平台。采购可能在期限前启动，规模收入则取决于范围识别、项目验收和续费。延期使2026年预算爆发的推断变弱，并可能把实施集中在2027—2028年；不能把期限以后全部视为无需求。

中国2026年9月14日发布的《人工智能安全治理框架》3.0提供新的风险与治理框架；GB/T 45654—2025《网络安全技术 生成式人工智能服务安全基本要求》于2025年4月25日发布、2025年11月1日实施。框架和推荐性国家标准可影响产品、采购与验收，但不能直接换算为全国新增付费软件金额，也不把“GB/T”自身描述为新增强制许可。[网信部门框架3.0，2026-09-14](https://www.cac.gov.cn/2026-09/14/c_1791137092283345.htm)，[国家标准原始登记，2025-04-25](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F67D3F376E0A0A0FF5317FB36B32A30A&refer=outter)

地域经济差异需落在业务：美国大型企业的云与软件订阅更易将控制放入既有平台合同；欧洲监管证据和本地履约可能增加专业服务与审计投入；中国对本地部署、数据与采购要求的适配，使本地交付与集成重要。后两项为I，不给没有来源的地区市场份额。数据驻留、认证、跨境限制和采购周期会抬高固定实施成本，使同一通用技术不能按全球统一净价或利润率交付。

## 五、供给侧：许可通常不稀缺，合格部署和责任闭环有结构性约束

### 5.1 有效供给的业务单位

软件可以复制，但可交付能力还需可运行产品、应用连接、经过验证的策略、客户数据接入、业务测试、人员与持续支持。供应商宣称支持某标准是设计能力；安全团队完成测试是工程验证；生产范围正式上线和续费才接近有效商业供给。名义功能数不是合格部署数。

| 层级 | 当前独立供给判断 | 主要约束与释放方式 | 价格和利润的方向 |
|---|---|---|---|
| 基础认证/策略原语 | 平台和开源均有现实能力，较接近充足供给 | 云容量、接口和客户配置；通常可弹性增加 | 包内和低价服务压低独立收费；采购方收益较大 |
| 普通安全软件 | 多平台、单点与托管能力并存，缺少全行业许可短缺证据 | 渠道、转换成本和合并产品质量 | 替换与打包可在续约时降净价 |
| PAM/IGA和复杂机器治理 | 技术供给不少，合格接入/治理责任可能不足 | 旧应用、权限语义、业务所有者与实施队伍 | 高责任项目能保持收费，但服务成本也高 |
| AI应用安全/治理 | 新进入者及并购扩产品；验证仍不充分 | 真实攻击/误报测试、动作安全、跨团队验收 | 不必然出现涨价；采购可推迟或接受平台基本层 |
| MDR/事件响应 | 人员与客户情境影响交付 | 自动化、流程标准化、招人、区域与值班 | 人力节约可被价格竞争传给客户 |
| 网络设备/平台 | 交付涉及硬件、渠道及安装，不能当无限复制的软件 | 元件、ASIC、库存、认证、性能与客户更新周期 | 单位吞吐变便宜和产品组合升级可同时发生 |

目前更接近**普通产品供给充足、预算/迁移约束较重要；高责任授权和修复存在结构性缺口**。证据是可用的云、开源与GA平台，以及ENISA的人员困难、实际修复所需团队投入。没有足够证据宣称全球安全产品整体短缺、因此普遍涨价。

### 5.2 独立供需估计与可审查的能力阈值

附录中的D是按客户任务、预算与付费采用建立的需求；S是按供应商和客户能够合格支持的年度部署/工作量建立的**条件能力假设**。S不由目标收入除以价格来证明。全行业实施队伍和合格项目成功率未知，故S用于压力测试，并非已观测的产能序列。

以狭义AI治理为例，2026校准点2.75亿美元、等价年净价5.5万美元对应5000个付费组织年。需求侧假设2027年覆盖量8500个、2028年14000个；增量来自用例纳管和真实付费采用，不能从法规直接推出。将2027年可寻址且已有实质AI资产的企业设为2万—3万家、付费采用25%—45%，得到5000—13500个组织年；企业总体和采用率均为I，不是调查事实，Okta等企业客户基础仅提供数量级参照。

供给侧另从实施估计：若存量90%可持续服务，加上250—650支合格团队、每队每年12—20个项目、验收成功60%—85%，2027年支持能力为6300—15550个组织年。模型基准9500个处于这一条件范围，需求8500低于基准能力；下界供给则会限制交付。团队数为未知的情景参数，不能据此声称已验证9500个产能。达到基准只需约5000个净新增合格交付，例如400队×20项目×62.5%验收＋4500存量；若这些队伍不能形成，收入应下调。

同样，AI应用安全2026年5080个10万美元等价部署年，2027年基准需求8382、能力10160；90%存量续服加约5600个新增交付可形成该能力，约400队×20项目×70%验收能够满足。2028年基准需求13208、能力16256，仍以团队增长和复用提高作为供给条件。AI应用的“部署年”是加权持续保护范围，不是一次扫描或每个聊天会话。

IGA校准为2.4万个25万美元等价企业合同年。2027年基准需求2.952万、能力3.12万；95%存量维持后需8400个新交付等价量，约1400队×10项目×60%验收。2028年能力4.08万对应新增11160等价量，约1550队×12项目×60%。这是可审查的履约门槛，真实全球团队存量U；大型平台伙伴网络和复用能降低门槛，复杂老系统与业务所有者缺失提高门槛。

上述区间交叉表明：AI治理与应用安全可能有高端结构性供给不足，也可能在付费采用不足时闲置。模型乐观2028年AI应用需求500、能力430，治理需求550、能力450，差额分别约14%、18%；它表示愿意付费但暂不能通过验收的工作量，不是软件本身无法复制。P可以上升也可以被平台替代压住，短缺并不自动兑现溢价。

### 6.3 价值与资本的联合判断

平台拥有客户入口、遥测和合同，较容易降低获客成本及分发成本；但客户会要求套餐折扣，集成失败或服务故障会使整个平台承担更大责任。跨平台中立治理、专门攻击研究和高责任权限仍可独立收费，前提是客户能检验其对平台基本层的增量价值。

检测原语、通用网关和目录容易竞争；执行边界、业务权限图、持续证据和修复闭环较难替换。难替换也可能来自沉重实施，而非技术优越；实施收入高但人力成本和付款周期长。大平台通过收购取得入口，卖方原股东获得一次性价值，并购方后续ROIC仍取决于支付价、留存与新增利润。

Alphabet原始披露的Wiz调整后收购价约295亿美元，与公告总价口径不同。本报告不利用两个口径的差额推断便宜或昂贵。C：若要求对295亿美元投入获得10%的年税后经营回报，需要约29.5亿美元年税后经营利润；没有独立Wiz利润与整合投入明细，无法断言该门槛已达到。[Alphabet收购会计说明，2026年披露、对应2026-03-11交易](https://www.sec.gov/Archives/edgar/data/1652044/000165204426000048/R17.htm)

利率和融资在此通过客户采购审查、私营公司融资期限、并购资本成本和回款传导；云价格与工资通过单位交付成本传导；数据驻留和贸易限制通过本地部署、产品资格及重复团队投入传导。没有证据支持把它们统一加为一个“宏观风险溢价”。

服务年度工时、网络设备同规格全球交付数以及其他软件加权覆盖总数U，因此使用各自2026＝100的工作量指数和美元基数，不能假装美元收入能力等于物理产能。服务以有质量验收的受保护工作量计量；网络以性能/保护等价覆盖计量，不能单看机箱数。下文给出服务小时的客户与供应商例子，并以模型分项推导整个服务池的方向与条件。

### 7.4 模型公式和三条路径的机制

对每个支付任务j和年份t：

- 实际合格交付数量指数：Q＝min(D，S)。D是客户愿付费且有任务的潜在有效需求，S是合格支持/交付能力；2026校准数量、净价与单位成本指数均设为100。
- 收入：R＝R₀×Q/100×P/100。P是净变现指数，明确包含套餐功能归属，不能用标价乘原始身份或Token数。
- 单位交付成本：K＝K₀×C/100，C反映每加权覆盖单位的计算、人力、日志/网络、支持及设备成本。
- 代表业务的交付贡献率：1－v₀×C/P。v₀为2026交付成本占收入比；它不自动等于公司GAAP毛利率。
- 固定费用：F＝f₀×R₀×F指数/100。此处R₀为一个同功能代表业务的2026收入；包括持续研发、销售、管理及经济性报酬，扩产品和合规仍需再投入。
- 代表业务EBIT率＝[Q×P/10000－v₀×Q×C/10000－f₀×F指数/100]÷[Q×P/10000]。费用、收入与数量采用同一业务边界。

全行业终端支出不直接乘上述利润率。代表业务假定保持相同任务市场中的相对份额，用于检验规模能否覆盖成本；真实厂商份额、经销净额、固定成本、并购资本、税、融资及赔付均不同，行业总利润U。附录费用底表是I，不是从未披露的公司细项冒推出来的F。

| 路径 | 2027—2028需求与交付 | 净价、单位成本与固定费用 | 谁较可能得到价值 |
|---|---|---|---|
| 悲观：覆盖增加、预算内化与竞争压价 | 多数保护量仍增加；员工增长慢、AI付费采用弱；供给一般充足，复杂接入仍不能省略 | 包内、开源和客户采购压P；计算降本但专家工资/复核刚性；研发/获客费用先支出 | 客户获得更多覆盖；弱单点和服务方收入/利润可能下降 |
| 基准：责任扩大、付费落地、净价温和受压 | 存量安全更新；IGA/PAM及机器治理增购；AI从试点走向生产，供应商/伙伴复用改善 | 单位成本下降；高级责任抵消部分基础降价；固定费用仍增长，AI治理未必盈利 | 有入口的平台与有责任闭环的专门产品；服务现金改善较温和 |
| 乐观：高责任生产采用加速且验收能力形成 | AI部署显著增加，传统软件和服务覆盖扩；应用/治理在部分阶段受合格交付约束 | 净价可由高级组合维持/提升，成本因复用下降；必要产品和交付投资更多 | 平台、权限/治理和闭环厂商；客户仍获得较低单位成本 |
| 突破分支：可信自主处置使服务劳动大幅下降 | 在基础路径之外，更多工作能以相同预算完成 | 工时和净价均下降；收入可下降而利润率增加 | 客户和高效率交付方；按人时销售且转型慢的厂商损失价值 |

基础安全软件2028年基准D131/P98，身份治理D153/P102，机器治理D185/P90，AI网关D380/P68，服务D120/P97，体现不同采用与定价机制，未使用一个统一增长倍率。乐观设备路径可包括客户更新、保护性能和后量子迁移；Cisco公开路线图涉及具体平台与软硬更新条件，不证明所有设备立即必须更换。[Cisco量子安全原始路线图，2026年材料](https://www.cisco.com/c/dam/en_us/about/doing_business/trust-center/docs/quantum-safe-communications-roadmap.pdf)

### 7.5 什么叫放量，什么叫利润扩张

客户覆盖放量只需Q上升；收入放量需Q×P上升；交付贡献增加还需P相对C改善；经营利润扩张需贡献额超过固定投入增量；现金释放还需合同回款覆盖资本化投入、更新、设备和营运资本。依次多一个条件，不能合并。

附录代表业务模型给出的2028年基准员工访问EBIT率约14%，IGA约8%，机器治理约7%；独立AI应用安全约－10%、AI治理约－29%。这些是成本/份额假设下的机制结果，不是厂商利润预测。它们说明数倍市场增长仍可被研发、集成和获客吸收。

AI网关乐观模型的经营利润率较高，依赖持续取得付费任务、成本快速下降、固定费用复用及没有被平台包内替代。若这一通用原语很容易复制，竞争会通过P或相对份额把理论利润交给客户；因此不能把表中的高利润率写成行业常态。相反，悲观中的大额负利润意味着业务需要缩减费用、退出或被收购，并不预测亏损机构会无限经营至2028年。

AI治理独立厂商基准需实现收入/2026收入约2.66倍，但固定投入约2.25倍且初始研发销售负担高；要达到盈亏平衡，给定基准成本/固定费，所需收入指数Q×P/100达到约394，而模型为266，或将固定费用降低约32%。这是经济门槛，不是监管标准。减少重复实施、降低获客成本或被大平台复用能改变结果；单独提高台账数量不足以过线。

### 7.6 套餐归属与独立收费的敏感性

本报告总AI池含独立账单和可归属的套餐安全付款，不把免费功能按影子标价计作支出。独立专用许可占比U，作为额外敏感性设2026年60%，2027年悲/基/乐40%/60%/70%，2028年30%/55%/75%，**不改变总池，只分配付款入口**。

C：在代表规模点下，2028年独立专用许可分别约0.765/3.906/10.411十亿美元，其他属于平台或组合归属；这些不是直接观测值，不与总AI池相加。若套餐没有对应增量付款且无法合理归属，应同时下调总池与独立占比，而非硬分出虚构收入。Standalone治理/网关的“市场重要”与“独立发行方可保留收入”因此是两个问题。

再作一个完全内化的反面分支：假设AI防护全部成为普通安全软件功能，2026年2.835十亿美元重新归回其他软件，后续按该行基准覆盖/净价指数131×98运行，保持同一2026总池。C：2028年整体变为302.252十亿美元，较原基准305.716减少3.463十亿美元，约占原结果1.1%。这不是确认AI没有价值，而是说明AI专项高增长对大安全池的增量影响有限，独立AI供应商收入却可因内化大幅减少。若真实账单存在交叉，必须重新分配并重估两个分项增长率，不能只声明避免重复后继续各自相加。

## 八、客户ROI、服务利润与自动化突破

### 8.1 同一SOC客户边界的示例

下面均为I，单位美元，客户、工作量、验收和成本使用同一边界。目的在于约束支付意愿，而非将一个样本假装为全球节约额。

- 现有年告警10万条，初审每条10分钟，约16667小时；含福利、工具与管理的每小时成本60美元，初审成本约100万美元。
- AI覆盖60%告警、对覆盖部分减少70%初审工时，释放7000小时，即42万美元能力。
- 额外异常复核按全部告警3%×10分钟＝500小时，质量审计1000小时，合计9万美元。
- 年许可18万美元、额外计算2万美元，持续净收益13万美元（尚未扣下述必要更新）；初始接入和验证15万美元，计入年度更新后第一年净现金约－5万美元，未含税和折现。
- 五年分析期假设每年持续更新/重新验证3万美元、第三年重大更新8万美元、期末残值0：现金序列为－15万起始投入；第1—5年分别10万、10万、2万、10万、10万美元。按10%折现净现值约16.9万美元（C，四舍五入）；任务保持和回款/节约兑现是必要条件。
- 若告警量增加而不裁员，收益是容量与质量，不是现金工资减少；若漏处置导致平均额外损失每年13万美元，持续净收益归零。该损失是门槛参数，不是已测事故概率。

因此，低成本模型本身不够。若每千条告警的复核分钟、误处置损失或连接维护上升，客户能付的许可会减少；若它持续完成更高价值修复，支付意愿可以高于纯初审节约。

### 8.2 同一MDR交付方边界的示例

2026代表交付方100客户×10万美元ACV＝1000万美元收入；交付成本600万（人员450万、云100万、质控/保险50万）；研发销售管理300万；EBIT100万。没有将客户内部工资加入供应商收入。

AI使人员成本减少150万，额外云成本40万、质控30万，交付净降80万至520万；如果续约价降10%，同等客户收入900万，固定费用仍300万，EBIT只有80万。**成本下降13.3%而经营利润下降20%**，说明节约可以被采购方拿走。若净价仅降5%，同条件EBIT130万，才出现供应商利润扩张。

将这个例子放回行业模型：基准服务2028年D120、S128、P97、C94，得到1082.52亿美元收入，代表经营率约7.5%；悲观P85、C105即使交付量108，代表经营率约－15.9%；乐观交付量134、P104、C85，代表经营率约20.2%。利润率仍是单位机制，不是全球服务总利润。只有多数合同具备降本和保价/扩客户能力，方向才可推广；无法识别这一占比时保留宽条件判断。

### 8.3 自动化突破的额外条件与数值

突破成功标准定义为：截至2028年，至少三家独立交付主体各自有50家以上生产客户，在可比较任务中自动闭环覆盖超过50%，单位客户人工交付小时减少至少30%，且可公开核验误处置/重大事件表现未恶化。“至少一个演示成功”不满足；这个研究门槛不是行业认证标准。

对基准服务分支施加额外机制：工作量需求/能力再增加20%，净价比基准再降20%，单位交付成本比基准再降25%，固定费用比基准再增10%。D144、S153.6、P77.6、C70.5、F126.5；C：收入约1039.22亿美元，比普通基准1082.52亿美元更低，交付贡献率约36.4%，代表EBIT率约8.1%。固定费和转型投入若更高，利润提升也会消失。

因此，可信自动化并非“只加更高增长率”的乐观情景：服务行业收入可能减少、客户覆盖扩大、较强交付方利润率改善。软件或模型平台可能获得部分原有服务价值，但不能将节省的工资和软件收入各加一遍。

本报告使用的研究阈值：若同任务净价下降超过累计覆盖增长的倒数门槛，收入即开始下降；例如覆盖＋20%时净价低于83.3，收入低于基期。若净价下降快于单位成本下降，交付贡献率下降。若合格能力低于需求超过约10%且客户不接受替代，才有条件形成可感知交付缺口；10%是此模型的观察门槛，不是行业标准。每项都需比较同一产品范围、地域、期间与单位。

### 9.4 覆盖缺口和结论对其敏感程度

1. **缺实际成交价、套餐安全归属和AI收入拆分，影响最高。** 它决定使用增长是否变收入。已在P、独立收费占比与宽基数范围中体现；不能靠供应商TAM补齐。
2. **缺全球合格实施人数、项目验收率和当前供给余量，影响较高。** S是条件压力测试；普通软件较接近充足供给，复杂权限/闭环交付偏结构约束的判断来自产品与客户证据，不是测量过的全行业产能。
3. **缺私营厂商的现金、留存和市场份额。** 保留其产品位置而不外推利润；已完成收购重新归属。
4. **缺中国及中小客户完整可比样本、消费者尾部分项。** 全球模型沿用总体锚，不能输出可靠地区或企业规模份额；地域合规的成本机制比精确地区金额更可信。
5. **Other Securing AI占比很高且方法冲突未桥接。** 模型最乐观AI结果尤其受此影响；若残余包含已在身份/其他安全中的收入，应重新分配或下调总量。
6. **模型固定费用及交付成本不是行业统计。** 代表业务利润只证明条件与门槛，不证明行业利润总额或任何股票回报。

可保留的方向判断是：安全责任扩大使行业存在现实增长基础；预算、包内定价和工程验收使增长不能等同于高利润；控制执行权、治理责任与完成修复比原始代理数量更有定价依据。该判断可被真实净价、独立收费、合格交付和同边界现金结果推翻。

| 员工、应用和持续治理采用D | 大规模员工接入基础、现实供应商增长、权限责任及已GA产品 | 每行在非供给约束区D变10%，收入同向变10%；代理原始数量不是此D |
| 复杂项目合格能力S | 人员困难、客户验收、团队×项目×通过率条件估计 | 若S高于D，继续扩能力对收入无直接帮助；若S低于D，收入对S一比一敏感 |
| 净变现P | 当前标价、包内证据及同任务功能分摊 | 收入对P一比一；捆绑可能使新增功能P接近0，未公开净价不宜给窄统计范围 |
| 单位交付成本C与v₀ | 公司交付/现金事实、计算和人力结构；宽压力范围 | C变10%使贡献率变－0.1×v₀×C/P；反面情景可以因复核/日志增加而上涨 |
| 固定费用f₀及F | 上市公司GAAP/调整后差异、独立厂商研发销售需求；没有完整细分观测 | F变10%时，EBIT率变化约－0.1×f₀×F/(Q×P/100)；AI初期对此更敏感 |
| Standalone付款份额 | 当前无法观察；2028悲/基/乐为30%/55%/75%压力点 | 不改变已归属的总池，但改变独立供应商可保留收入；若没有额外付款/合理分摊，总池也需下调 |
| 客户寿命和更新 | SOC示例五年、年度更新3万、第三年8万、残值0、折现10%，全部I | 接入失败/客户流失缩短寿命；不得把未释放人力当现金节约 |
| 新硬件/后量子更新 | 有公开技术路线，具体兼容与部署条件不同 | 既有设备可升级时新增机箱需求较少；性能组合提升不等于物理台数同比增长 |

为避免把A表单点误当精确预测，额外压力测试建议直接变动真实有疑问的参数：员工/普通软件未来付费D上下10%—15%、复杂治理/AI D上下20%—30%；P在A表情景点周围再上下10%—20%；AI治理和复杂实施S上下25%。这些是I压力范围而非置信范围，不要求每个扰动同时发生，也不能与B表的范围重复解释成完整概率分布。若某类功能被完全包内且没有可归属付款，P可以更接近0，现有数值点将失效，应转入替代分支。

网络与服务缺少全球统一物理数量，使用条件单位无法支持全球设备台数、FTE或真实产能缺口百分比的精确断言；它支持的是给定任务覆盖、验收、价格和成本时的经济门槛。证据支持普通许可不构成主要稀缺资源、复杂交付具有约束，但其程度仍必须由真实项目/合同验证。
