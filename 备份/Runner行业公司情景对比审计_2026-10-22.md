## 仍然适用的问题与边界

1. **上游失败不会硬性拦住下游。** queue-store.mjs 只把 pending、running、retry_pending 作为阻塞状态。实际隔离测试已证实最终 failed 或重试耗尽后会放行下一阶段。公司对比 requiredPaths 只检查情景投资结果目录存在，并不逐家保证本批情景投资报告成功、齐全或同日。新公司缺报告或旧报告回滚后，下游仍可能运行。
2. **当前已启动进程 maxJobs=500，小于全批 885 项。** 当前日志参数为并发 35、每次 120 分钟、最多 7 次尝试。即使全部一次成功且不发生配额退出，本进程最多处理 500 次，至少剩 385 项：背景＋行业＋公司共 379，接着只能处理 121 项情景投资，剩 132 项情景投资＋253 项公司对比。普通失败重试也占用次数。此为本进程启动参数，不是 runner 永久上限；默认 maxJobs 可为 Infinity。
3. **金融输入有 8 家新增公司缺口。** 最新 2026-10-21 快照覆盖 245 家；索引为 253 家，缺 AXON、ISRG、GE、HEI、REGN、VRTX、ROST、ACGL。文件自身还说明部分价格滞后，估值/财务/IV 沿用前一日。下游可独立联网补证，但不能假定同日且全覆盖。
4. **现有研究缺口需要上游实际填补。** 行业 93/102 有正式报告，缺 9 个新增或拆分主题；公司调研、情景投资、公司对比均为 245/253 有正式报告，缺上述 8 家。全部入队能安排补做，不保证它们全部成功。
5. **金融/研究截止没有自动冻结为一个共同截面。** 方案要求核对数据时点与可比窗口，但 runner 不会自动制作全批上游内容快照。跨日、重试及配额退出后，各项可能采用不同的实际截止与报价。公司对比须按其方案对齐目标及对手的价格日、目标期和证券口径。
6. **通过验收不等于内容正确。** 情景投资和公司对比的 JSON 按方案生成；runner 只检查同名文件、非空、本次修改及路径，不解析 JSON 字段或复核估值计算。当前新版方案新增或调整的字段不会导致路径级失败，也不会因此得到自动语义校验。
7. **运行中外部批量追加队列有竞态风险。** queue-store 的 appendActiveQueueItems 是读全队列后写回，没有跨进程事务；runner 内串行操作不覆盖外部 CLI。避免在它更新状态时执行数百次独立追加。此次没有观察到队列丢失，也没有修改活动队列。
8. **README 版本文字存在滞后。** 公司对比 README 在本次读取时仍写 20261011_044451，根目录实际已是 20261022_031413。runner 按唯一时间戳文件绑定，因此没有错选旧版，但人工查看 README 会误判。实际方案根文件与归档一致性已通过测试；本次没有修改 README。
9. **额度和超时仍可能中断批次。** 当前进程在额度使用达到 95% 阈值时收尾退出，恢复后需再次启动；不会自动驻留等待后完成所有剩余任务。新版研究深度能否在每项 120 分钟内完成，本次没有用真实模型执行验证。
