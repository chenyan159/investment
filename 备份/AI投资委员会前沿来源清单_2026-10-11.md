# AI 投资委员会：近期前沿来源与适用边界

调研日：2026-10-11。重点窗口：2026-09-11 至 2026-10-11，首尾日期均包含。

性质：一次性方法调研，非正式投资研究成果。共整理 18 组窗口内来源、5 组窗口外对照，以及 6 组重点外部 GitHub 项目的现行设计与效果材料；后者单独标明历史实验年代，不冒充本月新成果。同一项目的论文、代码和更新记录合并处理，不把它们算成独立的验证实验。

证据口径：论文描述的是作者报告的研究结果；机构文章描述的是机构或作者披露的过程；GitHub 文档主要证明公开设计和维护记录。本次没有运行这些仓库、复现论文实验、重新检查数学证明或做投资回测。下面“可借鉴”均为向 Investment 工作流迁移的设计判断，不是来源已经证明的投资效果。

配套方案：[AI 投资委员会设计调研](/D:/investment/备份/AI投资委员会设计调研_2026-10-11.md)。

**R01｜OpenAI 数学研究公开材料｜2026-10-06 发布**

来源：[官方介绍](https://openai.com/index/sharing-ai-progress-in-mathematics/)、[openai/math 仓库](https://github.com/openai/math)。

核实内容：当前目录列出 719 份稿件、372 个结果族，约 42% 顶层结果已有形式化材料；结果族会包含主结果、衍生结论和其他证明。多数结果采用同一内部未发布模型流程，仓库另提供部分推理摘要。

可借鉴：把论证与支持材料留成可审计产物，允许下游复用。

边界：这些数字不是 719 个已被独立确认的著名猜想。公开说明也不足以证明这批成果来自“很多模型自由辩论”，不能据此反推委员会拓扑。

**R02｜openai/math 的修订与验证范围｜2026-10-07 修订记录**

来源：[history.md](https://github.com/openai/math/blob/main/history.md)、[Comparator 验证说明](https://github.com/openai/math/blob/main/lean/ComparatorChallenges/README.md)。

核实内容：一处符号错误破坏了一个上游构造，导致三个关联稿件撤回，其他受影响材料随后修订；部分验证配置覆盖的是支持结果，需要逐项阅读范围说明。

可借鉴：为投资主张保存依赖关系。关键收入假设、证券口径或数据源失效时，自动重审依赖它的估值与选择；验证结果必须附带覆盖范围。

边界：撤回记录说明具体依赖失效，不意味着全部结果无效；反过来，仓库中存在 Lean 材料也不意味着每篇稿件的主定理均已核验。

**R03｜ScientistTwo｜2026-09-17 提交**

来源：[论文](https://arxiv.org/abs/2609.19644)、[全文](https://arxiv.org/html/2609.19644v1)、[项目页](https://scientist-two.github.io/)。

机制：发现研究局限，形成候选想法，先在小数据集上编码、批评和修正，再扩大实验；根据成功与失败轨迹演化想法，同时保留尚未尝试的方向；最终做消融、审稿和补充实验。

可借鉴：给反驳者一项实际验证任务；争论结束应产生新证据、失败记录或修订，而不只是新措辞。

边界：作者报告在 107 个问题中有 86 个超过所用 SOTA 基线；这是其机器学习实验，不是投资收益证据。模拟审稿分数不等于真实同行接收。

**R04｜Rethinking Multi-Agent Collaboration: When More Is Less / SAIGE｜2026-09-17 提交，09-18 修订**

来源：[论文](https://arxiv.org/abs/2609.19759)、[v1 全文](https://arxiv.org/html/2609.19759v1)。

机制：按任务需要增量生成 agent，通过内容检索建立信息依赖。作者发现多 agent 更适合依赖稀疏的长任务；紧密串联的流程常由单 agent 更有效完成，增加 agent 数或递归层数没有稳定收益。

可借鉴：不同公司、不同证据来源可以并行；共享同一组参数的估值推导和修订按依赖顺序推进。

边界：这是所测任务上的结论，不能直接给出 Investment 的最优并发数。

**R05｜SEPAL｜2026-09-30 提交**

来源：[论文](https://arxiv.org/abs/2609.39645)、[全文](https://arxiv.org/html/2609.39645v1)、[代码](https://github.com/zhansan114514/SEPAL)。

机制：三组私有 Actor–Critic 搭档分别偏向直接解答、证据与验证，内部多轮修改，最后才合并答案。研究还使用了角色专门训练的适配器。

可借鉴：先保留相互独立的研究轨迹，再交换结果，减少早期跟随。

边界：代码说明明确限制为每个实验单元一次固定试验，没有跨随机种子显著性或等计算预算优势结论。不能把其效果归因于三段角色提示，也不能把问答多数票照搬为选股规则。

**R06｜Beyond Final Accuracy: Auditing Communication in LLM Multi-Agent Systems｜2026-10-01 提交**

来源：[论文](https://arxiv.org/abs/2610.01042)、[全文](https://arxiv.org/html/2610.01042v1)。

机制：Independent–Communicate–Revise 固定初始推理轨迹，并加入“不接收消息、只继续思考”的对照。四个推理基准上，传递完整推理既增加纠错，也降低原本正确答案的保留率。

可借鉴：同时记录“错改对”和“对改错”；评估交流的增益时扣除额外思考本身的效果。

边界：文字更长、最后一致率更高，都不能单独证明沟通更好。

**R07｜Active Provenance Gate｜2026-09-25 提交**

来源：[论文](https://arxiv.org/abs/2609.31422)、[全文](https://arxiv.org/html/2609.31422v1)。

机制：最终综合之后，逐条对照辩论日志检查来源；允许有限自修复，仍缺依据就阻断相关结论并输出分歧。论文针对“总结者编出流畅共识”的问题。

可借鉴：裁决必须能回指证据与真实讨论记录，未消除的重大异议单独保留。

边界：忠实复述讨论不等于讨论内容符合现实；还必须另查原始财务资料和计算。不能只做一层语言模型蕴含检查。

**R08｜Verify Claims, Not Scores｜2026-10-01 提交**

来源：[论文](https://arxiv.org/abs/2610.01348)、[全文](https://arxiv.org/html/2610.01348v1)。

机制：把结论分成 supported、unsupported、unresolved、not evaluated，并写明成立范围；通过逐个替换组件定位损失，检查验证分数究竟约束了什么。

可借鉴：事实正确、计算可复现、情景有依据、未来收益更高，应是不同的主张与验收项。

边界：实验为合成环境中的受约束资产分配系统。作者明确没有评估 LLM 控制器、模型裁判或提示注入，不能当作真实金融多 agent 已有效的证据。

**R09｜LabAgent｜2026-09-11 提交**

来源：[论文](https://arxiv.org/abs/2609.13437)、[全文](https://arxiv.org/html/2609.13437v1)、[代码](https://github.com/fpxlei/LabAgent)。

机制：探索、复现与分层验证相连，把可执行技能、来源证据、执行记录和失败诊断留给后续工作。

可借鉴：委员会记忆应保存“哪一步失败、如何验证和修复”，而不只保存最终推荐。

边界：生物医学任务中的复现与发现结果，不能推出股票研究收益。agent 自述完成也不能代替独立验收。

**R10｜Claude-shaped science / BootLoops｜2026-10-01 发布**

来源：[作者与机构研究文章](https://www.anthropic.com/research/claude-shaped-science)。

机制：主会话分配任务与计算预算，项目使用独立会话，后台计算保存中间记录；写作、代码核查、对抗审稿分别组织，文件化计划帮助跨越长会话。

可借鉴：研究状态放进持久文件；裁判和核验者使用独立上下文；人负责值得解决的问题与最终判断。

边界：文中工作跨越数月，不能把全部产出算作最近一个月新增成果。作者也描述了过早宣告完成、未证明引理等问题。

**R11｜Yes, Claude can do nine loops｜2026-09-25 发布**

来源：[研究文章](https://www.anthropic.com/research/yes-claude-can-do-nine-loops)。

机制：通过不同计算路径推进九圈振幅计算，并由领域专家独立检查结果；长时计算与中间产物管理比即时聊天更关键。

可借鉴：同一估值结论最好有另一条可重算路径，例如从现金流和市场隐含预期分别检查。

边界：计算发生在八月底，独立检查在九月初，09-25 是文章发布日期。该案例不证明使用了委员会式多 agent 辩论，也不应表述为当月才完成的数学定理突破。

**R12｜Project Swap｜2026-09-24 发布**

来源：[机构实验文章](https://www.anthropic.com/research/project-swap)。

机制：让 agent 代表参与者进行书籍交换，检验理解偏好和协商的效果。

可借鉴：先明确持有期、风险约束、资金用途和备选方案；扮演某位投资名人的提示不能代替真实委托目标。

边界：这是物品交换实验，不是金融市场回测或资产管理结果。

**R13｜Agentic Economies for Autonomous Scientific Discovery｜2026-09-25 提交**

来源：[论文](https://arxiv.org/abs/2609.31562)。

机制：讨论自主科学发现中的资源配置、优先级、激励和责任制度。

可借鉴：研究预算分配给可能改变决策的未知问题，并为提出、核验、裁决分别记录责任。

边界：这是制度与架构层面的论述，不能当成已经验证的选股协作算法。

**R14｜TradingAgents｜近期版本 0.5.0、0.5.2、0.6.0**

来源：[仓库](https://github.com/TauricResearch/TradingAgents)、[更新日志](https://github.com/TauricResearch/TradingAgents/blob/main/CHANGELOG.md)。

日期与机制：09-18 强化按当时披露信息取数与组合上下文；09-29 让分析员并行，报告收齐后开始辩论，并记录运行配置；10-03 允许快、深模型层分别选供应商。

可借鉴：它是与投资委员会最接近的工程参照，尤其适合看分阶段汇合、历史信息截止与结果留档。

边界：项目并非本月首次出现；本条关注的是近期维护。公开框架和回测功能不证明稳定超额收益，现有角色也不应无条件覆盖 Investment 的输入规则。

效果补查：[旧论文 v7](https://arxiv.org/html/2412.20138v7) 的主表报告 2024-01-01 至 03-29 测试中 AAPL、GOOGL、AMZN 累计收益分别为 26.62%、24.36%、23.21%，对照主要为持有和技术规则。它不是最新版本的实盘战绩，也没有通过同预算强单 agent 对照单独证明“辩论”带来的增量。

**R15｜Feynman｜2026-09 至 10 月持续更新**

来源：[仓库](https://github.com/Companion-Inc/feynman)、[发布记录](https://github.com/Companion-Inc/feynman/blob/main/RELEASES.md)。

机制：公开研究工作流包含并行研究和引用检查，并分配 researcher、verifier、reviewer、writer 等职责。窗口内维护涉及子 agent 工具继承、检索限流、失败回退和并行工作流执行。

可借鉴：角色必须配套实际工具权限；多个 agent 同时查资料需要共享来源缓存、限流和清晰失败状态。

边界：这些主要是工程维护证据，不是独立的质量优越性实验。本次未安装或运行。

**R16｜agent-triforge｜窗口内更新至 2026-10-01**

来源：[仓库与公开版本说明](https://github.com/Ninety2UA/agent-triforge)。

机制：跨 CLI 协作、独立会话、结构化状态交接、写入归属和完成标记，减少一段长会话包办所有职责。

可借鉴：多人接力必须明确“谁改哪个产物、已验证到哪里、下一步是什么”；需要机器可读的执行结束信号。

边界：完成标记只证明运行协议结束，不能证明论证正确。社区实现的运行环境与本地 Windows/runner 不同，不建议直接整体移植。

**R17｜swarm-dynamics-lab｜2026-10-03 至 10-04 活动**

来源：[仓库](https://github.com/dmarzzz/swarm-dynamics-lab)、[实验协作规则](https://github.com/dmarzzz/swarm-dynamics-lab/blob/main/AGENTS.md)。

机制：人和 agent 通过共享仓库协调；先提交实验计划，再运行；结果包含失败、证据登记与分级。

可借鉴：保留研究议程、失败实验和结论版本，防止只记住成功案例。

边界：这是短时探索性研究，仓库本身限定了证据强度，缺少独立跨模型复现，不能把其统计或 agent 自评当成已确立规律。

**R18｜AAHP｜2026-09-28 的公开测量与现行协议**

来源：[仓库](https://github.com/homeofe/AAHP)。

机制：先读 manifest，再按任务读取状态、下一步、日志与信任记录，并附校验和、更新时间和有效性说明。

可借鉴：多个 agent 轮流运行时，用结构化交接包替代整段聊天转述，接收者仍能回到原始证据。

边界：近期节省量是项目自己的估算，不是跨系统 tokenizer 基准；文档已收回旧的夸大节省说法。HANDOFF.lock 只是约定式提醒，不能当作真正的并发互斥锁。

**B01｜窗口外对照：Prove2Me｜2026-08-28 提交**

来源：[论文](https://arxiv.org/abs/2608.28433)、[工作区仓库](https://github.com/prove2me/prove2me_workspace)、[证明流程](https://github.com/prove2me/prove2me_workspace/blob/main/references/prove.md)。

机制：把待证明命题组织成依赖图，子问题的状态与证明材料明确，重用已经核验的引理；还要检查命题本身是否与目标一致，避免循环证明和用假设代替证明。

投资迁移：先建立“需求—收入—现金流—每股价值—选择”的主张依赖图，再安排验证。数学形式系统的确定性不能直接迁移到未来经营假设。

**B02｜窗口外对照：Fermat's Last Theorem 形式化｜2026-09-04 发布**

来源：[Anthropic 官方文章](https://www.anthropic.com/news/formalizing-fermats-last-theorem)。

机制：文章描述多 agent 在约 11 天内推进 Lean 形式化，采用 Prove2Me 的命题依赖图、命题与证明分离，以及可搜索复用的中间结果。

可借鉴：共享状态、依赖控制和外部检查器，使长任务能够拆分和复用。

边界：这是对既有费马大定理证明的形式化验证，不是 AI 首次发现该定理的证明；发布日期也早于本次最近一个月窗口。

**B03｜窗口外对照：Emergent Cheating and Whistleblowing｜2026-09-03 提交**

来源：[论文](https://arxiv.org/abs/2609.04170)。

机制：研究群体在自主实验中利用评价漏洞，以及这类行为如何通过共享信息传播。

可借鉴：研究者不能自行修改验收标准、评分数据和失败定义；评价器由独立流程维护。

边界：单一案例研究不是所有 agent 群体都会作弊的证明，也不应据此否定共享知识。

**B04｜窗口外对照：autoresearch｜既有开源项目**

来源：[karpathy/autoresearch](https://github.com/karpathy/autoresearch)。

机制：单 agent 修改受限训练代码，运行固定时长实验，以明确指标决定保留或撤销，持续迭代。

可借鉴：对可重算的研究子任务，单 agent 加稳定外部反馈也是强基线。

边界：金融收益标签延迟、噪声大、可被反复调参过拟合。必须分开开发集与未触碰的时间外测试，不能无限优化同一段历史。

**B05｜窗口外且不用于推断协作方式：Komlós 相关数学稿件｜2026-09-10 提交**

来源：[Vector Balancing via Directional Total Variation](https://arxiv.org/abs/2609.11189)。

核实内容：论文提出有关 Komlós 问题的证明主张，并提到 AI 参与。

边界：本文查阅的公开材料不足以还原多 agent 编排协议，也没有在本次调研中取得独立数学界全面确认。因此不以它证明“某种委员会已经攻克问题”，仅列为容易在近期讨论中混入的邻近日期材料。

**C01｜HKUDS/AI-Trader：自主交易基准与现行协作平台**

来源：[当前仓库](https://github.com/HKUDS/AI-Trader)、[2025 年研究论文](https://arxiv.org/html/2512.10971v1)。

协作边界：旧论文主要让不同模型分别作为相同工具配置的独立交易者，属于竞争比较；现行仓库已扩展为 agent 信号交流和协作平台。不能拿前者成绩证明后者的群体讨论有效。

效果：旧实验股票窗口为 2025-10-01 至 11-07，美股 MiniMax-M2 为 9.56%、GPT-5 为 1.56%，QQQ 为 1.87%；A 股六个模型均未跑赢 1.65% 的基准。短窗口且为作者报告，本次没有审计其真实资金成交。

值得参考：统一任务、统一工具、保存时点决策、等待结果自然发生的评测方式。没有确认其最近一个月出现新的效果论文，故本项不列入近期突破。

**C02｜FinRobot：研究流水线、估值计算与审议**

来源：[当前仓库](https://github.com/AI4Finance-Foundation/FinRobot)、[V2 设计说明](https://github.com/AI4Finance-Foundation/FinRobot/blob/master/finrobot_desktop/README.md)。

机制：lead 编排数据、分析、建模、综合、报告五类 agent，加 bull、bear、judge；每步有类型约束、验证和重试。估值由确定性代码计算，再核对叙述与数字。

效果边界：公开材料能说明具体系统结构、样例与软件验证设计；本次查阅的 README/设计说明没有提供足以确认持续超额收益的独立对照结果。项目称“production”是其成熟度自述。

值得参考：优先借鉴数值计算、来源追踪和分步验收；不要把生成完整投委会报告视为决策质量已经得到验证。未确认上述功能首次发布日，按 2026-10-11 现行材料列入。

**C03｜MiroFish：群体模拟与情景推演**

来源：[666ghj/MiroFish](https://github.com/666ghj/MiroFish)。

机制：从种子资料建立关系图和角色，运行多轮社会互动模拟，再由 ReportAgent 访问模拟结果形成报告。

效果边界：当前 README 主要展示舆情与故事推演案例，本次未见其中给出金融预测的样本外对照、校准误差或持续交易结果；“预测万物”是产品愿景，不能作为效果结论。

值得参考：作为生成冲突情景、市场叙事和第二层后果的探索工具。模拟参与者是模型生成的，不是独立市场样本，不宜将模拟共识或投票占比直接当成概率。按现行公开项目列入，未把热度当作本月研究突破。

**C04｜virattt/ai-hedge-fund：多风格信号与组合账本**

来源：[仓库](https://github.com/virattt/ai-hedge-fund)、[现行路线图](https://github.com/virattt/ai-hedge-fund/blob/main/ROADMAP.md)。

机制：不同投资风格 agent 产出信号与论点，经组合规则融合并受风险上限约束；当前有回测和延续持仓的纸面交易账本。

效果边界：项目定位为教育概念验证。路线图中 point-in-time 数据正确性仍在进行，回测过拟合验证门槛和 LLM CIO 仍属计划内容，不能把这些规划当作已完成功能。

值得参考：统一信号接口、时点决策与不可随意重置的账本。优先级低于核心证据验证流程，不应因为“模拟巴菲特”等名称而给予权重。按现行材料列入，不声称最近一个月首次发布。

**C05｜Microsoft RD-Agent / RD-Agent-Quant：自主决定下一项实验**

来源：[仓库](https://github.com/microsoft/RD-Agent)、[论文 v2，2025-09-25](https://arxiv.org/html/2505.15155v2)。

机制：提出假设，转成代码和实验，验证结果，再决定继续优化因子还是模型；调度器根据反馈分配探索方向，保留失败与成功轨迹。

效果：作者在 CSI 300 数据、2017-01 至 2020-08 测试段的主表中报告联合优化版本 ARR 14.21%、IR 1.74；Alpha158 对照 ARR 5.70%。这属于特定历史策略和评价口径，不能称为今天可复制的实盘年收益。

值得参考：很适合委员会的“待验证问题 → 计算任务 → 结果 → 修订”环节。它研究因子与模型，不是长线公司投资论证的现成替代；其 2025 年论文不是本月新成果。

**C06｜Sakana AI Scientist-v2：并行探索、实验选择与外部审稿**

来源：[代码](https://github.com/SakanaAI/AI-Scientist-v2)、[公开实验仓库](https://github.com/SakanaAI/AI-Scientist-ICLR2025-Workshop-Experiment)、[2025-03-12 结果说明](https://sakana.ai/ai-scientist-first-publication/)。

机制：实验管理者引导树搜索，同时探索数条候选路径，运行代码、分析数据、生成论文；写作与评审单独配置。

效果：作者挑选的三篇投稿中，一篇在 ICLR 2025 workshop 获得高于平均接收门槛的评审分数；按预定实验协议撤稿，未进行后续 meta-review，不能说已经正式发表。分母也是挑选后的投稿数，不是全部生成尝试。仓库明确说 v2 更开放的探索不必然比 v1 更好。

值得参考：对多个投资假设保留分支，按外部证据分配进一步研究预算。已有明确评审产物，但不是投资效果证明，也不是本月新成果。

**采用次序**

搭建投资协作流程优先看 TradingAgents 的阶段与时间口径、FinRobot 的数值验收、RD-Agent 的实验反馈、Prove2Me 的依赖管理，以及 ICR / Active Provenance Gate 对交流和综合的检查。AI-Trader 适合学习前瞻评测；Feynman、agent-triforge、AAHP 适合工程交接；MiroFish 只先作为情景探索参考。所有迁移效果均需在 Investment 自己的数据和预算约束下检验。
