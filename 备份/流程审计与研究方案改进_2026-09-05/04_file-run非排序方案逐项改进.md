# file-run非排序研究方案：逐项职责、证据与具体改法

审计日期：2026-09-05。本文覆盖五份产业背景方案、会议通用方案及最近四个会议包装任务、24公司四分组与综合任务、区间涨跌。均为建议稿，不修改正式方案，也不覆盖已有历史研究。26个排序方法和91评估模板另见[排序各方案流程审计](<D:/drive/Investment/备份/流程审计与研究方案改进_2026-09-05/evidence/排序各方案流程审计.md:1>)。

## 1. file-run是执行容器，不能被当成一个研究方法

实际执行只读取队列指定的promptFile全文。因此目录中存在“会议调研方案”，并不代表四个conference包装任务必然继承它的每一条规则；同样，排序入口不会自动继承九月新合并的公司情景方案。核查单位必须是“任务身份—实际提示文件—它明确读取的公共方案—输出”。当前done中的9项是4会议、4分组和1综合，不是全部历史file-run任务；五产业背景、26排序入口与其他方案需单独登记，不是当前9项的别名。[实际提示读取](<D:/drive/Investment/tools/research-runner/prompts/file-run.mjs:5>)。

历史队列中存在大量迭代、测试与一次性评估，不应全部恢复成常规生产流程。通用file-run应保留，但正式研究身份与历史临时任务应分开列出。本文的“合并”指合并重复研究责任，不意味着把所有内容塞进一个巨型提示词。

## 2. 五份产业背景：保留五个互补问题，收缩五次独立重建同一全景

五份正式结果仍是7月9–10日，总计约38万字符。8月18日行业报告更晚，不足以单凭文件年龄证明背景全部错误；它暴露的是：行业研究所依据的背景版本、哪些变量仍有效、哪些被新资料替换，应当明确交付。四份背景严格禁止本地旧资料，Token方案已采用“先独立估算冻结、再读紧邻上期比较”的两阶段办法。独立重建有防锚定价值，但若每次五篇都重新完成所有上游模型，既增加重复，也没有天然得到一个可一致拼接的系统。

五份可共用的修订文本：

> 本报告只对指定的主问题负责。可以选择全新模型、发现目录之外的技术路线，或否定既有乐观假设。对下游有决定作用的数量，标明对象、地域、币种、期间、存量或流量、价值层级、事实与估算，以及上游版本。引用的同一项目、客户预算或芯片平台不能作为多个独立需求证据相加。常规更新允许复用已冻结事实，明确本次新证据和变化；独立重建作为另一个可识别的研究任务保留。两种任务不能混称为彼此独立的确认。

## 3. 会议研究：通用方案与四个实际包装任务分别处理
