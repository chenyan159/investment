# 四类流程的研究方案修改与文件整理建议

日期：2026-09-05。仅讨论industry、company、file-run排序、file-run背景/会议/专项。本文为详细建议，不执行正式文件修改、移动、删除或运行。

证据时点：主要依据本日凌晨完成的审计，本轮重新读取四类当前主方案与管理约定。中午复核发现若干原公司/行业报告已在上午更新过程中移入备份，历史样本按原版本理解，不冒充所有最新报告的现状。固定历史引用正是以下文件整理方案要解决的问题。

建议在这四类中统一两项原则：研究问题、模型、搜索顺序和篇幅由AI依据经济重要性选择；对象、关键数字口径、证据版本、事实与推断区别及决定性反证必须可审查。3个月和3—6个月是公司建议的目标窗口，不要求远期技术在六个月内全部产生收入。

“更新”指新版本替代当前正式入口；“合并”指一个研究职责由一个主体维护；“转角色”指继续提供审查/发现而不生成独立买入名次；“冻结”指暂停新运行等待重做；“淘汰”指退出独立方法身份。后四者均保留历史方案、结果和当时评估。

## 一、industry：保留独立行业研究，改成需求、采用与价值分配研究

### 1. 职责与主要变化

industry负责回答：客户为什么支出、支出转向哪里，技术替代如何改变有效需求与供给，谁能收费、谁保留利润，哪些证据会使判断改变，以及有哪些值得进一步研究的公司。行业研究可以形成原创的数量级模型和经营推断。

当前77个行业专题保留，暂不按名称批量淘汰。真正应先删除的是现方案中的预设答案：固定2026乐观背景、数据缺失向乐观填补、固定前10款芯片、至少5个瓶颈，以及2026/2027各3个拐点。现稿有优秀反证，并非全部遵循乐观推演；修改的目的在于让正确探索受到正式授权。

证据：[当前行业方案](<D:/drive/Investment/基本面/行业调研/研究方法/行业调研方案.md:4>)；[逐题审计与10份行业样本](<D:/drive/Investment/备份/流程审计与研究方案改进_2026-09-05/evidence/公司与产业流程审计.md>)。样本中的“未来3个月”有7份指期间收入、3份指未来时点年化/未来12月池；此比例不外推77份。

### 2. 研究方案逐项改法

目标文件：`基本面/行业调研/研究方法/行业调研方案.md`。

| 当前位置 | 建议动作 | 下一版要写清的研究任务 |
|---|---|---|
| 开头与结尾的乐观立场 | 重写 | 不预设景气、供需或利润方向。允许超常增长、衰退、效率替代与价值迁移等假说；缺数据不决定估算方向。 |
| 只读产业背景、禁止其他本地证据 | 重写 | 允许可追溯原始材料、相关公司事实和相邻行业研究；同层结论是待验证主张，不能凭重复出现就当独立证据。保留与下游排名的判断隔离。 |
| 第1题：固定10款芯片与2026/27 | 重写 | 先识别真实付费方、使用场景和采用机制。芯片路线仅在有关时使用，可核验、挑战或补充背景中的路线；不要求应用、机器人和航天从GPU建设开始。 |
| 第2题：已放量产品 | 保留并改接口 | 定义需求单位、价格、采用率和可收费边界；注明总池、可加子池和不可加相邻池。0—3月、3—6月的采用与交付变化单列，NTM/远期规模保留。 |
| 第3题：在研产品 | 保留并放宽 | 区分技术可行、工程验证、客户验证、付费采用、规模交付与现金贡献；成熟与在研产品可共用采用路径。早期产品允许条件、量级、阈值或NA，不强造各期精确金额。 |
| 第4题：供给与至少5瓶颈 | 保留问题、删数量 | 研究真正限制交付或利润的因素；可以是客户预算、认证、软件、人才、资金，也可以不存在显著瓶颈。区分名义产能、有效产能与客户愿意支付的需求。 |
| 第5题：壁垒和价值捕获 | 加强 | 分开系统重要性、稀缺程度和利润控制权。调查客户自研、开源、标准化、捆绑、集中采购和供应商扩产；解释谁受益、谁受损及原因。 |
| 第6、7题：年度各3拐点 | 合并重写 | 改成滚动变化与证据窗口：0—3月、3—6月及远期。允许渐进变化或没有重大拐点；区分宣布、技术实现、客户采用、收入确认与市场获知。 |
| 第8题：公司全部列出、不遗漏 | 重写 | 形成有覆盖边界的竞争/候选地图，允许索引外公司、私人竞争者和客户自研方。说明证券与经营资产关系、未查明部分和候选价值，不承诺无限完整。 |
| 大量数字与高密度要求 | 重写 | 重要估计给机制、量级、来源、敏感性和反证；同一事实/模型只交付一次。没有新增判断的数字不以数量加分。 |

建议下一版的主体研究问题收敛为七组，AI可合并、调整顺序或突出更重要的新问题：

1. 行业边界、客户任务与支付来源。
2. 需求、预算与现有/新技术的采用和替代路径。
3. 有效供给、约束、价格与供给反应。
4. 价值分配、竞争反应与利润控制权。
5. 同口径的关键规模和经营模型。
6. 接下来两个季度的证据变化、反证与条件分支。
7. 公司候选、未解决问题及原框架未覆盖的新发现。

这不是七章等长模板；需要时可以深入一项，简述不重要项。报告开头只需有一个短交付区：核心判断/变化、关键数字口径、决定性来源、最强反证、未来观察窗口、候选公司。正文保持自由推理。

### 3. 哪些专题扩、哪些先划边界

建议先形成以下五组增量专题，再依据独立需求单位、客户、竞争和采用机制决定是否拆成常设行业条目：

| 拟扩展问题 | 研究重点 | 与现有覆盖的边界 |
|---|---|---|
| 企业AI/Agent工作流经济 | 付费任务、成功率、人工接管、预算归属、替代席位还是增加使用量 | 不重复推理运行时的底层资源调度 |
| 创作、文档和内容生产 | 使用增长如何到增量付费、渠道控制和利润；旧产品被蚕食与新产品附着 | 不把AI-influenced收入直接当AI新增收入 |
| 数据、数据库与软件平台收费 | 数据入口、开源、自建、存储/计算收费及客户迁移成本 | 区别于CXL/eSSD器件和KV数据流物理能力 |
| 安全、权限与AI治理 | 实际采购方、部署障碍、责任与预算；独立采购还是平台捆绑 | 不以“安全重要”直接推导独立厂商高利润 |
| 广告、推荐与分发的AI回报 | 转化、预算、利润、流量控制及算力投入回报 | 不把云公司全部CapEx都归为外售AI需求 |

这些是从公司经济问题出发的拟议覆盖，不是五个已确定必须新增的永久目录。保留尚无明确上市公司映射的高信息价值探索空间。

现有AI-native/KV、CXL、eSSD与运行时先划主责：系统数据流/架构，内存扩展硬件，存储器件/控制器，软件调度/运行效率分别有独立问题；液冷系统、小组件、流体也先按交付责任和利润机制区分。只有同一需求模型、来源、候选和反证反复重合且没有独立用途，才把专题降为另一专题的模块。不能仅按文件名相近合并。

### 4. 文件整理

- **保留**`行业索引.md`与六个现有分类目录；77份现稿暂不整体搬家。索引是当前正式专题/报告入口。
- **更新**当前行业方案和本域`AGENTS.md`中的资料边界、版本规则。方案更新前保存完整旧版；之后当前入口只对应一个批准使用的版本。
- **新增**`研究方法/历史版本/<版本日期>/行业调研方案.md`保存不可变的旧方案；版本说明可与之并列，不把修复历史写进新方案正文。
- **新增**`专题边界与候选登记.md`：记录题目、需求单位、已有相关专题、独立研究价值、拟新增/拟合并/暂不处理。它是管理文件，不要求每份报告重复全表。
- **报告更新**继续保留分类根层一个当前正式文件；同时为每次发布保存固定路径的版本档案。今后跨报告引用指向不可变档案，当前文件由该版本生成，避免双份手工维护。
- **历史断链**建立旧路径→真实备份路径的映射，并让引用读取能沿映射找到原版本。不得用最新行业稿冒充旧引用，也不需要为了整理改写旧报告的推断。
- **专题合并**先发布能覆盖被合并职责的新稿，再把旧专题状态改为并入并标接收者；旧报告保留。专题拆分则明确哪一部分需求归谁，旧总池不与新子池重复累计。

建议的增量结构如下；`版本档案`为提案，不是现有已实现路径：

```text
基本面/行业调研/
  行业索引.md
  专题边界与候选登记.md
  研究方法/
    行业调研方案.md
    历史版本/<方案版本>/行业调研方案.md
  <现有分类>/
    行业调研_<主题>_<日期>.md              # 当前正式视图
    版本档案/<主题ID>/<发布ID>/报告.md     # 固定引用；生成后不搬动
    备份/                                # 既有历史原样保留
  引用映射.json                           # 老路径到原版本的定位信息
```

发布ID要区分同日重写，不能只靠日期。正式视图和档案必须同一内容、同一版本；检索默认只读取索引指定视图，不把两者当两份支持。此规则需要本域发布/索引选择配套，不能只创建目录就宣称解决引用问题。

## 二、company：保留公司原创尽调，合并重复经营模型

### 1. 职责与主要变化

company负责把行业机会变成公司特有的经营判断：公司靠什么收钱、客户为什么选它、份额/价格/产品组合如何变化、订单怎样交付、增长需要占用多少资本、什么会让经营假设失效。这里需要技术和商业原创推断，不能降为公司公告摘要。

最大调整是把现第5题产品收入、第7题产能与认证、第8题订单增长合为一条相互约束的经营推导，避免三组假设各自乐观；同时保留低增速现金业务、被蚕食业务和有潜力的小产品。

依据：[当前公司方案](<D:/drive/Investment/基本面/公司调研/研究方法/调研方案.md:2>)；[公司逐题审计和正反例](<D:/drive/Investment/备份/流程审计与研究方案改进_2026-09-05/evidence/公司与产业流程审计.md>)。

### 2. 研究方案逐项改法

目标文件：`基本面/公司调研/研究方法/调研方案.md`。

| 当前位置 | 建议动作 | 下一版要求 |
|---|---|---|

| 第6题固定BOM/MW/rack/GPU/port | 改为适配 | 硬件可用内容量，设备可用吞吐/合格产出，软件可用seat/usage/工作流，项目可用验收或容量；无经济含义的单位可不做。美元产能与物理产能分开。 |
| 第9题竞争和技术主流 | 加强 | 包括客户自研、开源、捆绑、替代预算、渠道/数据控制、竞争者响应及谁承担资本成本；主流技术不保证公司能收费。 |
| 输出密度与标题 | 重写 | 前部给关键变化、经营驱动、证据/模型分界、反证、近期信息确认和未解决项；正文结构自主。重大模型只写一次，不以数字数量衡量完成度。 |

### 3. 下一版正文组织建议

可采用六组问题，不强制六章等长：

1. **经济实质与业务地图**：客户、产品/服务、付费机制、收入与资本结构；低增长但关键的现金业务不能遗漏。
2. **历史经营与关键变化**：解释收入、利润、现金差异，区分业务变化、会计变化与一次性因素。
3. **机会、替代与竞争**：同一机会中公司的独特优势、资格、潜在份额、蚕食和失败路径。
4. **统一经营模型**：采用、订单、供给、量价、交付、利润与现金使用同一组关键驱动。
5. **近端确认与远期价值**：哪些事实会在0—3月/3—6月被确认，何时才有规模收入；二者不需同时发生。
6. **反面解释与自由探索**：最强反证、尚未解决的重要变量，以及原框架没有问到但可能改变判断的发现。

需要允许明确写“行业需求大，但本公司当前没有可验证的捕获优势”；也允许“当前收入很小，但这次客户确认消除了一个决定性不确定性”。不能把没有公开点值等同零价值，也不能把潜在客户资格等同订单收入。

### 4. 更新深度与文件整理

192家公司全部保留，不按最近涨跌删除。当前前30、最强落选替代者、重大信息变化公司和新发现应获得更深验证；其余公司仍保留覆盖与线索扫描。深度由会改变判断的问题决定，不能永久锁死当前前30。

一次重大财报/订单变化不必重写全部基础技术史。报告可用增量研究更新受影响模型，再形成自洽当前正式稿；原有事实被保留时注明仍适用，不能简单换日期冒充全新尽调。独立从头挑战作为可选择的研究模式保留，不把所有更新都包装成独立确认。

| 文件 | 整理动作 |
|---|---|
| `研究方法/调研方案.md` | 更新当前方案；先保存旧版本，新增版本号与适用边界 |
| `研究方法/历史版本/` | 不可变保存旧方案及变化说明 |
| `公司索引.md` | 继续作为证券、公司、分类和当前报告的权威入口；新增证券须分清经营资产与交易载体 |
| 十个现有公司分类目录 | 保留；不因公司跨多个行业就复制多份正式公司稿，用关联关系表达跨行业业务 |
| 每家当前正式稿 | 一个当前入口；逐次发布自洽更新，不同时保留多份含糊的“最新” |
| `分类/版本档案/<ticker>/<发布ID>/报告.md` | 新增的固定来源版本；当前稿由其生成，后续引用使用稳定路径 |
| 既有`备份/` | 原样保存旧原文；补定位映射，不改写历史数字使其符合后续结果 |
| 阶段材料 | `tmp/`仅作过程材料；有复用价值的证据进入正式稿来源，有保留价值的一次性分析进备份 |

不建议拆出192份独立“新产品报告”再让公司稿拼接。只有跨公司确实共享的机制交给industry；公司特有产品、合同、执行和资本约束仍在同一公司版本中维护。这样减少模型不一致，也保留完整经营上下文。

## 三、file-run排序：26个身份整理成九项研究职能，并明确前30成稿责任

### 1. 先确定保留什么

### 3. 九项职能的研究方案怎么写

所有保留方法都新建完整自洽版本，输入采用当期可追溯的经营与价值研究及公司/行业原文；25份旧入口要求读取退役评估的条款需要在新版本替换，不能只把路径字符串换掉后沿用旧分数语义。这里仅规定排序如何读取证据，不讨论其他流程的改法。

| 职能 | 必须解决的问题 | 可删除的强制设计 |
|---|---|---|
| 01 赔率 | 当前价格要求什么；哪种经营与信息路径会在3/6月改变价格；与替代公司相比为何值得承受风险 | 通用0—100维度表、未证明有效的固定权重、上涨自动加分 |
| 02 兑现 | 定义事件、时间窗口、进入/失效条件；真实性、发生可能性、信息价值与价格影响分别判断 | 证据强度线性转换成概率，固定两个报告期，所有已收入项目优先 |
| 04 朴素基准 | 用少数预先明确的经营与价格判据提出可理解排序，暴露复杂模型的新增贡献 | 增加越来越多维度以追上复杂榜；看结果后调整基准 |
| 06 三视图 | 哪些公司因为成长、价格、事件假设不同而会换位；最强反例是什么 | 三套同分换权重、三个完整独立票；不必要的全池重估 |
| 07 收入跃迁 | 从客户问题/产品能力到份额、量价、交付及资本需求的跃迁；什么证据足以确认 | 以多年收入倍数直接代替3月收益；没有现金捕获的规模排名 |
| 08 证据审查 | 哪个缺口会改变候选选择；怎样补证；缺口是否足以暂缓某个结论 | URL数量分、信息齐全奖励、未知自动归零或全部淘汰 |
| N02 反证审查 | 风险发生机制、暴露、缓释程度、替代解释；风险是否被当前价格补偿 | 不区分风险可描述与已解除；总风险分遮蔽决定性单一风险 |
| N03 新预期差发现 | 新信息是否改变了此前未被定价的量、概率、时间或每股捕获；需要回源验证什么 | 双变化同时成立的硬门槛；必须官方精确一致预期才允许推断 |
| N06 高凸性探索 | 是否有非线性采用/技术/商业变化；成功价值归谁，投入与稀释会吞掉多少 | 强制一年五倍、满额名单、早期无收入即零价值或反过来无限期权价值 |

明确02与N03的边界：N03先发现“什么被误解或新改变”；02研究“它什么时候、以什么证据被确认”。07关注可解释的经营能力/收入跃迁；N06允许更早、更非线性、尚未形成稳定经营模型的探索。同一机会被两者讨论，保留来源关系，不重复计票。

前30综合成稿方案应规定：

1. 统一研究池、信息截止和价格锚；候选池包括主序以及发现任务提出的挑战者。
2. 分别给三个月、六个月判断，说明三至六个月的事件时序；不给两个期限复制同一个远期价格。
3. 对入围与最强落选者，回应影响选择的证据、反证和分歧，注明继承假设及新增推断。
4. 区分当前可执行、需价格/事件条件成立、观察与资料不足。前30是重点审查范围，不强行给30只买入标的。
5. 重大分歧不平均掩盖；合理条件差异可保留，不合理的对象/口径冲突须回源核清。
6. 不重做全池完整估值，也不把九个角色票数或简单平均名次当成结论。

- **RSS**：实验能力与持续付费生产分开，关注干预、维护、节拍与总成本；保留传统控制和专用机器人等不同路径。
- **Farnborough**：正式合同、政府采购、意向与条件订单分开；航空、航天、认证交付、维修经济分别分析，不套AI硬件单位。
