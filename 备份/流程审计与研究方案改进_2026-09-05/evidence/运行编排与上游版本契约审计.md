# 运行编排与上游版本契约审计

核查日期：2026-09-05。只读当前 runner、队列、方案和测试；没有启动 runner、重排任务或修改正式源。本文提出的是下一版运行约定与研究输入条款，不是生产代码实现。其作用是保证研究在正确资料和时点上发生，不能把调度成功、文件齐全或哈希一致当成投资判断正确的证据。

| 2 | company | 公司调研其次 |

## 二、file-run 的业务位置与调度位置可能相反

行业方案明确只允许使用项目内“产业背景”资料，而会议底稿正是写给行业和股票研究的上游。历史背景任务也是 file-run，例如 Token 框架、头部芯片。因此通用执行方式并不意味着业务上属于最后一层。[行业输入边界](<D:/drive/Investment/基本面/行业调研/研究方法/行业调研方案.md:6>)、[DAC 底稿用途](<D:/drive/Investment/基本面/tmp/research-runner-prompts/2026-08-18/conference_dac_2026.md:7>)、[背景任务历史绑定](<D:/drive/Investment/tools/research-runner/queue-backups/20260711_213031_queue.done_before_usage-limit-reset.jsonl:7>)。

如果把新背景、会议更新与其消费者行业研究一起放进现行混合队列，行业组先领取，背景 file-run 却被挡在最后组；行业可能使用上一版背景，甚至需要的新底稿尚不存在。即使把背景任务写在 JSONL 第一行，领域优先组仍优先于行序。这是条件成立时可由代码推导的顺序风险；本次没有据此认定历史行业研究实际读错版本。

同组也不等于串行。runner 可以同时持有多个执行中的任务，按行先领取 group，再领取 master，并不检查 group 是否完成。[并发领取入口](<D:/drive/Investment/tools/research-runner/runner.mjs:693>)。但 8 月 19 日这批有重要反证：四组最晚 14:01:44 完成，master 到 14:04:09 才启动；没有看到该批 master 抢跑。[四组与 master 记录](<D:/drive/Investment/tools/queue.done.jsonl:178>)。而当前 master prompt 已要求四份非空且 `status=complete`、精确公司集合及共同快照字段一致，任一失败停止。[master 前置检查](<D:/drive/Investment/备份/24家公司最新投资价值多情景评估_2026-08-19/prompts/05_24家公司综合排名与配置_prompt.md:10>)。准确问题是这些保护主要依靠人工批次安排和具体 prompt，尚不是通用调度依赖合同。

拟新增“依赖与放行”条款：任务先声明自己消费的已冻结成果，区分必需上游与可选补充。背景属于被相关行业消费的前置研究；master 必须绑定本批次各组的成功成果身份。必需上游失败或版本未到，不得仅因优先组已清空而宣告输入就绪；可选资料缺失则由 AI 说明影响并继续。无依赖的公司、行业可以并行，不要求所有研究一律排成一条长链。先把这条规则写成可审查的批次运行约定，再讨论实现，不应只把全部 file-run 移到最前方而制造另一种倒序。

## 三、入口身份没有自动继承；已经存在的版本锁也有边界

file-run 包装器仅读取队列指定的 `promptFile` 全文，再附加输出合同。其领域 `requiredPaths` 为空，通用校验检查 prompt 路径存在及输出范围，不自动解析正文中的上游依赖，也不自动追踪另一份“最新研究方案”。[实际提示组装](<D:/drive/Investment/tools/research-runner/prompts/file-run.mjs:4>)、[领域声明](<D:/drive/Investment/tools/research-runner/domains/file-run.mjs:23>)、[文件存在校验](<D:/drive/Investment/tools/research-runner/domains/file-run.mjs:135>)。

所以正式方案更新、文件夹改名或公司评估并入情景决策，都不会自动迁移已经复制的 file-run prompt。上一份排序审计已核实：26 个登记入口仍是各目录最高迭代，但 25 个实际读取退役评估，0 个显式接入合并情景。编号“最新”与业务合同“现行”不是同一件事。[排序入口逐项核查](<D:/drive/Investment/备份/流程审计与研究方案改进_2026-09-05/evidence/排序各方案流程审计.md:17>)。

不过，不能说系统完全没有版本清单。当前公司决策领域已按 `sourceDate + subject` 唯一绑定共享市场快照，验证文件日期、路径、非空、SHA-256 和必要标记，并把固定正文注入提示；这是已有保护。[批次绑定要求](<D:/drive/Investment/tools/research-runner/domains/company-investment-decision.mjs:129>)、[快照哈希校验](<D:/drive/Investment/tools/research-runner/domains/company-investment-decision.mjs:152>)、[正文注入](<D:/drive/Investment/tools/research-runner/prompts/company-investment-decision.mjs:21>)。它锁住这一类共享输入，尚不能证明所有公司、行业底稿以及一般 file-run 输入也被同样冻结。

拟新增“入口登记”条款：每个可重跑方案登记一个稳定方法身份、现行版本、唯一 prompt 路径、生命周期和预期成果类别；运行实例另有 run 身份。复制或改写 prompt 必须说明继承哪个方案版本、改了哪些研究约束。旧版本可复现但不默认为现行；输入扩展运行不是新投资哲学。迁移验收须对照真实 prompt、来源语义和消费层，不以 junction 可访问或目录最高 R 号替代。

拟新增“批次 manifest”条款：在现有共享快照机制基础上，登记本批次确实需要的研究方案与上游成果路径、版本/哈希、所属公司或行业、用途及必需性。冻结的是被使用的文件集合，不是要求锁死整个磁盘。研究途中发现新关键资料可以纳入，但记录新增来源、可得时间和导致的判断变化；若资料晚于本次事实截止，则另列事后更新，不偷偷写入原预测。由此保留探索能力，也能解释两个方法为什么得出不同结论。

## 四、四种时间与经济口径不能混成一个 sourceDate

当前输出日期来自任务启动日期；普通公司提示只是读取现行方案、替换公司名、附加输出要求，队列 `sourceDate` 不会因此自动变成全资料的截止限制。[输出日期来源](<D:/drive/Investment/tools/research-runner/validators/output-validator.mjs:177>)、[公司提示组装](<D:/drive/Investment/tools/research-runner/prompts/company.mjs:4>)。具体方案仍可能要求时点限制，因此不能倒推出所有报告实际用了未来资料；能确认的是通用执行层没有仅凭这个字段强制冻结全部事实。

拟修改“输入事实截止”条款，分别说明：研究使用的信息可得截止、所述经营事实所属期间、证券价格与估值锚的交易时刻、报告真正完成并可用于交易的时刻。晚公布的旧季度数据仍不能用于更早预测；9 月写出的 7 月主题报告也不能凭文件名当作 7 月可交易建议。最新事实可以用于新的建议版本，历史回看只能使用当时可得证据。前30结果分别对应三个月和六个月观察终点，跨夜和非交易日的进入口径要写清楚。

拟修改“口径继承”条款：只对会影响关键比较的数值回显币种、计量单位、财务期间、GAAP/调整后、企业值/股权值、普通股/ADR 与稀释口径。跨来源混用前说明转换；不能拿一个估值日的市值除以另一种证券单位的利润。未知字段允许保留区间、合理估算或不适用，由 AI 说明敏感性；不要求因为缺官方点值就放弃有价值的技术与商业推断。manifest 负责文件身份，研究正文负责经济含义，两者不能互相代替。

## 五、文件验收是明确设计；业务审查应另有职责

本地验证检查路径、非空、运行期间修改时间；目录输出还要求恰好一个新建或修改文件。[本地验证](<D:/drive/Investment/tools/research-runner/validators/output-validator.mjs:47>)、[文件与时刻检查](<D:/drive/Investment/tools/research-runner/validators/output-validator.mjs:94>)。测试明确要求所有生产领域不能注册 `validateOutputContentForItem`，另有用例保证即使存在内容钩子也不调用。因此“没有内容校验”是刻意的边界，不能写成漏实现。[禁止内容钩子](<D:/drive/Investment/tools/research-runner/test/output-contract.test.mjs:84>)、[忽略内容的测试](<D:/drive/Investment/tools/research-runner/test/output-contract.test.mjs:151>)。本次只读测试，没有执行会生成测试文件的测试套件。

同时，prompt 中“身份不一致视为未完成”是研究者必须执行的要求；文件验证成功本身并不证明研究者已经正确回显全部字段。这两种完成状态应在运行约定中分开。[快照回显要求](<D:/drive/Investment/tools/research-runner/prompts/company-investment-decision.mjs:31>)。建议保持本地输出验证的职责，不加一个凭关键词、表格数量或第二模型喜好自动判定投资真伪的钩子。

拟新增独立“来源与口径审查”条款：审查文件是否为指定版本、信息是否越过截止、公司集合是否错配、数字是否能从引用复算、币种股数是否混用、同源证据是否重复。这类确定事实可以阻止错误身份成果被当作合格输入；对仍可研究的缺口记录限制，不自动终止整份探索。它应有自己的审查结果与状态，不能把本地文件通过改名为内容通过。

拟新增“关键判断挑战”条款：对前30及 AI 选出的最强落选反例，集中检查科技进展如何转化为每股回报、三/六个月内何种信息改变定价、最强相反解释是否成立。允许审查者提出新机制、回到一手资料，允许原模型反驳审查意见；不能以统一打分、固定网页数量或强制同意消除分歧。无法消除的冲突应保留来源、条件和名次影响，交给综合研究作公开判断，而不是运行器暗中裁决。

## 六、可直接用于下一批次的条款示例

这些示例是拟议约定，不声称现行队列已经支持同名字段；也不要求立刻把每条约定变成程序硬校验。

| 现有约定需要补足的地方 | 下一版具体条款 |
|---|---|
| 只写领域与队列先后 | “本行业批次引用背景版本甲；背景乙的更新是本次必需前置。乙未完成时，该行业暂不放行；不依赖乙的其他行业可继续。不得以其他背景已完成代替乙。” |
| 同组 master 放在 group 后面 | “master 仅消费清单指定的四个组成果。领取顺序不能代替完成确认；缺组、错公司集合或不同批次身份时等待或报告阻塞，不联网重建缺组后冒称已完成原批次汇总。” |
| 任务失败后领域屏障消失 | “上游失败分别标记必需缺失与可选缺失。必需缺失须解决或显式形成新的降级研究版本；可选缺失由研究者解释它最可能影响哪个判断，不因一份补充材料失败停掉全部研究。” |
| 复制 prompt 后默认继承新方案 | “本次运行绑定明确版本及实际提示 hash。复制稿与正式入口不同，须说明目的和差异；不会因为文件名含最新或路径仍可访问而自动继承新合同。” |
| sourceDate 兼作所有日期 | “所有决定前30入围的事实注明何时公开及其经营期间。报告完成时间与价格锚分开；资料晚到只进入后续版本，不能重写原截止日下的结论。” |
| 字段未知即套默认中性分 | “身份和单位冲突先澄清；经济参数未知允许区间或有依据的推断。说明该不确定性是否足以使候选与替代公司换位，而不是自动填50分或直接淘汰。” |
| done 被消费为质量已通过 | “任务完成只表明锁定文件生成。研究者自检、来源口径审查、投资判断挑战分别说明已做什么、尚有什么冲突；没有审查记录不得显示为已获独立验证。” |
| 上游评级在下游反复投票 | “保留来源链：继承的事实、继承的假设与下游新增推断分开。若两个方法只重用同一上游评级，它们不构成两份独立支持；允许质疑上游，不允许为配合下游榜单倒改事实。” |

例如某客户定点尚未披露最终订单量，文件身份和公开日期可以确定，经济量级仍可能只能估算。正确的合同不应把后者伪装成前者已验证，也不应要求有确定订单量才允许研究。AI 可以判断技术认证如何改变商业成功概率，并给出价值区间；前30审查则追问这种信息是否新于市场已有预期、在三/六个月窗口是否可能被确认。这样把硬约束放在事实身份，把创造性留在技术与投资推断。

另一个例子是行业报告在批次中途出现修订。若它只是改错字，下游可以记录等价修订；若它把可交付产能或利润池从一个量级改到另一个量级，就不能让部分公司读旧版、部分读新版而仍声称同一横截面。应记录受影响的公司与结论，形成一致口径的新比较版本；不必重新研究与修订无关的全部公司。这里的边界需要研究者根据经济影响判断，哈希变化本身只能提示文件变化，不能自动衡量投资重要性。

## 七、应修改什么，不应让控制平面承担什么

下一版运行说明应把五项合同连起来：入口身份回答“执行哪个版本”；依赖放行回答“哪些成果已就绪”；manifest 回答“实际用了哪些文件”；事实截止与经济口径回答“这些数字能否在同一时点比较”；输出与独立审查回答“文件已生成，以及哪些检查确实完成”。技术实现仍可后置，先用具体批次证明这些条款可执行，并记录例外，而不是先增加大量硬字段。

研究方案只规定应解决的经济问题、允许的证据与可审查判断；运行路径、队列和输出路由留在编排说明。现有测试也明确要求标准研究方案不写 runner/入队操作，新增条款不应把控制面噪声塞回每个公司研究问题。[研究方案与路由分工](<D:/drive/Investment/tools/research-runner/test/output-contract.test.mjs:109>)。从这项审计能提出的结论是依赖和版本合同应更明确，不能由此宣布投资能力已经提高；是否减少漏判，仍要由新建议生成后的三个月、六个月证据回答。
