## 一、结论先行

这项重构值得做，但目标应定义为“基于历史可得信息的概率预测与风险分布系统”，而不是承诺稳定猜中未来涨跌。

最合理的总体结构是：

1. 先建立统一、无未来信息泄漏的目标和数据层。
2. 每个因子家族用一份独立 `研究方案.md` 完成定义、数据获取、样本外检验、稳定性和淘汰判断。
3. 每个通过门槛的因子输出标准化的样本外预测序列，而不只是叙述性 Markdown 报告。
4. 总研究方案只组合已经冻结的子因子预测，比较等权、稳健中位数、受约束回归和 stacking；不把几百个原始字段一次性扔进黑箱。
5. 每次最终预测同时给出方向概率、收益分位数、波动率、最大回撤概率、相对强弱和数据新鲜度。

初步建议建立 18 个候选因子研究方案，分两批运行；第一批先做价格/趋势、波动率、期权、宽度、盈利预期、信用、利率、宏观意外、尾部风险，以及 QQQ/小盘/SOX 的专属相对因子。传统估值主要服务半年至一年，不应拿来强行解释 10 日涨跌。季节性、图形形态、单一情绪指标和历史相似日只能作为低优先级 challenger。

## 三、统一预测契约

所有因子研究和总模型必须先遵循同一个 prediction contract。

### 3.1 目标资产

| target_id | 研究目标 | 长历史指数 | 可交易复核代理 | 备注 |
|---|---|---|---|---|
| `NDX` | 纳斯达克 100 / QQQ | Nasdaq-100 | QQQ | 指数用于长历史，ETF adjusted total return 用于可交易复核 |
| `SPX` | 标普 500 | S&P 500 | SPY | 同时报告价格收益、总回报和超额收益口径 |
| `TOTAL_US` | 美国全市场 | CRSP/Wilshire 类全市场指数 | VTI | 最终数据源需确认历史、授权和点时间口径 |
| `SMALL_US` | 美国小盘 | Russell 2000 或稳定的小盘总回报指数 | IWM | 需避免用今天的成分股回填历史 |
| `SOX` | 半导体 | Nasdaq PHLX Semiconductor Index | SOXX/SMH | 指数方法与成分变化必须保留历史版本 |

原则：训练优先使用官方/授权的长历史总回报指数；ETF 用于可交易性和费用、分红复核，不能只靠 ETF 较短历史训练一年期模型。

### 3.2 预测时点与期限

- 标准信号时点：美国交易日 `D` 收盘后。
- 只能使用在 `D 16:00 ET` 前已经公开、且系统已经采集到的信息。
- 收盘后发布的信息最早进入 `D+1` 模型。
- 周末和休市日新闻映射至下一个可交易日，并保留原始发布时间。
- 预测窗口固定为未来 `10/21/63/126/252` 个交易日，不混用自然月。
- 若未来需要盘前预测，必须建立独立 `pre_open` contract，不能与收盘模型混用。

### 3.3 每个 target × horizon 的输出

每个因子和总模型至少输出：

1. `expected_total_return`：未来累计总回报预期。
2. `expected_excess_return`：相对匹配期限无风险利率的超额收益。
3. `prob_up`：未来累计收益大于 0 的校准概率。
4. `return_q05/q25/q50/q75/q95`：收益分布分位数。
5. `expected_realized_vol`：未来实现波动率。
6. `prob_drawdown_5`、`prob_drawdown_10`：窗口内最大回撤超过 5%/10% 的概率。
7. `expected_max_drawdown`：未来窗口路径最大回撤。
8. `relative_return`：QQQ-SPX、小盘-SPX、SOX-SPX/QQQ 的同期相对收益。
9. `confidence`：基于历史支持度、样本外稳定性和当前是否超出训练分布。
10. `data_freshness`：最旧关键输入、最新关键输入、缺失率、异常状态。

不能只报 accuracy。美股长期上涨会使 `always-up` 看起来很好；概率模型必须报告 Brier、log loss、校准曲线、AUC 与 balanced accuracy。

## 四、搜索与证据后的因子优先级

### 4.1 总体证据判断

需要把“收益方向”和“风险状态”分开。最新的大样本复核显示，大量经典股票收益预测变量在扩展样本中失去显著性或样本外能力；传统估值单因子尤其不能被当作短期万能信号。[Goyal、Welch、Zafirov 2024](https://academic.oup.com/rfs/article/37/11/3490/7749383) 对 46 个变量的复核发现，相当一部分后来失效，仍稳健的只有少数。[Welch–Goyal](https://www.nber.org/papers/w10483) 的经典负面基准也表明，大量变量样本外无法战胜历史均值。

这不等于完全不可预测。合理的符号/经济约束可能带来很小但有经济意义的改善，[Campbell–Thompson](https://www.nber.org/papers/w11468) 给出了这种结果；[Rapach、Strauss、Zhou](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=1544161) 表明组合多个较弱预测可以降低预测波动并改善稳定性。但系统的默认先验仍应是：预测力弱、会漂移、很容易被回测夸大。

相较收益均值，波动率和尾部风险更可预测。[Fed 2025 的 S&P 500 滚动比较](https://www.federalreserve.gov/econres/feds/linear-and-nonlinear-econometric-models-against-machine-learning-models.htm) 显示状态切换 HAR 等透明模型稳定优于多种复杂 ML；[Andersen、Bollerslev、Diebold、Labys](https://www.nber.org/papers/w8160) 也为实现波动率的时序可预测性提供了基础。因此短期系统的主价值应更多来自风险分布、事件窗口和相对强弱，而不是一个生硬的涨跌标签。

一些信号会同时表示“短期风险升高”和“中期预期收益升高”。例如高尾部风险或高 VRP 可能提高近期回撤概率，同时提高持有风险所要求的未来回报。因此每个因子必须对收益均值、波动率和左尾分别建模，不能把一个风险指标机械翻译成“看空”。

### 4.3 有较强时域证据的重点方向

- 方差风险溢价的收益预测证据主要集中在 2–4 个月，正好对应 63/126 日研究。[Federal Reserve：Variance Risk Premia](https://www.federalreserve.gov/econres/feds/stock-return-predictability-and-variance-risk-premia-statistical-inference-and-international-evidence.htm)
- 宏观模型与分析师 S&P 500 盈利预测之间的偏差，对 3 个月收益有点时间证据。[Federal Reserve 2024](https://www.federalreserve.gov/econres/feds/predicting-analysts-sp-500-earnings-forecast-errors-and-stock-market-returns-using-macroeconomic-data-and-nowcasts.htm)
- Fed 对宏观意外的研究显示，实际活动意外、价格意外和 FOMC 信息对股票反应不同，且依赖经济状态和市场注意力；事件研究必须使用“实际值减当时共识”，不能只用 CPI/NFP 水平。[Fed 宏观新闻与股票](https://www.federalreserve.gov/econres/notes/feds-notes/macroeconomic-news-and-stock-prices-over-the-fomc-cycle-20201014.html)、[Fed FOMC 综述](https://www.federalreserve.gov/econres/feds/the-effect-of-the-federal-reserve-on-the-stock-market-magnitudes-channels-and-shocks.htm)
- 新闻文本可以产生预测信号，但需要以当时可见文本训练并严格避免词典/模型重训泄漏。[Ke、Kelly、Xiu](https://www.nber.org/papers/w26186)
- 小盘、高波动和高主观估值股票更易受总体情绪影响，因此情绪研究应优先看“小盘-SPX”和“QQQ-SPX”的相对表现，而不是只预测 SPX。[Baker–Wurgler](https://www.nber.org/papers/w10449)

## 六、每份单因子研究方案的统一模板

每份 `MFxxx_研究方案.md` 至少包含：

```markdown
# MFxxx 因子名称：大盘多期限单因子研究方案

## 0. 方案元信息
- factor_id、版本、状态、创建日期、负责人
- 因子类别、数据截止原则、预计成本/授权等级

## 1. 研究问题与经济机制
- 理论传导、预期方向、非线性/阈值、状态依赖
- 零假设、可证伪条件、可能的反向因果

## 2. 预测目标
```

## 八、统一验证护栏

### 8.1 点时间数据

所有输入至少保留：

- `observation_time`
- `release_time`
- `available_to_model_time`
- `revision_id / vintage_date`
- `source_url / source_file_hash`
- `ingested_at`

宏观数据优先使用 [ALFRED](https://alfred.stlouisfed.org/help) 或 Philadelphia Fed 的 [Real-Time Data Set](https://www.philadelphiafed.org/surveys-and-data/real-time-data-research/real-time-data-set-for-macroeconomists)。CFTC COT 必须按周五发布时间而不是周二仓位日期进入模型；[CFTC 官方说明](https://www.cftc.gov/MarketReports/CommitmentsofTraders/index.htm) 明确通常周五发布前一周二的持仓。FINRA margin 是月度且通常次月第三周发布，[FINRA 历史统计](https://www.finra.org/rules-guidance/key-topics/margin-accounts/margin-statistics) 也必须按真实可用日滞后。

### 8.2 时间序列样本外

- 禁止随机 train/test split。
- 采用 expanding 或 rolling walk-forward。
- 10/21/63/126/252 日重叠标签在训练、验证和测试边界做 purge；embargo 至少覆盖目标期限。
- 子因子先冻结公式和超参数，再在 outer OOS 产生伪实时预测。
- 总模型必须有独立第二层 OOS；不能用子研究已经反复挑选过的测试段再训练组合权重。
- 重大危机做 `leave-GFC-out`、`leave-COVID-out`，并单独报告加息、降息、通胀、低波动、高波动状态。

### 8.3 统一基准

| 任务 | 必须比较的基准 | 指标 |
|---|---|---|
| 收益幅度 | 滚动历史均值、零超额收益、简单 AR/动量 | OOS R²、MAE、RMSE |
| 方向概率 | always-up、滚动上涨概率 | Brier、log loss、校准、AUC、balanced accuracy |
| 波动率 | HAR-RV、匹配期限的隐含波动率 | QLIKE、MSE、区间覆盖 |
| 回撤/尾部 | 滚动历史分位数、简单 GARCH/HAR | quantile loss、VaR exceptions、ES、Brier |
| 相对强弱 | 零相对收益、相对动量、静态 beta/style | OOS R²、hit rate、回撤 |

### 8.4 多重检验与重叠收益

长期预测回归容易因持久变量、小样本和重叠收益制造假象。[Nelson–Kim](https://www.nber.org/papers/w3297) 证明，即使真实收益不可预测，也可能复制出表面上的长期可预测性；[Harvey、Liu、Zhu](https://www.nber.org/papers/w20592) 说明 factor zoo 下普通 `t>2` 门槛不够。

因此必须：

- 预登记窗口、变换、方向和期限。
- 记录所有尝试，不只记录成功版本。
- 使用 horizon-aware HAC、block bootstrap 或等效稳健推断。
- 对嵌套预测采用适当的 Clark–West 类检验。
- 使用 FDR、stepdown、Reality Check/SPA 类修正。
- 报告滚动系数、符号稳定性、置信区间和失效期。

## 九、总研究方案与组合模型

### 9.1 总模型只消费冻结的 OOS 子预测

推荐流程：

```text
原始点时间数据
  -> 各 MFxxx 独立构造特征
  -> 各 MFxxx 生成冻结的 walk-forward OOS 预测
  -> 因子质量门槛与冗余检查
  -> 总模型组合预测
  -> 方向 + 分布 + 风险 + 相对强弱报告
```

总模型不直接读取子报告中的主观“看多/看空”结论，也不应首先读取全部原始特征。它读取每个子因子的标准化预测、置信度、OOS 表现、适用 target/horizon、数据新鲜度和当前是否超出训练支持区间。

### 9.2 每个 target × horizon 单独组合

25 个 target × horizon 任务分别比较：

1. 历史均值/always-up 基准。
2. 简单等权平均。
3. 稳健中位数或 trimmed mean。
4. 受符号/权重约束的线性组合。
5. 正则化 stacking。
6. 只有在 OOS 明确改善时才允许的 regime-dependent 权重。

优先选择最简单、校准最好、跨时期最稳定的组合，不按样本内最高 R² 选模型。

### 9.3 因子进入总模型的门槛

因子可以获得三种结论：

- `pass`：有样本外增量、稳定、点时间合格，可进入总模型。
- `monitor`：对风险或某些 regime 有信息，但收益预测不稳定，只作 overlay。
- `reject`：样本外无增量、依赖单一危机、存在泄漏或高度冗余，不进入组合。

即使一个因子不能预测收益，也可能因稳定预测波动率/回撤而保留；不能以单一“显著/不显著”决定全部用途。

## 十、Research Runner 的使用方案

### 10.1 当前能力

现有 `file-run` 可以：

- 读取 Investment 根目录内任意研究方案文件。
- 为每个任务启动独立 Codex 线程并开启 live web。
- 锁定一个 `expectedOutputFile`。
- 并发运行多个因子任务。

但它目前没有：

- `dependsOn` / DAG / `all_success`。
- 同一输出路径的活动任务冲突保护。
- `file-run` 的旧结果备份和失败回滚。
- 因子报告与机器可读 bundle 的内容 schema 校验。

所有 `file-run` 处于同一优先组。如果子因子和总方案同时入队，总方案可能提前启动；即使某个子因子最终 failed，调度器也不会自动阻止总方案。

### 10.2 短期：安全的两阶段运行

第一阶段只入队单因子：

```powershell
cd "D:\drive\Investment\tools\research-runner"

npm run queue:add-file-run -- `
  --run-id="market-factor-MF001-trend-20260712" `
  --prompt-file="技术面/研究方案/单因子/MF001_价格趋势_研究方案.md" `
  --expected-output-file="技术面/研究结果/因子/MF001/主报告_2026-07-12.md" `
  --reasoning=max

npm run queue:validate
npm start -- --concurrency=3
```

确认所有相关任务均 `done`，且没有 `pending/running/retry_pending/failed` 后，第二阶段再入队总研究：

```powershell
npm run queue:add-file-run -- `
  --run-id="market-forecast-master-20260712" `
  --prompt-file="技术面/研究方案/总方案/MF_MASTER_大盘多期限预测总研究方案.md" `
  --expected-output-file="技术面/研究结果/总预测/大盘多期限预测_2026-07-12.md" `
  --reasoning=max

npm run queue:validate
npm run once
```

这是重构后的建议路径。正式采用前需要同步更新 `技术面/AGENTS.md`；在更新目录规则之前，正式结果仍应写入现有核心 `技术面/技术面/` 下的合规子目录。

首批并发建议 3，而不是默认 10；等确认输出隔离、数据锁和资源竞争后再提高。

### 10.3 中期：新增正式 domain

建议给 runner 增加：

- `market-factor`
- `market-forecast`
- `seed-market-factor-from-plans`
- 通用 `batchId / dependsOn / dependencyPolicy=all_success`
- 相同 `expectedOutputFile` 冲突校验
- 结果 bundle schema validator
- 备份和失败回滚
- 依赖失败传播、DAG 无环校验和测试

仅靠调整 domain 优先级不够；必须显式保证“全部必需子研究成功且批次/as-of 一致”后，总研究才可领取。

## 十三、实施顺序

### Phase 0：冻结与审计

- 对现有 250 个文件做 inventory、hash、数据截止日和引用扫描。
- 冻结 `common_daily_v1` 与现有报告快照。
- 标记失效路径、乱码、空 ZQ feature、tmp 隐式依赖。
- 不搬迁、不删除。

验收：任何旧结果都能通过 manifest 找回；备份/legacy/tmp 默认排除。

### Phase 1：预测契约与目录骨架

- 更新 `AGENTS.md/README.md`。
- 创建 target/factor/label/data-source registry。
- 创建统一单因子模板、总方案模板、runbook 和依赖清单。
- 创建 Python dependency manifest 与 tests 骨架。

验收：一个空白 MF 方案能通过 schema；runner 路径与正式目录规则一致。

### Phase 2：目标、标签与点时间数据 v2

- 补全 TOTAL_US 和 SMALL_US。
- 为五资产建立 10/21/63/126/252 日 forward return、excess return、vol、MDD、tail、relative labels。
- 引入 `available_at`、vintage、source hash。
- 修复现有宏观、宽度、集中度、NFP、ZQ 和估值风险。

验收：随机抽样日期可以回答“当日模型到底知道什么”；任何 label 不出现在特征侧。

### Phase 3：第一批 12 个因子研究

- 每份方案先预登记，再实现脚本、walk-forward 和标准输出。
- 先跑简单可解释模型，再将复杂模型作为 challenger。
- 每个因子给出 pass/monitor/reject，允许不显著和失败结论。

验收：五资产 × 五期限覆盖；机器可读 OOS 预测可由脚本复算。

### Phase 4：第二批 6 个因子与冗余清理

- 补 positioning、跨资产、估值、微观结构、季节性等。
- 做相关性、增量 OOS、共同暴露和 factor clustering。
- 删除冗余只指从“总模型候选”移除，不删除研究记录。

验收：每个保留因子都有清楚的独立增量或明确的风险用途。

### Phase 5：总研究方案与 ensemble

- 只消费冻结 OOS 子预测。
- 对 25 个任务比较等权、中位数、受约束组合和 stacking。
- 建立独立 outer OOS、校准、stress test 和模型降级策略。

验收：至少不劣于朴素基准；若不能超越，报告“无增量”而不是强行给信号。

### Phase 6：生产预测与监控

- 生成统一日期的五指数、五期限报告。
- 输出数据新鲜度、缺失因子、支持区间、概率校准和近期漂移。
- 建立周/月更新、因子失效、数据异常、模型回退 runbook。

验收：任何缺失或过期因子都不会静默进入总预测；上次可用模型和朴素基准可自动回退。
