## 二、模型、方向与 NA 纪律

### 2.1 因果结构

`终端需求与库存 → 订单和供给缺口 → 交期/利用率/价格 → 公司可售量与价格传导 → 增量毛利`

行业层只描述共同状态，公司层只描述目标公司把共同状态落入销量、价差与毛利的能力：

```text
RegimeUp       = max(IndustryRegime, 0)
RegimeDown     = max(-IndustryRegime, 0)
UpsideCapture  = RegimeUp × Exposure × SellableCapacity × UpsidePassThrough
DownsideLoss   = RegimeDown × Exposure × VolumeDownsideSensitivity × (1 − DownsideProtection)
                 + CompanyNetCostShock
PricingCapture = UpsideCapture − DownsideLoss
```

所有公司参数均为 0—1，且高值方向固定：

| 参数 | 高值含义 | 口径约束 |
|---|---|---|
| Exposure（E） | 收入、客户和产品与目标细分市场高度匹配 | 不用宽泛行业收入代替具体规格/地区/合同暴露 |
| SellableCapacity（SC） | 当前已合格、已验收且可交付能力高 | 在建、拟建、待认证和未爬坡能力不计 |
| UpsidePassThrough（UP） | 上行期能保留价格、组合或稀缺溢价 | 区分现货和合同，不把 ASP 单独当利润 |
| DownsideProtection（DP） | 下行期有合同、服务、续约或成本优势保护 | 与上行传导方向分开，不混用 |
| VolumeDownsideSensitivity（VDS） | 需求下行时销量/利用率损失大 | 高值是不利方向，只进入损失项 |
| CompanyNetCostShock（Cost） | 行业状态未含的公司特有成本冲击高 | 不重复扣需求恶化、市场价差或行业库存 |

### 2.2 变换与显示分

机器表中的 `raw_value` 即 `PricingCapture`，单位为无量纲增量毛利捕获指数。机器表的 `transform=T1` 定义如下：

1. 在 `peer_group` 内用中位数和 `1.4826×MAD` 计算稳健 `z_raw`；尺度下限为 0.0600，`z_raw` 截尾于 [-3, 3]。同组少于 3 家时，仅为 z 值使用其正式大类作回退，绝对捕获值不被回填。
2. `z_neutral = reliability × z_raw`，低可靠度只把相对偏离向 0 收缩，不把缺失值变成中性值。
3. `display_score = clip(1,10, 5.5 + 4.5×raw_value + 0.4×z_neutral)`。绝对捕获占主导，相对同业只作校正，因此“同业最弱但仍有正捕获”的公司不会被机械打成极低分。
4. `interval_low/high` 是证据与情景不确定性区间，不是统计置信区间；半宽为 `0.45 + 1.55×(1−reliability) + 0.35×abs(IndustryRegime)`。

### 2.3 情景定义

逐公司“下/基/上”保持公司当前 E、SC、UP、DP、VDS、Cost 与同业相对项不变，只把行业状态分别设为 `IR−0.30`、当前 IR、`IR+0.15`（均截尾至 [-1,1]）。上行情景不加入未来产能；下行情景显式允许正景气跨入负状态。它是敏感性分析，不是概率加权目标价。

### 2.4 NA

LWLG、OKLO、SMR 的 `raw_value`、z 值、区间和显示分全部保持 `NA`。原因不是“看空”，而是截至资料截止点缺少至少一组可核验的当前量产/运营收入、合格可售能力、合同价格或成本经济性。POET 已有有限商业/验证证据，故保留低可靠度数值，但把当前 SC 压低且区间加宽。

### 6.2 关键共同反证

- **订单不等于终端需求。** 服务器、光模块、设备与工程链条都要求用出货、验收、客户库存与取消率交叉验证，不能仅以积压或管理层形容词定景气。
- **现货不等于合同经济性。** HBM、NAND、HDD、光器件、电力与化学品均区分 spot/contract；合同锁价、重定价频率、材料传导和折扣决定公司捕获。
- **名义产能不等于可售产能。** AI 数据中心、NeoCloud、核能、光器件、SiC、先进封装和新电池项目只计已通电、已认证、已爬坡、已验收能力。
- **紧缺会均值回归。** 光器件、冷却、变压器、HBM 和先进封装的高 IR 均附带扩产、良率改善、客户自研或平台切换的反转条件。
- **低景气不等于零价值。** SiC、光伏和泳池设备中的公司仍可凭合同、成本、份额或售后获得保护；模型通过 DP 和公司特有参数保留这种差异。
- **成本不得重复扣分。** 行业共同的需求恶化、ASP/成本差和库存压力只进入 IR；Cost 只保留公司自己的低利用率、融资、折旧、项目亏损或执行冲击。

### 6.3 结论反转监控顺序

1. 先看订单质量：B2B、取消、重复下单、客户/渠道/公司库存位置。
2. 再看瓶颈吞吐：合格产能、良率、交期、利用率及客户验收，而非公告名义产能。
3. 再看价格—成本差：合同 ASP、折扣、重定价频率、原料/电力/折旧/保修成本。
4. 最后落到公司：当前可售量、产品适配、客户集中、合同保护与份额。只有四层同向，才上调捕获结论。

## 九、使用限制

本结果是供需状态与公司毛利捕获能力的截面特征，不是证券推荐。IR 的持续期是依据现有订单、库存、产能和合同证据形成的阶段判断；一旦领先指标触发反转条件，应先重估行业共同状态，再重估公司参数，不能只机械平移显示分。对披露颗粒度较低、客户集中或项目型收入占比较高的公司，应优先使用区间和反转条件，而非单点分数。
