# 边缘云、应用交付与无服务器计算行业调研：交付量、可收费执行与价值分配

研究截止日：2026-09-18。财务事实以截止日前已公布材料为限，主要为 2025 全年及 2026 年第二季度；预测覆盖 2026—2029 自然年。金额除特别说明外均为美元，B 表示十亿美元，M 表示百万美元；1 B = 10 亿美元。报告中的年度市场收入均为当年流量，不是年末 ARR。

证据标记：**F**＝公开披露事实；**M**＝管理层目标或厂商性能主张；**C**＝根据给定数据直接计算；**E**＝本报告研究估算；**U**＝尚不可识别。预测区间是参数条件范围或情景范围，不是统计置信区间。

研究输入边界：本地研究输入仅检索了 `基本面/行业调研/产业背景/`；目录 AGENTS.md 仅用于执行规则。没有读取其他公司报告、行业结果、排名、历史对话或记忆作为研究输入。背景材料中的 CDN 市场规模没有直接沿用；Medley 线索已追到 USENIX 原始论文页面。完整模型、证据登记和参考链接集中保存在本报告，未另建正式报告。

## 一、核心判断及其可证伪边界

**本行业最有依据的基准路径，是传统交付保持弱增长、应用交付增加附加值、CPU 无服务器平台扩张；行业收入不能随执行量同比例外推，利润则取决于降本、竞争和再投资。尚无证据支持把整个行业判断为物理产能短缺。** 真正稀缺的部分是可以承担生产责任的状态管理、迁移兼容、隔离、故障恢复与客户工作流入口。它们能创造价值，但未必由独立边缘供应商收费。

1. **已有经营证据同时支持增长与价值流失。** Fastly 2026Q2 Network Services 收入同比增长 17%，Akamai 同期按重分类后的 Delivery and other cloud applications 口径下降 6%；两者不是完全相同产品，不能直接计算份额转移，却足以反驳“所有交付商随流量一起增长”。Cloudflare 整体收入增长 36%，但不能把安全和其他平台业务都归为 Workers。详见事实底表。[S01][S02][S03]
2. **“边缘执行”不必发生在最靠近用户的节点。** Cloudflare Placement 明确允许把执行移到数据库附近；地理分散的网络、集中或区域化的状态，以及统一控制平面，是可以共存的。客户购买的是端到端完成任务的成本与可靠性，节点数量本身不能解释支付意愿。[S12]
3. **AI 新增需求中，最有价值的单位可能是被隔离和授权的代码实例，而非 Token 或 HTTP 请求。** 普通 Workers 按请求与 CPU 时间计费；Dynamic Workers 还对每天创建的唯一实例收费。代码和 ID 复用可大幅改变费用。因此“Agent 更多”对收入的传导，必须经过付费采用、独特代码数量、复用率、净价和客户预算。[S10][S11]
4. **可审查的规模结论比通用“边缘计算 TAM”窄得多。** 本报告估计 2025 年核心市场 A+B+C 为 **6.35—12.20 B，代表基数 8.85 B**：大宗 CDN 4—7 B、托管动态应用交付 2—4 B、边缘 CPU/开发者执行平台 0.35—1.20 B。全部为 E，置信度低至中，尤其云厂商产品收入与合同拆分误差较大。2027 年基准条件范围 **7.65—15.15 B，代表值 10.79 B**；2029 年 **9.11—18.61 B，代表值 13.02 B**。不能把这些范围称为披露的市场规模。详见第七节及附录 A。
5. **区域 CPU 无服务器市场 D 另列，不能冒充边缘云。** 2025 年研究范围为 1.5—8.0 B，代表值 3.6 B；范围很宽，原因是调用统计无法分离内部、免费和外部付费流量，平均 GB·秒也未披露。Lambda、Cloud Run、Azure Functions 的增长对边缘平台既是需求验证，也是强替代。A+B+C 与 D 的平台转售费用还须去重，不能直接拿两项上限当终端支出。[S16][S17]
6. **最强反面解释：边缘平台可能只是通用云和应用框架的低价附属能力。** AWS 已把交付、安全、DNS、日志和边缘执行打包为固定月费；区域无服务器也在改进并发和 CPU 计价。如果客户无需迁移状态即可获得接近的体验，独立边缘平台的增长可能主要表现为更多免费调用、交叉销售或替代原有收费。[S13][S14][S18][S19]

当前没有解决的三个决定性问题是：Cloudflare 的外部 CPU 执行收入究竟多大；主要云厂商交付和函数业务真实折后单价是多少；生产级 Agent 的代码复用和付费留存如何演变。报告对这些问题给出范围与阈值，不把未知写成已兑现收入。

## 二、市场边界：同一张账单只能归属一次

### 2.1 可加子池与相邻市场

| 编号 | 本报告统计对象 | 客户购买的经济单位 | 计入与排除 |
|---|---|---|---|
| A | 大宗 CDN：视频、软件包、游戏更新、静态对象分发 | 成功交付 GB、约定峰值带宽、最低消费 | 计入对最终应用/内容采购方的交付收入；不计源站存储、视频制作、GPU 生成费用、互联网接入费与自建 CDN 内部结算 |
| B | 托管动态应用交付：全球路由、负载分配、API/网页加速、非安全主导的交付控制 | 付费应用部署、受 SLA 约束的请求、年度服务合同 | 计入 A 之外的动态交付和控制附加值；专门 WAF、DDoS、SASE、身份安全排除；企业自管 ADC 设备及维护不并入 |
| C | 边缘 CPU/开发者执行平台：Workers、Compute、EdgeWorkers、CloudFront Functions/Lambda@Edge 等 | 外部付费 CPU 时间、执行请求、必要的平台订阅及编排收费 | 包含由边缘平台调度至数据附近的执行；排除 GPU 推理、通用数据库/对象存储、独立可观测性、安全收费、平台内部自用 |
| D | 相邻对照：区域 CPU 无服务器执行与托管函数/容器运行 | GB·秒、CPU·秒、实例时、外部付费函数请求 | Lambda 区域服务、Azure Functions、Cloud Run 中 CPU 应用执行等；不计全部 PaaS、Kubernetes、通用 IaaS 或 GPU serverless |

**核心市场 N=A+B+C。** B 对“应用交付”的定义特意限于托管服务；F5、NetScaler、NGINX、HAProxy、Envoy 等自管方案是关键竞争和替代对象，其整家公司收入不进入 N。D 保留完整情景作为替代路线对照，而不是把地域上在中心云的运行强称为边缘。

混合合同优先按独立售价、合同服务项和主要采购任务拆分。无法拆分时，保留归属区间，且同一合同各部分之和不得超过合同收入。例：客户支付 100 给平台，平台向上游云支付 30；终端池计 100，分层供应商可分别记录 100 与 30，但不能说最终需求为 130。平台毛利若为 60，也不等于产业增加值为 60：研发、销售、人力等仍要扣除，云厂商增加值须另核。

Cloudflare 将自己的安全产品跑在 Workers 上、AWS 内部使用 Lambda、CDN 节点间复制内容，都不自动形成新增外部 C/D/A 收入。AI Gateway 转发的模型 Token 费用和内容版权支付也不归本专题。

### 2.2 需求归谁负责，谁能削减预算

| 客户任务 | 采购、使用、验收与失败成本 | 预算来源 | 容易观察的支付边界 |
|---|---|---|---|
| 直播、视频、游戏更新 | 媒体/游戏基础设施团队采购，播放器或终端使用，按卡顿、首帧、成功率验收；赛事版权方和业务方承担用户流失 | 多数替代既有带宽和托管预算；大型活动增加短期预算 | 单位观看小时实际交付 GB × 商业外包份额 × 净价；观看量增长不等于外包收入增长 |
| 电商、API、全球 SaaS | 平台工程和业务共同采购，SRE 验收尾延迟、错误率、回滚；业务方承担支付或交易中断 | 应用基础设施支出内部转移，跨境扩张可带来新增 | SLA 合同保底、成功请求成本、减少源站负载的实际节省 |
| 开发者函数和应用托管 | 开发团队采用，平台工程/FinOps 放行，生产事故由客户与服务商共同承担 | 服务器运维预算转移，加上一部分新应用预算 | 从注册/试用到付费生产部署，再到持续月度消费；下载数、开发者数均非客户收入 |
| Agent 工具调用、隔离执行 | AI 产品团队发起，安全和数据所有者决定访问权限，企业采购审核；越权和错误写入损失可远超算力账单 | 新增 AI 产品预算与原自动化预算替代并存 | 收费完成任务数、独特代码实例、复用率、权限控制、日志与失败重试 |

需求侧基本式为：`客户任务量 × 外包比例 × 生产付费比例 × 每任务计费工作量 × 净价`。技术效率可以同时提高第一项、压低第四项，最后还可能通过议价压低第五项；本文不默认哪一个更大。

## 四、技术如何改变采用、成本与收费

### 4.1 三种运行机制，各有适用客户

| 路线 | 截止日成熟度与证据 | 客户经济收益 | 限制与价值捕获 |
|---|---|---|---|
| CDN 缓存、分层回源、压缩和路由优化 | 已大规模交付；ByteDance Medley 已在商业直播系统部署 | 减少中间传输、源站负载、峰值冗余与卡顿 | 更多效率可变成更低采购费用；不能把特定 midgress 的降幅乘到整个 CDN 成本上。[S20] |
| V8 isolate / Wasm 沙箱 | Workers 和 Fastly Compute 已商业化；Dynamic Workers 在 2026-03-24 公布 open beta | 轻量启动、密集多租户、短任务按需运行 | 兼容性和权限模型影响迁移；轻量沙箱并非任意 Linux 环境。厂商“100 倍启动提速”不是独立通用基准。[S21][S22] |
| 区域函数、共享并发容器、受管实例 | Lambda、Cloud Run、Vercel Fluid 等已商业化 | 更接近现有数据库，兼容成熟语言库；并发复用减少空等成本 | 可夺走原本设想迁往边缘的工作负载；CPU、内存驻留和实例保留的收费口径不同。[S18][S19][S23] |
| 状态化边缘和持久工作流 | Durable Objects、Workflows 等已有产品；动态创建状态/工作流是更早阶段的新能力 | 会话、协调、失败后恢复，降低开发负担 | 状态一致性、地域、热键、故障域和迁移成本成为瓶颈，不能以无状态吞吐量替代验证。[S24][S25] |

原始 Medley 论文报告 midgress 成本下降 **76.83%**，其经济含义是特定架构和工作负载下的中间带宽优化，而不是客户最终账单下降 76.83%。假设 midgress 占某交付商总成本 10%—30%，同样改进完全适用且无新增成本，理论总成本降幅也仅为 **7.7%—23.0%**；真实推广还须扣除工程、存储、冗余和不同客户流量结构的影响。这个传导算式比把论文性能直接当 TAM 更有解释力。[S20]

### 4.2 数据位置可能比网络位置更重要

一个需要五次串行数据库往返的请求，若每次跨区域往返 40 ms，仅这部分就约 200 ms；把执行移到数据库旁，假设本地每次 1 ms，加一次 40 ms 远程入口转发，则约 45 ms。**155 ms 的差额只是工程示例 C，不是服务商测得的普遍收益。** 它解释为什么“执行靠近用户”与“任务更快”不是同义词。Cloudflare 官方 Placement 文档给出的也是这一机制。[S12]

因此，全局入口、就近缓存、区域执行、状态化协调可能构成混合架构。它减少客户全面迁移需求，也限制边缘供应商对所有后端支出的占有。更强状态绑定会提高留存，但也增加厂商承担的恢复与兼容责任。

Cloudflare 2025-06-12 的事故是反证：Workers KV 底层存储依赖故障导致多个产品受影响，持续 **2 小时 28 分钟**；缓存、代理等服务并非全部受影响。全球节点分布不能消除共同状态依赖和控制平面的故障域。这是历史事件，不据此断言截止日仍存在相同未修复问题。[S26]

### 4.3 一个百万请求示例：计价差异远大于“无服务器”标签

统一示例为每月 100 万次 CPU 轻任务，每次主动 CPU 10 ms、等待外部服务 1 秒；忽略免费额度、企业折扣、税费，且不把不同架构视为完全等效产品。

| 计价路径 | 可复算账单示例 C | 解释 |
|---|---|---|
| Workers 标准增量 | 请求 0.30 美元 + CPU `1,000,000×10 ms÷1,000,000×0.02=0.20` 美元，共 **0.50 美元** | 实际账户仍有最低月费和包含额度；不收费的等待时间不代表内存与状态没有供应商成本。[S10] |
| 区域 Lambda 示例，配置 1 GB、每次计费 1 秒 | `1,000,000×1 GB·秒×0.0000166667+0.20≈16.87 美元` | 这是公开 x86 示例费率的计价比较；不是相同性能测试，也不涵盖 API Gateway、日志、网络与优惠。[S17] |
| Vercel Fluid | 主动 CPU `10,000 秒÷3,600×0.128≈0.356 美元`；再加内存驻留及请求费 | 公开起始价内存 0.0106 美元/GB·小时、请求 0.60 美元/百万；并发复用使每请求分摊内存改变，不能把 CPU 费用当总账单。[S18] |
| Dynamic Workers，100 万次均产生不同代码/ID | 唯一实例费约 `1,000,000×0.002=2,000 美元`，另加请求和 CPU | 同样 100 万次，如果每天重复同一个 ID 和相同代码，30 天仅 30 个计费实例日，即 **0.06 美元**实例费。启动 CPU 另计。[S11] |

最后一行意味着：独特代码执行和复用执行不是相同商品。厂商按独特实例收取的是隔离和创建管理的费用；用户可能通过参数化、缓存、固定工具或通用沙箱减少独特实例。**短代码运行越便宜，供应商越需要证明“创建和治理”值得持续付费。** 本报告没有把 2,000/0.50 的比值解释为可持续价格溢价，因为所购买能力和安全边界不同。

若客户每年产生 1 亿次新的独特实例，按上述标价实例费约 **20 万美元**；若每年增长到 10 亿次，约 **200 万美元**。必须证明省下的工程、人力、错误与延迟损失足以覆盖费用，才能从功能使用跨入企业预算。

### 4.4 客户收益确实存在，但案例不能替代分布

OneTrust 的厂商案例披露约 **每周 640 亿次 hits**，客户称使用 Workers 后延迟减半、相关成本下降 90%；C&A 案例描述购物高峰流量可增加十倍。它们支持“波动、全球读取、轻量逻辑适合托管执行”，但为供应商选择的成功案例，原始账单、合同和比较配置未公开，页面未给明确发布日，均按 2026-09-18 访问标记，不当作 2026 年新增采用或行业均值。[S27][S28]

作为数量级桥梁：640 亿/周相当于一年约 3.328 万亿次 hits；若其中全部是 10 ms 的额外收费 Workers 请求，按前例边际标价只约 **166.4 万美元/年**。这是反事实定价练习，不是 OneTrust 账单。要仅靠类似轻执行形成 0.65 B，约需 390 个这种付费工作量当量，或者更多较小客户、较重执行及平台订阅。这解释为什么“万亿请求”本身不足以证明数十亿美元 CPU 收入。

### 4.5 标价向净价的传导

AWS 在 2025-11-18 发布 CloudFront 固定月费套餐，原始档位为 0/15/200/1,000 美元，整合多项服务且无按使用超额收费；适用流量额度、资格与超量政策仍须遵循文档。它不是没有边界的无限供给。2026-09-03 又增加 API 管理支持，降低自动化采用的摩擦。[S13][S14]

bunny.net 公布的 Volume CDN 起价 **0.005 美元/GB**，更高用量档至 **0.002 美元/GB**；Standard 网络地域价格和节点覆盖不同。Fastly 的小用量公开 CDN 价可明显高于这个数，不能据此判定企业净价差距。阿里云 ESA 的边缘函数另列 **0.72 美元/百万请求**，交付和日志仍可能额外收费。以上均是公开标价锚，本文大宗 A 模型采用的 0.0036 美元/GB 是折后混合单价假设，不是行业报价调查结果。[S29][S30][S31]

小客户套餐可立即重定价，企业合同的价格、承诺用量和产品组合通常随续约或增购改变。本文模型假设显著传导时间为 **6—18 个月 E**；紧急赛事容量和超额用量可能更快，固定承诺合同可能更慢。若供应商靠安全、日志和平台捆绑保住总账单，A/B 的可归属收入仍可能下降。

## 五、有效供给：总体可扩展，局部合格能力不完全可替代

### 5.1 供给判断不能拿收入倒推后再证明自己

供给侧采用三类独立证据：公开网络配置与架构；已经交付的功能、限制和恢复机制；在同类工作负载下可增加的计算/互联能力。收入仅用于另一侧的需求检查，不被视为已安装硬件。

Cloudflare 2026-04-10 披露 **500 Tbps** 是 330 多个城市的**配置外部互联端口容量之和**，并明确不是峰值流量，部分余量用于 DDoS。Fastly IR 页面列 **532 Tbps** 网络容量，但没有给出本报告所需的分地区、合同等级和 CPU 剩余能力。两者不能简单加成客户在同一地区可购买的 SLA 容量。[S32][S33]

对于网络，`有效交付上限=端口配置×地域匹配系数×可持续使用比例×协议/冗余折扣`；对于执行，`有效完成量=可分配 CPU×可用运行时间×利用率÷每任务 CPU 时间`，还受内存、租户配额、数据库、并发和故障恢复约束。可交付能力必须按具体客户所在地、任务与 SLA 检查。

| 供给对象 | 独立供给证据或工程边界 | 需求侧交叉检查 | 截止日判断 |
|---|---|---|---|
| 大宗 CDN | 对 2026-09-19 至 2027-09-18 的前瞻 12 个月，固定单个 532 Tbps 名义网络，理论输送量约 `532×3.942=2,097 EB`；假设符合目标地域的比例 25%—50%、可持续负载 20%—35%，得 **105—367 EB**条件能力 | 同一前瞻 12 个月假设季度收入维持 2026Q2 Network Services 的 133.9 M，即 **535.6 M 运行情景**；大宗占 50%—75%、净价 0.002—0.004 美元/GB，对应 **67—201 EB**。这不是 2026 或 2027 全年收入预测，也不是已知用量 | 区间重叠，不能量出真实利用率；结合多家供给与降价机制，更接近总体可扩展、局部事件性紧张，而非统一短缺 |
| 动态应用交付 B | 能否通过迁移、规则一致性、压力测试、多云回滚和 SLO 验收；端口不能替代工程能力 | 部署当量增长由生产系统数与单系统复杂度驱动；同一客户可能需要两家合格供应商 | 主要限制是客户改造、采购和可验证可靠性；高合规地域、复杂状态场景有结构性缺口 |

这里没有给出“全行业已测得 S/D=某个数字”，因为缺少各家按相同 SLA 的已部署和可售容量。两个样本也不足以覆盖全球。但证据支持一个有方向的结论：**价格竞争、套餐化、客户自建与可替代架构，比 CPU/带宽普遍稀缺更能解释当前经营差异。** 对大宗供给没有统一短缺的判断置信度中等；对全部状态化 Agent 能力供给充足的判断不成立。

### 5.2 CPU 需求究竟需要多少可售物理能力

独立工程模块：10 万个可分配 CPU 核，一年 8,760 小时，可持续有效利用率 35%—55%，形成 **3.07—4.82 亿 CPU 小时/年**。每次任务 20 ms 时，相当于 **55.2—86.7 万亿次/年**；单次内存驻留与等待并发可能先到上限。该模块不表示任一家已经安装了这些核，也不把 GPU 算力换算进去。

若普通 C 的可归属变现为 **0.08—0.18 美元/有效 CPU 小时 E**，形成 1 B 收入需要 **55.6—125 亿有效 CPU 小时**，即约 **115—408 万核**，取决于售价和利用率；平台订阅、唯一实例收费越高，所需物理 CPU 越少。这个阈值说明以纯 CPU 大规模替代云需要真实网络服务器与租户利用率，不能只凭已经覆盖几百城市推断收入无上限。

普通边缘 x86/Arm CPU 并不以先进 GPU/HBM 为必需条件。电力、内存、SSD、服务器和传输涨价会通过机房、设备折旧与带宽采购传导；若终端合同价格已锁定，供应商先承担压力。区域云与 CDN 的资本配给也可能因 GPU 投资倾斜而收紧，但本次没有获得足够证据把这种可能性写为当前普遍缺货。

### 5.3 供给反应及其时滞

本文采用以下工程/商业周期假设 E：既有节点的软件调度与配置为天到周；增加既有设施服务器和互联为 1—2 个季度；新地区、运营商深度互联和复杂企业迁移为 2—6 个季度。这是情景参数，非行业公布的平均交期。需求先放量、资源暂时闲置或新地区爬坡，会使成本曲线偏离理想利用率。

2026-09-10 Comcast/Fastly 联合公告将 Fastly 软件嵌入 Comcast 网络，后者有超过 200 个分布式边缘计算中心。**这是软件进入接入网、共享已有位置资源的实际合作，不是已披露的新收入合同金额。** 分成比例、额外资本责任及可复制程度未公开。其可能同时提高可交付容量、降低传输成本，并把部分价值留给接入运营商；不能把更靠近用户自动等同于 CDN 单价提升。[S34]

### 5.4 独立资产现金模型：更多流量仍可能不创造资本回报

为检验现金而构造一个 **100 Gbps 可售交付单元**，不是特定公司项目报价：初始投入 20 万美元，经济寿命 4 年、末期残值 2 万美元；每年必要更新现金 1 万美元；首年托管、互联、运维及分摊支持固定现金 16 万美元，随后每年 +3%；可变成本首年 0.0006 美元/GB、每年 −8%；初始净价 0.0036 美元/GB。容量折算为全年满载 3.942 亿 GB，只对该单元终端收费，不叠加上游收入。无额外营运资本占用、无税和融资假设。

| 同一资产的路径 E | 第 1—4 年利用率 | 同品净价年降幅 | 第 1—4 年收入（万美元） | 第 1—4 年净现金，含必要更新、末年残值（万美元） | 初始投资后 4 年累计现金 / 10% 折现 NPV（万美元） |
|---|---|---|---|---|---|
| 悲观 | 6% / 12% / 18% / 20% | 15% | 8.51 / 14.48 / 18.46 / 17.43 | −9.90 / −5.62 / −3.12 / −2.74 | **−41.38 / −37.86** |
| 基准 | 8% / 20% / 30% / 35% | 8% | 11.35 / 26.11 / 36.03 / 38.68 | −7.54 / 4.28 / 12.05 / 15.75 | **4.54 / −3.50** |
| 乐观 | 12% / 28% / 40% / 45% | 3% | 17.03 / 38.54 / 53.41 / 58.28 | −2.81 / 14.97 / 27.43 / 33.51 | **53.10 / 33.32** |

复算：`GB_t=394,200,000×u_t`；`p_t=0.0036×(1−降价率)^(t−1)`；`现金_t=GB_t×[p_t−0.0006×0.92^(t−1)]−160,000×1.03^(t−1)−10,000+末年20,000`。不把折旧再次从现金扣除；若核算经济利润，原始资产每年折旧为 `(200,000−20,000)/4=45,000`，必要更新另作一致处理。第 5 年若继续营业需再次更新，不能保留第 4 年利润却省略新一轮资本投入。

首年包含必要更新的现金盈亏平衡利用率为 `170,000÷[394,200,000×(0.0036−0.0006)]≈14.4%`；含原始资产经济折旧且将更新作当期经济成本时约 **18.2%**。这些是本研究阈值，不是行业标准。基准累计现金回正但 NPV 仍为负，直接反驳“有毛利、流量上涨就值得扩产”。最敏感的是利用率、降价和固定成本，而非单纯采购便宜设备。

有三条价值迁移机制最值得关注：

- **入口由 DNS/缓存转向代码部署。** 框架和企业采购平台决定默认运行位置，网络性能成为可比较能力；拥有最多节点不一定拥有最高客户转换成本。
- **核心锁定由执行转向状态和权限。** 标准 HTTP、Web API 和 Wasm 可降低代码迁移成本；数据模型、工作流历史、密钥权限和故障恢复仍使生产迁移昂贵。锁定价值与系统责任同时增加。
- **节省转移给客户，也可能扩大市场。** 只有在节省后的新增任务支出超过原有单位费用下降时，供应商收入才扩大。以收入表示，若单位收费下降 30%，付费工作量至少增加 `1/0.7−1=42.9%` 才能维持原收入；毛利还取决于单位成本是否同步下降。

政策和地域风险只通过具体机制进入判断：数据驻留与访问权限限制合格运行位置，增加状态复制和验收成本；跨境连接质量会改变有效供给；机房电力和设备价格会压缩固定合同毛利。本文未对未经逐条核验的法域规定作法律断言，也没有把泛化地缘风险直接加成价格溢价。

## 七、规模基数的独立估算与覆盖缺口

### 7.1 为什么不直接使用通用市场报告 TAM

允许读取的 NSDI 背景报告曾采用 2026E CDN 25—35 B 粗估，但没有足以在本专题边界内复算的安全、托管、自建、设备和转售拆分。本报告将其视为待核验线索，不作为先验结论。**本报告较低的 N 估计主要是统计边界不同，不能据此声称全球产业实际萎缩。**

没有任何一家已披露全行业 A/B/C 的可比收入。以下估算分为客户需求桥梁与供应商归属桥梁；后者是收入归属核查，**不是物理供给估算**。模型中心用于复算路径，不代表已统计到如此精确的市场。

### 7.2 2025 年客户需求桥梁 E

### 8.2 从毛利到经营利润与现金

附录毛利只是服务交付后的第一层剩余。对任一行，`经营利润=毛利−研发−销售−管理−其他经营费用`；`税前经营现金近似=经营利润+非现金折旧等−资本开支−营运资本增加`。股权激励虽不在当期现金中支出，却稀释股东，不应在经济利润中无条件消失。平台预付费可能改善现金，但未使用额度是否续费决定收入质量。

2029 基准代表行中，A/B/C/D 的毛利率约为 **43.8% / 75.4% / 67.3% / 64.0%**。这分别是经营费用率的盈亏平衡上限，不是净利润率。下表增加一组可替换的同边界费用与资本假设，用于检验“利润兑现”而非预测上市公司 EPS。

### 8.3 突破分支：独特 Agent 代码成为大规模收费对象

突破不是把普通调用增速再上调。它要求企业接受按独特代码/权限实例收费，平台解决隔离、状态、审计和权限问题，且参数化复用没有消灭计费基数。2029 年额外独特实例收费达到 **1 B/年**，按净价 **0.0005—0.002 美元/实例日**，需要 **5,000 亿—2 万亿计费实例日/年**，即平均每天约 **13.7 亿—54.8 亿**。这远高于“有几个成功 Agent 案例”。[S11]

以 20 万个持续付费企业/平台租户当量、每年 250 个活跃日为例，需要每租户每天 **1 万—4 万个**独特计费实例日才能达到该阈值。租户是部署采购当量，不是自然人，也不是重复注册账户。若每个组织 90% 的代码可稳定复用，新增实例费将显著下降；CPU 和状态收入可能增长，但须在 C 内替代计量，不能再把同一账单加一遍。

供给条件为：支持数十亿次日创建的控制平面、足够状态和审计吞吐、可验证隔离，以及完整收费权限。若每次创建和执行合计 CPU 10—100 ms，5,000 亿—2 万亿次/年需要约 **139 万—5,556 万 CPU 小时/年**；以 35%—55%利用率折算约 **288—18,121 核**。这个量级低于普通 CPU 变现所需核数，因为收入依赖创建和治理单价，**不是假设 CPU 物理稀缺**。持久内存、存储和浏览器/完整 Linux 沙箱另受约束，不能用此轻实例阈值覆盖。

经济结果的条件范围：在普通 C 乐观路径之外，独特实例净新增收费 **0.5—1.5 B**，直接服务成本占新增收入 **30%—60%**，新增毛利 **0.20—1.05 B**；还需销售研发及资本。只有扣除与原 CPU/平台订阅的替代后才可加总，成功的 1 B 门槛仅覆盖该区间上部。相关收入也可能被云平台、企业自建或应用框架拿走，不保证独立 CDN 获利。

## 九、演进顺序、概率与最强反证

### 9.1 时间顺序决定收入确认

- **2026H2：** 成熟交付续约与价格重置继续影响当年收入；新 Agent 隔离/工作流功能应先验证试用转生产、账单和故障恢复。Comcast/Fastly 合作先看实际运行和复制，再看合同与收入，不能在公告日计入全年市场。
- **2027：** 基准需要早期生产客户扩量、兼容迁移和状态能力稳定，供给通过既有资源和工程组织扩展。应出现可重复的付费 cohort 与明确的 C 收入证据，只有注册数增长不足以支持模型。
- **2028：** 多租户复用和区域云竞争进入更大规模合同续约，效率收益开始分配给客户；采用快但净价降得更快，会把路径推向悲观，即使物理用量仍创新高。
- **2029：** 看状态和工作流入口是否建立可持续预算，必要更新资本能否被覆盖；突破要达成行业级收费实例门槛，而不仅是技术开放可用。年度规模均在附录保留。

### 9.3 竞争性假说与区分观察

| 假说 | 最强支持 | 最强反对或保留 | 未来能区分的观察 |
|---|---|---|---|
| H1：AI 使独立边缘平台成为新的应用操作层 | 动态代码隔离、状态/工作流和跨云入口已形成可购买产品 | 兼容、状态、治理并非边缘厂商独占；产品可用不等于客户愿付高价 | 非安全 C 收入、生产付费留存、每完成任务净价和现金同步改善 |

研究阈值：若核心非安全服务连续两年付费工作量增长而收入不增，说明单位变现损失已超过扩量；若 C 的收入增长长期快于 CPU 用量，必须解释是订阅/实例收费、客户组合，还是统计边界扩大。**这些是分析纪律，不是预设好坏方向。**

报告覆盖全球主要上市平台、云厂商、关键中国供应商、开发框架平台、接入网和客户自建；小区域 CDN、封闭合同、企业内部函数和未披露私营产品收入未逐一统计。缺口主要扩大规模和利润区间，不足以推翻“需求使用量、物理能力和可归属收入需要分别建模”这一机制判断。

## 附录 A：逐年情景底表与复算规则

所有金额为 B。Q=**可收费工作量**相对 2025 的指数，P=同一工作量当量的净变现指数，C=同一当量服务成本指数；均为 E。A 的 Q 可换算为交付 EB，P 可换算为美元/GB；B 是固定权重的大/小部署组合，C 是固定权重的 CPU/实例/平台收费组合，D 是区域执行资源组合。后三者不是物理核数或免费请求数；未来产品组合变化也计入 P，并与可比价格分开观察。

复算公式：

- 代表收入：`R=R_2025×Q×P`。
- 代表服务成本：`COGS=R_2025×k×Q×C`。
- 代表毛利：`GP=R−COGS`；条件毛利率范围：`1−k高×C/P` 至 `1−k低×C/P`。
- 表中收入括号仅传播第七节的**基数范围**，公式为 `[R0低×Q×P, R0高×Q×P]`；Q/P/C 本身仍不确定，不应把括号称为完整预测区间。
- 2028 年各参数采用 `X_2028=√(X_2027×X_2029)`，X 分别为 Q/P/C。它只是相邻年度均值的透明过渡假设，不是把期末运行率乘十二，也不假定真实客户爬坡恰好线性。
- 展示保留两位小数只为查账，计算用未舍入数；特别是 C 和 D，实际估算准确度远低于小数位。

这些是刻意保留较宽的**主观压力参数**，不是测得的标准误差，也不按独立分布相乘。每条路径的 Q/P/C 同时改变可能有相关性：客户需求差会降低利用率，供给降本常传导至价格，不能总选高 Q、高 P、低 C 而不说明机制。

中心基数的局部敏感性：A 净价每下降 0.0001 美元/GB，在 1,500 EB 用量下收入减少 **0.15 B**；B 大部署年支出每变化 1 万美元，在 4 万当量下影响 **0.40 B**；C 企业付费组织多 1 万、每年 3 万美元，影响 **0.30 B**，但从其他平台迁移不能算全行业净增；D 每次平均 GB·秒的不确定性通常比每百万请求 0.20 美元的调用费更重要。

D 是替代参照，表中结果不得直接当作已识别行业全貌；尤其 2029 乐观上限依赖 2025 高基数与大幅增长同时发生。若将 D 与 N 做扩展边界展示，还应扣除托管平台向 D 的转售采购，本文不发布未经去重的扩展总量。

2029 乐观 B/C/D 毛利率上缘需要高密度复用、稳定单位变现且低支持成本同时成立，明显强于当前可核实证据。它是机制上界，不是当前公司毛利率的自然延长；若降本被客户议价吸收，应下调 P 而不是保留全部利润。

这里的“税前经济现金”对股权激励作保守经济成本处理，没有当成零成本加回；它与上市公司正式 FCF、自由现金流权益价值、ROIC 均不同。可租赁和自购设备的折旧/资本边界也可能不同，不能直接将本表比例比较成投资优劣排序。没有分部投入资本、租赁承诺和收购商誉拆分，不给出伪精确行业 ROIC。

最终审查的优先顺序：

1. 核实合同主付费对象、独立售价和转售层级，先保证收入不重复。
2. 用同客户、同产品、同地区的工作量与净价区分增长来源，固定观察季度和年度。
3. 将 CPU、内存、状态、带宽和错误重试的实际账单接到每个成功任务，不按 Token 简单线性推导。
4. 看合格运行位置、状态依赖、故障回滚和迁移验收，不能把节点数或端口数当完整有效供给。
5. 保留研发销售、人力/股权、必要更新、租赁和营运资本，确认毛利是否变成经济现金。
6. 当独立产品收入或成本披露推翻基数时，更新底表参数和范围，不为维护原情景而倒推事实。
