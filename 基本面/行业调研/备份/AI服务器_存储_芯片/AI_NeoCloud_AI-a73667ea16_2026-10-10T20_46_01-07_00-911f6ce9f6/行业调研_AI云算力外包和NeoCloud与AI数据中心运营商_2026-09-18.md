# AI云算力外包和NeoCloud与AI数据中心运营商：交付稀缺、信用分层与资本回收

研究截止日期：**2026-09-18，美国太平洋时间**。纳入当日公开的Nscale首次S-1，不纳入此后实际发生的事件。动态报价按本次访问状态记录，不能据此追认历史改价日期。主要财务观察期为2026年4—6月；Oracle采用截至8月31日季度；所有期间单独注明。

金额默认名义美元；**B=十亿美元，M=百万美元；1B=10亿美元**。容量除特别说明外为IT侧GW；GW年是全年平均可用容量的时间积分，不是年末容量。F=披露事实；M=管理层目标或估计；C=直接计算；E=本报告研究估计；U=公开资料不足。预测区间均为**条件参数范围或情景范围，不是统计置信区间**。

## 一、核心判断：行业确实在放量，但当前短缺的经济对象不是一张GPU

**本报告最支持的路径是：2026—2027年，能在承诺时间内交付、通过客户验收并获得融资的完整AI计算服务继续紧张；2028年前后，代际、地区、合同和客户信用导致的分化扩大。收入增长可能很快，持有硬件的股东回报却未必同步改善。** 完整产品包括计算、网络、存储、故障恢复、模型运行环境及履约责任；仅有土地、接电申请、设备订单或多年合同，不能证明已形成这种产品。

六个决定性发现：

1. **当前证据不支持“NeoCloud租价已全面下行”。** Nebius披露Q2新签合同的单位MW年收入提高，并称旧代GPU的新签价格较Q1高逾30%；其短期紧急容量交易与多年包销合同不同。北美机房低空置及新租约涨价也支持局部紧张。但这都是特定样本、产品组合和合同窗口，不能证明所有GPU或所有园区拥有永久定价权。具体事实和口径集中在第二、五节。
2. **交付差距比合同总额更有信息量。** Nscale截至8月底约25,000颗GPU在运行，而在运行加签约约461,000颗；前者仅相当于后者约5.4%，不是设备利用率。IREN的当期云收入、运行ARR和年底签约ARR也分属三个阶段。合同规模很大并不虚假，但多数现金创造能力尚待形成。
3. **客户信用是生产要素。** 同一公司可用投资级客户合同获得较低成本GPU融资，也会为非投资级客户部署付出更高利率。GPU稀缺程度相似，不代表融资成本相同。预付款同时减少融资需求、锁住客户，并把后期服务费提前收取；不能重复当作当期收入和以后现金。
4. **“AI数据中心运营商”至少有三种利润结构。** 拥有GPU的云商承担代际和再出租风险；纯机房房东承担建设、接电和租户信用风险；软件及托管平台可能赚取服务费并把硬件风险留给合作方。三者的EBITDA率、资本密度和现金回收不能直接排名。
5. **ASIC扩张既是GPU替代，也是第三方外包的新入口。** Anthropic通过Google/Broadcom及专门融资平台扩张，意味着“客户自研/定制芯片”不必等于“客户自己建设和运营所有设施”。GPU租赁商可能流失份额，合格机房、系统运营商和融资组织者却仍获益。
6. **最强反证是：当前稀缺主要由提前融资和少数大客户的抢购形成，终端支付不能覆盖持续更新。** 若后续订单主要由预付款、股权和债务滚动支撑，续约净价下降，而单位工作负载效率提高后新增付费任务不足，收入增长也可能伴随硬件资产减值。另一方面，新签价上涨、客户主动提前接收容量和已有运行收入，反驳了“所有订单都是没有使用价值的循环融资”这一过强解释。

## 三、行业边界、客户任务与支付路径

### 3.1 三层账与一个去重例子

| 层级 | 商品和经济单位 | 支付来源/责任 | 本文处理 |
|---|---|---|---|
| 最终应用与模型客户 | 每个成功任务、研发周期、合格输出、模型能力 | 企业IT/研发/人工替代预算，消费者付费、广告收益，或模型公司的融资；最终失败成本由业务部门和模型方承担 | 需求来源；应用收入、免费token不直接计GPU外包收入 |

假设客户花100购买模型服务，模型方花35向云商租算力，云商花6向机房租容量、4支付电力。可以分别研究100、35、6、4对应企业收入，但**终端需求不是145**，行业增加值也不是任何一项收入的简单总和。若Azure先采购CoreWeave容量再卖给模型方，本文在NeoCloud边界计CoreWeave的服务费；估算整个AI云最终销售时，必须消除这笔上游采购重复。

Oracle兼有大型综合云与专用AI集群供应商特征，属于直接竞争者和采购/交付参照；本报告不把OCI所有IaaS收入混入NeoCloud核心表。微软、Google、Amazon也同时是客户、替代供给方、渠道和标准制定者。Crusoe同时建设机房并经营云，必须按具体合同拆分，不能把旗下所有MW都视为GPU云。

### 3.2 四类任务决定四种支付意愿

**前沿训练和后训练。** 客户买的是按期完成实验、收敛稳定性和研发迭代速度。每卡价格便宜但通信慢、故障后重跑多，可能提高合格训练成本。预留大集群的价值包括容量同时可得和实验结果确定性。融资预算能够支持早期采购，但最终仍须从模型收入、企业价值或持续资本投入回收。

**大规模专用推理。** 训练和推理不宜按供应商名称划分。长上下文、MoE、视频与高频服务也可使用长期预留集群，归G1。客户验收包括TTFT、TPOT、并发下尾延迟、可用性和单位合格输出成本；缓存命中、重试、内容审核和路由都会改变“每百万token”的真实资源消耗。

**企业和开发者弹性工作负载。** 容量小、地域约束和峰谷差大，更重视接口、数据连接、合规和运维。按需云、抢占实例、小模型与本地推理可互相替代，归G2。可用GPU多不一定有足够付费并发；闲置时长由资产持有者承担，价格可能先于大型包销合同下跌。

**主权、科研和物理AI。** 公共预算支付数据控制、国家能力和研究可获得性，不必以短期云业务利润为唯一目标。机器人训练/仿真、科学模型可能成为新大客户，但实际机器人销售或研究突破不能由一个GPU订单证明。[Nscale与Figure于2026-09-03公布合作](https://www.nscale.com/press-releases/nscale-and-figure)属于这条采用链上的合同进展；不能当作2026已经完成规模交付。

新增外包支出还可能只是客户原先自建投资向服务费用转移。收入“从无到有”可以发生在NeoCloud，却未必增加整个产业的最终计算任务。

## 四、技术如何转化为经济结果

### 4.1 真正需要跟踪的是合格输出/瓦/美元

定义客户单位任务成本：

```text
合格任务成本 =
(计算租费 + 网络/存储 + 数据搬运 + 运行工程 + 失败重试损失)
÷ 达到质量、延迟和可靠性要求的成功任务数
```

GPU峰值FLOPS、模型生成token数和客户收入不成固定比例。新GPU提高吞吐后，若客户价格同比例下调、工作量不够增加，硬件拥有者的回报可能下降；若性能改善使原先不能实时提供的服务进入商业采用，需求会扩大。

[MLCommons于2025年4月说明MLPerf Inference v5.0的测试约束](https://mlcommons.org/2025/04/llm-inference-v5/)：离线吞吐与在线TTFT/TPOT是不同测量维度。这项较早的原始标准仍适合解释口径，但本报告不把旧版本性能当作2026生产实测。

| 技术变化 | 采用阶段/证据 | 放量机制 | 谁可能损失价值、必要反证 |
|---|---|---|---|
| 机架级GPU、NVLink域和高速跨节点网络 | 已有商业交付；CoreWeave另披露完成Rubin系统bring-up/validation，验证不能替代客户规模验收 | MoE专家并行、长上下文及大集群效率改善；买方按完成任务而非单卡采购 | 网络拓扑或液冷不合格会使设备滞留；基准测试优势需在相同模型、精度、并发和SLO复现 |
| Prefill/decode分离、KV缓存路由、连续批处理 | [NVIDIA Dynamo 1.0技术文档/博客](https://developer.nvidia.com/blog/?p=113961)，2026-03；已提供生产部署能力 | 提高每MW合格输出，让有限电力支持更多服务；也可解锁长上下文 | 开源软件扩散会使优化收益让渡给客户；“最高7倍”是特定组合比较，不作为行业通用倍率 |
| 跨云数据访问、调度和训练工具 | CoreWeave Q2推出跨云功能；[Nebius合作方云模式](https://nebius.com/newsroom/nebius-introduces-business-model-to-scale-ai-cloud-globally-through-infrastructure-partnerships)，2026-07-15 | 降低迁移和多云部署门槛；软件可运行在合作方资产上 | 同时削弱锁定，可能更容易价格竞标；独立软件收费与服务成本尚未充分披露 |
| TPU/Trainium等专用路线 | [Anthropic—Google/Broadcom](https://www.anthropic.com/news/google-broadcom-partnership-compute)，2026-04-06；[Anthropic—Amazon](https://www.anthropic.com/news/anthropic-amazon-compute)，2026-04-20，原始客户披露 | 对稳定规模任务减少单位成本；第三方机房和托管仍可承接 | GPU云份额可能下降；移植、算子、互联及模型变动会使名义性价比失效 |
| 蒸馏、量化、缓存与本地小模型 | 已存在可用路线，但本研究不宣称所有企业规模采用 | 降低一次任务的外部算力；扩大低预算应用 | 云端工作量必须增长得足够快，才能弥补每任务资源和成交价下降 |

因果阈值可以简单表达：若每单位合格工作量的资源需求减少40%，而净租价再降15%，保持相同云收入需要合格付费工作量增长约**1/(0.6×0.85)−1=96%**。这是同质量、同任务边界的E/C示例，不是预测所有任务的效率改善40%。

**效率突破对房东和GPU云商的方向未必一致。** 在电力紧张、客户愿意继续扩大服务时，效率改善提高租户承担租金的能力；在客户任务预算固定时，同样任务可以少租GPU乃至少租机房。判断方向需要同时观察新增付费任务和已签容量是否被持续使用。

### 4.2 外包不等于GPU独立品牌永远拥有客户

GPU云商有三条商业路线：以硬件和融资交付为主；以运行工程和完整平台为主；以合作方资产加软件/SLA为主。前两条容易在收入中看到规模，第三条可能收入毛额更小、资本效率更高。若同一服务从自持GPU变为合作方持有，软件平台收入下降未必是经营衰退；反之，转成收入毛额确认也不代表增加值增长。

Nebius已明确合作方管理设施和硬件、自己负责云软件和服务水平。这个边界变化有证据，但费率、赔偿、收入确认及已上线合作规模不足，因此不把“资本轻”直接列为已实现高ROIC。

## 五、有效供给：从电力权利到可收费服务

### 5.1 一条必须逐项目核对的交付链

```text
土地/接入申请 → 有约束力的电力安排 → 建设与融资关闭
→ 机电/液冷和网络就绪 → GPU安装与调试 → 客户性能及SLA验收
→ 起租/计费 → 实际负载爬坡 → 服务费回收
```

上述阶段可并行，也可能退回。实际供给接近同时可用的电力、合格机房、安装完毕的设备、网络和运维能力中的短板；不能把各项拥有比例独立相乘后当统计概率。多家供应商共用一个项目的电力和机房，不得重复累计。

[NVIDIA FY27 Q2电话会，2026-08-26，第3页](https://investor.nvidia.com/files/content_files/TRANSCRIPT_-NVIDIA-Corp-NVDA-US-Q2-2027-Earnings-Call-26-August-2026-5_00-PM-ET.pdf)称其NeoCloud伙伴预计2026年底installed capacity约8GW，2025年底约3GW。这是供应商对伙伴群的M/F混合锚，不是独立审计的可收费IT容量；是否包括主权专用、待验收和其他非商用设施，未完整披露。**本报告将它用于供给上限和增长约束，不用8GW×8760小时冒充全年实际收入。**

供给周期的有依据方向：

- 存量机房改造可以比绿地建设快，但挖矿园区仍需升级冗余供电、UPS、发电机、光纤和液冷。已有矿机耗电不等于已经符合AI客户SLA。
- 绿地项目从施工到上电可以出现不足一年案例，但不应作为所有项目工期。[Crusoe 2026-03-27公告](https://www.crusoe.ai/resources/newsroom/crusoe-announces-new-900-mw-ai-factory-campus-in-abilene-texas-to-support-microsoft-ai-infrastructure)称Abilene首两栋共200MW不到一年上电；新增900MW园区首栋目标为2027年中。既有1.2GW与新增0.9GW合计2.1GW是同一地点的嵌套规模，不再相加。
- [Nscale 2025-10-15微软合同](https://www.nscale.com/press-releases/nscale-microsoft-2025)包括约200,000颗GPU、多国部署；Texas约104,000颗及约240MW从2026 Q3分期交付是目标。S-1随后提供了运行数量。旧公告的目标必须让位于较新实际阶段，不能只引用较大数字。
- [得州政府2026-08-03接入审计指令](https://gov.texas.gov/news/post/governor-abbott-directs-comprehensive-data-center-audit)针对推进中的接入项目；474GW左右申请不是批准负荷，更不是未来数据中心需求。[Galaxy 9月8日更新](https://investor.galaxy.com/news-releases/news-release-details/galaxy-provides-update-ercot-batch-zero-large-load)还披露了审计期间的条件分类进展。因此不能笼统断言全得州既有运行项目停运，也不能把条件分类当无条件接电许可。

### 5.2 为什么短缺与闲置可以并存

100MW可用在偏远低电价地区，并不能自动替代要求数据驻留、低延迟连接、指定芯片、指定网络和客户验收流程的100MW。对于大型训练，跨地域拆分更可能降低同步效率；对推理，跨区传输又受延迟、成本与数据权限限制。

因此本报告的供给表包含匹配/计费上限b：G1高于G2，因为长期预留可为大块容量提供合同覆盖；G2即使工程就绪，也可能因地域、峰谷和小客户碎片化而不能把全部时间售出。b不是芯片内部计算利用率，也不是对需求强弱的循环证明；模型另以客户预算D限制实际收入。

## 六、需求侧与供给侧的独立估算及联合判断

### 6.1 需求预算：不由供给数量反推购买意愿

需求模型按**直接向GPU NeoCloud支付的采购方**分为模型实验室L、超大云采购H、其他企业/开发者/科研E。一个最终任务若经超大云转售，其上游采购只进入H，不同时进入L或E。训练、后训练和推理共同参与预算；不按token增幅直接放大美元。

客户侧现实约束包括：

- [微软FY26 Q4原始电话会，2026-07-29](https://www.microsoft.com/en-us/investor/events/fy-2026/earnings-fy-2026-q4)：季度资本支出41B，约三分之二为短寿命资产，现金PP&E 35.8B。其较新CY2026约175B口径涉及租赁分类变化；不能把此前约190B到175B全解释为实物需求减少。大客户有持续投入能力，但这些数字包含非AI及自建，不能直接归为NeoCloud收入。
- [Oracle FY27 Q1公告，2026-09-10](https://investor.oracle.com/investor-news/news-details/2026/Oracle-Announces-Q1-Results-Driven-by-Triple-Digit-Growth-in-Cloud-Infrastructure-Revenues/default.aspx)：截至8月底IaaS季度收入约7.4B，新增交付850MW数据中心容量，F；全部IaaS并非AI。这同时支持AI外部购买扩大和传统云加速自供两种解释。
- Anthropic在前述客户原始公告中配置GPU、TPU和Trainium；与Amazon的“最高5GW”及2026年底近1GW Trainium目标是不同时间尺度。其长期部署承诺不能全部当2026 GPU NeoCloud预算。
- [Lambda—微软多年度合作，2025-11-03](https://lambda.ai/blog/lambda-announces-multibillion-dollar-agreement-with-microsoft-to-deploy-ai-infrastructure-powered-by-tens-of-thousands-of-nvidia-gpus)，披露金额为multibillion、GPU为数万颗，保留该数量级，不补造精确合同额。这与IREN、Nscale、CoreWeave等共同证明超大云外购是一条真实采购渠道。

需求预算不是已审计的行业实际支出。附录A公开每个采购组的金额假设，并将其分配至G1/G2；模型的最大软参数是实验室融资持续性、超大云自供替代和中小客户付费采用。依据强弱依次是已运行收入、已签合同及资金来源、技术/客户采用、再到未披露的行业总预算。

### 6.2 供给预算：先确定年度可用能力，再考虑能卖掉多少

G1/G2的S来自已运行机群、在建交付与新机架验收的年度时间积分。以NVIDIA伙伴3GW至8GW的轨迹、第二节公司运行容量与第五节项目阶段作交叉约束，剔除不属于商业云销售的部分，并为年末集中上电留出爬坡。**不因需求D较高就把名义电力上调为有效供给。**

| 供给侧检查 | 2026基准 | 2027基准 | 2028基准 |
|---|---|---|---|
| G1+G2全年平均合格IT能力S，GW年，E | 3.25—4.35 | 6.8—9.1 | 9.7—13.6 |
| 建设/验收解释 | 既有运行资产全年贡献＋2026分批交付；8GW年末installed并不全年收费 | CoreWeave、Nebius、IREN、Nscale等已签项目分期上线，加私营云商；多国接电不能互替 | 更多绿地、代际刷新和软件迁移形成完整能力；超过已签可见部分，置信度下降 |
| 供应链与资本约束 | 设备、机架、机电、合同融资缺一不可 | 在建交付及融资关闭变为更重要的筛选条件 | 若效率替代强、客户融资弱，已建资产可能仍存在而商业利用下滑 |

为检验这一量级，3—8GW安装轨迹若按交付时点得到全年平均4—6GW，商业归属取70%—90%、合格运行取80%—95%，对应2.24—5.13GW年；基准3.25—4.35位于此宽约束内。这里的比例都是E，不是NVIDIA提供的事实，且并非严格独立。公开资料不足以进一步证明每一GW的商业归属，故保留宽情景，不能把该检查包装成完整自下而上清单。

**北美C供给独立从机房样本估算。** 2026全年样本平均容量假设11—13GW、AI适用/归属30%—38%，加样本外约1.7—1.9GW，约束为5—6.8GW年。2027采用样本14—18GW、AI占40%—45%、样本外2.4—2.9GW；2028采用18—23GW、45%—50%、样本外3.9—4.5GW，分别形成8—11、12—16GW年。AI归属比例和样本外容量是低置信度E；CBRE实际只提供总体市场锚，没有披露这些AI拆分。C包括服务超大云自持设备的房东，因此不必等于NeoCloud租赁容量。

上述参数并不是统计误差很小的估计。若CBRE样本外AI供给被重复计入，或AI适用与实际租用混淆，C市场会明显高估；每减少1GW实际起租能力，按当前租金大约减少1.8—2.2B年收入能力。

### 6.3 对三个时期的判断

| 时期与路径 | 需求、供给和价格共同机制 | 更可能获益者及现金结果 |
|---|---|---|
| 2026悲观P | 已投入形成收入惯性，新增融资/验收慢；小客户需求和计费率较弱，G1净价10—12M/MW年 | 有优质已起租合同者较稳；闲置GPU和先扩团队的弹性云承压 |
| 2026基准B | 需求预算37—56B，G1/G2供给仍不足以在所有地区与规格完全满足；新合同价格支撑、既有机群均价低于新签高价 | 合格集群交付和客户信用更值钱；行业收入32.1—53.2B，仍需大量外部资本 |
| 2026乐观O | 新设备、验收与客户预付顺利，短交期容量获得溢价；放量与提价并存 | 拥有即刻可用容量的云商与优质电力房东获益，买方单位任务成本仍可能因效率下降 |
| 2027悲观P | 供给惯性继续增加，预算不充分；专用集群G1开始需求受限，G2明显碎片化过剩 | 收入仍可增长，但资本耗用与利息后可能普遍亏损；旧GPU和低信用项目风险最大 |
| 2027基准B | 预算76—118B、平均合格供给6.8—9.1GW年；晚2026合同贡献全年，新代与旧代净价分化 | 收入71.8—116.0B；已锁高价且低融资成本的新资产获益，不能推导全部行业FCF转正 |
| 2027乐观O | 更多新任务、预算及供应链同时释放，G1净价16—19M/MW年；依然存在工程约束 | 机房、运行平台和硬件商共同放量；建设成本与竞争会分走部分利润 |
| 2028悲观P | 效率替代和预算收缩超过新需求，G1净价降至6.5—9，G2降至6—9M/MW年；收入可下降 | 房东可能先受合同保护，后受租户重组；GPU债权人和股东承担残值压力 |
| 2028基准B | 工作负载扩张、供给继续增长，但新旧代分层，平均净价不再依靠普遍上涨 | 规模进一步扩大，价值更多归属控制客户与软件、拥有便宜资本和持续可用电力的一方 |
| 2028乐观O | 规模采用跨越传统软件，先进供给大幅增加且预算跟得上 | GPU核心收入可达196.5—325.0B；需要高资本强度扩张，不能当作轻资产软件收入估值 |

数量化比较的操作：对每一细分，需求可购买容量为D/Y，商业供给上限为S×b，单位均为GW年。若前者更大，差额是给定价格和SLO下未被本市场满足的需求，可能转到其他云、自建、延后或消失；不能把缺口全称已签订单。

例如2027基准G1在低参数点，D/Y=64/13≈4.92GW年，S×b=5.8×0.88≈5.10GW年，接近需求约束；G2低点则12/13≈0.92GW年对1.0×0.60=0.60GW年，匹配能力偏紧。总量接近平衡，仍可能有弹性可用服务和特定地域短缺。若把所有上界/下界交叉组合，紧缺与过剩都可能出现，故现实判断来自新签价和交付行为，而不是区间相交本身。

## 七、利润与资本：预付款改善融资，不自动创造价值

### 7.1 不能从EBITDA跳到股东现金

CoreWeave第二节的调整后EBITDA到调整后营业利润落差，显示资产耗用的重要性；再扣利息，股东收益与高EBITDA率很不一样。IREN披露的短回收期按GPU及配套资本支出除以合同收入减直接成本，未必包含完整机房投资、平台费用、税收、更新及融资；本报告不拿它与完整资产IRR等同。

[IREN FY26原始公告](https://www.sec.gov/Archives/edgar/data/1878848/000187884826000051/irenreportsfy26results.htm)披露微软相关3.6B GPU融资利率6.0%，新非投资级客户部署中2.4B融资利率9.0%。这是特定结构的合同经济差异，不是全行业贷款利差。融资期限、摊还、担保、现金限制和客户质量仍需逐笔看。

收入增长的来源要拆开：

- **数量：** 新GPU和新机房实际起租；年末交付大幅影响下一年收入，不能只看期末ARR。
- **价格和组合：** 新代GPU、短交期溢价、旧代续签和平台附加服务；每MW收入增加不一定是同产品涨价。
- **成本：** 设备、内存、网络、液冷、能源、运行人员和失败率；电费未必是最大项。
- **资本：** 在建时长、融资利率、预付抵扣、资产更新和残值；这些可以吞掉运营改善。

### 7.2 一个真实合同锚揭示的现金错位

IREN微软合同约9.7B、设备相关约5.8B，差额约3.9B覆盖整个合同期间的机房、运行、利息、税和回报；**差额不是利润**。20%预付约1.94B，按条款从第24个月以后抵扣，C。前两年的现金可能好于后期；将预付款留在“经营现金流”，再把全额合同年费当未来现金，会高估累计回款。

若为了获得6%融资必须保留抵押账户或现金储备，则融资额也不等于随时能用于下一个园区的钱。融资覆盖96%的GPU采购，不代表96%的完整项目资本开支已覆盖，更不代表股东无风险。

### 7.3 100MW同一资产的五年检验

附录D固定同一100MW GPU租赁资产：GPU及配套2.70B，安装/启动0.05B，初始营运资本0.05B；机房采用经营租赁，所以不再同时加入房东建设资本。2027投产，2030必要部分更新0.45B，2031处置并释放营运资本。三情景采用相同资产边界、五年观察期，区别只在收费爬坡、净价和残值；未把“乐观”改成不承担GPU投资的软件平台。

| 同一100MW资产，E/C | 悲观P | 基准B | 乐观O |
|---|---:|---:|---:|
| 初始现金投入 | 2.80B | 2.80B | 2.80B |
| 五年累计税前无杠杆现金，含更新、处置与营运资本回收，减初始投入 | −2.66B | **−0.03B** | +2.83B |
| 12%折现、税前无杠杆NPV | −2.57B | **−0.69B** | +1.39B |
| 名义回收 | 五年内不能回收 | 五年接近但未完全回收 | 第二个经营年末附近；时间积分仅粗略判断 |

这里的基准是**这一新投资项目的中性参数**，不是断言行业每个既有项目都回报不佳。2026新签20—25M/MW的高价若长期锁定、客户付款可靠，可能接近本资产乐观路径；低价旧约、昂贵设备和迟交付则不同。完整复算参数在附录D，不使用统一“几年折旧所以几年赚钱”的推理。

同样的硬件，年现金净价每提高1M/MW、计费率90%，100MW一年收入增加90M；满额IT负荷下PUE 1.2、电价每升0.02美元/kWh，一年电费约增加21M。对这类租卡资产，**净价、计费率和购置价格的敏感性通常大于几分钱电价差**，但停电造成的交付违约可能远大于正常电费。

### 7.4 纯机房的另一种单位经济

取100MW纯机房，建设资本1.2B，年净租金1.9M/MW、计费率95%，收入180.5M；固定运营25M、随计费容量成本0.12M/MW约11.4M，NOI约144.1M，扣维护资本15M后129.1M。该示例NOI/成本约12.0%，是项目稳定期收益率，不是股东IRR。

若60%贷款、利率7%、本金直线15年摊还，首年利息50.4M、本金48M，税前股东现金约30.7M，对初始股本480M约6.4%。提高租金、降低建造成本或释放杠杆可改善回报；建设延迟、附带未获补偿的升级和低信用租户都会破坏它。[JLL 2026原始展望](https://www.jll.com/en-us/insights/market-outlook/data-center-outlook)预测全球shell/core平均建设成本11.3M/MW，且另列租户技术装修；因此此处12M/MW是有锚的E，不能加上GPU后仍称纯房东成本。

从行业角度，机房利润扩张需要**起租快于固定成本、租约补偿建设与升级投入、融资成本受控**；GPU云利润扩张还需要**在初始合同及残值期间赚回更短寿命设备**。这就是两类资产不能用同一毛利率或回收期阈值的原因。附录D4把纯机房延长至15年，计入起租爬坡、维护、升级和残值后，基准10%折现NPV仍约−0.10B；较稳定的租金并不保证新建资产达到资本回报要求。

## 九、开放发现：从“租卡公司”到信用、软件和ASIC托管的分工

### 9.1 信用包装本身形成一种规模优势

低成本融资来自可承认的合同现金流、资产抵押和追索结构，不只来自借款人的公司规模。若大客户愿意提供预付款和较稳定条款，它把自身信用的一部分传递给供应链；云商相应让渡价格、容量优先权和自由调度空间。资本越紧，这种交换越重要。

这可以解释看似矛盾的现象：宏观利率没有大幅下降，个别项目融资却变便宜；同一家云商收入暴增，股权仍大量稀释；软件平台拓展后披露收入增速下降，但现金风险可能减少。检验不能仅看总债务，要看同一项目的融资摊还是否匹配合同收款和设备更新。

### 9.2 ASIC外包平台X：规模很大，但“融资额=收入”错误尤其严重

[Apollo 2026-06-09原始公告](https://www.apollo.com/insights-news/pressreleases/2026/06/apollo-leads-35-billion-capital-solution-for-broadcom-ai-xpv-platform-in-partnership-with-blackstone-and-leading-global-banks-3308896)披露Broadcom AI XPV初始35B资本方案，帮助Anthropic此前公布的超过1GW计算扩张自2026年中开始推进；平台目标是到2028年支持超过20GW。**35B是资本方案，20GW是平台愿景，两者都不是当年付费供给或运营商收入。** 同源新闻转载不增加确认权重。

[Anthropic于2025-11-12直接公布与Fluidstack建设美国AI设施的50B投资计划](https://www.anthropic.com/news/anthropic-invests-50-billion-in-american-ai-infrastructure)，提供客户侧原始证据，但50B仍是多项目投资计划，不能再与融资方案、芯片采购和云服务费相加。这一计划也不能证明所有设施使用同一种芯片。

X以非传统超大云自身资产负债表、由独立资产持有/融资实体提供的专用加速器基础设施使用费为边界；训练/推理软件服务费若含在其中，不再另加。该边界与G1/G2的GPU相分离，但与C机房有上游重叠。财务披露不足以确定全平台收入确认主体，故X仅列**条件合同经济规模**，不并入第一节核心市场总量。

| 年份/情景，均为E | 年均完成验收并可提供服务的容量GW年 | 可计费比例 | 每计费MW年资产使用费M | 可收取服务费规模B | 现金运营成本假设/资本约束 |
|---|---:|---:|---:|---:|---|
| 2026 P / B / O | 0.05—0.15 / 0.15—0.35 / 0.30—0.60 | 60%—80% / 75%—90% / 85%—95% | 10—14 / 12—16 / 14—18 | 0.3—1.7 / 1.4—5.0 / 3.6—10.3 | 每可用MW固定2—3M＋每计费MW可变1—2M；资本30—45M/MW |
| 2027 P / B / O | 0.3—0.7 / 0.8—1.5 / 1.8—3.0 | 60%—80% / 80%—95% / 90%—98% | 8—12 / 12—17 / 14—19 | 1.4—6.7 / 7.7—24.2 / 22.7—55.9 | 固定1.8—3M＋可变1—2M；资本28—45M/MW |
| 2028 P / B / O | 0.5—1.2 / 2—4 / 5—8 | 50%—75% / 80%—95% / 90%—98% | 6—10 / 11—16 / 13—18 | 1.5—9.0 / 17.6—60.8 / 58.5—141.1 | 固定1.8—3.2M＋可变0.8—2M；资本25—45M/MW |

可收服务费=S×b×Y，是完整服务年的条件能力，不是已披露收入。2026为当前可用基期估计；2025该新融资路径下的独立实际收入U，不强造零基数。此处最有约束的事实只有初始超过1GW的分期项目及融资，2027—2028扩张依赖新增客户、验收和资本落实；即使乐观也未采用20GW目标全量兑现。

需求侧另给年度可执行采购预算上限：2026 P/B/O为1—3/3—6/6—12B，2027为3—8/12—30/30—65B，2028为5—12/30—75/80—160B；这些是E，来自初始客户部署、扩展客户数量和任务移植速度的压力范围。实际规模取min(预算，上表能力)。若仅兑现一个初始项目而无后续扩张，2028不得使用2—8GW平均能力。X没有完整独立客户预算普查，置信度低于GPU核心表。

经营结果可由表中公式逐项复算：税前融资前运营余额=收入−S×固定成本−(收入/Y)×可变成本；资本年耗用以四至六年寿命、0%—15%残值敏感性检验，不能直接把运营余额当利润。以2027 B为例，运营余额完整端点包络约4.0—20.1B；对应年资本耗用约3.2—16.9B，二者不能独立挑最优端点后宣称高ROIC。附录C补充X的经济余额包络。

### 9.3 可证伪的突破分支

**突破不是再多一个GPU型号，而是运营商把同SLO下每MW合格输出提升约2倍，同时客户付费工作量增长超过效率替代，且软件收入可以跨合作方资产复用。** 作为2028基准路径中的子分支，假设G2付费任务量比基准额外增80%、单任务净价再降30%，则G2收入相对基准为1.8×0.7=1.26倍，即约18.1—44.6B；若物理效率提高2倍，实现这些额外任务的资源需求仅为基准约90%。这可释放容量、降低成本，不需要所有GPU小时收入都上涨。

成立还要求客户迁移、可比生产SLO、工具链、数据连接和合作方运维同时通过。若只显示实验吞吐加倍，却没有付费任务或独立软件收费，属于技术进展，不算此商业突破。软件收费作为G2内部结构变化处理，不再加一次平台总收入。

## 十、演进时序、概率与最强反面解释

### 10.1 时间与观察顺序

| 时间 | 应出现的阶段性证据 | 哪个结果仍不能据此确认 |
|---|---|---|
| 2026 Q3—Q4 | 已签项目分批验收、起租；Nscale运行机群、IREN后续Horizon、Nebius晚年容量；贷款和客户预付兑现 | 年末ARR不等于全年现金，也不证明2030残值 |
| 2027 H1 | 2026晚投产资产贡献完整季度；实际收费和负载爬坡；新合同净价与旧约区分 | 单季收入增幅可能只是时间积分，不代表新需求又翻倍 |
| 2027 H2—2028 | 新一代机架与ASIC规模部署、旧GPU续签、供应链成本与接电约束变化 | 新代商业化不自动证明旧代没价值；也不自动保证所有地区扩产 |
| 2029—2031 | 首批大额三至五年合约续约、更新支出、二手残值和债务摊还 | 当前高EBITDA不能替代这一检验 |

本报告不给三个代表情景强行分配合计100%的权重，因为供给顺利但需求较弱、技术突破但净价下跌等混合路径没有被三个代表点穷尽。给出下列**主观事件概率**，精度有限，不是统计模型输出：

| 事件/成功标准与截止时间 | 概率性质及判断 | 依据、上调/下调证据 |

### 10.2 两个竞争假说与区分它们的证据

**H1：结构性外包行业。** 模型复杂度与企业生产任务持续增加，超大云也需要专用交付伙伴；平台和信用融资形成可重复能力。支持：同季度可确认收入、近期新签净价、客户主动提前起租、公共原始采购合同。反证：新增采购越来越集中在一个终端客户，项目之间轮流延期，已运行资产续约价与现金回收恶化。

**H2：资本推动的阶段性稀缺。** 抢占容量和融资把订单提前，真实付费任务无法长期承担全部设备更新；规模增长将以残值损失、租户重组或云商兼并结算。支持：合同与实际运行差距、客户预付驱动的现金流、资本密度和利息。反证：在剔除预付和一次性收入后，成熟资产现金仍覆盖必要更新，且多个独立客户保持续约和增加付费任务。

最有辨识力的观察不是新增backlog新闻，而是：

1. **同资产、同型号、同地域的续约净价和付费时间。** 研究预警阈值：连续两个季度净价下降超过20%且计费率低于70%，需要下调该资产回收；阈值来自附录单位经济敏感性，不是行业规范。
2. **客户预付款抵扣开始后的现金。** 若经营现金改善主要来自新预付，而旧项目收款下降，必须分期核算，不以合并现金流掩盖旧资产。
3. **可计费MW/已交付MW和已交付MW/签约MW。** 不跨公司强行比较分母；用公司自身连续披露判断阶段迁移。
4. **同类新项目融资条件。** 实际融资利率、抵押覆盖、摊还期限、预付款比例与客户信用同时记录；利率下降而其他约束变严，不一定是改善。
5. **必要更新后现金。** 更新资本支出从增长资本中独立辨认，防止长期“没有维护资本”的模型高估回报。
6. **纯房东经常性租金与一次性装修/电费。** AI标签带来的收入增长若主要是建设转售，应降低对稳定现金规模的判断。

## 十一、覆盖限制与仍未解决的问题

本次仅读取项目内“基本面/行业调研/产业背景/”范围的2026-09-18建设规模、Token经济及全局口径材料，作为线索和边界提示；读取根目录与目标层级AGENTS仅为操作规则。未读取其他行业报告、公司报告、排名或旧任务缓存作为研究输入。背景材料中的行业规模与预测没有直接作为本报告情景数值；关键外部事实独立核查。用户给定路径是唯一正式成果。

## 附录B：供需、净价与收入逐项底表

### B0. 公式和区间算法

以下单位可直接相乘：**S用GW年，Y/f/v/k用M/MW年，结果自然为B**，因为1GW=1,000MW且1B=1,000M。

```text
D = 全年可执行需求预算，B
S = 全年平均工程合格供给，GW年
b = 最大可匹配/计费时间比例，不是芯片计算利用率
Y = 每计费MW的全年净服务费，M/MW年
Q = min(D / Y, S × b)                       # 实际计费容量，GW年
R = Q × Y = min(D, S × b × Y)              # 服务收入，B
Eop = R − S × f − Q × v                    # 税前、融资前、资本耗用前经营余额
A = Eop − S × k                            # 经济资本耗用后、利息和税前余额
```

f包括所选资产边界内的固定现金运营/平台/租赁支出；v是随计费容量发生的现金成本。C的f/v只含房东侧成本，不含被排除的电费代收。GPU云f包括向房东支付的租金，因此不能再把房东利润加到“终端增加值”而不抵消。

k是经济资本年耗用准备，不是公司披露折旧，不是当年实际更新现金。k含设备经济寿命、必要基础设施刷新及残值的不确定性；GPU主要以约25～40M/MW硬件及配套投入、约4～6年经济寿命约束，P允许回收期缩短及资本耗用较高。C主要以10～15M/MW设施及更长寿命约束。模型实际采用k逐行明示，不把所有GPU强定为相同折旧年限。

R采用参数区间的可行最小/最大值。Eop/A除全部参数端点外，还计算**S=D/(b×Y)供需切换点**，避免漏掉固定成本和供给上限共同决定的最优值。因此成本结果往往比“低端对低端、高端对高端”更宽。区间内各变量并非现实独立分布；包络只是可复算压力范围，不分配频率。

### C5. 从经营结果到资金约束

- GPU平均项目若新增1GW、设备及配套25～40M/MW，需要25～40B资本，另加未包含的自建机房和营运资本。1GW并不因为存在多年backlog就已被融资；钱到位和容量到位要分别证明。
- 全年新增平均供给与年末新增资产不是一回事。晚12月投产的资本已经投入，年度S贡献却很少，因此**不能用相邻两年平均S差额机械计算当年CapEx**。
- 一个资产项目借款20B、利率从6%到9%，在本金相同时一年利息增加0.6B；若贷款到期早于合同剩余回款，还需要额外再融资。债务成本下降可以改善股东回报，但不能修复负的税前无杠杆NPV。
- 客户支付45%～55%设备款式预付款的个别新合同有供应商披露支持，但不能给所有行业项目统一设定50%预付，也不能以预付金额降低资产原始成本。
- 若融资利息已经计入公司成本，不应在本模型Eop之后重复扣除同一笔。本文模型从融资前口径开始，实际公司比较需逐项映射。

### D3. 复算、敏感性与不应混用的回报指标

```python
# 金额B；三条路径均使用同一资产和初始现金
initial = 2.80
discount = 0.12
Y = {
    "P": [12, 10, 7, 4.5, 3],
    "B": [14, 14, 13, 9, 6],
    "O": [20, 20, 18, 14, 10],
}
u = {
    "P": [.50, .70, .60, .40, .30],
    "B": [.70, .92, .93, .85, .70],
    "O": [.80, .96, .97, .93, .85],
}
residual = {"P": .10, "B": .25, "O": .40}
for scenario in Y:
    flows = []
    for i in range(5):
        revenue = .1 * Y[scenario][i] * u[scenario][i]
        operating_cash_cost = .25 + .12 * u[scenario][i]
        refresh = .45 if i == 3 else 0
        terminal = residual[scenario] + .05 if i == 4 else 0
        flows.append(revenue-operating_cash_cost-refresh+terminal)
    npv = -initial + sum(cf/(1+discount)**(i+1)
                         for i, cf in enumerate(flows))
    print(scenario, round(sum(flows)-initial, 4), round(npv, 4))
# P -2.6600 -2.5666
# B -0.0300 -0.6851
# O  2.8268  1.3907
```

- **购置成本：** 初始资本每变化0.50B，其他相同，NPV反向变化0.50B。基准回收不足不能只靠小幅节电修复。
- **价格：** 各年Y提高1M/MW，在基准u下收入现金依次增加0.070/0.092/0.093/0.085/0.070B；12%折现合计约0.30B。因此提高净价、计费率、初始资本效率和延长经济寿命需要组合兑现。
- **预付款：** 若有0.60B客户预付在2026年底到账，再在2029—2031每年抵扣0.20B，合同总收款不变，12%下NPV改善约0.22B；基准NPV仍为负。预付款可显著降低融资需求，但不可同时保留后期未抵扣全额现金。
- **债务：** 70%初始融资为1.96B，10%利率、五年等额本金，每年本金0.392B。基准第一年融资前现金0.646B，首年本息0.588B；2030更新后融资前现金约−0.037B，同年仍有约0.470B本息。因此前两年现金覆盖不证明整个期限无再融资需求。该说明不与无杠杆NPV重复扣本金。
- **经济停机选择：** P在2030后运营余额转负。理性业主可能停机或不更新，但仍可能承担机房租金、解约和贷款。上述P是继续履约的压力路径；不建造更多亏损供给、及时处置可以改善结果，改善幅度取决于可取消条款而非GPU标价。
- **寿命和残值：** 将账面折旧延长并不增加现金。基准终值每增加0.10B，当前NPV只增加约0.057B；以高残值救活低租价项目需要很强证据。
- **效率收益：** 对同一预留GPU小时合同，吞吐优化首先改善客户任务成本；云商只有续约提价、提高计费率或转为按结果收费，才一定增加收入。不能把软件效率提升直接加到既有固定合同收入。

每年t=1…15的公式：

```text
R(t) = 0.1 × 首年每MW租金 × 计费率(t) × (1+租金递增)^(t−1)
现金成本及维护(t) = (首年固定运营 + 首年可变运营×计费率(t) + 首年维护) × 1.02^(t−1)
CF(t) = R(t) − 现金成本及维护(t) − [t=8时的额外升级] + [t=15时的残值]
NPV(r) = −1.20 + Σ CF(t)/(1+r)^t
```

第7.4节的12% NOI/成本是未计爬坡、维护、退出和资本时间价值的稳定期指标；此处才是相同资产边界的长期现金检验。10%折现只是相对长期租约的一种研究门槛，另列12%防止通过降低门槛制造优劣结论。没有主张长期房东合同一定比GPU合同安全：租户破产、重大升级或尾端设施失配都可损害残值。若建设成本从1.20B增至1.40B而租金不变，上述各NPV再减少0.20B。
