## 一、结论先行：AI需求是否足以支撑2026—2028基础设施扩张

**已经存在可观的真实付费需求，但现有公开证据不足以证明全部建设能在经济寿命内回收。最强的经营证据来自代码、企业工作流及云端模型服务；最大的推断缺口是全球同质量成功任务量、净实收价格、有效利用率，以及未来资产更新成本。**

本报告不把AI需求压缩成一个市场规模数，而建立三本相互连接的账：客户最终支付、平台间收入与现金转移、基础设施资产与融资。核心结果如下：

| 判断对象 | 当前结论与数量 | 成立条件、置信度及主要反证 |
|---|---|---|
| 全球文本使用量 | 当前归一化文本调用量约**200—820T/day，73—299Q/year**；用于模型的参考点480T/day，即175.2Q/year | 低置信度条件估计；包含缓存读取，不是独立新文本，也不是全量多模态。平台覆盖、中文tokenizer和内部调用归属仍有较大缺口 |
| 当前实际推理工作量 | 上述文本约2.2—35.9×10^27 FLOPs/year；加多模态约2—12×10^27，合计约4.2—47.9×10^27 | 使用明确列示的模型混合与缓存假设；不是芯片出货统计，不含训练 |
| 2026最终支付 | 基准**180—270B**，计算参考点220B | 去除应用→API→云内部重复收入；含单独识别的增量广告收入，不把全部广告收入算AI收入 |
| 2027、2028最终支付 | 基准分别**290—470B、440—780B**；参考点375B、600B | 需要采用、续费、任务频次和实际收费同时改善；不是将远期账号直接乘年费 |
| 2026全球AI相关CapEx | 基准**560—740B**；参考点650B | 从大型公司总CapEx拆分AI归属，再补其他地区与运营商；不是公司披露的“全球AI CapEx” |
| 2027、2028AI相关CapEx | 基准**650—980B、750—1,220B**；参考点810B、980B | 属于预算/投产条件路径，不是已签不可撤销采购 |
| AI自有现金覆盖当年CapEx | 基准参考点约**10%、15%、22%** | 合并产业链、剔除内部转移后的AI运营现金估计；其余依赖非AI业务、融资、存量现金和预付款，不代表全部建设不合理 |
| 单资产回收 | 示例资产税前、无杠杆回收约**1.6—2.6年**，但下行情景**6年仍未回收**；整机更新后持续回收约4.4年 | 这是明确租价/利用率/寿命条件下的样本，不是全球平均回收期 |
| 需求与供给 | 高质量、可交付、有电力和网络的容量仍偏紧；低价值API更易竞争；全球通用GPU是否过剩尚无同口径利用率证明 | 不能用一个低价实例或一个满载集群推断全球状态 |

2026—2028的增长更可能来自**每个活跃付费用户处理更多任务、Agent调用链与上下文增长，以及更多工作流进入生产**；标价下降对收入形成抵消，缓存、蒸馏和路由又对实际计算量形成抵消。前沿模型能力提高可以增加有价值的任务，但benchmark成功率不是企业续费率。Google披露API吞吐从上一季度约16B tokens/min上升到约22B；这是使用量锚点，不是同幅收入增长的证明。[R1：Google Q2经营说明](https://blog.google/company-news/inside-google/message-ceo/alphabet-earnings-q2-2026/)

最容易提前投资的是：依赖少数模型客户和外部融资的NeoCloud、需求尚未成形的主权/地方AI项目、以及用未来Agent收入支撑当期建设的模型平台。大型云厂可以用既有业务现金和内部广告/推荐收益承担提前投资，但必须防止把这种融资能力误当成项目ROI。

## 二、研究口径、资料边界和估算方法

### 2.1 四类证据与五项防重复规则

- **F，披露事实**：保留原始值和“超过/约/至少”等限定。企业自行公布的运营数据仍不是独立审计结果。
- **G，管理层指引/目标**：CapEx指引、run-rate目标、未来产品表现，不等同已实现。
- **E，研究估算**：从外部锚点与明确假设推导，公开公式、范围与反证。
- **H，研究判断/条件事件**：概率、供需状态、采用速度，注明条件和主观性。

| 易混淆项目 | 本报告处理 |
|---|---|
| 最终支付与平台收入 | 客户向应用付100，应用向模型付25、向云付10，模型再向云付12.5：最终支付只有100；三层收入各自列示，不能求和当市场 |
| seat与API | 套餐内token不追加API标价收入；额外账单才计收入。代码功能包含在办公/通用套餐时按主用途分配一次 |
| 训练与推理 | 训练用FLOPs/GPU-hour；合成数据和RL rollout归入训练预算，避免同时加进用户推理和训练乘数 |
| token与有效计算 | 缓存命中token是读取/计费量，不能等同重算；不同tokenizer先给桥接系数，多模态保留秒、图、分钟和FLOPs |
| CapEx与合同/租赁 | RPO不是收入或CapEx。云客户租费不是客户设备CapEx。金融租赁资产计资本投入时，不把本金偿还再当新增资产；经营租赁另列承诺，不凭分类变化认定实物建设下降 |

文本归一化单位N-token定义为：相同原始文本在一个固定参考tokenizer下的token数量。由于无法取得平台原始文本，本报告以转换系数区间近似；**这是可复算的条件归一化，尚不是实际重分词的统一数据集**。工作量用固定参考单位W计量：1 W=10^11 FLOPs；模型效率变化改变每N-token消耗多少W，W本身定义不变。W只比较计算量，不代表任务质量等价；质量须另过任务验收门槛。

年度token量指当年实际流量积分。当前run-rate是一个时点年化值，2026全年参考140Q低于当前175.2Q run-rate，反映上半年低于当前水平；二者不能混用。

### 2.2 推导链与公式

    采用→活跃付费主体→任务/主体→调用/任务→输入、缓存、输出→成功结果
    实收收入→可归因服务成本→毛利→运营现金→可承担CapEx
    工作量FLOPs + 显存/带宽/时延约束→有效容量→更新/新增/在建资产

    I = Σ(调用次数×单次输入)；O = Σ(调用次数×单次输出)
    T = I + O
    API收入 = 未缓存输入×净价 + 缓存读取×净价 + 缓存写入×净价
              + 输出×净价 + 工具/存储等收费
    F_text = T × [(1-o)×((1-h)×f_in+h×f_cache)+o×f_out]
    f中另含架构、注意力、拒绝/重试和质量档位差异；已包含的项不再乘一次
    N_eq = F_total / (10^15 × 31,536,000 × u)
    容量GPU-hour = N_eq×8,760（包含未有效运算的可用时段）
    峰值等效有效GPU-hour = F_total/(10^15×3,600)；两者相差利用率u
    有效GPU-hour仍是计算归一化，不是实际设备计费小时
    训练F = Σ(run数×单run FLOPs×实验/后训练倍数)
    单位成功任务全成本 = 所有尝试的API/自有设施/工具/复核/集成成本 ÷ 成功任务数
    CF_t = 可归因收款 - 现金运营费 - 税 - 营运资本增加 - 维护/更新投入
    NPV = -初始资产投入 + Σ[CF_t/(1+r)^t] + 末期残值/(1+r)^寿命

N_eq是**峰值1 PFLOP/s、有效利用率u的标准容量单位**，近似H100级计算比较单位，不能直接叫实际H100出货量。实际GPU/ASIC数量=N_eq/该设备对指定负载的实测等效系数。采用实测tokens/GPU-hour时不再乘u。税前无杠杆资产模型与有融资的股东现金分开。

### 2.3 区域覆盖与可识别程度

全球需求至少分为美国平台全球业务、中国本土服务、欧洲及其他地区。美国平台的海外用户已经在其披露内；不得再按海外人口加一遍。中国监管统计和豆包平台统计存在包含关系，只用前者作区域锚，后者校验。主权AI支出可能流向美国云厂、欧洲服务商或本土供应商，按最终付款和资产所有者分别归属。

对于xAI、Meta内部推理、Mistral、Cohere、Perplexity、开源自部署和边缘AI，没有取得覆盖一致的token与收入全集：用受约束的剩余项承接，不虚构公司级流量。机器人机体、自动驾驶整车和传统推荐广告系统不是文本token模型覆盖范围；其新增AI计算单列敏感性，不把整车/工业市场并入生成式AI收入。

### 4.3 可复算的成本、缓存与毛利示例

设自有设施每标准容量单位初始投入40,000美元；GPU/服务器30,000、网络4,000、机房/电力分摊6,000。GPU及网络折旧4年、机房15年：年折旧8,900美元。现金服务费4,504美元/年，包括电费约1,025美元（1.3kW×8,760h×0.09美元/kWh）和其他运维/网络/软件3,479美元。**电力按全年容量等效费用预算，是保守简化，不等于设备全年峰值功耗。**

若u=25%、峰值10^15 FLOP/s、f=0.9×10^11 FLOPs/N-token：

    年tokens = 10^15×31,536,000×25% ÷ (0.9×10^11) = 87.6B
    摊销服务成本 = (8,900+4,504) ÷ 87,600M = 0.153美元/M
    若u=15%—35%、f=0.3—1.5×10^11，成本约0.036—0.425美元/M
    未包括研发、销售、利润税、融资与额外长上下文内存约束

这个0.036—0.425是**理想化混合工作量条件成本**，不适用于每个闭源前沿模型。加入显存副本、低时延和故障冗余后可乘1.3—3倍，即约0.05—1.28美元/M；乘数必须由部署测试验证。可容忍批处理和小模型靠近低端，低batch大模型/长推理靠近高端或超过上界。成本参考0.153，若净收入0.30/0.60/1.20美元/M，服务毛利分别49%/74.5%/87.3%；如果实际成本0.425而净价0.30，毛利为-41.7%。这些不是任何平台已披露毛利。

缓存经济例：一组原生token输入9M、输出1M；输入缓存命中80%，剩余1.8M都写缓存。按Sonnet 5当前标准价：

    费用 = 1.8×2.50 + 7.2×0.20 + 1×10 = 15.94美元
    混合实收 = 1.594美元/M（无折扣）
    无缓存、无写入：9×2 + 1×10 = 28美元
    这里不能再对1.8M既收普通输入又收缓存写入；按实际提供方规则处理

若h由80%增至90%，总token相同而费用下降；若Agent把已经缓存的上下文重复读十次，总token可以大增，但新增计算主要是KV读取与新输出。缓存同时节约prefill，又可能增加HBM驻留、SSD溢出和传输，不是所有存储都按token线性增长。

### 4.4 同质量价格弹性与业务ROI

    Δlog收入 ≈ Δlog成功任务数 + Δlog每成功任务实收
    Δlog硬件计算 ≈ Δlog任务数 + Δlog尝试次数/任务 + Δlog计算/尝试
    若单位成本减半，任务数变为原来的2^ε；计算需求比例=2^ε×0.5
    ε<1时计算收缩，ε>1时计算扩张；此式只隔离成本效应，不含能力变化

| 场景 | 同质量成本减半后的任务增长条件 | 对供给方的含义 |
|---|---|---|
| 成熟批处理/摘要 | 1.1—1.5倍，业务总量相对有限 | 硬件计算约0.55—0.75倍，收入可能下降 |
| 代码/知识工作Agent | 1.5—3倍，取决于成功率、复核与预算 | 计算0.75—1.5倍；不能预设Jevons效应必然成立 |
| 视频/科研探索 | 2—5倍尝试，付费结果增长可能仅1.1—2倍 | 计算1—2.5倍，但预算约束和补贴可能压毛利 |
| 内部广告推荐 | 工作量由预测收益控制 | 需要A/B测试增量广告毛利或成本节约；不可把全部广告收入记AI |

以上是情景弹性条件，不是经验回归系数。

可验算任务例：每次尝试API1.5美元、工具0.5美元、人工复核10分钟×60美元/小时=10美元，成功率80%，则每成功任务成本=(1.5+0.5+10)/0.8=15美元。若API减半但复核不变，则14.0625美元，只下降6.25%。原人工30分钟=30美元时，毛节约15美元；若还有集成摊销8美元、责任损失准备3美元，客户净收益只剩4美元。客户最多愿支付的增量受这4美元限制，不能把30美元人工预算全部交给模型公司。

编码PR例：每尝试API8、工具2、复核0.5小时×80=40美元；成功率70%，每合并PR约71.43美元。API成本减半只降至65.71美元。只有同时把复核降至0.25小时且成功率提至85%，成本才降至约30.59美元。这些都是例算，全球cost/merged PR仍未知。

### 5.2 显存、KV、带宽与存储校验

标准GQA示例：80层、8个KV heads、head dimension128、KV每元素2字节：

    KV bytes/token = 2(K,V)×80×8×128×2 = 327,680 bytes≈0.3125MiB
    单个128k上下文约40GiB；32k约10GiB
    32个128k并发会话约1.25TiB KV，尚未包含模型权重和工作缓冲

若模型总权重70B、FP16约140GB，单块80GB显卡即使FLOPs足够也装不下；量化、分片、GQA/MLA、KV压缩与SSD溢出会改变约束。MoE的激活参数决定主要计算，**总参数仍影响权重存储**。DeepSeek-V3公开671B总参数、37B激活参数就是二者不能混为一谈的例子。[R36](https://arxiv.org/abs/2412.19437)

KV读取需求约=并发会话数×每会话KV bytes×解码步速率；粗例1.25TiB×20步/s≈25TiB/s，分摊到设备并受attention实现影响，说明带宽可能先于FLOPs限制吞吐。PagedAttention解决KV碎片和共享，不是让KV的物理容量归零。[R37](https://arxiv.org/abs/2309.06180)

持久化文本另算：480T/day×4 bytes/N-token×保存1%×30天×2副本≈1.15PB；保存0.1%则0.115PB。日志中应去掉重复缓存前缀，不能把每次读取的全部上下文永久存一份。视频参考50B收费秒/年，3次尝试，2MB/s码率、保存30天、2副本，对应约49PB；不同码率/保留期线性变化，原始训练素材另列。GB/GiB分别按十进制/二进制处理，不混用精度。

## 七、训练与推理：架构、预算及产业链差异

### 7.1 训练需求的独立条件估算

DeepSeek-V3技术报告披露2.788M H800 GPU-hour，模型671B总参数、每token激活37B；该训练阶段数据不含完整公司研发、失败实验及全部基础设施投资。不能从某一次训练较便宜推论全球训练预算会下降。[R36](https://arxiv.org/abs/2412.19437)

Epoch观察前沿训练计算长期快速增长，为上界机制提供参考；由于最新闭源模型没有完整FLOPs披露，本报告不把历史4—5倍趋势机械延长到所有训练。[R44](https://epoch.ai/trends)

悲观中标准容量仍增，是因为利用率恶化会提高满足同样任务的装机需求；**这不是企业一定会买更多设备**。实际财务约束会迫使延迟任务、关闭闲置容量或修复调度。悲观2028较低CapEx反映预算收缩，不能从需求模型N直接推出采购必增。

### 8.2 预测范围与边界条件

| 情景 | 最终支付B：2026 / 27 / 28 | AI CapEx B：2026 / 27 / 28 | 经济机制 |
|---|---|---|---|
| 悲观 | 150—220 / 180—300 / 200—400 | 500—650 / 400—650 / 300—650 | token持续增长，低价/免费/重复调用占比升，Agent收入和现金捕获不足 |

范围由现实支付锚、采用/净价组合和预算包络共同约束；不应将上端支付与下端成本任意配成“最优利润”。2028远期范围尤其依赖企业生产化、政府预算与资金市场，不具有窄预测精度。

基准2026→2028：文本3倍，净每token FLOPs系数0.689倍，所以文本F约2.067倍；利用率改善使文本容量只约1.72倍。总F因训练/多模态变动增约2.607倍，总标准容量约2.172倍；最终支付增约2.727倍。这个分解说明收入与计算增长由不同变量共同决定，既不能用token3倍推出芯片3倍，也不能仅凭每token成本下降就认定硬件需求下降。

### 8.3 从需求容量到采购预算：保留无法解释的差额

采购必须使用存量—流量关系：

    当年可服务新增容量 = (当年资本投入 - 在建/前置工程投入 - 未覆盖负载投入) / 单位交付全栈成本
    年末容量 = 年初容量 + 投产新增 - 退出/报废
    当年平均容量 = 年初容量 + 新增×当年运行比例 - 退出×当年影响比例
    需求容量缺口 = 满足任务需要的容量 - 实际可服务容量

没有全行业年初装机、在建转换、退出量与等效芯片组合，不能唯一推得每年新增采购。2026若650B中60%当年形成完整可用资产，单位40k美元，则交付9.75M标准容量；若平均只运行半年，提供4.875M全年容量。再加年初存量，可能明显高于本模型5.40M已覆盖需求。这一差异提示四种可能：

1. 单位全栈成本或实际模型F远高于参考假设；
2. 实际投产比例远低于60%，较多钱投向未来电力、机房和未完工设备；
3. 传统推荐、内部自用、边缘或其他未覆盖需求很大；
4. 的确存在超前建设和未来利用率风险。

不能在缺证时自动选择前三种解释。反推65%之外的参数变化：若单位成本60k且当年交付比例40%，650B只对应4.33M交付、半年度2.17M平均容量，差异会明显缩小。这里完整保留成本和投产时间，不通过任意“需求倍数”消掉矛盾。

资本强度也分三项：API净价是流量价格；N×单位全栈成本/年工作量是存量资本强度；年度K/年工作量混合扩张和前置工程。2026基准已覆盖资产216B/140Q=1.54美元/年N-token百万的存量资本比；分母只用文本但分子含训练/多模态会夸大，因此**该比值不能叫文本单位token资本成本**。严格文本专属应1.60M×40k/140Q≈0.457美元/年百万N-token，再按寿命和现金运维推摊销成本。

本报告不为三组代表点强行分配合计100%的概率，因为情景区间有重叠且不能证明穷尽所有状态。以下是主观事件概率区间H，依据付费锚、同业采用经验、技术/建设周期；不是历史样本拟合。

在token价格继续下降时，仍可能受益的是：有低成本ASIC/集群效率的服务商、有分发与付费留存的应用、以及真正约束吞吐的内存/互联环节。是否转成公司利润，取决于竞争价格、产品组合、客户集中、供应扩张和折旧；本报告不从产业需求直接给股票排序。

若Agent不达预期，首先观察用量超额收费减少、企业套餐闲置、API净价和模型层毛利；其后是NeoCloud续约/融资和高端推理部署，再后才是长交期HBM/网络/机房订单调整。已签采购可以延迟反证传导，供应商当前强收入不是最终需求永续的证明。

### 10.3 对十个最终问题的直接回答

1. **增长来源**：基准来自持续付费任务、使用频次和Agent工作流；token价格对收入有抵消，模型复杂度与效率对算力相互抵消。2026—2028基准token3倍，文本计算仅约2.07倍。
2. **训练/推理产业链**：训练更依赖大集群同步与HBM/scale-out；推理更受decode带宽、KV、时延、调度和任务成功率约束，两者都消耗网络/存储/电力。
3. **收入支撑CapEx**：有真实收入解释部分投资，但AI自身现金尚不足以覆盖全部扩张；这不排除用内部收益和其他现金合理提前建设。最脆弱的是融资约束强、客户集中的资产。
4. **价格继续下跌**：成本领先、结果可收费、留存强的公司可能受益；高成本模型与缺少差异化的租赁收入首先被压缩。
5. **Agent/多模态失速**：先看付费任务和API毛利，再看NeoCloud续约/融资，随后是交付与上游新增订单；不能只盯当季硬件收入。
6. **日常指标**：每成功任务全成本、净续费、实际账单、cache-read/重算、计费利用率、同SKU续约价、已接电可计费MW、扣预付款CFO。
7. **当前run-rate**：约200—820T/day归一化文本调用、73—299Q/year，参考480T/day；只是一套透明条件估计，多模态和训练用另账。
8. **30/90日与六个月变化**：使用和付费证据增强，缓存/计费口径使旧推算失效；最新数据支持维持增长基准，不足以宣告全部CapEx合理或普遍过剩。
9. **供需分化**：高质量可交付集群与低价值API处于不同竞争状态；公开价格和管理层称“受限”都不能替代有效占用率。
10. **效率/ROI**：有同厂商任务成本改善信号，但全球真实PR成本、人工接管、预算利用率仍未知；只有同质量成功任务的全成本与续费一起改善，才提高长期需求假设。

### 11.2 第三方交叉验证与不能直接比较之处

Menlo估计2025企业GenAI支出37B、重述2024为11.5B；其调查约500名美国企业决策者，采用自下而上模型，历史数据对推理相关项目有排除/重述。它支持企业付费快速增长，但**不能把本报告2026全球最终支付220B/37B算成市场增长率**：地域、消费者、多模态、直接云、自部署与年度不同。若希望做增长率，必须从外部重新采集相同口径的2026样本。[R45](https://menlovc.com/perspective/2025-the-state-of-generative-ai-in-the-enterprise/)

IEA数据中心用电是物理上限交叉检验，不是AI收入证据；Epoch训练趋势是技术/投入趋势，不是愿付价格；公司案例是存在性证据，不是行业平均ROI。可比数据不足时明确“不比较”，没有调用本地上期报告补数。

### 11.3 最小复算包：输入、单位和依赖关系

本报告内已包含全部计算参数，无需另一份正式模型文件。

| 输出 | 必要输入 | 复算路径 |
|---|---|---|
| 当前文本run-rate | 四章流量池上下界/归一化/重复项 | 分项相加→日量×365，保留机械183—830与研究约200—820 |
| 各场景三年使用/支付 | 三章底表；八章总Q/D | 逐行乘同年度情景比，合计回到总Q/D |
| API实际收入 | 按模型/区域/档位的I、cache读/写、O与净价 | 独立计费项相加；与seat内调用去重 |
| 文本F | 全年Q×每N-token f | 10^15×10^11=10^26，表中转10^27时除10 |
| 全球覆盖负载总F | 文本F+训练F+多模态F | 不再加Agent系数或合成数据第二遍 |
| 标准容量M | 总F以10^27计÷31.536÷u | GPU-hour B=容量M×8.76；等效GW=容量M×1.3 |
| 实际卡数/机架/HBM | 标准容量、实测等效系数、rack密度/显存 | 实际型号未知时仅给条件范围 |
| 三层收入 | D；0.55/0.25/0.20与内部采购比例 | 第六章公式；禁止总收入当最终支付 |
| 资本预算/融资 | K、mD、非AI现金、外部最终客户预付款 | 外部融资/存量现金=K-mD-其他现金-预付款 |
