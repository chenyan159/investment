# 全球AI需求与Token经济框架

**报告日期：** 2026-07-10  
**主要数据日期：** 2026-07-09；财报、产品和技术资料覆盖至 2026-07-10  
**估值/股价快照日期：** 不适用。本报告不是单一公司估值报告；API 价格、GPU 租赁价格与基础设施成本快照日期为 2026-07-10。  
**方案版本：** 2026-07-10  
**核心结论摘要：**

1. **真实需求存在，而且正在从聊天转向工作负载，但当前 CapEx 尚不能靠当年 AI 毛利自我覆盖。** 本期独立估算的全球底层实际处理量为 **350-520 万亿 tokens/day**，年化 **128-190 千万亿 tokens（quadrillion，以下简写 Q）**；其中 Google 已披露的全产品面为 3.2Q/月、OpenAI 与 Google 的模型 API 合计已构成至少 49 万亿 tokens/day 的硬下限。2026 年非重复 AI 基础设施 CapEx 约 **$500-720B**，资产所有者可归因 AI 收入约 **$240-360B**，可归因毛利/现金贡献约 **$90-155B**。结论是“需求足以支持继续建设”，但不是“当年现金流已经覆盖建设”。
2. **2026-2028 年 token 增量的第一驱动力是 Agent 调用链，而不是新增聊天用户。** 基准情景下，处理 token 从 2026 年 **110-180Q** 增至 2028 年 **805-1,585Q**；两年增量中，Agent 步数与工具调用贡献约 35%-45%，上下文、推理链和多模型路由贡献约 25%-35%，用户数与使用频率贡献约 15%-25%，多模态文本化与合成数据贡献约 10%-20%。
3. **价格会继续下降，但“质量调整后的价格下降”不等于所有榜单价下跌。** 标准/轻量 API 的质量调整价格预计每年下降 45%-65%；高可靠 Agent、长上下文、搜索工具和推理 token 可维持溢价。原始 token 增长 2-4 倍/年，收入不需要同步增长，只需在成本下降后保持 45%-70% 的年增速，便可逐步改善 CapEx 回收。
4. **推理的物理瓶颈已从纯 FLOPs 转为 HBM 容量与带宽、KV cache、调度、存储和网络；训练仍是大规模连续 GPU/ASIC、HBM 与 scale-out 网络的峰值买家。** 2026 年推理约需 **4-12B GPU-hours**、平均 **0.5-1.4M H100-equivalent（H100e）有效在线加速器**；考虑延迟余量和 45%-65% 有效利用率，对应名义推理池约 **0.9-2.6M H100e**。训练与后训练另需约 **1.5-4.0B GPU-hours**。
5. **高端算力与低价值 token 已进入两个不同的供需阶段。** B200/B300、TPU/Trainium、HBM4、800G/1.6T 网络和可并网电力仍偏紧；A100、普通小模型 API 和低差异化 token 已平衡或宽松。高端 GPU 租赁价格仍在约 **$4-11/GPU-hour**，而轻量 API 已低至输入 **$0.25-0.50/M tokens**。这不是总量“短缺/过剩”二选一，而是结构性紧缺与通用算力通缩并存。
6. **最扎实的收入证据来自云、模型 API、代码 Agent 和带量企业软件；最脆弱的是尚无高频生产使用的通用企业 Agent、低利用率 NeoCloud 和以主权叙事替代本地需求的项目。** Salesforce 已披露累计 28.6T tokens 与 3.8B Agentic Work Units；OpenAI/Anthropic 的企业收入、用户与吞吐同步增长；但行业仍缺统一的 cost/task、人工接管率和成功率公开口径。
7. **基准情景下，新建设施简单回收期从 2026 年的 3.2-8.0 年改善至 2028 年的 1.6-3.8 年；现金回收仍明显慢于服务器折旧。** 若 token 量增速连续两个季度低于 80%、高端 GPU 有效利用率低于 50%、租赁价同比下跌超过 35%、或 Hyperscaler CapEx 指引下修超过 15%，基准情景必须下调。
8. **投资含义不是“token 越多，所有 AI 硬件都等比例受益”。** 最直接的量驱动是 HBM/DRAM、互连、推理 ASIC/GPU、存储和电力利用率；GPU 厂商与 NeoCloud 还取决于售价、折旧和融资；低差异化 API、纯 seat 套餐与前置建设的机房最容易被价格下降或利用率不足抵消。

> **本期核心估算冻结声明（Phase A）：** 下列 run-rate、三情景和结论已于 2026-07-10 在未读取任何本地旧报告、索引、缓存或中间结论的条件下，由当期外部资料独立建立并冻结。第四章的上期桥接仅在冻结后执行；旧报告只用于版本比较，不是本期事实来源。

## 一、结论先行：AI 需求是否足以支撑 2026-2028 基础设施扩张

### 1.1 核心判断：需求是真的，建设速度仍领先于现金回收

AI 基础设施扩张当前有三层支撑：

- **硬使用量支撑：** Google 2026 年 5 月披露全产品面处理 3.2Q tokens/月；OpenAI 2026 年 4 月披露 API 超过 15B tokens/minute；Google 模型 API 2026 年 5 月约 19B tokens/minute。两家 API 的可核验合计下限已达 49T tokens/day，且不含 ChatGPT 第一方流量、Anthropic、Meta、自托管、中国平台与内部广告/推荐模型。
- **硬收入支撑：** OpenAI 2025 年收入年化已在 **$20-22B**，Anthropic 2026 年 5 月收入 run-rate 在 **$46-48B**；Salesforce Agentforce ARR 在 **$1.1-1.3B**，Adobe AI-first ARR 超过 **$0.5-0.6B**。收入已不是纯试验预算。
- **硬订单支撑：** CoreWeave backlog 约 **$99-100B**，Oracle RPO 约 **$635-640B**，Microsoft 商业 RPO 超过 **$600-625B**；但订单期限、客户集中、预付款和取消条款意味着订单池不能等同于当期收入。

与此同时，Alphabet、Amazon、Microsoft、Meta 四家 2026 年 CapEx 指引简单相加约 **$690-720B**，再考虑 Oracle、NeoCloud 和主权项目，全部基础设施支出更高。因其中包含非 AI 云、物流、办公和未完工项目，本模型只归因 **$500-720B** 至 AI；即便如此，2026 年 AI 毛利/可归因现金贡献仍只覆盖约 13%-31%。因此：

> **基础设施建设有真实需求底座，但 2026 年仍是“以未来 3-8 年需求、战略稀缺性和长期合同融资当前 CapEx”，不是“当年 token 收入已经付清当年 CapEx”。**

### 1.3 2026-2028 增长来自哪里

| 增长因子 | 对 2026-2028 token 增量贡献 | 对收入增量贡献 | 物理含义 | 反证 |

## 二、研究口径、资料边界和估算方法

### 2.1 两套账：物理账与收入账

| 账本 | 计数单位 | 如何去重 | 用途 | 不可直接用于 |
|---|---|---|---|---|
| **Provider-side 物理账** | 实际进入模型的输入、输出、推理/中间与缓存读取 token | 每次底层模型执行计一次；SaaS 调用第三方 API 只在 API 提供商处计物理量 | GPU-hours、HBM、网络、电力、成本 | 把 SaaS、API、云三层收入相加 |
| **Application-side 逻辑账** | 用户任务、Agent 步骤、音视频等价 token | 一个业务任务可展开为多次模型执行；保留调用链放大 | cost/task、任务 ROI、场景需求 | 推导独立物理容量时直接相加 |
| **资产所有者收入账** | 云实例、API、订阅、广告增量的非重复收入 | 下游 SaaS 收入与上游 API 成本不层叠；按资产现金流归属 | CapEx 回收期 | 代表整个生态“总产值” |

本报告的“token”默认指 tokenizer 处理的原始输入、输出和明确计费的推理 token；图像、音频、视频只在“应用等价 workload”中按计算成本折为文本 token，不伪装成实际 tokenizer 数量。缓存命中仍消耗 HBM/网络和部分算力，因此进入物理账，但按折扣价进入收入账。

### 2.2 核心公式

```text
场景 token 需求(year, scenario)
= Σ[活跃用户 × 请求/用户 × 输入 tokens/请求 × (1 + 输出/输入比)
    × 模型调用链长度 × (1 - 缓存/去重节省率)]
```

```text
推理 GPU/ASIC-hours
= 原始 token volume ÷ (有效 tokens/GPU-hour × 在线服务利用率)
```

```text
FLOPs/token（近似）
= 2 × 活跃参数量 + attention/prefill 项
```

对于 MoE，计算项使用活跃参数，但显存、路由和通信必须同时考虑总参数与专家分布；对长上下文，attention/prefill 与 KV cache 不能被 `2 × active parameters` 简化掉。

```text
推理收入
= input tokens × input realized price
 + output/reasoning tokens × output realized price
 + seat/workflow/outcome fee 的 token 等价收入
```

```text
推理毛利
= 推理收入 - 加速器折旧 - 电力 - 网络/存储 - 运维 - 服务软件成本
```

```text
AI CapEx 简单回收期
= cohort AI CapEx ÷ 稳态年化可归因毛利或现金贡献
```

```text
训练 FLOPs
= Σ[最终训练 run × 6 × 参数量 × 训练 token]
 × 架构修正 × 实验/后训练/失败 run 倍数
```

```text
单位任务全成本
= token/API 成本 + 基础设施摊销 + 搜索/工具费 + 存储/网络费 + 人工复核成本
```

### 2.3 锚点、估算和置信度

| 等级 | 定义 | 示例 | 报告处理 |
|---|---|---|---|
| A：硬披露 | 公司一手、监管文件或正式价格表 | Google 3.2Q/月；OpenAI 15B/min；Alphabet CapEx **$175-185B** | 作为区间中心或下限 |
| B：可复算 | A 级数字经透明公式转换 | 15B/min = 21.6T/day；1GW 约 **$32-45B** upfront | 显示公式和口径 |
| C：交叉估算 | 两个以上独立来源与物理边界一致 | 全球 350-520T/day；推理 4-12B GPU-hours | 给宽区间和反证 |
| D：代理指标 | 无统一公开数据，用研究/产品指标替代 | 人工接管率、cache hit、budget utilization | 不作为单点事实，明确低置信度 |

所有美元数字均用区间；公司给出的点值也用四舍五入误差或口径误差转换为窄区间。金额为名义美元，未做通胀调整；年度默认日历年，Microsoft/Oracle 财年数据会单独注明。

### 2.4 关键物理假设

| 参数 | 本期区间 | 来源与含义 | 敏感性 |
|---|---:|---|---|
| 混合输入/输出比 | 6:1-10:1 | OpenRouter 大样本与 Agent coding 长输入交叉校验 | 输出占比越高，算力与收入越高 |
| 已调度时段原始 tokens/GPU-hour | 35-100M | 由约 10-28K tokens/s 的混合负载折算；再乘 45%-65% fleet 利用率，得到约 20-65M fleet-level | fleet-level 每提高 2 倍，所需 GPU-hours 约减半 |
| 在线有效利用率 | 45%-65% | 延迟、峰谷、显存碎片、容错与排队约束 | 低于 45% 会快速破坏毛利 |
| 加速器+CPU+本地网络 IT 功率 | 1.2-2.1kW/accelerator | GB300 NVL72 约 142kW/72 GPU 为上端锚点 | 决定 MW、rack 与电费 |
| AI 专用 PUE | 1.12-1.25 | Epoch 1GW 模型中心值 1.14 | 对电费敏感、对总 TCO 次于服务器 |
| 高密度 rack | 72 accelerators、100-250kW | GB200/GB300 NVL72 与混合机架 | 直接决定机房改造 |
| IT 折旧/经济寿命 | 3-7 年 | 云厂折旧政策、CoreWeave 6 年 GPU 寿命 | 回收期最敏感参数之一 |
| 1GW upfront CapEx | **$32-45B** | Epoch 风格化中心值约 **$37-39B** | 服务器配置、地区和自研 ASIC 可显著改变 |

### 4.1 当前 tokens/day、tokens/year 与等价 workload run-rate

物理校验：Google 全产品加 OpenAI API 已提供 **125-134T/day** 的不重叠硬下限；第三方公开估算约 40Q/季度，折合约 430-450T/day，落在本模型中段。当前输出 token 约 **35-75T/day**，混合输入/输出比约 **6:1-10:1**；长上下文（单调用输入 >32K）占请求约 5%-12%，却占原始 token 约 18%-32%。

应用侧“等价 workload”约 **470-800T/day**：它把图片、音视频和工具 I/O 按计算成本折为文本 token，也保留一个任务内的多模型链；因此只能用于任务和算力敏感度，不能与 provider-side 账本相加。

### 4.3 单位 token 收入、成本与毛利

| 指标 | 当前区间 | 2027 基准 | 2028 基准 | 解释/反证 |
|---|---:|---:|---:|---|
| 付费 token 混合实际收入 | **$1.0-3.5/M** | **$0.55-2.0/M** | **$0.25-1.1/M** | output、工具、priority 拉高；cache/batch 拉低 |
| 全部原始 token 实际收入 | **$0.10-0.60/M** | **$0.06-0.35/M** | **$0.03-0.20/M** | 含免费、内部、缓存与未货币化 token |
| 全部原始 token 服务成本 | **$0.06-0.35/M** | **$0.03-0.18/M** | **$0.015-0.10/M** | 若 GPU 利用率 <50%，成本下降会显著放缓 |
| 高推理/长上下文任务成本 | **$0.8-12.0/M 输出等价** | **$0.35-6.0/M** | **$0.15-3.0/M** | HBM、prefill、KV cache 与延迟约束决定 |
| gross margin/token | 35%-70% | 40%-75% | 45%-80% | 若榜单降价快于成本 >15pct，毛利恶化 |

收入弹性可写为：

```text
AI revenue growth ≈ token volume growth
                  + realized price/token growth
                  + workflow/outcome premium growth
                  - free/internal mix dilution
```

基准情景中 token 量增长 150%-220%/年、实际收入/token 下降 45%-60%/年、付费组合与 outcome 溢价贡献 5%-20%/年，对应资产所有者 AI 收入增长约 45%-70%/年。价格战并不自动摧毁收入；只有当价格下降快于成本下降且 volume/利用率不能补偿时，毛利才恶化。

## 五、从 token 到 GPU/ASIC、存储、网络、电力和 CapEx

### 5.1 从 token 到 GPU-hours：FLOPs 只是第一步

以当前年化中位数约 155Q 原始 token 为例：

```text
已调度时段吞吐 = 35-100M raw tokens/GPU-hour
fleet-level 吞吐 = 已调度吞吐 × 45%-65% 有效利用率
                 ≈ 16-65M raw tokens/GPU-hour
```

```text
纯 token payload GPU-hours
= 128-190Q ÷ 20-65M
≈ 2.0-9.5B GPU-hours/year
```

再加入峰值容量、故障冗余、模型加载/切换、低 batch 高 SLA、未被 token 完整代表的视觉/音频和少量重复执行，本模型取 **4-12B H100e GPU-hours/year**。这对应平均有效在线 **0.5-1.4M H100e**；按 45%-65% 有效利用率及调度余量，名义推理池约 **0.9-2.6M H100e**。

这个换算不会得出“全球只需要两三百万块物理 GPU”。H100e 是跨代性能单位，且已售/已装加速器还服务训练、推荐、科学计算、空闲冗余和未纳入 token 的负载。Epoch 的硬件映射显示截至 2025 年约售出 20.2M H100e、只明确定位到约 5.2M operational H100e；“卖出”不等于“当前有效推理在线”。

### 5.3 KV cache、存储和网络：为什么长上下文不是“免费 token”

```text
KV bytes/token
≈ 2 × layers × KV heads × head_dim × bytes/element
```

对 70B 级 GQA 模型，未压缩 KV 可能约 0.2-0.5MB/token；FP8、MLA、量化和分层缓存可降低 2-8 倍。若同时维持 1M 个、平均 25K context 的 Agent session：

```text
live KV = 1M × 25K × 0.05-0.30MB/token
        ≈ 1.25-7.50PB
```

这只是 live KV，不含 repo index、RAG 文档、工具结果、日志、checkpoint 和媒体对象。2026 年 110-180Q token 即使每 token 只保留 0.5-2 bytes 压缩日志，也产生约 55-360PB 年度写入；真正把存储推到 EB 级的是向量索引、版本化上下文、训练数据和视频/音频原件。

网络同样分为两层：训练需要低延迟 all-reduce/all-to-all 的 scale-out fabric；推理需要 prefill/decode 解耦、专家路由、KV 跨节点读取和工具/存储流量。GB300 NVL72 每 72 GPU 机架内部 NVLink 总带宽约 130TB/s，单 GPU 外部 NIC 可达 800Gb/s；因此 Agent token 增长直接拉动交换芯片、光模块、NIC/DPU 和网络调度，而不只是 GPU。

### 6.3 回收期分解

```text
1GW AI factory 年化 TCO ≈ $7-13B/year
稳态所需收入 ≈ 年化 TCO ÷ gross margin before depreciation
             ≈ $10-22B/year/GW
```

采用 1GW upfront **$32-45B**、IT 寿命 3-7 年、PUE 1.12-1.25、利用率 55%-75%：

| 稳态情形 | 1GW 年收入 | 年现金毛利 | 简单回收期 | 判断 |
|---|---:|---:|---:|---|
| 低利用/价格快速下跌 | **$7-11B** | **$2-5B** | 7-18 年 | 服务器寿命内难回收，必须减值或延寿 |
| 基准 | **$13-20B** | **$6-10B** | 3.2-7.5 年 | 可由长期合同支撑，但现金流前置压力大 |
| 高利用/高价值 Agent | **$22-35B** | **$11-19B** | 1.7-4.1 年 | 足以扩建；要求 utilization 与 realized price 同时稳定 |

当前市场的问题不是总收入为零，而是 **建设 cohort 的资本成本先发生、付费 workload 后爬坡**。CoreWeave Q1 收入约 **$2.0-2.2B**、adjusted EBITDA 约 **$1.1-1.2B**，但利息约 **$0.5-0.6B**、净亏损约 **$0.7-0.8B**，说明高利用率和长合同仍可能被融资结构吞噬。Oracle FY26 自由现金流约 **-$24B 至 -$23B**，同样说明订单增长不等于自融资能力。

### 6.4 收入覆盖 CapEx 的判定

| 判定层 | 2026 | 2027 | 2028 | 结论 |
|---|---:|---:|---:|---|
| AI 收入 / AI CapEx | 33%-72% | 45%-100% | 63%-138% | 收入层 2027-2028 有机会接近覆盖 |
| AI 毛利/现金贡献 / AI CapEx | 13%-31% | 18%-49% | 28%-72% | 现金层仍需多年累计 |
| 累计收入对 2026-2028 累计 CapEx | — | — | 60%-115% | 只在基准上半区达到收入覆盖 |
| 累计毛利对累计 CapEx | — | — | 25%-58% | 2028 前大概率不能完全自我融资 |

因此“AI 收入能否覆盖 CapEx”的正确答案分两层：**收入 run-rate 可以在 2027-2028 对当年 CapEx 接近 1 倍；真正可分配毛利/现金流在 2028 前仍大概率低于当年 CapEx。** 云厂能继续投入，是因为传统云、广告和软件现金流、客户预付款、长期合约和资本市场共同融资，不应把这些都误称为 token 已经回本。

## 七、训练 vs 推理：不同 workload 对产业链的差异拉动

### 7.1 训练 vs 推理硬件需求表

### 7.2 训练需求推导

对 dense model，预训练计算近似 `6 × N × D`；对 MoE，计算用 active parameters，而权重存储和部分通信用 total parameters。最终 frontier run 只是冰山：架构搜索、小规模实验、数据筛选、失败 run、RL rollout、蒸馏和 synthetic data 通常使总研发计算达到最终 run 的 5-15 倍。

| 指标 | 2026 | 2027 | 2028 | 置信度/反证 |
|---|---:|---:|---:|---|
| 全球 frontier/near-frontier 最终大 run | 15-30 | 20-45 | 25-60 | 低；训练可能集中到更少公司 |
| 单个顶级 final run FLOPs | 0.3-3.0 × 10^27 | 1-10 × 10^27 | 3-30 × 10^27 | 低；架构效率可打破外推 |
| 实验+后训练倍数 | 5-12× | 5-15× | 4-15× | 合成数据可增，蒸馏可降 |
| H100e GPU-hours | 1.5-4.0B | 2.5-7.0B | 4.0-12.0B | 中低；若 scaling 回报下降则减半 |
| 直接训练计算成本 | **$20-55B** | **$35-95B** | **$60-170B** | 不含全部研发和设施；按内部/合同价区间 |

训练最先证伪的信号是：顶级 final run 数量下降、训练集群预约减少、前沿能力对计算的边际提升趋平、或公司把新容量从训练转向推理。相反，合成数据、长 horizon RL、世界模型、视频和主权模型竞争会提高后训练/实验倍数，即使参数 scaling 放缓。

### 7.3 两类需求对产业链的弹性

| 产业链环节 | 训练 token/FLOPs 弹性 | 推理 token 弹性 | 价格/效率抵消 | 投资判断 |
|---|---:|---:|---|---|
| 高端 GPU | 高 | 中高 | 新代 2-10×/MW 效率、ASP 风险 | 受益真实，但数量不与 token 等比 |
| 自研 ASIC | 中高 | 高 | 降低外购成本，软件生态是门槛 | token 越规模化越受益 |
| HBM | 高 | 很高（长 context） | GQA/MLA/量化降低 bytes/token | 最直接的“复杂度+token”受益层之一 |
| Scale-up/NVLink | 很高 | 高（大 MoE/分离式推理） | 模型缩小可压制 | Frontier 与高端推理直接受益 |
| Scale-out Ethernet/光互连 | 很高 | 高 | 压缩/拓扑优化抵消部分端口 | 训练集群与 Agent 路由双驱动 |
| SSD/对象存储 | 高 | 高（Agent/视频） | retention、去重和分层降低成本 | 更依赖 workload 留存而非纯 token |
| 电力/冷却 | 高 | 高 | 每代能效提升，但 Jevons 反弹 | 最慢交付、最不易被单代替换 |
| NeoCloud | 间接受益 | 直接受益 | 租价、折旧、利息可吞噬需求 | 必须同时看利用率与资本结构 |

### 9.3 如果价格下降，谁仍能赚钱

```text
利润弹性 ≈ volume 弹性
          + (成本/token 降幅 - 实际价格/token 降幅)
          + utilization 改善
          + outcome/分发溢价
          - 折旧与融资压力
```

- **仍可受益：** 自研 ASIC 占比高、cache/batching 强、利用率高且有应用分发的 Hyperscaler；按容量/带宽而非榜单 API 价收钱的 HBM、网络与高性能存储；能把 token 变成广告、交易、workflow outcome 的应用平台。
- **受益但有条件：** GPU 厂商需要 token 需求增速大于每代效率提升并维持 ASP；NeoCloud 需要合同价、利用率和融资成本同步健康；电力/EPC 需要项目从公告进入并网和装机。
- **最易被压缩：** 无差异 API reseller、无限量 seat 套餐中的重度用户、老卡高电耗容量、只有 capacity booking 没有生产 workload 的项目。

### 9.4 需求不达预期时的证伪顺序

1. **第一层（1-8 周）：** API 配额放松、priority premium 消失、GPU 租价/现货价下跌、实例随时可用、credits 使用率不足。
2. **第二层（1-2 个季度）：** Agent success/retention、merged PR、企业 attach、AI ARR 和云 AI 增速走弱；模型公司 compute/revenue 上升。
3. **第三层（2-4 个季度）：** Hyperscaler CapEx guide 下修、NeoCloud backlog 取消/重谈、HBM/网络 lead time 缩短、库存上升。
4. **第四层（1-3 年）：** 数据中心延期/取消、电力容量退回、服务器减值、融资违约。只在第四层才承认问题，已经太晚。

### 10.3 十个核心反证条件

| 风险/反证 | 量化阈值 | 最先受损 | 对模型动作 |
|---|---|---|---|
| token 增长不及预期 | provider tokens 增速 <80%/year 两季 | API、推理 GPU、网络 | 基准 token 下调 25%-40% |
| 价格战快于成本 | realized price 跌幅比 cost 跌幅快 >15pct | 模型 API、NeoCloud、云毛利 | 毛利率下调 10-20pct |
| GPU 利用率不足 | 高端 fleet <50% 两季 | NeoCloud、GPU 新订单、电力 | CapEx 下调 15%-30% |
| 企业 ROI 不达标 | budget utilization <60%；续费/attach 停滞 | 企业 Agent、SaaS uplift | 企业/Agent token 下调 30%-50% |
| Agent 质量停滞 | success <50%；takeover >40% | coding/enterprise Agent | 仅保留辅助型需求 |
| CapEx 指引下修 | 四大云合计 guide -15% 以上 | GPU、HBM、网络、EPC | 2027/28 CapEx 下调 20%-35% |
| GPU 租价崩塌 | H100 YoY <-35%；B200 QoQ <-20% | NeoCloud、老卡资产 | 缩短短缺期、增加减值 |
| 训练 scaling 回报下降 | final run 减少、能力/FLOP 改善停滞 | 高端 GPU、scale-out | 训练 GPU-hours 减半 |
| 内存/电力成本超预期 | 内存/电价涨幅 >token 成本优化 20pct | 长 context、低价 API | 成本区间上调、价格下限提高 |
| 融资链收紧 | NeoCloud 利息/收入 >20%，合同重谈、预付减少 | NeoCloud、项目开发商 | 回收期延长 2-4 年 |

### 10.4 结论的可证伪表达

- **基准情景成立的最低条件：** 到 2026 年末 provider-side run-rate 达 160-230Q/year；Agent 任务成功率中位数超过 55%；高端 GPU 有效利用率保持 50%-70%；2027 年资产所有者 AI 收入至少 **$380-580B**；四大云未将合计 CapEx 指引下修 15% 以上。
- **乐观情景升级条件：** 连续两个季度 Agent steps/task、成功率、paid retention 同升，且 cost/task 下降；企业 credits 利用率 >75%；高端 GPU 租价稳定而交付量上升；gross margin/token >55%。
- **极度乐观情景升级条件：** Agent 成为默认生产入口、outcome pricing 广泛形成、token 量连续两年 >3×，同时 tokens/GPU-hour 和供给各提高 >2×/year。仅有模型 benchmark 或 CapEx 公告不足以升级。
- **下行情景触发：** 任意两个红色阈值连续两个季度成立，2028 token、收入和 CapEx 中位数分别下调 40%-60%、30%-45% 和 20%-35%；若同时出现融资收紧，NeoCloud 和主权项目的 CapEx 再下调 20%-40%。

### 11.3 口径限制

1. 平台披露的 token 可能包含 cached input、reasoning token、图片/音频 token、内部调用或不同 tokenizer；报告只在同一平台内做趋势比较，跨平台使用宽区间。
2. AI 收入没有统一会计定义。云 AI、模型 API、企业 SaaS uplift、广告增量和硬件销售不能层叠；本报告以资产现金流重排，仍可能误分传统云与 AI 云。
3. CapEx 指引包含非 AI 项目、土地、物流、办公、网络与融资租赁；AI 归因是 C 级估算。订单、RPO、backlog、预付款和 announced GW 均不等于已确认收入或 operational load。
4. GPU-hours 统一为 H100e 仅为比较。ASIC、Blackwell/Rubin、量化、MoE、Dynamo、batch、latency SLA 会让真实物理 GPU 数显著偏离 H100e。
5. 2027-2028 的核心变量相乘，区间不是统计置信区间；“极度乐观”用于检验物理可交付性，不代表概率最高。
6. 本报告没有把任何旧本地研究当作事实来源。Phase B 的上期正式报告只用于第四章变化桥接；每个当前数字均回到本附录列出的当期外部资料。
