# 全球AI需求与Token经济框架研究方案

## 一、研究目标与自主判断

建立一套可复核的框架，把应用使用量、付费、token 与等价工作量、价格与成本、训练与推理需求、算力利用率、AI 收入和基础设施投入连接起来。研究要回答：谁在使用 AI，谁付钱，产生多少可比工作量，谁保留收入和现金，能负担多少基础设施预算；AI 基础设施建设由哪些真实需求支撑，训练和推理分别拉动哪些环节，哪些需求只是叙事或提前投资。

依据证据判断研究期（Y0—Y2）的需求，允许增长、结构性替代、价格挤压和需求收缩同时存在。缺少直接披露的 token、算力小时、调用量和企业 AI 收入可以做大胆估算，但写清估算链条、口径、来源日期、置信度和反证条件。

以下问题是研究责任提示，不是固定搜索顺序、等长章节或必须填满的问卷。研究者自主选择切入点、模型、分析单位、深度与呈现方式，可以重组问题、深入意外发现或质疑既有分类。没有精确数字时给有依据的范围、数量级、条件或未知；不为填满表格制造答案。

时间口径：以研究截止日所在自然年为基期 Y0（已过期间用实际披露，其余为估计），前瞻覆盖其后两个完整自然年 Y1、Y2；报告中把 Y0、Y1、Y2 写成具体年份。需要时可延伸更远，但不缩短。

## 二、资料与证据边界

- 每次独立展开研究，只依据外部公开资料；除本研究方案外，不读取本地文件作为研究输入。需要比较不同时期时，从外部原始披露建立口径一致的分期数据。
- 独立联网获取资料，优先 AI 平台和云厂的价格、用量、收入与资本开支披露，企业软件的 AI 付费与采用数据，模型卡、技术报告和系统论文，公开的用量统计和官方统计。行业数据用于交叉验证和区间约束，转述同一来源的多个渠道不算独立确认。
- 明确研究截止日期；重要事实注明来源、公开日期与对应经济期间，区分披露事实、管理层目标、直接计算、研究推断与未知。
- 披露数字保留原值、原范围及限定，不把确定数字改成预测区间；归属、换汇和模型误差另列。可比变化先统一对象、地域、单位和期间，范围或口径变化与真实增长分别解释。
- 可信非正式线索可以开启研究，标明日期、来源、利益关系、验证状态与替代解释；重要结论追到具体证据，多源冲突时解释口径与原因。

## 三、核心研究问题

### 1. 需求分层与付费主体

按有经济意义的场景分层，例如训练与后训练、消费聊天与搜索、代码与开发者、企业流程、多模态与视频、agent、广告、科研、主权与私有部署；分层可以调整。每个场景说明付费主体、收费单位、使用强度和硬件压力。

付费人数、席位和预算要有现实基数和可服务范围，处理多账号、多席位、捆绑订阅和 API 支出的重叠。研究从试用、稳定使用、付费、续费到扩大部署的转化，以及集成成本、数据条件、人工复核、组织调整和替代方案对采用的影响；模型能力和商业采用速度分别判断，试用成功不等于持续付费。

### 2. 工作量计量与当前运行速率

独立估计当前的 token 或等价工作量运行速率：以最新的硬披露为锚，加上可验证的新增量，扣除重复统计和口径排除项。输入、输出、缓存命中与重算分别计量，缓存 token 的计费量不等于重新计算量；不同 tokenizer、模型、模态和质量目标的 token 不直接相加，图像、音频、视频保留各自的工作量单位。调用次数已包含 agent 步数时不再乘调用链长度。

用外部可比期间的数据解释使用量、价格、工作负载结构和模型效率的变化，区分真实增长与统计口径变化。关注近期（约 30 至 90 日）对判断有实质影响的新信号，以及过去半年供需状态的迁移；每项信号写清事件日期和资料发布日期。

### 3. 价格、成本与效率

区分标价、折扣后实收价、套餐分摊收入和每成功任务收入；研究生成 token 的成本构成（加速器折旧、电力、网络与存储、运维、软件）和单位任务全成本（外购服务、自有基础设施、工具和人工复核，外购价已包含的硬件成本不重复计入）。

需求对价格、质量和效率的反应是核心估计对象：同等结果质量的成本下降能新增哪些任务，原有任务会用更多还是更少计算，客户获得的价值有多少转化为服务商的实收收入。可以用分场景的条件范围或弹性估计；token 降价不自动意味着任务全成本下降，也不预设效率改善一定扩大或压缩硬件需求。

### 4. 从需求到基础设施

把工作量换算为加速器数量、算力小时、内存与存储、网络、电力和建设投入。计算量模型还要用显存容量、带宽、KV cache、时延和网络约束校验；使用实测有效吞吐时不再扣一次利用率。训练、后训练和推理分别计量，说明它们对加速器、HBM、扩展网络、存储和电力效率的不同压力。

### 5. 收入、现金与回收

按真正的付费主体和收款主体拆开最终付费任务、免费或补贴使用、内部自用和实际推理工作量。客户回报、平台收入与毛利、运营现金和基础设施预算分开建立桥接；区分 AI 业务自身现金、其他业务现金、外部融资和客户预付款，以及战略投入和内部自用价值。客户省钱不自动等于平台留存利润，token 增长不自动同比例放大收入或新增采购。

资产回收用完整的年度现金表支撑：资产构成、初始投入、投产爬坡、续约降价、计费利用率、运营现金、税费与融资边界、经济寿命、更新投入和残值。当年收入对当年 CapEx 的覆盖只反映资金承受能力，不等于回收期；毛利包含折旧时不能代替现金流。

### 6. 供需状态

判断高端算力、通用算力、API token、代码与企业 agent、消费 AI、HBM/KV cache/SSD 分别处在什么供需阶段，大型云和专业算力云有何差异，价格、利用率、交付期和配额说明了什么。

## 四、关键估计与情景

主要需求场景在 Y0、Y1、Y2 给出悲观、基准、乐观的使用量和付费规模，可以用基准底表加情景差异参数，前提是能还原各结果；保留当前可比基数、付费主体、使用强度、净价和去重口径。悲观可以表现为使用增长但价值捕获恶化，不必等同于使用量下降；突破可来自能力跃迁、成本下降或新任务形成，需要说明额外条件。客户节省成本、平台保留利润和资产回收分别判断。

对决定结论的重要事件或情景，适当给出实现概率或概率区间，明确对象、成功标准、目标时期、依据和主要未知，以及会使判断上调或下调的新证据。每个概率注明是无条件事件概率、给定哪些条件的成功概率，还是整条路径的权重；相关事件不能直接按独立事件相乘。仅互斥且覆盖完整的情景权重合计为100%。突破可以是某条路径的子分支，也可以跨越多条路径，须按经济机制说明；若为子分支，明确P(突破|母情景)或P(突破)，无条件子事件概率不超过母情景概率，换算时保留条件。事件发生、规模渗透和利润兑现分别界定，“至少一个案例成功”不能代替行业规模判断。概率精度与证据相称，交代支持该范围的可比经验或主观判断理由；证据不足可用宽区间或定性，不为每个变量填百分比，也不将代表情景点当作置信区间或概率分布。

预测区间注明是参数条件范围、情景范围还是有统计依据的置信区间，说明主要上下界由什么约束，不能仅为简洁而收窄。

## 五、报告交付

用中文输出自洽研究，一级标题为“全球AI需求与Token经济框架”，正文记录研究截止日期和主要数据日期。前部简洁说明 AI 需求能否支撑研究期的基础设施扩张、需求增长主要来自哪里、当前运行速率与近期变化、最关键的反证与未解决问题。

核心交付物有两项：主要需求场景的使用量与付费规模表（场景×年份×情景，注明单位、付费主体、关键参数和重叠项），以及从需求到收入、现金、基础设施投入和回收的桥。其余表格、公式和章节按解释需要组织，参数底表可以放在同一报告附录。重要来源注明支持的数字或判断、日期以及一手或二手性质。

交付前检查：付费与使用是否去重；不同单位的工作量是否被直接相加；回收期是否用现金而非收入覆盖率；效率和降价的影响是否同时考虑了扩张与压缩两种可能。

允许超出上述问题寻找更重要的需求机制和反共识洞见，说明其经济影响与可证伪方式。
