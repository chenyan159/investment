# AI token使用供需前线跟踪：2026-07-02

报告日期：2026-07-02，美国太平洋时间。  
资料窗口：重点覆盖 2026-06-02 至 2026-07-02 的公开消息、公司披露、媒体/渠道线索；同时使用项目内 2026-06-10/11 的 `全球AI需求与Token经济框架`、`AI-native存储与KV Cache基础设施`、`AI集群调度与推理运行时` 作为底层口径。  
口径说明：本文的 token 指大模型输入、输出、cached context、长上下文、reasoning、tool call 和 agent 中间状态等可计量模型使用量，不指加密货币 token。`1P token = 10^15 tokens`。

## 0. 结论摘要

1. **目前最大、最可验证的 token 使用场景是 API / 开发者平台和模型即服务，不是普通聊天。** OpenAI 披露 API 超过 `15B tokens/min`，Google 披露 Gemini direct API 超过 `16B tokens/min`，两者合计约 `44.6T tokens/day`、`16.3P tokens/year`。在全球总量估算里，API/开发者平台当前年化 run-rate 约 `18-32P`，仍是最硬锚点。
2. **最大边际增量和最大成本痛点是 coding agent / agentic workflow。** GitHub 6 月 1 日开始把 Copilot premium usage 改成基于 input/output/cached tokens 的 AI Credits；Gartner 6 月 24 日警告 AI coding token 成本会冲击企业预算；TechCrunch、UBS 和 OpenClaw 案例都指向同一个事实：agent 让 token 消耗从“人问一句”变成“系统连续工作数小时”。
3. **全网当前推理 token 年化 run-rate：基准 `55-85P tokens/year`，保守 `45-55P`，激进 `85-130P`。** 这比项目 6 月 11 日基准 `45-70P` 略向上修，但没有上修到极度乐观，因为企业端已经开始设预算闸门，说明 token 需求很强但价格弹性也很强。
4. **供需关系是“高端推理算力紧平衡 + 低价值 token 价格下行”。** AWS EC2 Capacity Blocks 7 月 1 日价格更新、CoreWeave `99.4B` 美元 backlog、Oracle `638B` 美元 RPO 和 `75B` 美元客户预付/自供 GPU 都说明高端 capacity 仍有定价权；但 UBS/TechCrunch 的企业节流信号说明低 ROI token 会被砍掉或迁移到更便宜模型。
5. **过去半年最大的变化：从“谁能拿到 GPU”变成“谁能把 token 变成 ROI”。** 2026 年初供给侧主线是 H100/H200/Blackwell allocation、云 GPU 价格、长约和电力；到 6 月以后，主线变成用量计费、预算控制、token observability、KV cache、长上下文成本、agent 成功率和模型路由。
6. **投资映射：最强方向不是泛 AI 应用，而是 token 效率栈。** 直接受益层包括推理 runtime、KV cache / memory tiering、HBM/DRAM/enterprise SSD、cost observability、budget control、模型路由和高价值 vertical agent；受压层是低效率 GPU 租赁、固定低价无限量 seat、无差异模型 API 和没有工作流闭环的 AI 插件。

## 2. 当前最大使用场景是什么

### 2.1 按“可验证 token 量”排序

| 场景 | 当前年化 token run-rate 判断 | 可靠性 | 判断 |
|---|---:|---|---|
| API / 开发者平台 / 模型即服务 | `18-32P` | 高到中 | 最大硬锚点。OpenAI + Google direct API 已披露 `16.3P/year`，再加 Anthropic、AWS Bedrock、Mistral、Cohere、xAI、企业私有调用和 batch API 后，API 仍是最可验证大头 |
| 消费聊天和 AI search | `10-22P` | 中 | 用户数最大，但单次 token 较短、免费/订阅混合，真实 token 和收入不完全披露 |
| 企业办公、RAG、流程 agent | `7-16P` | 中 | Microsoft 20M+ Copilot paid seats、WorkIQ 17EB 数据上下文说明潜力大，但活跃率和 token/seat 不透明 |
| Coding agent / 开发者 agent | `6-15P` | 中 | 还不是总量最大，但增速最快、成本冲击最大；OpenClaw 的 100-agent 样本证明重度使用可把小团队变成 TB/day 级 token 消费者 |
| 内部广告、推荐、客服、批量推理 | `10-25P` | 低到中 | Google/Meta/Amazon 内部 AI 量可能很大，但未统一披露 token；只能作为全网估算加项 |
| 多模态、视频、语音 | `2-8P` 文本等价 | 低 | GPU 秒和媒体 token 很重，但各平台计量口径不统一 |

**结论：** 如果只看公开可审计、可付费的 token，最大场景是 API / 开发者平台；如果把 Google/Meta/Amazon 内部广告、搜索、推荐和 consumer AI 都纳入，消费/搜索/internal AI 可能与 API 接近，但不可验证性更高。真正改变供需斜率的是 coding agent 和企业 agent，因为它们把上下文、工具调用、检索、代码执行和中间推理都变成持续 token 消耗。

### 2.2 为什么 coding agent 是“边际最大变量”

OpenClaw 样本给出一个粗略压力测试：

```text
603B tokens / 7.6M requests = 79.3k tokens/request
603B tokens / 100 agents = 6.03B tokens/agent/month
603B tokens / 30 days = 20.1B tokens/day
```

这不是普通企业平均值，而是极端、预算不受限的实验；但它解释了为什么 GitHub、OpenAI、Anthropic、Cursor 类工具都在从固定 seat 走向 usage-based / credits / budget caps。一个成熟团队如果把 agent 放进 PR review、issue triage、测试生成、代码修复和文档更新流水线，token 消耗的上限不是“工程师一天问多少次”，而是“agent 可以并行跑多久”。

## 3. 全网 token 使用量估算

### 3.1 硬披露锚点

| 平台 | 披露 | 换算 |
|---|---:|---:|
| OpenAI API | `15B+ tokens/min` | `21.6T/day`，`7.9P/year` |
| Google Gemini direct API | `16B+ tokens/min` | `23.0T/day`，`8.4P/year` |
| 两者合计 | `31B+ tokens/min` | `44.6T/day`，`16.3P/year` |

这只是 direct API，不包括 ChatGPT/Gemini App、Microsoft Copilot、Meta AI、Anthropic、AWS Bedrock、企业私有部署、内部广告/推荐、coding agent、batch inference 和多模态。

### 3.2 当前 run-rate 三情景

| 情景 | 年化 tokens/year | tokens/day | 主要假设 |
|---|---:|---:|---|
| 保守 | `45-55P` | `123-151T/day` | OpenAI + Google API 为 16.3P，其它平台和内部/消费端约 1.8-2.4 倍；企业节流明显 |
| 基准 | `55-85P` | `151-233T/day` | API 继续增长，consumer/search 维持高频，coding/enterprise agent 已经放量但被预算控制 |
| 激进 | `85-130P` | `233-356T/day` | Anthropic/AWS/Microsoft/Meta/internal/batch token 明显高于公开可见；agent 使用尚未被预算强限制 |

与项目 2026-06-11 旧基准 `45-70P/year` 相比，本文把当前年化 run-rate 调整到 `55-85P/year`。上修理由是 6 月以后 coding agent 和 enterprise agent 的消费强度证据更多；没有大幅上修的理由是 UBS/TechCrunch/Gartner 同时显示企业正在节流，说明高用量不是无价格弹性。

## 4. 当前供需关系

### 4.1 需求端：不是没有需求，而是开始分层

| 需求层 | 当前状态 | 价格敏感度 | 真实度 |
|---|---|---:|---|
| OpenAI / Google / Anthropic / AWS API | 高速增长，硬披露强 | 中 | 高 |
| Coding agent | 增速最快，成本最难预测 | 高 | 中高 |
| Microsoft/GitHub/Salesforce/ServiceNow enterprise workflow | 付费 seat 和 credits 真实，但 active usage 不完全披露 | 中高 | 中高 |
| Consumer chat/search | 规模大，单 token 变现弱 | 高 | 中 |
| 内部广告/推荐/search AI | 流量巨大但归因不透明 | 低到中 | 中 |
| 主权 AI / 私有 AI 工厂 | 合同真实，但利用率需验证 | 中 | 中 |

需求端的关键变化是：企业没有停止使用 AI，而是从“越多越好”切换到“token 要有预算、归因和 ROI”。这对总量不是立即利空，反而说明 token 已经进入运营成本科目；但低价值问答、重复上下文、无缓存 agent 和固定价无限量 seat 会被压缩。

### 4.2 供给端：高端 capacity 仍偏紧

硬信号：

- AWS Capacity Blocks 7 月 1 日价格更新，并明确价格会基于 supply/demand 周期调整。
- CoreWeave Q1 backlog `99.4B`、active power `1GW+`、contracted power `3.5GW+`，且推出 Dedicated Inference / Flexible Capacity。
- Oracle RPO `638B`，大规模 AI 合同里客户预付或自供 GPU 合计 `75B`，说明客户愿意参与融资和硬件锁定。
- Amazon Q1 现金流披露显示 TTM PPE purchases 净增加 `59.3B`，主要反映 AI 投资；AWS revenue `37.6B`，chips business run-rate `20B+`。

软信号：

- Anthropic 5 月提高 Claude Code/API limits，并列出 SpaceX、AWS、Google/Broadcom、Microsoft/NVIDIA、Fluidstack 等 compute/capacity 安排，说明限制来自 capacity 而不是需求不足。
- Meta Compute 计划若落地，说明部分 hyperscaler 会把自建能力商业化，但 TechCrunch 同时指出 Meta 自己的 AI 服务收入不透明，这更像 CapEx 回收压力，不是全行业供给过剩。

**当前判断：** 高端 Blackwell/H200/H100/TPU/Trainium/GB200 级 capacity 仍是卖方市场；普通低端 GPU、通用 token、开源小模型和非差异化租赁会更接近买方市场。

## 5. 过去半年供需关系的变化

| 阶段 | 需求端变化 | 供给端变化 | 供需结论 |
|---|---|---|---|
| 2026-01 至 2026-03 | Google direct API 从 `7B/min` 到 `10B/min` 再到 Q1 `16B/min` 的趋势开始显现；OpenAI 披露 API `15B/min`、Codex 快速增长 | AWS GPU reservation 年初已有涨价信号；Blackwell/H200 allocation 仍紧；CapEx 继续上修 | 典型供给紧缺阶段，平台用限额和补贴吸收需求 |
| 2026-04 至 2026-05 | GitHub 宣布 6 月 1 日转 AI Credits；OpenAI/Anthropic/Codex/Claude Code 的 agent 使用强度成为主线 | Anthropic 宣布更多 compute deals 和 limits 提升；CoreWeave/Oracle/Amazon 披露大规模 backlog/CapEx | 供给在扩，但 usage 也在更快扩；固定价模式开始失效 |
| 2026-06 至 2026-07 | 企业预算约束和 token discipline 出现；Gartner、UBS、TechCrunch 均指向 coding/agent 成本失控 | AWS 7 月 1 日 Capacity Blocks 价格更新；Meta Compute 传闻显示 hyperscaler 尝试变现自建 capacity | 进入结构性紧平衡：高价值 token 继续扩张，低 ROI token 被砍，供给端分化 |

半年前市场更像“算力供给不够，需求只要拿到卡就会来”；现在更像“高端算力仍不够，但需求必须证明能把 token 变成收入、效率或可付费 workflow”。这会让 token 使用量继续增长，但增长质量从 DAU/WAU 转向 `tokens/GPU-hour`、`cost/task`、`agent success rate`、`cache hit rate` 和 `gross margin/token`。

## 6. 供给端和消费端的最前线判断

### 6.1 供给端前线

1. **GPU/ASIC 不是唯一瓶颈。** 长上下文和 agent 把瓶颈从 GPU compute 扩展到 HBM、DRAM、KV cache、enterprise SSD、CXL、网络、调度、数据中心电力。
2. **reserved capacity 有定价权。** AWS Capacity Blocks、CoreWeave Dedicated Inference、Oracle 客户预付/自供硬件都说明客户愿意为确定性付费。
3. **token 价格下降不等于物理供给宽松。** 模型蒸馏、MoE、batching、cached tokens、Search as Code 等能降低单位 token 成本，但高价值 agent 会把省下来的成本继续花掉。
4. **hyperscaler 自建可能挤压 NeoCloud。** Meta Compute 类计划若变多，CoreWeave/Nebius 这类 NeoCloud 的估值逻辑会从“有卡就稀缺”转向“合同质量、利用率、利息和客户集中”。

### 6.2 消费端前线

1. **普通聊天仍大，但不是投资上最强增量。** 聊天的 tokens/request 和付费意愿有限，更多是分发入口。
2. **coding agent 是 token 强度最高的已商业化场景。** 它天然有长上下文、repo index、多轮工具调用、测试/日志/CI 输出和反复修改；因此最快从固定订阅转向 usage credits。
3. **企业 agent 需要数据上下文，token 使用和数据层绑定。** Microsoft WorkIQ `17EB+` 数据上下文、Copilot paid seats、GitHub credits 都说明企业 AI 的真正成本不是一句 prompt，而是组织数据、权限、检索、缓存和工作流状态。
4. **AI search / research agent 会成为大 token 场景，但会被架构优化压低单位消耗。** Perplexity 的 Search as Code 是典型方向：更多操作在代码/检索层完成，少把中间状态塞进模型上下文。
5. **视频/多模态是算力强而 token 口径弱。** 如果按文本 token 计可能不大；如果按 GPU 秒和生成资产计，供给压力很大。投资上更应映射到 GPU/HBM/存储/电力，而不是只看 text token。

## 7. 投资含义和后续跟踪

### 7.1 最值得跟踪的方向

| 方向 | 为什么 |
|---|---|
| 推理 runtime / 调度 / cost observability | 企业节流后，能证明 `cost/task` 降低的软件更有预算 |
| KV cache / memory tiering / CXL / enterprise SSD | agent 和长上下文把 KV cache 变成热路径，不再只是存储附属 |
| 高带宽内存和先进封装 | 高价值 token 仍吃 HBM、CoWoS/SoIC、HBM4/3E 供应 |
| AI credits / usage billing / budget control | 从 GitHub 到企业 IT，token 管控会成为标准功能 |
| 模型路由和低成本模型迁移 | UBS 提到开源/中国模型可能受益，企业会把低价值任务迁到便宜模型 |
| Dedicated inference / reserved capacity | 供给紧时，确定性 capacity 比 spot 便宜与否更重要 |

### 7.2 需要警惕的反证

| 反证 | 阈值 |
|---|---|
| 主要平台不再披露 tokens/min 或 QoQ 增长低于 `20-30%` | 说明 token 增长从高速转入常态 |
| AWS/GCP/Azure 高端 GPU reserved 价格连续两个季度下调 | 说明供给端从紧平衡转过剩 |
| CoreWeave/Oracle 类 backlog 延期、取消或客户预付下降 | AI 工厂需求质量变差 |
| 企业 AI tools 数量减少且 paid usage 不回升 | token spend optimization 变成实际需求收缩 |
| coding agent 的 `cost/merged PR` 或 `cost/resolved issue` 无法下降 | coding token 需求从高增长回落 |
| cache hit rate、context reuse、batch utilization 停滞 | token 成本无法继续下行，价格战伤毛利 |
