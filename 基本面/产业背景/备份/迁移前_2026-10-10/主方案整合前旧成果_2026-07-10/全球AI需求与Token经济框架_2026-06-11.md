# 全球AI需求与Token经济框架

报告日期：2026-06-11

主要数据日期：2026-03-31 至 2026-06-10；少数技术论文和产品定价采用截至公开页面可访问时的最新版本。

估值/股价快照日期：本报告不做单股估值；上市公司财务、CapEx、RPO 和业务快照使用 2026-04-29、2026-05-07、2026-06-10 附近披露。

核心结论摘要：

- **结论 1：AI 基础设施扩张有真实需求锚点，但 2026 年仍不是“收入自然覆盖 CapEx”的阶段。** OpenAI 披露 2026-03-31 月收入约 20 亿美元、API 处理超过 150 亿 tokens/min，Google 披露 Gemini API 客户直接调用超过 160 亿 tokens/min，Microsoft 披露 AI 业务 ARR 超过 370 亿美元。这些是需求侧硬锚点。问题在于 Microsoft、Alphabet、Amazon、Meta 2026 年合计 CapEx 指引已接近 6,950-7,250 亿美元，若按 65%-85% 归因于 AI 和云 AI，仍明显高于同年可识别 AI 毛利。
- **结论 2：2026-2028 的核心变量不是“有没有 AI 需求”，而是 token 增长能否从聊天/API 扩展到 agent、代码、企业流程和多模态，并把利用率维持在商业化水平。** 本报告基准情景估计全球在线/批量推理 token 需求从 2026 年 45-70P tokens/year 增至 2028 年 230-420P；乐观情景为 2028 年 500-900P；极度乐观情景为 2028 年 1,000-1,800P。P token = 10^15 tokens。
- **结论 3：训练继续决定峰值网络、HBM 和集群工程，推理开始决定长期现金流、利用率和电力效率。** 训练拉动最高端 GPU/ASIC、HBM、先进封装、scale-out 网络和并行文件系统；推理拉动长上下文 KV cache、内存容量、SSD/对象存储、推理调度、低延迟网络、机柜功率密度和电力成本。
- **结论 4：token 价格下降不是简单利空。** 对 OpenAI、Anthropic、Google、GitHub Copilot 这类使用量直接计费或用 usage credits 约束用量的服务，价格下降会扩大场景；对纯 GPU 租赁、低差异化 NeoCloud 和低利用率机房，价格下降会直接压缩回收期。赢家是能把单位 token 成本下降快于价格下降、并把需求转成更高频 workflow 的平台。
- **结论 5：最危险的“伪需求”不是消费聊天，而是没有明确 token 使用和现金流闭环的提前 CapEx。** 主权 AI、战略模型训练、客户预付款 AI 工厂和 GPU 租赁合同都可能是真需求，也可能是把 2027-2029 的需求前置到 2026 的资产建设。反证指标是 GPU 租赁价格下跌、RPO 取消或延期、云 AI 毛利率继续下滑、企业 AI seat 活跃率不足、agent 成功率低且任务步数无法货币化。

## 一、结论先行：AI 需求是否足以支撑 2026-2028 基础设施扩张

### 1.1 需求侧已经有三个可复核锚点

| 锚点 | 最新可见数字 | 日期 | 解释 | 置信度 |
|---|---:|---:|---|---|
| OpenAI 商业化 | 月收入约 `$2B`，ChatGPT 900M+ WAU，50M+ subscribers，API 超过 15B tokens/min，企业收入占比 40%+ | 2026-03-31 | 直接说明 consumer、enterprise、API 三条需求同时放量 | 高 |
| Google Gemini API | direct API use by customers 超过 16B tokens/min，较上季增长 60% | 2026-Q1 | 单一平台客户 API 年化约 8.4P tokens，是全球 token 估算下限锚点 | 高 |
| Microsoft AI business | AI business ARR 超过 `$37B`，同比 +123%；M365 Copilot paid seats 超过 20M | 2026-Q3 FY | 说明企业 AI 已进入付费 seat 和 Azure consumption，非纯试用 | 高 |

```text
OpenAI API 15B tokens/min
= 21.6T tokens/day
= 7.9P tokens/year
```

```text
Google Gemini API 16B tokens/min
= 23.0T tokens/day
= 8.4P tokens/year
```

仅 OpenAI API 与 Google Gemini API 已披露部分合计约 16.3P tokens/year。考虑 ChatGPT 消费端、Microsoft Copilot、Anthropic Claude、AWS Bedrock、Meta 内部广告/推荐/助手、企业私有部署、代码 agent、多模态与批量推理，本报告把 2026 年全球推理 token 需求基准区间设为 45-70P tokens/year，约为两个披露 API 锚点的 2.8-4.3 倍。

### 1.3 最核心的判断

AI 基础设施建设由四类真实需求支撑：

1. **已经货币化的 API 和 AI seat**：OpenAI、Microsoft Copilot、GitHub Copilot、Salesforce Agentforce、ServiceNow、Adobe、Datadog 等。
2. **云 AI 和 GPU/ASIC capacity contract**：Azure、Google Cloud、AWS、Oracle、CoreWeave 等，体现在 AI ARR、Cloud backlog、RPO、prepayment 和 signed capacity。
3. **内部 AI 对原有业务的增收或降本**：Meta 广告、Google Search/Ads、Amazon shopping/Rufus/Connect、Microsoft security/coding/office。
4. **战略性训练和主权 AI**：短期不一定有 token 收入，但出于模型主权、国家安全、平台竞争和客户锁定而前置建设。

当前叙事风险主要在两处：

- **把 CapEx 当需求本身**：GPU 订单、数据中心开工和电力接入只能证明供给扩建，不能证明最终 token 付费。
- **把用户数当 token 现金流**：WAU、MAU、下载量需要转换为请求频次、上下文长度、输出长度、agent 步数、价格和毛利，才是可复核需求。

## 二、研究口径、资料边界和估算方法

### 2.1 资料边界

本报告按独立产业背景研究处理，不读取、引用或继承本地旧报告、索引、缓存或中间结论。事实、数字、公司映射和判断来自公开外部资料；本地文件系统只用于写入最终 Markdown。

### 2.2 单位和定义

| 单位 | 定义 |
|---|---|
| P token | 10^15 tokens，即 1 quadrillion tokens |
| H100e | H100/H200/MI300/B200/TPU/Trainium 等不同加速器折成 2025-2026 主流 H100 级推理算力等价，供跨代比较 |
| B200e | 以 B200/DGX B200 级 FP4/FP8 推理吞吐折算的高端 Blackwell 等价 |
| AI 收入 | AI API、AI SaaS seat、GPU/AI cloud、模型服务、AI 相关云实例和可归因广告/应用增量收入，不含 NVIDIA/AMD 等硬件供应商销售额 |
| AI CapEx | GPU/ASIC、服务器、网络、存储、数据中心、电力、冷却和 finance lease 中可归因于 AI 的基础设施投资 |
| token 成本 | GPU/ASIC 折旧、电力、网络、存储、运维、调度软件和模型服务成本，不含大部分研发和销售费用 |

### 2.3 估算主公式

```text
场景 token 需求(year, scenario)
= 活跃用户数 × 使用频次 × 每次输入 token × 输出/输入倍数 × 模型调用链长度
```

```text
推理 GPU/ASIC 需求
= token volume × FLOPs/token ÷ 有效利用率 ÷ 单 GPU/ASIC 年有效 FLOPs
```

```text
推理收入
= input tokens × input price + output tokens × output price
+ subscription / seat / workflow fee 的 token 等价收入
```

```text
推理毛利
= 推理收入 - GPU/ASIC 折旧 - 电力 - 网络/存储 - 运维 - 模型服务软件成本
```

```text
AI CapEx 回收期
= AI 基础设施 CapEx ÷ 年化 AI 毛利或可归因现金流
```

```text
训练需求
= 模型训练 run 数 × 每次训练 FLOPs × 后训练/实验倍数
```

### 2.4 推理算力换算参数

| 参数 | 基准取值 | 乐观取值 | 极度乐观取值 | 说明 |
|---|---:|---:|---:|---|
| 平均 FLOPs/token | `80-180 GFLOPs/token` | `120-260 GFLOPs/token` | `180-420 GFLOPs/token` | 小模型降本向下，reasoning、agent、多模态向上 |
| 有效利用率 | `12-22%` | `18-30%` | `25-38%` | 含 batch、prefill/decode、显存、网络、可用性、碎片化 |
| 输入/输出 token 比 | `55/45 到 70/30` | `50/50 到 65/35` | `45/55 到 60/40` | agent 和代码任务提高输出、工具调用和中间 token |
| 长上下文 token 占比 | `8-15%` | `15-25%` | `25-40%` | 长上下文主要拉动 KV cache、HBM、SSD 和延迟 |
| token 年降价 | `25-45%` | `15-35%` | `0-25%` | 高价值 workflow 可维持价格，通用聊天降价更快 |

### 2.5 置信度规则

| 置信度 | 含义 |
|---|---|
| 高 | 公司一手披露、监管文件、官方定价页、技术论文直接数字 |
| 中 | 公司一手披露加本报告换算，或多来源一致但非完整披露 |
| 低 | 非正式线索、第三方估算、客户案例外推、缺少完整口径 |

## 四、Token 经济模型：数量、价格、成本、毛利和降价路径

### 4.1 Token 价格和成本表

| 模型/服务类型 | 输入价格 | 输出价格 | 成本区间 | 毛利率区间 | 降价速度 | 主要证据日期 |
|---|---:|---:|---:|---:|---:|---|
| Frontier API | `$2.5-15/M tokens` | `$15-90/M tokens` | `$1.0-8.0/M tokens` | `35-70%` | `15-35%/year` | OpenAI/Anthropic pricing, 2026 |
| Mainstream API | `$0.3-3/M tokens` | `$1.5-15/M tokens` | `$0.15-2.0/M tokens` | `40-75%` | `25-45%/year` | Anthropic Sonnet、Gemini、OpenAI mini |
| Cheap/mini API | `$0.05-0.5/M tokens` | `$0.2-2.5/M tokens` | `$0.02-0.4/M tokens` | `30-70%` | `35-60%/year` | Gemini Flash/Lite、OpenAI nano/mini |
| Cached long-context | `normal price 的 5-25%` | 输出正常计价 | `$0.02-0.8/M cached tokens` | `50-85%` | `20-50%/year` | OpenAI/Anthropic/Google cache pricing |
| Batch inference | normal price 折扣约 50% | normal price 折扣约 50% | 低于在线推理 `20-60%` | `35-75%` | `25-50%/year` | OpenAI Batch、Anthropic batch |
| 企业 AI seat | `$18-30/user/month` 起，enterprise 可更高 | token 等价取决于使用强度 | `$5-25/user/month` | `30-70%` | seat 价格较稳，单位 token 成本下降 | Microsoft Copilot pricing and seats |
| Coding agent seat/credits | `$10-100/user/month` 个人；enterprise `$19-39/user/month` 基础价加 usage | token/credits 等价 | 高波动，重度 agent 用户可能超订阅价 | `0-60%` | 由请求制转 token 制 | GitHub Copilot 2026 usage billing |
| Agentforce conversation/action | `$2/conversation` 或 Flex Credits/action | 非 token 直接计价 | 取决于 steps/task 和模型路由 | `30-75%` | outcome/action 价格更稳 | Salesforce Agentforce |
| 视频/多模态 credits | `$0.01-1+ / asset or credit` | 非纯文本 token | GPU 秒、存储、版权成本高 | `10-60%` | 取决于分辨率和延迟 | OpenAI、Google、Adobe、Runway 公开价格与产品页 |

成本区间为本报告估算，不是公司披露。核心假设如下：

```text
单位 token 折旧成本
= 单机/集群 all-in CapEx ÷ 折旧年限 ÷ 年有效 token capacity
```

```text
年有效 token capacity
= 峰值 FLOPs/sec × 秒/年 × 有效利用率 ÷ FLOPs/token
```

以 2026 高端推理服务器为例：

| 参数 | 保守 | 基准 | 乐观 |
|---|---:|---:|---:|
| all-in accelerator + server + network + DC capex / H100e | `$120k-250k` | `$80k-180k` | `$60k-140k` |
| 折旧年限 | `3 年` | `4 年` | `5 年` |
| 有效利用率 | `10-15%` | `15-25%` | `25-40%` |
| 平均 FLOPs/token | `200-400G` | `80-200G` | `40-120G` |
| 折旧成本 | `$0.7-4.0/M tokens` | `$0.15-1.2/M tokens` | `$0.03-0.4/M tokens` |
| 加电力、网络、存储、运维后 | `$1.0-6.0/M tokens` | `$0.25-1.8/M tokens` | `$0.06-0.7/M tokens` |

### 4.2 为什么价格会下降但收入仍可能增长

```text
AI 收入增长率
≈ token volume 增长率 + mix/usage 增长率 - price/token 降价率
```

若 2026-2028 token volume CAGR 为 `120-220%`，而 blended price/token 每年下降 `25-45%`，则收入仍可保持 `60-130%` 年增长。反之，如果 token volume 增长降至 `40-60%`，而价格仍下降 `40-60%`，收入会快速失速，CapEx 回收期会拉长。

### 4.3 Token 等价收入框架

企业 seat 不直接按 token 收费，但可以转成 token 等价：

```text
企业 seat token 等价价格
= 月费 ÷ 月 token 使用量
```

示例：

| 月费 | 月使用量 | 等价收入 |
|---:|---:|---:|
| `$30/seat/month` | `10M tokens/month` | `$3/M tokens` |
| `$30/seat/month` | `50M tokens/month` | `$0.6/M tokens` |
| `$30/seat/month` | `150M tokens/month` | `$0.2/M tokens` |

这说明 enterprise AI 的风险不是 seat 价低，而是重度 agent 使用会把固定 seat 转成低价 token 包。GitHub Copilot 转向 usage-based billing，本质是把这个风险重新转嫁给高用量用户。

### 4.4 Token 价格下降的产业含义

| 情况 | 受益方 | 受压方 | 解释 |
|---|---|---|---|
| 价格降、成本更快降 | 平台、优化软件、ASIC、HBM、推理调度 | 低效云租赁 | 平台毛利率可稳，低效供给被淘汰 |
| 价格降、成本慢降 | 客户、应用层 | 模型 API、NeoCloud、GPU 租赁 | 收入增长被 volume 抵消不足 |
| 高价值 agent 维持价格 | SaaS、垂直 agent、workflow 平台 | 单次问答产品 | 价格从 token 转向 outcome |
| cached/long-context 成本下降 | RAG、代码、法律、金融、企业文档 | 低内存推理卡 | KV cache 和存储成为新瓶颈 |

```text
单位 token 资本强度

```

| 口径 | 2026 | 2027 | 2028 | 投资含义 |

### 5.4 长上下文和 KV cache 的非线性影响

长上下文不是简单增加 tokens。它会改变瓶颈：

| 变量 | 短上下文问答 | 长上下文/RAG/代码 | Agent memory |
|---|---:|---:|---:|
| prefill 计算 | 低到中 | 高 | 高 |
| decode 计算 | 中 | 中 | 高 |
| KV cache | 低 | 高 | 很高 |
| 显存/HBM | 中 | 高 | 很高 |
| SSD/对象存储 | 低 | 中高 | 高 |
| 调度复杂度 | 低 | 高 | 很高 |
| 收入弹性 | 低 | 中高 | 高，但需 ROI 证明 |

结论：如果 2027-2028 的增长来自 agent 和长上下文，HBM、DRAM、SSD、CXL、推理调度、对象存储、低延迟网络和电力效率的受益弹性会高于单纯 GPU 数量。

### 7.2 训练需求的估算链条

DeepSeek-V3 技术报告给出一个效率锚点：671B total parameters、37B activated per token、14.8T training tokens，全训练约 2.788M H800 GPU-hours。这个数字不能直接外推 frontier labs，因为闭源 frontier training 包含更大模型、多次 ablation、数据清洗、post-training、RL、safety、eval 和失败实验，但它给出一个下限：

```text
高效 MoE 大模型一次正式训练
≈ 2.8M H800 GPU-hours
```

本报告训练需求估算：

| 年份 | Frontier/大模型正式 run | 实验和后训练倍数 | 全球训练 GPU-hour | 主要约束 |
|---|---:|---:|---:|---|
| 2026 | `20-50` 次大 run 等价 | `5-15x` | `0.8-2.5B H100e-hours` | HBM、网络、数据、训练稳定性 |
| 2027 | `30-80` 次 | `6-20x` | `1.5-5B` | 主权 AI、合成数据、RL |
| 2028 | `40-120` 次 | `8-25x` | `3-10B` | scaling 回报和电力 |

### 7.3 推理需求的估算链条

推理公式：

```text
GPU-hours
= tokens × FLOPs/token ÷ accelerator_FLOPs/sec ÷ utilization ÷ 3600
```

示例，2026 基准中位：

```text
60P tokens/year × 140G FLOPs/token
= 8.4e27 FLOPs/year
```

若折算为 2 PFLOPs H100e peak、18% 有效利用率：

```text
8.4e27 ÷ 2e15 ÷ 0.18 ÷ 3600
= 6.5B H100e GPU-hours/year
= 0.74M H100e active-year
```

推理需求对产业链的关键不是单一 GPU 数量，而是持续利用率。训练集群可以接受高峰值和阶段性空闲，推理集群如果利用率不足，单位 token 成本会迅速恶化。

| 间接受益 | SaaS 数据连接器、权限治理、DLP、安全审计 | 企业 AI 落地需要，但不一定吃到 token 增长最大份额 |
| 伪受益风险 | 只有“AI-ready”标签、无客户合同的数据中心 | 如果无签约用电和租约，可能只是叙事 |
| 伪受益风险 | 低端 GPU 租赁和无差异 NeoCloud | 价格下降和 hyperscaler 自建会压缩空间 |
| 伪受益风险 | 没有 workflow 频次的 AI 软件插件 | seat 付费难持续，token 需求不足 |

### 9.3 如果 token 价格继续下跌，谁仍受益

| 仍受益 | 原因 |
|---|---|
| 自有分发平台 | 可以用低价 token 提升原有广告、订阅、云和软件收入 |
| 自研 ASIC/TPU/Trainium 平台 | 成本下降快，能保持毛利或抢份额 |
| HBM/高带宽内存 | 价格下降通常刺激更多 token 和更长上下文 |
| 推理优化软件 | 客户越关注成本，越需要 routing、cache、batching 和 observability |
| 高价值垂直 agent | 按 outcome 收费，不完全暴露于 token 单价 |

| 被压缩 | 原因 |
|---|---|
| 纯 GPU 租赁 | token/API 降价会传导到实例价格 |
| 固定低价无限量 seat | 重度用户 token 成本可能超过订阅收入 |
| 无效率模型 API | 同质化模型会被低价开源/小模型替代 |
| 低利用率数据中心 | 折旧和电力刚性，价格下跌时回收期恶化 |

## 十、反证条件、风险和后续跟踪清单

### 10.1 需求侧反证条件

| 反证条件 | 触发阈值 | 影响 |
|---|---:|---|
| API token 增长停滞 | OpenAI/Google/Anthropic 等 token/min 连续两个季度低于 `30% QoQ` 或不再披露 | 2027-2028 token CAGR 下修 |
| AI ARR 放缓 | Microsoft AI ARR、OpenAI revenue run-rate、Google Cloud AI 线索低于 `50% YoY` | 收入/CapEx 回收期拉长 |
| 企业 seat 活跃不足 | paid seats 增长但 token/seat 或 active seat 不升 | SaaS AI uplift 被证伪 |
| Agent ROI 不足 | steps/task 上升但 success rate、retention、paid conversion 低 | agent 需求从极度乐观回到基准 |
| Token 价格战过快 | frontier/mainstream API 每年降价 `>60%` 且毛利无改善 | 模型服务和 NeoCloud 毛利受压 |
| GPU 租赁价格下跌 | H100/H200/B200 spot 或 reserved 价格连续下跌，实例可用性宽松 | 供给过剩和利用率不足 |
| CapEx guide 下修 | hyperscaler 或 NeoCloud 下修 AI CapEx、延期数据中心 | 基础设施订单链回撤 |
| RPO/合同质量恶化 | RPO 增长但现金预付款减少、客户集中升高、交付延期 | AI 工厂需求可信度下降 |

### 10.2 风险

| 风险 | 方向 | 解释 |
|---|---|---|
| 模型效率超预期 | 对应用利好，对硬件强度利空 | 小模型、MoE、speculative decoding、distillation 降低 FLOPs/token |
| reasoning token 膨胀 | 对算力利好，对毛利不确定 | 高价值任务可付费，低价值任务会被限制 |
| 电力和并网瓶颈 | 对订单交付利空，对电力设备利好 | GPU 到货不等于可上电 |
| 内存/先进封装涨价 | 对供应链收入利好，对云厂回收期利空 | Microsoft 已披露组件涨价影响 CapEx |
| 客户集中 | 对 NeoCloud 风险高 | CoreWeave、Oracle 类合同可见性高但集中度和融资敏感 |
| 监管和版权 | 对多模态和数据训练利空 | 视频、音乐、出版、企业隐私会限制使用 |
| 开源模型降价 | 对应用利好，对闭源 API 和租赁利空 | 低成本模型压低通用 token 价格 |

### 附录 B：最小可复核模型模板

```text
输入：
1. 场景：consumer chat / coding / enterprise / agent / multimodal / batch
2. users or seats
3. requests per user per day
4. input tokens/request
5. output tokens/request
6. chain length or steps/task
7. model class and FLOPs/token
8. input/output price
9. effective utilization
10. accelerator peak FLOPs and all-in CapEx

输出：
1. tokens/day and tokens/year
2. revenue/year
3. GPU-hours/year
4. active GPU/ASIC equivalent
5. power MW/GW
6. depreciation cost/M token
7. gross margin
8. payback period
```

示例：

```text
enterprise coding agent
= 20M paid developers
× 8 active days/month
× 25 agent requests/day
× 40k total tokens/request including context, output and tool calls
= 160T tokens/month
= 1.9P tokens/year
```

若高频团队把 agent request 提升至 200/day、每次 100k tokens，则同一开发者基数可变成：

```text
20M × 12 active days/month × 200 × 100k
= 4.8P tokens/month
= 57.6P tokens/year
```

这就是 coding agent 的弹性来源，也是 usage-based billing 必然出现的原因。
