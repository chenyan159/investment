## 新闻口播稿

今天的 AI 产业链新闻，表面看没有一个单点爆炸式的新模型发布，但如果把过去 24 小时的高信号信息连起来，主线其实非常清楚：AI 正在从“会回答问题的模型”，变成三种更硬的产业能力。第一，是能参与真实攻防的安全能力；第二，是用先进制程、先进封装和供电冷却堆出来的算力能力；第三，是进入企业开发流程、财务预算和安全控制面的 agent 分发能力。更重要的是，今天也有一篇新的评测论文给整个行业泼了一盆冷水：短程任务和窄域自动化在加速，但真正能跨几个月理解世界变化、调整策略、持续预测未来的长程 agent，仍然非常弱。

先说今天最值得重视的一条：AI 安全已经不是理论讨论，而是开始进入实战作业流。Google Threat Intelligence Group 在最新 threat tracker 里说，威胁行为者使用生成式 AI 的方式，正在从早期的辅助写作、翻译、钓鱼文案，升级到漏洞发现、利用生成、恶意软件混淆、自主操作、供应链攻击和 agentic reconnaissance。这里最关键的新事实是，Google 说他们首次识别到一个威胁行为者使用了一个零日漏洞利用，并且有高度信心判断，这个零日的发现和武器化受到了 AI 模型支持。这个漏洞不是传统 fuzzing 最擅长抓的内存破坏，也不是简单的输入校验错误，而是一个 2FA bypass 类型的高层语义逻辑漏洞：代码里硬编码了一个信任假设，功能表面上看是对的，但安全策略上是破的。Google 的判断很重要，因为这说明前沿模型最危险的地方不只是会写 exploit boilerplate，而是会读懂开发者意图，发现传统扫描器不容易建模的“策略矛盾”。

更细的一层是，攻击方已经在把模型接进工作流。Google 观察到，与中国和朝鲜相关的一些威胁活动，对 AI 辅助漏洞研究很感兴趣；有行为者用“资深安全审计员”“C/C++ 二进制安全专家”这类 persona prompt 来引导模型；也有人把真实漏洞知识库接入 Claude Code skill 插件，用 2010 到 2016 年间 WooYun 平台 8.5 万多个真实漏洞案例做上下文，让模型像有经验的漏洞研究员一样审代码。另一个细节是，APT45 被观察到发送数千个重复 prompt，递归分析不同 CVE 并验证 PoC。这不是一个研究员偶尔问 ChatGPT 的故事，而是把模型当成规模化漏洞工厂的一部分。

Google 报告里还有一个更像未来威胁形态的案例：PROMPTSPY。它是一个 Android backdoor，把 Gemini API 接到恶意软件操作链里。公开报道最早说它用 Gemini 做持久化，例如把恶意应用固定在最近任务里；Google 进一步分析发现，它还有一个叫 GeminiAutomationAgent 的自主 agent 模块。这个模块会把手机屏幕上的 UI 层级序列化成类似 XML 的结构，通过 HTTP POST 发给 gemini-2.5-flash-lite，并要求模型返回结构化 JSON，里面包括 CLICK、SWIPE 这类动作类型和屏幕坐标。也就是说，恶意软件不只是藏在设备里等人远控，而是开始让模型理解屏幕状态、判断下一步该点哪里、该怎么滑、该怎么维持访问。这件事的行业含义非常大：安全防御不能再只盯恶意代码签名，还要盯“模型调用 + 状态感知 + 动作执行”这套运行模式。

这也解释了为什么 OpenAI Daybreak 值得放到同一条主线里看。Daybreak 不是一个普通安全产品页面，而是 OpenAI 对“模型能力会被攻防双方同时使用”的正式产业化回应。OpenAI 的表述是，AI 现在可以帮助防守者跨代码库推理、识别细微漏洞、验证修复、分析陌生系统，并更快从发现走到修复；但同样的能力也可能被滥用，所以要把扩展后的防守能力和信任、验证、比例化安全措施、问责机制捆在一起。Daybreak 的工作流包括 secure code review、threat modeling、patch validation、dependency risk analysis、detection 和 remediation guidance。这里的核心不是“AI 帮你找 bug”这么简单，而是把漏洞发现、补丁生成、测试验证、审计证据回传接进日常开发循环。

OpenAI 还把访问层级分成 GPT-5.5 default、GPT-5.5 with Trusted Access for Cyber、GPT-5.5-Cyber。默认模型用于通用开发和知识工作；Trusted Access 面向经过验证的防守工作，比如代码审计、漏洞 triage、恶意软件分析、检测工程和补丁验证；GPT-5.5-Cyber 则给授权红队、渗透测试、受控验证这类更敏感任务更多能力，但同时配更强的验证和账户级控制。这是一个明显的策略变化：前沿模型公司不再简单地说“我们拒绝网络攻击请求”，而是在设计一个有权限分层、有审计、有合作伙伴、有安全边界的 cyber capability distribution system。未来谁能用最强 cyber 模型，可能变得像谁能买最高端 AI 芯片一样，是一个受资格、合规、地缘和企业合同约束的问题。

再接上 Anthropic Mythos 的新增细节。昨天我们已经提过 Mythos 类网络安全模型会改变安全节奏，今天补充的是更具体的定量信息。TechRadar 的文章提到，Anthropic 在 2026 年 4 月 7 日发布 Claude Mythos Preview 后，影响已经超过安全圈；它能在主要操作系统和浏览器里自动发现大量 critical 和 high severity 漏洞，其中包括一个存在 27 年的 OpenBSD 漏洞。英国 AI Security Institute 的测试显示，Mythos 可以完成一个 32 步的模拟企业网络攻击，从侦察到完全接管，在人类专业人员那里大约需要 20 小时。这里必须加一句限制：这些测试是在实验环境里，没有主动防御、监控很少，也缺少真实防守工具；Firefox exploitation 测试还没有启用浏览器进程 sandbox。所以它不是说今天的模型已经可以横扫高防生产环境，而是说在受控环境里，AI 已经把漏洞研究和攻击链组合的时间压缩到让安全组织必须重新定义节奏。

最有启发的一句话是，安全正在变成经济学。AISI 在网络攻击模拟里给 Mythos 每次尝试 1 亿 tokens；10 次运行中，Mythos 完整完成 32 步攻击 3 次。文章提出的问题非常尖锐：攻击者投入更多 token，发现就更多；那防守方是不是也必须投入更多 token，才能在攻击者之前找到同一批漏洞？这其实把安全预算从“买工具、请顾问、做年度渗透测试”，推向“持续 token spend + 持续漏洞运营”。未来企业的关键指标不只是漏洞数量，而是 externally exposed vulnerabilities 的 mean time to remediate，也就是外部可触达漏洞从披露到真正修掉的时间。因为 AI 会加速 patch diffing：补丁一发布，模型就可以比较旧代码和新代码，反推出修了什么、哪里可利用。补丁本身会变成攻击线索。

今天的第二条大主线，是硬件和制造端。TSMC 的最新技术论坛资料，被 Reuters 报道后值得重新放进 AI 产业链主线。TSMC 现在预计，到 2030 年全球半导体市场会超过 1.5 万亿美元，这比之前的 1 万亿美元预测高出一大截；其中 AI 和高性能计算预计占 55%，智能手机占 20%，汽车占 10%。这意味着，TSMC 不再把 AI 当作一个高增长应用，而是在把 AI/HPC 当作未来半导体市场的主体结构。更具体的数字是，TSMC 说 2025 和 2026 年一直在更快扩产，并计划 2026 年建设九期晶圆厂和先进封装设施；最先进的 2nm 和下一代 A16 产能，2026 到 2028 年 CAGR 预计达到 70%；CoWoS 先进封装产能 2022 到 2027 年 CAGR 超过 80%；AI accelerator wafer demand 从 2022 到 2026 年预计增加 11 倍。

这些数字跟本轮 AI 芯片叙事完全对得上。现在真正的瓶颈不是“有没有模型需求”，而是 4/5nm AI GPU 和 ASIC 产能、3nm AI/HPC 和 HBM base die、2nm/GAA 新节点、CoWoS/SoIC/3DFabric 先进封装、HBM KGD、ABF 载板、TCB 和混合键合设备、测试老化、机械翘曲、热应力、液冷和供电这些环节能不能同步扩张。市场经常把 AI 芯片简化成 NVIDIA GPU，但 TSMC 的数据更像是在说：未来四年，AI 算力供应是一整套“工艺平台 + 封装平台 + HBM + 供电冷却 + 客户认证”的复合产能竞赛。

TSMC 这次还给了全球制造 footprint 的几个关键时间点。Arizona 第一座 fab 已经投产，第二座 fab 计划 2026 年下半年 tool move-in，第三座 fab 已在建设，第四座 fab 和当地第一座先进封装设施预计今年启动；日本第一座 fab 已经用 22nm 和 28nm 量产，第二座 fab 因强需求升级到 3nm；德国 fab 按计划建设，先提供 28nm 和 22nm，之后跟进 16nm 和 12nm。这些看起来像地理扩张，其实背后是 AI 供应链的政治经济学：先进逻辑和封装仍然高度集中，但客户和政府都在要求更分散、更可审计、更有韧性的供应。未来 AI 硬件竞争不是单纯的“谁的芯片快”，而是谁能拿到稳定的先进节点、先进封装、HBM、光互联、电力和机房上电节奏。

第三条主线，是编码 agent 的渠道战。Windows Central 引述 The Verge 的报道说，Microsoft 正计划减少内部对 Anthropic Claude Code 的使用，把员工推向 GitHub Copilot CLI。报道里最有意思的地方，不是说 Claude Code 不好，恰恰相反，Claude Code 在 Microsoft 员工里非常受欢迎。Microsoft 从去年 12 月开始给开发者、项目经理和设计师开放 Claude Code，用来直接在工作流里体验 AI coding assistant；过去六个月里 Claude Code 的内部受欢迎程度反而让公司开始收缩，因为它会削弱 Microsoft 自己的 GitHub Copilot CLI。报道称，Experiences + Devices division，也就是 Windows、Microsoft 365、Outlook、Teams、Surface 等团队，预计到 6 月底前停止使用 Claude Code，并在接下来几周切到 Copilot CLI。另一个现实因素是 Microsoft 财年在 6 月 30 日结束，取消 Claude Code licenses 可以削减运营成本。

这条新闻的产业含义很清楚：AI coding agent 的竞争不会只由模型智商决定。很多工程师可能觉得 Claude Code 好用，但企业最后采购和默认分发时，还要看 repo 权限、代码安全、审计、身份、预算、合规、遥测、IDE 集成、CI/CD 接入，以及平台方是否能把工具直接适配自己的工程流程。Microsoft 高管 Rajesh Jha 的解释也很典型：Copilot CLI 给了 Microsoft 一个能和 GitHub 直接塑形、适配自家 repo、workflow、安全预期和工程需求的产品。换句话说，Claude Code 可以在体验上赢用户，但 Microsoft 掌握 GitHub、VS Code、Azure、Entra、Microsoft 365 和企业合同，掌握的是默认入口和控制面。这也是为什么编码 agent 未来会像云服务一样，出现“最佳模型”和“默认平台”之间的张力。

这一点会反过来影响芯片和数据中心。编码 agent、security agent、office agent、customer service agent 一旦进入企业默认工作流，推理 token 需求会从聊天窗口变成后台常驻任务。每一次代码审查、每一次 patch validation、每一次 dependency risk analysis、每一次 repo-wide refactor，都要消耗推理算力、上下文缓存、存储读写和网络带宽。企业不一定会感知到自己在“买 GPU”，但云厂和模型公司会把这些 token 需求折算成数据中心、HBM、CoWoS、液冷、供电和网络订单。所以 Microsoft 推 Copilot CLI，不只是产品竞争，也是把开发者推理负载留在自家云和自家控制面里。

但今天也必须讲一个冷水：长程 agent 仍然很弱。FutureSim 这篇 2026 年 5 月 14 日提交的论文，题目是 Replaying World Events to Evaluate Adaptive Agents。它不是让 agent 做一个静态 benchmark，而是把真实世界事件按时间顺序回放，让 agent 在自己的原生 harness 里接收新闻、更新判断、预测 2026 年 1 月到 3 月之间的世界事件。这个设置更接近真实投资、真实战略和真实运营：世界不是一次性给定的题目，而是信息一点一点到来，问题会 resolution，策略要更新，记忆要保留，还要处理不确定性。结果并不好：最佳 agent 的准确率只有 25%，很多系统的 Brier skill score 甚至比“不做预测”还差。

这件事非常重要，因为它告诉我们，今天的 AI 产业是“两速世界”。一边，窄域作业正在快速自动化：模型能写代码、改代码、找漏洞、做安全 triage、读屏幕、生成动作、写补丁、分析依赖、帮助工程师完成短周期任务。另一边，真正的开放世界、长时间跨度、动态信息更新、策略修正和概率校准，仍然是巨大瓶颈。也就是说，AI 会先改变“作业流”，再改变“战略流”。投资和产业判断不能把这两件事混在一起。看到安全模型 20 小时完成模拟攻击，不等于自动 CEO 已经能规划三年；看到编码 agent 会改 repo，不等于它能跨一个季度管理产品路线图和客户需求变化。

今天最前瞻的叙事，可以总结成四句话。第一，AI 攻防进入 token 经济时代，安全预算会从人力和工具扩展到持续模型调用、持续漏洞发现和持续修复验证。第二，AI 硬件进入复合瓶颈时代，先进制程、CoWoS、HBM、ABF、测试、液冷、供电和上电节奏共同决定算力交付，不再是单一 GPU 问题。第三，编码 agent 进入平台分发时代，最强体验不一定赢企业默认入口，能控制 repo、身份、安全、合规和成本的生态会有更强议价权。第四，长程 agent 仍然没有过关，未来半年到一年，真正值得跟踪的不是谁又把 benchmark 刷高一点，而是谁能在真实、动态、长时间跨度环境里稳定更新信念、校准概率、调用工具并承担后果。

所以今天的关键词不是“一个新模型”，而是“作业流重构”。网络安全的作业流会被 AI 重构，先进封装和芯片产能的作业流会被 AI 需求重构，软件开发的作业流会被 coding agent 重构。但真正的未来智能，仍然卡在长程适应、世界模型、记忆、搜索、策略更新和不确定性推理上。这个差距，正是未来几年最重要的研究机会，也是最重要的投资分水岭。

## 创新性与前瞻性观点

1. **安全 token spend 可能成为新的攻防预算单位。** 如果攻击者通过更大 token 预算提高漏洞发现率，企业防守也必须用持续 AI 扫描、补丁验证和自动化证据链对冲，而不是一年一次渗透测试。
2. **最危险的模型能力不是“写 exploit”，而是识别语义逻辑矛盾。** Google 的 2FA bypass 案例表明，LLM 擅长读意图和上下文，可能补上传统静态分析/模糊测试的盲区。
3. **AI cyber 模型会走向访问分层和地缘控制。** OpenAI Daybreak 和 Anthropic Mythos/Glasswing 的共同信号是，高能力安全模型可能像高端芯片一样受资格、合同、政府合作和责任机制约束。
4. **CoWoS 是显性瓶颈，但真实瓶颈是复合系统。** 本地研究和 TSMC 新资料一致指向：HBM KGD、interposer、ABF、TCB/HB、测试老化、机械翘曲、热应力、液冷、供电、客户认证共同决定 AI accelerator 交付。
5. **编码 agent 正在从模型竞争变成企业控制面竞争。** Microsoft/Claude Code/Copilot CLI 的案例说明，企业内部 adoption 的决定因素会包括成本、财年、repo security、平台可塑性和默认入口。
6. **短程自动化强，不代表长程自主强。** FutureSim 的 25% 最佳准确率提醒：agent 能做任务，不等于能可靠地跨数月追踪世界、修正策略并做概率校准。
