## 9. 优先候选研究包

### 9.1 Amazon GW Ranch：5GW 私网改变的是供电机制

- **事实与时间线**：TCEQ 许可列 35 台简单循环燃机和 5,000MW 名义输出；8 月 8 日 Amazon 向 NYT 确认项目将供其数据中心。开发商的 7.65GW 与许可排放上限属于不同口径。
- **新增洞见**：超大规模客户把现场燃气从应急/桥接推进到可替代公共并网的主供电。项目可绕开排队，也把燃气管线、燃机交付、排放和地方许可变成算力交付的关键路径。
- **支持与边界**：监管文件支持设备和上限；Amazon 只向媒体确认客户身份/电价主张。没有 Amazon 公告、土地/租约、机组订单、建设许可汇总、实际负荷或容量因子。
- **验证问题**：三栋许可、首期 MW、燃机 OEM、燃气输送合同、冷却用水、排放控制、PPA/租约、诉讼与施工。
- **避免重复**：不复述 AI 用电总量和德州并网常识；只讲私网机制、许可物理量和客户状态跃迁。

### 9.2 Firebird：投运事实与三层扩张承诺

- **事实与时间线**：2025 年首次提出 Armenia AI cloud；2026 年 2 月称取得 41,000 颗追加 GPU 授权；8 月 8 日 Hrazdan 投运并具名 Perplexity。
- **新增洞见**：早期 sovereign AI 规划获得真实设施和客户锚点，同时复制到哈萨克斯坦。NVIDIA 拟投资提高生态支持，金额和条件未知。
- **三层口径**：当前投运设施；2027 年 Armenia 70,000+ GPU/300MW；2028 年全球 2GW。哈萨克斯坦 125MW 为场地/审批主张。
- **验证问题**：在线 GPU、MW、利用率、Perplexity 工作负载、NVIDIA/CoreWeave 投资、BIS 编号、当地电力与开工。
- **避免重复**：不把远期 GPU/MW 合计为现有容量，不展开 sovereign AI 宏观口号。

### 9.3 vLLM：陈旧状态与外部 peer 两类隔离

- **状态链**：async scheduler 丢弃 step 后留下 accepted=0；index -1 在 CPU 可合法读末尾、GPU 可能读邻接 allocation。NULL_BLOCK_ID 跳过 read/write，区别于只 clamp 到 slot 0。
- **资源链**：每个未连接 peer 占三只 ZMQ socket且无淘汰；约 340 peer 可达到默认 1,023 上限。草案同时加入 cap、handshake timeout 和 idle eviction。
- **证据边界**：两条均有代码与测试，仍为开放 PR。zero-accept 已量化到 75.9% 元素差；P2P 的未授权远程入口和稳定版范围待核。
- **判断变化**：8 月 8 日的多模态放大属于请求内容资源；今日把风险扩展到 runtime state 和分布式 session 控制面。
- **验证问题**：默认 flags、release、auth、公网/租户可达性、production trace、跨 GDN/KDA 模型与长时 soak。

### 9.4 SGLang：局部张量正确不代表全局语义正确

- **跨流所有权**：#34076/#34077 分别让已释放 tensor 被 decoy 重用、旧 owner tail 覆盖新 owner。需要显式 event/fence 和 generation ownership。
- **全局 head 语义**：DCP 复制 KV 后局部形状暗示 4:1，模型全局仍是 16:1；修复把 GSM8K 拉回普通 TP4 水平。
- **shape/stride**：单行 shard 被 is_contiguous 接受，stride(0) 仍是 CP pitch，低频命中越界。
- **位置状态**：EAGLE3 expanded rows B×K 与 mRoPE B 行失配，批量图像请求可击穿服务。
- **归约与测量**：固定 NCCL channels 消除一个模型的 KL；profiler 同步缺口把 stage 归因夸大 2—3 倍。
- **验证问题**：合并/stable、fence/clone 性能、其他 GQA/mRoPE 模型、多节点、剩余非确定 kernel 和公开 benchmark 勘误。
- **避免重复**：不重讲 8 月 8 日 sconv 缓存损坏；围绕 owner、global mapping、stride、rows 和 channels 五个新契约展开。

### 9.5 CUDA compiler 与 FlashInfer test discovery

- **编译器链**：CUDA 13.1—13.3 对混合 shared pointer 的 lowering 丢失全部 peer CTA 输出；错误槽位数量与拓扑完全对应。拆分 pointer path 是项目侧规避，NVIDIA 根修未知。
- **QA 链**：FlashInfer 五个 decorated 模块没进入 inventory，测试 template 从未注册，参数化 suite 静默 skip。guard 直接检查源模块与注册表的守恒。
- **新增洞见**：正确性门禁要验证 compiler 版本×拓扑和 test discovery 完整性。只跑现有 test list 无法发现“测试从未生成”。
- **验证问题**：NVIDIA compiler ticket、最小 PTX/SASS 差异、FlashInfer 历史漏测 failures、CI guard 合并和稳定镜像。
- **避免重复**：8 月 8 日 FlashInfer release 回滚/FP8 竞态只说明已知基线。

### 9.6 Agent 状态、审批与配置安全

- **OpenAI Agents**：replay-unsafe 显式批准保持 fail-closed；RunState 修复 acknowledged checks、guardrail final turn 和 legacy shell output；credential mount 需要 exact-path runtime acknowledgment。全部在 main，等待 release。
- **Google ADK**：配置 code reference 可把 PyYAML unsafe loader 暴露成工具，RCE marker 已复现；state_delta 在无 new_message resume 路径被忽略。两条均未合并。
- **机制**：durable agent 需要同时保护“恢复后仍在的审计事实”“危险重放的批准来源”“宿主凭据 mount 的授权范围”“配置能解析出的 callable 集合”。
- **验证问题**：schema migration、两次 round-trip、provider 语义、符号链接/TOCTOU、第三方包 callable 清单、CVE 与 stable release。
- **避免重复**：不重新展开一般 agent sandbox/approval 概念；只讲本次具体状态跃迁和未闭合边界。

### 9.7 训练与 serving 经济性

- **TensorRT-LLM**：每请求 1,206 个 bias 在大 vocab 下疑似 dense 化，p50 token time 约 19.3→35ms，吞吐近半。需把功能开关、batch、vocab、传输量和 GPU active 同时报。
- **OpenRLHF**：loss 有限值、样本数和 optimizer steps 三个守恒均可被默认/常见路径破坏。保存 checkpoint 成功无法证明发生训练。
- **vLLM dynamic K**：策略输出 K=0 却继续固定 K=2 draft，表面配置开启未改变计算。实际 drafted token 与吞吐决定收益。
- **SGLang profiler**：阶段时间归因修正后，优化瓶颈从 decoding 移回 denoising。
- **验证问题**：当前 stable、跨模型/规模、实际数据移动、修复前后成本、checkpoint 重算和公开 benchmark 勘误。

### 9.8 Goodfire 与 Marvell：前沿主张的可验证路径

- **Goodfire**：定价和实验额度已公开，成功实验质量、GPU 成本、客户采用和项目毛利仍由公司叙述。最值得追踪的是每个有效 discovery 的全成本和独立复现率。
- **Marvell**：32TB/16 hosts 提供明确系统形态；50% latency 与 6.6× TTFT 来自 emulation/simulation。最值得追踪的是实机跨 rack、功耗、故障域、coherence 和每 TB 成本。
- **Nous/Heron**：实现和机制有解释价值，缺客户/认证/benchmark。只作为状态层与电力架构背景。
- **避免重复**：不把作者或 CTO 的定量口径升级为行业事实；每项都保留原始场合、实验层级和缺失分母。
