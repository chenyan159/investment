# 每日AI产业链新闻｜2026-09-05

Anthropic 用 Claude 在十一天内完成费马大定理的端到端 Lean 形式化，并公开了可编译证明、逐步证明路线和多重核验材料。真正跨越的门槛是把数千页现代数学组织成三万多个可由内核逐项检查的定理，同时也暴露出算力成本、代码可读性、既有成果复用和人类语义审阅仍是规模化形式验证的关键约束。

## 新闻口播稿

今天是二零二六年九月五日。今天只选择一项内容，集中讲 Anthropic 在九月四日公开的费马大定理完整形式化，以及这项工作怎样把 AI 数学从生成一段看起来合理的证明，推进到交付一个可以独立编译、逐项追踪依赖并由证明内核验收的工程产物。

先把成果本身说清楚。费马大定理说，当整数指数大于二时，不存在三个正整数，使前两个数的对应次幂之和等于第三个数的对应次幂。Andrew Wiles 在上世纪九十年代完成了人类数学证明，Richard Taylor 随后与他共同修补了早期版本中的关键缺口。数学界对定理的正确性早已有极高信心。九月四日新增的成果，是把完整论证写进 Lean 四：最终仓库包含约一千三百万行 Lean 代码，过程中证明约三万零三百个定理，最终证明使用约两万九千五百个；几十个 Claude agent 协作十一天，消耗约六十亿个输出 token。

这组数字很大，含义却需要精确限定。Claude 没有找到费马大定理的新证明，也没有发现新的数学结果。它沿用的是 Darmon、Diamond 和 Taylor 在一九九五年整理的 Wiles—Taylor-Wiles 路线，并复用此前社区形式化项目中的一部分代码。公开归属清单列出一百零六个含 Imperial College London FLT 项目或 flt-regular 项目材料的文件，另有二十三个文件复现 Mathlib 文本。仓库其余大部分工作，是把散落在论文和数学传统里的定义、引理、约化与兼容层补成 Lean 能够完整接受的依赖链。因此，今天值得追踪的能力是大规模自动形式化，而非数学发现。

可以先用一条简化路线理解为什么这个任务如此庞大。假设费马方程存在反例，数学家先把问题约化到某个素数指数，再由反例构造一条很特殊的椭圆曲线，称为 Frey 曲线。接下来要证明这条曲线关联的伽罗瓦表示具有足够强的不可约性，同时又能从 Wiles 的模性工作推出它是模的。Ribet 的降层定理随后把这份表示压到很低的模形式层级，最终要求二级权二尖点形式空间里存在一个非零对象；那个空间实际为零，于是反例导致矛盾。

人类论文能够用名字调用 Mazur、Langlands—Tunnell、模性提升和 Ribet 降层等巨大结果，也会省略领域专家视为常识的转换。Lean 需要知道每个对象的类型、每条假设的来源和每次改写是否合法。仓库公开的证明路线把主链分为反例约化、Frey package、不可约性、模性、降层和最后的零空间六段，并明确记录每个著名定理在这里究竟证明到什么强度。它没有顺手证明这些理论最一般的版本，只证明费马大定理链条真正需要的那一段。这种范围控制，是把数千页文献变成可完成工程的必要条件。

形式化里的“证明通过”也要拆开理解。Lean 并不评价文字是否优美，也不会因为一个文件名叫“Wiles 定理”就相信它。证明代码最终生成一个形式项，内核检查这个项能否从给定定义和公理推出精确声明。公开仓库把结论写成自然数上的命题：指数至少为三，三个底数均为正时，等式不成立。默认构建还检查整条证明只依赖 Lean 常用的三个标准公理，即命题外延、公理选择和商类型健全性。

仓库进一步排除了几类常见逃生门。正式模块中没有留下 `sorry`，没有额外声明 `axiom`，没有使用 `native_decide` 绕过内核，也没有 `unsafe`、外部实现或部分定义来充当证明。这个检查很重要，因为在大型形式化项目里，构建成功和数学闭合并非天然同义；只要某处保留一个未完成占位符，后面的数万条依赖仍可能全部显示为可编译。把允许的公理集合锁定，并扫描这些绕过路径，才让“编译通过”接近我们真正关心的结论。

第二道核验是 comparator。它使用只依赖 Mathlib 的挑战文件重新陈述费马大定理，检查 Anthropic 证明的结论、结论涉及的常量和标准库中的目标完全一致，并让整个环境重新经过 Lean 内核。这样做解决了形式验证里一个容易被忽略的问题：机器可以完美证明错误的命题。若把正整数误写成某个更窄集合，或者指数边界少覆盖一种情况，证明本身仍可能严丝合缝。comparator 不能替代全部语义审阅，却能把最终形式声明与社区已有声明逐项对齐。

第三道核验来自另一个内核。公开材料称，独立用 Rust 编写的 nanoda 接受了同一环境导出的约一百零五万二千二百三十四个声明，没有报告错误。团队为 nanoda 加了四个小补丁，其中一个输出进度，三个加速定义相等性搜索；仓库声明这些补丁没有增加、删除或削弱类型规则。第二内核降低了单一 Lean 实现缺陷导致误判的风险，不过补丁本身、导出工具和构建链仍需要外部审阅，所以“计算机检查”应当理解为一个可缩小、可复验的信任基础，不能理解成脱离软件和硬件的绝对真空。

Kevin Buzzard 的检查提供了最关键的外部证据。他正在领导另一项费马大定理形式化项目，也长期参与 Lean 数学社区。Buzzard 表示自己已经编译 Anthropic 的代码并运行 comparator，结果通过；他还花了许多小时查看代码，并仔细检查约一百行不属于普通数学定义或定理证明的内容，判断它们只是在定义一个便利 tactic。这个核验显著提高了可信度，同时仍有明确范围：一位领域专家完成了独立构建和有针对性的代码审阅，尚未出现多家团队从干净环境复跑全部验证、逐页审阅数学语义的结果。

理解十一天的速度，还要看背后的组织系统。Claude 最初的多 agent 尝试很快失去项目全局状态，协作效率下降。Anthropic 随后切换到 Prove2Me。这个平台把待证定理组织成有向无环图：一个节点只有在依赖节点完成后才能进入正确位置，agent 可以寻找当前可做的任务，也可以复用其他 agent 已经完成的结果。定理声明和证明被拆到不同文件，依赖关系单独维护，既减少重复编译，也让多人并行时不必频繁修改同一处代码。

Prove2Me 还为每条形式声明保存自然语言描述，帮助 agent 搜索已有结果。这个细节看起来普通，却直接决定六十亿 token 是否会被重复劳动吞掉。若三万个定理只剩机器生成的十六进制名字，新 agent 很难知道某条引理已经存在；若搜索能把人类描述映射回精确 Lean 声明，先前工作就会形成复利。Anthropic 称，早期失败尝试产生的非样板代码仍有大约百分之七进入最终证明。失败没有全部变成废料，前提是系统能够标记哪些局部产物可信、它们依赖什么、后来又被谁引用。

这与八月已经讲过的 AI 数学长程研究形成清晰区别。此前 Grothendieck 常数工作最有价值的材料，是模型怎样探索、失败、人类怎样决定改变研究方向，以及错误摘要怎样让未经验证的数字在长任务中漂移。今天的费马大定理项目预先知道目标和主要数学路线，系统的核心任务是补齐形式依赖并保持数十个 agent 的共享状态。探索性研究考验选题品味与新洞见；大规模形式化考验规格、调度、复用、编译和验收。两者都需要长期状态管理，失败代价与最终证据形态并不相同。

仓库规模也提醒我们，十一天只描述 agent 生产阶段，不代表社会验证成本已经接近零。公开说明显示，从头构建需要 Linux 或 macOS，因为 Windows 上部分路径过长；九十六个并行任务的构建耗时五小时三十二分，内存峰值约一百五十三 GB。comparator 单核重放接近十四小时四十六分，峰值约二百三十 GB。构建目录约占六十七 GB，中间 C 文件还可能增加约二百二十 GB。独立团队要完整复验，需要高配机器、固定工具链和相当长的等待时间。

版本冻结在这里也属于证明的一部分。仓库指定 Lean 四点三十三点一和 Mathlib 四点三十三点零，并把依赖锁到明确提交；构建说明特别指出，这个 Lean 版本包含二零二六年的内核健全性修复。形式证明会随定义、编译器和库发生变化，今天通过的源码若在未来工具链上无法重放，外界需要区分兼容性故障、证明脚本失效和逻辑结论失效。可靠的长期保存应同时封存源码、依赖哈希、构建镜像、挑战声明、内核版本与验证日志。对企业软件来说，这与模型、数据和评测的版本链相似，只是数学证明把可追溯要求推到了每个定义和每条推理规则。

可读性是另一项尚未完成的工作。仓库为约两万九千五百一十一条定理和一千四百五十个定义模块生成了约三百九十 MB 的离线网页，可以查看每条声明引用什么、又被谁引用，也能沿关键里程碑浏览依赖图。Lean 声明是权威内容，英文摘要和建议引用由机器生成，只能当导航。代码里的名称大量来自自动流水线，注释也基本被移除；仓库明确标为研究工件，不维护，也不接受贡献。它已经适合内核检查和依赖追踪，还没有变成数学家愿意长期维护的精炼公共库。

Buzzard 对这一点的评价很直接：这项工作在数学上几乎没有增加知识，因为费马大定理及其证明早已被专家接受；它在自动形式化上展示了新能力。他自己的项目仍要把现代数论中的基础对象贡献给 Mathlib，并建设便于人类探索现代证明的动态文档。两条路线衡量的是不同产出。一份一千三百万行、可以验收的研究工件证明机器能够跨过端到端门槛；一个简洁、可读、可复用、长期维护的库则决定这些代码能否降低下一项形式化任务的边际成本。

六十亿输出 token 也不能直接换算成确定的美元成本。项目使用的是大致可与 Claude Fable 5.1 相比的内部研究模型，外界不知道其推理硬件、批处理方式、缓存命中、失败分支、内部转移价格和人工工时。按公开 API 零售价相乘，只能得到假设场景，无法代表 Anthropic 的实际支出。更可用的经济指标应当包括每个被最终使用的定理消耗多少 token，多少工作来自既有库，失败任务占多少算力，以及同一套 scaffold 在第二个大型定理上能否显著降本。

这项成果对产业链的价值路径因此分成几层。最靠近今天事实的是前沿模型推理需求：长程形式化可以消耗十亿级 token，并需要稳定的并行 agent、编译资源与状态数据库。再往下是证明助手、定理搜索、依赖图、版本锁定、可复现构建和第二内核检查等工具。更长期的价值来自科研审核：若论文在提交人类说明的同时附上形式证明，编辑和审稿人可以把精力集中到命题价值、假设选择与解释，而把大量局部逻辑交给机器复核。每一层都存在商业机会，今天没有收入、客户数量或可持续毛利数据，不能把一次里程碑直接写成市场规模。

最值得警惕的误读，是把形式正确等同于语义充分。Lean 保证某个精确声明从给定公理和定义推出。它不会判断中间定理的名字是否忠实，也不会评价形式版本是否抓住了人类文献全部意图。最终目标通过 comparator 对齐，证明路线文档又把著名步骤的实际强度逐项列出，这两项设计显著降低了“证明了邻近命题”的风险。大规模数学语料仍需要专家检查定义、假设、归属和可复用性。机器内核负责逻辑闭合，数学共同体负责意义、重要性与知识组织。

另一个边界是泛化。费马大定理拥有清晰目标、成熟的人类证明路线和多年积累的 Mathlib 及社区代码，适合测试“把已知数学完整形式化”。开放研究中的定理常常连正确命题都尚未确定，关键定义会变化，反例可能迫使项目转向，专家还要决定某条技术路线是否值得继续。Anthropic 提到，三个个人 Claude Max 订阅通过 Prove2Me 在三天内完成 Vinogradov 三素数定理的一项形式化，这提供了较小规模的迁移样本；距离证明不同领域都能以相近速度和质量复用，还缺统一任务集、成本记录和独立团队对照。

未来验证这项能力，可以沿五个节点观察。第一，更多外部团队能否在固定 commit、固定 Lean 与 Mathlib 版本上完成干净构建、comparator 和第二内核复跑。第二，仓库中的定义和引理有多少能经人工整理进入 Mathlib，代码量能压缩多少，维护成本是否下降。第三，后续大型定理是否公开总 token、失败任务、人工干预、复用比例和墙钟时间，让不同 scaffold 能够按同一口径比较。第四，形式化是否真的发现重要文献缺口或更正已发表结果，并得到领域专家确认。第五，AI 生成的新数学能否在结论出现的同时交付可读论证与形式证明，使机器核验从事后大型工程变成研究流程的一部分。

这五个节点里，任何一个出现实质进展，都足以重新评估自动形式化的成本曲线和科研价值。若后续只有更多代码行数、token 数或单次演示，信息增量会很有限；若独立复现、公共库吸收、跨定理迁移、文献纠错和人机审阅工时开始形成连续数据，形式验证才会从惊人的研究工件走向可重复的科研基础设施。
