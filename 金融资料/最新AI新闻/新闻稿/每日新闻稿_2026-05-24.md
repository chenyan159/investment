## 新闻口播稿

各位早上好，今天是 2026 年 5 月 24 日。周末的一手发布不算密集，但今天有两条线索值得认真讲：第一条，是 xAI 和 SpaceX 把 AI 数据中心的电力矛盾摆到了台前；第二条，是企业 agent 的 token 成本开始进入管理层视野。它们看起来一个在讲能源，一个在讲软件账单，放在一起看，指向同一个变化：AI 产业的竞争正在从“谁有更强模型”，扩展到“谁能让模型稳定、便宜、可控地跑起来”。

先讲 xAI 和 SpaceX。

TechCrunch 5 月 23 日根据 SpaceX 披露材料做了一篇解读，里面有几个数字很抓人。xAI 已经在用天然气 turbine 给数据中心供电，并计划再购买约 28 亿美元的 turbine 设备；过去两年，xAI 还购买了约 6.97 亿美元的 Tesla Megapack 电池，用来管理峰值负载。材料里还把今天全球数据中心大约 40GW 的用电规模，放到未来 AI compute 可能继续指数式扩张的框架里讨论。更远的叙事，是 SpaceX 认为太空里的太阳能、辐射冷却和激光通信，长期可能承载 space-based data center。

“太空数据中心”这个概念很抓人。更现实、更关键的变化在于，AI 数据中心的电力路线已经从采购绿色电力、签 PPA、排队并网，进一步走向自备发电、储能、选址和垂直整合。过去市场谈 AI 基建，第一反应往往是 GPU、HBM、先进封装、光模块。现在越来越多建设案例告诉我们，算力链条继续往外扩散，扩散到变压器、开关柜、燃气 turbine、储能、电力工程、液冷、水资源、地方许可，甚至天然气供应。

xAI 的特殊性在于，它背后有 Musk 体系内的几块拼图：xAI 要模型和数据中心，SpaceX 有发射、卫星和长期太空基础设施叙事，Tesla 有 Megapack 和能源业务。短期看，天然气 turbine 加 Megapack 是为了让地面集群尽快上电，减少被传统电网扩容节奏卡住的时间。长期看，SpaceX 把 AI 算力需求接到太空基础设施上，是在给市场讲一个更大的垂直整合故事。

但我们要把短期订单和长期想象分开。短期可验证的是 turbine 采购有没有供应商，交付节奏是什么，能对应多少 MW 或 GW，站点许可是否通过，Megapack 对应多少 MWh，具体服务哪个数据中心。长期的 space-based data center 目前更适合作为 optionality 来跟踪。把服务器送上轨道，要解决发射成本、维护、散热、辐射防护、网络延迟、训练任务能否分布式运行等一串问题。这个方向有想象力，但在投资上不能直接当作 2026 到 2027 年的确定订单来折现。

这条新闻对产业链的提示很明确。AI 数据中心的瓶颈排序还在变化。GPU 仍然关键，但如果没有电，没有配电，没有冷却，没有施工和许可，再贵的 GPU 也只能停在交付计划里。投资上，未来几个月需要继续盯三类公司：第一类是真正能缩短 time-to-power 的电力设备和现场发电方案，包括燃机、燃料电池、储能、UPS、变压器、开关柜和电力 EPC；第二类是能把高密度机柜稳定跑起来的热管理和液冷链；第三类是掌握站点、电力合同和客户负载的 AI cloud 或 hyperscaler。概念可以先听着，订单、容量、交付时间和许可记录才是硬证据。

第二条线索，是 agent 的 token 成本。

Tom's Hardware 5 月 23 日把近期几条报道合在一起讨论：Microsoft 据报正在推动部分团队从 Claude Code 转向自家的 GitHub Copilot CLI；Fortune 5 月 22 日也提到，agentic AI 的 token 消耗可能远高于普通聊天，企业虽然看到单位 token 成本下降，但用量增长可能把总账单推得更高。OpenClaw 创作者 Peter Steinberger 此前披露过 30 天超过 130 万美元的 OpenAI token 消耗，这个数字当然很极端，但它让市场第一次直观看到：当 agent 真的长时间读代码、开工具、跑测试、反复修复，推理账单会从“产品毛利的小变量”变成“企业预算的大变量”。

普通聊天产品的成本比较容易理解。用户问一句，模型答一句，最多多轮补充。Coding agent 和 enterprise agent 的成本结构完全不同。它会读整个代码库，检索历史上下文，打开浏览器，调用 shell，运行测试，失败后重试，还可能把任务拆给多个子 agent。一次看似简单的“帮我修这个 bug”，背后可能是几十轮模型调用、几十万甚至上百万 token、多个工具环境和一段持续运行的云端 sandbox。

所以企业现在关心的问题会变得非常朴素：这个 agent 跑一次，值不值？如果它用十几分钟省掉一个工程师半天时间，账单可以接受；如果它为了一个小改动烧掉大量 token，最后还要人工重做，那就会被预算约束拦下来。未来 coding agent 的竞争，不能只比“谁写得更聪明”，还要比四件事：任务成功率、单位任务成本、长任务稳定性，以及企业能不能审计和管控。

Microsoft 这条线索也要谨慎解读。它推动 Copilot CLI，既有成本因素，也有平台战略因素。Microsoft 拥有 GitHub、IDE、企业身份、代码托管和 Azure 算力，当然希望把开发者工作流留在自己的体系里。如果 Claude Code 在内部太受欢迎，会削弱 Copilot CLI 的战略位置。对外部投资者来说，重点不在于简单判断 Claude Code 或 Copilot CLI 谁赢了，而在于企业会把 agent 工具纳入采购治理：谁拥有账单，谁拥有审计，谁拥有权限，谁拥有数据边界，谁就更容易留下来。

这会带出一批新的基础设施机会。第一是 AI FinOps，也就是把 token、模型调用、工具调用、sandbox 时间和任务结果对应起来，让企业知道钱花在哪个团队、哪个业务单元、哪个任务上。第二是模型路由和缓存，把简单步骤交给便宜模型，把关键推理交给强模型，用 prompt cache、context compression 和增量索引降低重复成本。第三是 agent observability，记录 agent 读了什么、改了什么、调用了哪些工具、失败在哪一步。第四是权限和安全，把 agent 的执行边界限制在合规范围内，不让一个 agent 任务拿到过大的系统权限。

第三条新闻是 OpenAI Codex 的限流事件解除。OpenAI Status 显示，5 月 22 日开始的 Codex rate limit 问题在 5 月 23 日 10:58 PDT 标记为 resolved。这个事件本身不算大新闻，但它是观察 coding agent 商业化的真实信号。功能发布时，大家关心它会不会写代码；进入生产环境后，客户关心的是排不排队、长任务会不会中断、失败后能不能恢复、企业版有没有更稳定的容量池和 SLA。

把这条和刚才的 token 成本放在一起，逻辑就很清楚了。Agent 更像一个持续运行的云端工作负载，不该按普通网页聊天框来理解。它需要模型推理，需要工作目录和运行环境，需要浏览器，需要测试环境，需要队列，需要沙箱，还需要恢复机制。OpenAI、Anthropic、Google、GitHub、Cursor 后面的竞争，会越来越接近云服务竞争：谁能稳定运行，谁能给出可预测账单，谁能接企业内网，谁能让安全团队放心，谁就更容易把 seat 变成真实工作流。

第四条是 Anthropic Managed Agents 的补录。5 月 19 日，Anthropic 的 Claude Developer Platform 增加了 MCP tunnels 和 self-hosted sandboxes。严格说这不是今天首发，但过去几天我们主线没有深挖它，而它正好解释了企业 agent 下一步为什么会从 IDE 插件走向控制层。

Self-hosted sandbox 的意思，是工具执行可以跑在企业自己的环境里，或者跑在受管 sandbox provider 里；Anthropic 的 agent loop 负责 orchestration、context management 和错误恢复。MCP tunnel 的意思，是 agent 可以通过企业部署的轻量 gateway 访问私网里的 MCP server，比如内部数据库、私有 API、知识库、工单系统，而且不需要把这些服务暴露到公网。换成更直白的话，Claude 仍然是大脑，但手和工具可以放在企业自己的边界内。

这件事为什么重要？因为企业真正部署 agent 时，主要障碍往往落在执行边界上：代码和数据不能随便出边界，内部 API 在私网里，凭证不能暴露给模型，安全团队要审计每一次调用，法务和合规要知道数据怎么流动。Self-hosted sandboxes 和 MCP tunnels 对应的正是这些硬约束。它们把 agent 从一个“能回答问题的应用”，推向一个“能在企业内部受控执行任务的 worker”。

这条线索也和 OpenAI Codex、Google Antigravity、Dell/OpenAI 本地 AI Factory、CrowdStrike 接 Claude Compliance API 放在一条线上。企业 agent 的平台化要解决五件事：执行环境、私网连接、身份权限、审计日志和成本控制。模型公司如果只提供 API，会被企业系统集成层拿走一部分价值；模型公司如果把 agent runtime、sandbox、MCP、审计和计费都打包好，就更容易进入高价值工作流。
