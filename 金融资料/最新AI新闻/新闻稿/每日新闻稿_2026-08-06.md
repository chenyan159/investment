# 每日AI产业链新闻｜2026-08-06

Sandisk 的财报把数据中心 NAND 景气拆成了销量和价格两部分，科学编程基准审计与 SGLang 修复则分别揭示评测工具和推理运行时怎样悄悄改写结果。今天还关注 Azure 生产轨迹显示的 agent 服务器资源错配，以及 Netlist—Samsung、Solaris 两份把内存和现场电力合作推进到正式条款的新合同。

## 新闻口播稿

今天是2026年8月6日。今天选择六组、共七项内容：先看 Sandisk 与 Western Digital 的存储财报，再讲 SciCode 基准审计、Azure agent 工作负载架构、SGLang 的静默缓存错算，最后分析 Netlist 与 Samsung 的五年协议，以及 Solaris 扩大的现场电力合同。

第一组从存储开始。Sandisk 在8月5日公布截至7月3日的财年第四季度业绩。季度收入八十九点六五亿美元，环比增长百分之五十一，同比增长百分之三百七十二；GAAP 毛利率达到百分之八十四点六，环比又提高六点二个百分点。数据中心收入二十九点七七亿美元，环比增长百分之一百零三，去年同期只有二点一三亿美元。公司同时把下一季度收入指引放在一百零三亿到一百零八亿美元，毛利率指引仍在百分之八十三到百分之八十五附近。

这份财报最有用的一句话，是公司把环比收入增长拆成大约三分之一来自销量、三分之二来自价格。数据中心需求确实在增长，当前利润跃升的更大推动力来自涨价。这个分解避免把所有收入增量都解释成新增比特出货，也提醒我们，八成以上毛利率里包含很强的周期价格因素。若未来 NAND 供需转松，价格贡献可能比服务器装机需求更早回落；若价格保持、销量继续增长，收入质量才会得到第二层确认。

公司还披露，自4月财报电话会宣布五份 New Business Model 协议后，又签了五份，其中三份来自新客户，两份扩大原协议。总数已经达到十份。公开材料没有给客户、期限、最低采购量、预付款、取消权或定价公式，因此这些协议能够证明客户关系扩大，暂时无法按不可撤销订单或确定收入计算。下一步需要把协议数量接回比特出货、库存、数据中心收入和价格变化；只看“十份协议”很容易高估它的财务确定性。

Western Digital 同日公布的硬盘业务提供了横向证据。季度收入三十七点四七亿美元，同比增长百分之四十四；非 GAAP 毛利率百分之五十四点四，自由现金流十二点八亿美元。公司预计下一季度收入四十一亿美元上下浮动一亿美元，非 GAAP 毛利率百分之五十五到百分之五十六。NAND 与近线硬盘的产品结构不同，两家公司收入、毛利和现金流同时上行，说明 AI 数据中心正在扩大一整套持久化存储需求：训练数据、推理语料、检查点、日志和冷热分层都需要容量。这个横向确认仍缺少客户集中、每 exabyte 售价、订单期限和实际容量出货，不能用两份强劲财报直接推演存储周期已经失去波动。

因此，今天对存储链条的新增判断可以写得很具体。需求叙事已经进入收入和现金流，但 Sandisk 本季增量主要由定价驱动。后续验证要把销量、单位价格、协议条款、产能纪律和库存放在同一张表里。若价格下降而数据中心比特出货加速，收入与毛利会出现不同方向；若协议开始披露最低量、期限和预付款，长期可见度才会明显提高。8月13日的 Sandisk 投资者日，也将是检查这些分母的下一处公开节点。

第二项是一篇8月5日提交的论文，题为 SciCode-Verified。SciCode 用研究级数学、物理、化学、生物和材料问题测试模型能否把科学推导写成可运行的数值代码。它的测试集有六十五道主问题，每道又分成累计依赖的子问题；前一步的错误会传到后面，只要一个子问题失败，整道主问题就记为失败。这种结构让测试缺陷具有放大效应。

论文作者逐题审计后识别出二百六十三个缺陷。其中一题的规格无法确定唯一答案，作者将它移除；其余六十四题里有二百六十二项得到修正。最关键的是，一百九十二项缺陷会把正确且遵循指令的答案判错，覆盖五十八道主问题，也就是百分之九十一。这里面一百五十项需要物理或数学专业知识才能识别。最大一类是题目没有规定符号、索引、随机数或数值约定，标准答案却只接受其中一种；其他问题包括错误的金标准、依赖特定随机序列的测试、过紧容差、题意与答案互相矛盾，以及接口定义错误。

作者在同一套运行框架下重新评测十二个前沿模型，只替换原版和修正版基准数据。子问题通过率从原来的百分之四十五到百分之六十，升到百分之八十四到百分之九十八；主问题通过率从百分之九到百分之二十七，升到百分之六十九到百分之九十二。GPT-5.6 Sol 在带专家背景材料的设置中达到百分之九十八点三子问题通过率和百分之九十二点二主问题通过率。模型之间的排序也发生变化，说明旧缺陷同时扭曲绝对难度和相对名次。

这个结果上修了模型执行科学代码的能力判断，也暴露了新的评测瓶颈。修正版在带背景设置下已经接近饱和，继续用它区分顶尖模型会越来越困难。移除专家背景以后，几个代表模型的主问题通过率仍落到大约百分之五十二到百分之六十六，说明自主补齐推导、识别非标准公式和处理领域事实仍有明显空间。论文大部分模型结果是单次 pass at one，运行波动会影响小幅差距；DeepSeek 的部分修正版结果来自三次平均，比较时还要保留口径差异。

作者公开了修改记录，并安排第二名领域专家做对抗式复核，这提高了可审计性。目前仍缺独立团队逐题复算，也没有看到采用 SciCode 的公共榜单、政府评测和训练流程已经完成迁移。接下来最值得看的节点是第三方能否复现缺陷、榜单是否回算历史成绩、模型报告是否改用修正版，以及新的高难度题目能否在没有专家背景的条件下维持区分度。今天真正改变的洞见，是科学能力评测的主要成本已经包含领域专家对题目和金标准的维护，单靠更多模型采样无法修复一把刻度错误的尺子。

第三项讨论 agent 工作负载怎样改变服务器设计。一篇8月5日发布的系统论文使用 Microsoft Azure 的二十四小时生产轨迹，并在四套开源框架上做受控实验。传统大模型服务把一次推理当成主要工作单元；agent 请求会在模型推理、工具调用、浏览器或代码执行、状态编排之间反复切换。论文在生产轨迹中观察到，超过百分之二十七的请求里，工具执行时间已经不低于模型推理时间。

受控实验覆盖 SWE-Agent、Trae、CORAL 和 Owl，硬件是一台九十六核 AMD EPYC 7V12 与八张 A100，并把并发从一提高到三十二。四套框架的主机 CPU 中位利用率只有百分之六到百分之三十一，GPU 的 SM 活跃度低于百分之五十五；低平均值背后却有尖锐峰值。Trae 在顺序阶段的 CPU 利用率中位数约百分之十一，一旦同时释放编译和测试工具，利用率会冲到接近百分之百。按平均值缩减资源会卡住峰值，按峰值静态配置又会在模型生成或外部等待期间闲置大量容量。

论文据此实现了名为 Agora 的原型。CPU 一侧，它把延迟敏感的调度器和编排器核心隔离出来，只在工具 runner 的闲置核心上放置共存任务；编排器还会提前告知下一次工具突发，以及工具主要消耗计算还是等待网络。在低负载实验中，共存任务保留百分之九十五的独立吞吐，agent 变慢低于百分之三。把高低两个运行点合并看，额外工作保留约百分之七十四吞吐，主机利用率提高约百分之三十一，agent 延迟代价约百分之三点三。

GPU 一侧的结果很能说明边界。对 Owl，合并相同模型的多个角色并预取下一名 agent 状态后，Agora 释放三分之一 GPU，生成吞吐提高百分之八十二，尾延迟改善二点五倍。对 CORAL，同样的收割策略释放一半 GPU，却让吞吐下降百分之七十一，尾延迟恶化十六倍。CORAL 的多个角色同时活跃，资源需求缺乏互补性，过度合并直接制造争用。因此，论文中的最高收益属于特定工作负载，无法当作所有 agent 服务器的通用节省比例。

这项研究改变的是资源规划的单位。采购和调度不能只按 token 吞吐或单次推理峰值估算，还要记录工具时间占比、CPU 突发、角色是否共享模型、哪些角色会同时活跃、主机内存中的状态预取，以及尾延迟服务目标。论文没有披露 Azure 轨迹的请求总量、客户分布、模型结构或单位成本，Agora 也还只是原型。后续若公开代码、真实多租户部署、隔离与安全测试、以及每完成一个任务的服务器成本，agent 原生服务器才会从架构方向进入可采购的产品指标。

第四项来自 SGLang 8月5日合并的一次正确性修复。Breakable CUDA Graph 为了复用已经捕获的图，会把 token 缓冲区填充到一个预设桶大小。查询、键、值和缓存位置已经按真实 token 数截短，positions 位置张量却仍带着填充出来的虚拟 token。Decode Context Parallelism 会根据位置判断 KV 缓存归属，虚拟位置因此可能与真实 token 争用同一个物理 KV 槽位，缓存内容被静默改写。

这类故障最危险的表面特征是服务完全正常。修复者使用 Qwen3.5-397B-A17B FP8、十六路张量并行、四路 DCP、FP8 KV cache 和 Breakable CUDA Graph，对 GSM8K 的一百二十八道题做零温度测试。修复前通过一百一十二题；四行位置截断修复后连续三次都通过一百二十六题。前后四轮共五百一十二个请求全部返回 HTTP 200，没有任何非二百状态码。运维面板若只看请求成功率、进程退出和延迟，很可能把这次质量损失当成模型波动。

最近几周 SGLang 已经出现过容量预算和分层缓存不变量修复，这次新增证据直接落到了端到端答案质量，也满足重新深查的条件。受影响范围仍需收窄：公开测试只覆盖一套大模型、并行拓扑、缓存精度和一百二十八题，补丁已经进入主线，尚未给出明确的稳定版边界，也没有在其他任务和并行组合上系统复测。修复没有更改内核或图配置，作者因此没有做速度测试。

工程验收需要增加一条语义链：同一权重在图捕获开关、不同桶大小、并行方式和 KV 精度之间做确定性对照；服务监控同时采样任务正确率、logprob 或固定金丝雀请求；发布记录写清受影响提交和稳定版。HTTP 成功只能证明协议完成，无法证明缓存身份、位置映射和最终答案仍然正确。下一次值得更新的节点，是稳定版本发布、统一回归矩阵、更多任务复现，或真实生产事故说明影响面。

第五项是 Netlist 与 Samsung 的五年协议。Netlist 在8月5日提交的 8-K 显示，协议于7月31日生效，双方在8月4日签署相关文件。Samsung 获得 Netlist 专利组合的全球非独占许可，Netlist 获得部分 Samsung 专利的免版税许可；双方同时解决文件列明的待决诉讼，并建立产品供应、技术合作和未来第三方 ITC 行动的信息协作安排。

现金条款分成两层。Samsung 先支付二点三九亿美元毛额，扣除韩国预提税后，Netlist 预计收到约两亿美元。此后从生效日起到2031年第二季度共有二十个季度，每季许可费毛额最高三千二百九十万美元、税后最高约二千七百五十万美元。季度金额依照协议中的收入公式计算，还可能受到调整和 Samsung 退款权影响。把首付款和所有季度上限相加，可得到八点九七亿美元毛额、约七点五亿美元税后上限；这是理论上限，不能按固定年金写入预测。

供应条款同样要读准方向。Netlist 获得每年向 Samsung Semiconductor 采购最高三亿美元 DRAM 和 NAND、五年最高十五亿美元的权利。文件没有写最低采购量，这十五亿美元代表采购上限，既不等于 Samsung 已经获得十五亿美元订单，也不等于 Netlist 必须完成同额采购。供货价格、产品组合、毛利和转售客户也没有公开。它提高了 Netlist 在紧张内存市场中的采购通道确定性，实际收入与利润仍要等采购、库存周转和客户销售来验证。

Samsung Semiconductor 还同意以总计一百万美元认购一千万股 Netlist 普通股，股份从发行一周年起每年释放百分之二十，最后一批在第五周年释放。公司新闻稿的风险说明称这笔认购当时尚未完成，8-K 写明预计最迟8月11日交割。这个安排带来长期绑定和现有股东稀释，认购金额本身很小，不能单独当成对公司价值的市场定价。真正的状态跃迁来自多年诉讼被转换成首付款、按收入变化的许可费、供应权和技术协作。后续要看首付款到账、季度公式实际结果、股票交割、采购量与毛利，以及其他诉讼是否出现独立和解；Samsung 协议不会自动迫使 Micron 或 Google 采用相同条款。

第六项是 Solaris Energy Infrastructure 扩大三份长期合同。公司8月5日披露，这些扩围项目合计新增预期年化调整后 EBITDA 超过一亿美元。这里的“预期”来自公司测算，描述合同进入相应服务阶段后的年化贡献，不能与本季度已经确认的利润直接相加。

最大变化来自2月签下的 Hatchbo 协议。范围扩成约六百六十兆瓦的 turnkey 电厂，覆盖发电设备、balance of plant、电池储能，以及面向 AI 工作负载的能源管理系统；期限从十年基础期加五年延长选择权，变成十年基础期加八年选择权。另一份4月签订的技术客户协议加入更多配套电气、储能和基础设施服务；一名大型能源客户又把微电网容量从六十兆瓦提高到约八十兆瓦，期限从四年延至六年。

本季度真正已经运行的分母需要单独保留。Solaris Power Solutions 平均约九百五十兆瓦容量在产生收入，环比增长百分之四；该分部收入约一点五八亿美元，调整后 EBITDA 约九千六百万美元。集团调整后 EBITDA 一点零八亿美元，环比增长百分之三十。九百五十兆瓦描述现有运营平均容量，Hatchbo 六百六十兆瓦描述扩围后的未来项目，两者不能相加成已经上线的一点六一吉瓦。

合同扩围提高了未来交付的可见度，也把现场供电从单纯租用发电设备推进到电厂配套、储能和 AI 负载管理。仍未知的项目分母包括分批交付时间、客户信用支持、设备采购、资本由谁承担、最低付款、取消责任、燃料与许可、选择权是否行使，以及预计 EBITDA 从哪一季开始确认。公司已完成十三亿美元无担保债融资，并有六点五亿美元未使用信贷额度，这增强总体资金能力，却没有自动证明每个项目已经完成专项融资。下一处关键证据是首批上电、客户验收和实际 EBITDA 入账；届时才能判断扩大的合同范围是否按计划穿过建设、运营和现金回收三道门槛。
