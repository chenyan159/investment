## 5. 前沿人物、X与技术讨论

- **vLLM 三类状态边界**：Kimi+EAGLE3 structured output 是生产可用性事故；async Mamba align 是 D2H/row ownership 竞态；DFlash 量化是 bypass `quant_method`。三条各自保留 signal，口播可合成“控制状态、请求状态、权重量化状态都需由 runtime 显式执行”。
- **SGLang 的确定性与低证据高严重性**：DSV4 ring residency 已合并并有 19 项反事实回归；Kimi-K3 跨 prompt reasoning 泄露与 HiCache hang 只有单环境现场，分别保留 B 和 P1 待复验，不能和已证实修复同一语气。
- **分布式 KV 生命周期**：Mooncake 的 req_id ABA 给出 underflow、stale generation 与 11,267 KV blocks 滞留；DiskBackend 则是跨调用的 pinned buffer/DMA event ownership。一个击中控制计数，一个击中数据缓冲。
- **训练正确性**：Megatron GTP/DDP 会聚合上一轮权重；DeepSpeed AutoTP 以 process-wide global 污染多模型。两项均提示吞吐重叠和多模型复用必须保留 per-lifecycle/per-model metadata。
- **agent SDK 合同**：MCP low-level Server 展示 schema 却不执行；ADK rehydration 用 value equality 同时制造 O(n²) stall 与 prompt 丢失；ADK Go v2.2.0 已正式交付路径穿越、跨用户删除和并发修复。三者的发布状态分别为开放 PR、开放 PR、稳定 release。
- **本轮 X 负结果**：已检查前沿实验室/研究人员/CEO 的公开 profile syndication 与博客 feed，没有取得可同时核验身份、原帖时间、原帖正文和新增判断的独立 X 信号。syndication 可能滞后，因此结论只写“本轮未取得可核原帖”。

## 9. 优先候选研究包

### 研究包 A｜Muse Glimmer：本地 agent 的模型、量化、runtime 与安全边界

**核心事实与时间线**

- 8/9 10:51 PDT：HF artifact repo 创建，权重无门禁，Apache-2.0。
- 8/9 17:00：HF/Meta 技术材料发布，交付 BF16、两档 4-bit 与 DFlash drafter。
- 8/10 03:28：Transformers v5.15.0 正式支持；llama.cpp Muse support PR 在截止前合并，新的 build release 尚未形成。
- 架构约29.6B，含约1.8B perception encoder；131,072+ context，text+image input/text output。

**数字与主张**

- K-Quant-Dynamic/17GB 的目标硬件为 32GB/24GB，厂商称 15 项平均 accuracy degradation 0.2%/1.0%。
- DFlash block size 16、5 个 hidden-feature layers；RTX5090 batch1 greedy 74.9→233.4 tok/s，M4/M5 Max 分别 23.7→37.8、26.6→50.2。
- MCP Atlas 75.5、DeepSearch 74.6、SWE-Pro 51.2；Qwen3.6 在多项 GUI/coding/multimodal 指标更强。
- CI Memories violation 26.4%，AgentDojo ASR 28.4%；Meta 建议不可逆动作加入 human-in-the-loop。cyber/LoC risk 部分为相对 Muse Spark 推断。

**为什么是新洞见**

云/API 模型被蒸馏成一张高端消费 GPU 可承载的开放资产，训练后能力、量化、speculative drafter 和 runtime 同时成为一套部署产品。新的判断集中在本地 agent 供给、隐私/延迟和单位部署门槛，不能扩成所有 agent 任务领先。

**支持、反证与待核**

- 支持：真实权重、许可证、模型卡、方法报告、Transformers stable 和 llama.cpp 合并。
- 反证：benchmark 混合内部 harness；竞争模型多项领先；安全表不占优；没有独立 24GB memory peak、长期工具任务、量化 parity 或单位成功成本。
- 最值得写：17GB/24GB 的工程含义、DFlash 速度条件、day-0 runtime 现实、安全指标与独立验证清单。
- 不应重复：开放模型通用好处、Meta 历史模型名单、agent 市场宏观背景。

### 研究包 B｜1GW HiMSEN：从数据中心许可走到设备订单

**核心事实**：HD Hyundai 与 Corban 的合同 6.738 亿美元、9.6MW engine、总计1GW；4月 AEG 订单684MW，两笔合计1.684GW。供应商称终端为美国大型科技公司运营的数据中心。

### 研究包 C｜structured output 生产事故：三 backend 没有可用退路

**生产现场**：vLLM 0.26.0、2×4 B300、Kimi-K2.6 NVFP4+EAGLE3。xgrammar 每小时多次 FSM error 并周期性杀 engine；guidance 全 500；outlines timeout 不取消 compile thread，35分钟达到320GiB并 OOM。

**新机制**：结构化输出的失败不止 grammar correctness。speculative token/state、tokenizer 支持、compile isolation、timeout cancellation、retry policy、health/reload 共同决定可用性。关闭 spec 不复现是相关证据，尚未证明根因完全位于 EAGLE3。

**证据边界**：单一生产方、未维护者确认；没有独立流量、schema复杂度分布或完整日志。25—30分钟 reload 与 1—2天频率不能直接外推其他模型/backend。

**验证问题**：可取消 worker/process；per-schema compile budget/cache；spec on/off 同流量；backend 自动降级；错误隔离到请求；health 是否覆盖 grammar workers；修复版复验。

### 研究包 D｜speculative state：row ownership、量化语义与 ring residency

| 子信号 | 新根因 | 证据强度 | 不能混淆的边界 |
|---|---|---|---|
| vLLM async Mamba align | D2H copy 与 InputBatch `condense()` 共享可变行 | A-/B+，等价路径512/512 | CUDA main 尚缺 runtime native 复现 |
| vLLM DFlash quantized KV | raw weight slice+`F.linear` 绕过 `quant_method` | A-/B+，开放 draft fix | 显式崩溃与静默 scale 丢失取决 dtype/quant scheme |
| SGLang DSV4 ring | draft D>4 少写 compress ring、host/GPU planner 不一致 | A，修复已合并、旧版19项失败 | 端到端平均 benchmark 没显著暴露错误 |

**判断**：三项共同要求执行系统保存请求行的生命周期、权重模块的量化方法和 KV ring 的未来可达性。它们属于同一上位“speculative state correctness”，仍保留不同 signal 便于跟踪修复和受影响版本。
