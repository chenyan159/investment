## 1. TensorWave 3.5 亿美元融资：AMD 生态把“第二供应源”做成可租容量

### 新闻事实

2026-06-10，TensorWave 宣布完成 3.5 亿美元 Series B，估值 15.5 亿美元。融资由 Magnetar 和 AMD Ventures 共同领投，Maverick Silicon、Nexus Venture Partners、Western Frontier 继续参与。资金用途指向全球 AI infrastructure footprint 扩张，并部署下一代 AMD Instinct MI355X GPU clusters，服务 LLM training、high-throughput inference 和 generative AI workloads。

TensorWave 披露的几个数字值得单独放出来：

- 已上线 8,192 颗 AMD Instinct MI325X GPU，是北美最大的 AMD-based AI training clusters 之一。
- 正在准备更大规模的 MI355X 部署，覆盖北美多个新数据中心区域。
- 已锁定超过 2GW long-term data center capacity。
- 已被 Fireworks AI、Luma AI 等 AI-native 客户用于大规模生成式 AI 和 production inference。
- TensorWave 自称是 exclusively powered by AMD Instinct Series GPUs 的 AI cloud。

来源：

- TensorWave / AIwire 转发新闻稿：`https://www.hpcwire.com/aiwire/2026/06/10/tensorwave-raises-350m-series-b-at-1-55b-valuation-to-expand-global-amd-powered-ai-infrastructure/`
- TensorWave 官方页：`https://tensorwave.com/blog/tensorwave-raises-350-million-series-b-at-1-55b-valuation-to-expand-global-amd-powered-ai-infrastructure`

### 背景和前因后果

过去一年 AI 算力交易的单位不断变大：GPU 小时、reserved cluster、MW、GW、长期 lease、private credit、off-balance-sheet SPV、data center power bank 同时出现。NVIDIA 生态已经通过 CoreWeave、Nebius、Nscale、IREN、Fluidstack、Applied Digital 这类主体形成“芯片 allocation + 电力 + 融资 + 长约客户”的闭环。AMD 如果只有 MI300 / MI350 / MI355X 产品发布，没有可稳定采购和运维的云算力层，客户切换成本会很高。

TensorWave 这轮融资的意义在于：AMD 开始把资金投向自己生态里的容量运营商，让企业客户能够以云服务方式接触 AMD GPU，而非自己承担全栈迁移风险。这个动作和 NVIDIA 投资、担保、订单、warrant 绑定 NeoCloud 的做法属于同一方向，但规模更小、生态更早。

项目内行业研究对 NeoCloud 的核心判断是：2026-2028 年最强的容量撮合层，需要同时拿到 GPU / ASIC allocation、电力和场址、长约客户、低成本融资、液冷 / rack 交付和高利用率调度。TensorWave 同时给出了 AMD GPU、2GW 数据中心容量、客户样本和融资支持，正好落在这个框架里。

### 为什么重要

第一，AMD 的 AI GPU 市占率问题，短期看芯片规格，长期看可用容量和迁移工具。Fireworks AI、Luma AI 这类客户若能用 AMD 云承载训练和推理，ROCm、编译器、kernel、网络、存储、调度、监控都会被真实 workload 打磨。

第二，2GW long-term capacity 说明 TensorWave 的约束已经从“有没有卡”扩展到“有没有电力和机房”。在当前美国 AI 数据中心电力接入紧张的环境下，能锁到长期容量本身就是供给壁垒。

第三，AMD Ventures 共同领投把“芯片厂商投资客户”的争议也带进 AMD 生态。市场会追问循环融资和真实需求：钱是否最终回流到 GPU 采购，客户是否愿意独立付费，利用率是否足够高，GPU 残值和下一代切换是否能覆盖债务成本。

### 业内评论和反对观点

支持观点会强调三点：企业需要 NVIDIA 之外的可用产能；MI355X 的大 HBM 容量适合 memory-intensive workloads；TensorWave 这样的专用云能把迁移难度隐藏在托管服务后面。

反对观点集中在四个问题：

- ROCm 和 CUDA 的生态差距仍会影响开发者迁移。
- MI355X 到 MI400 / MI455X 的代际切换可能压缩旧 GPU 租价。
- NeoCloud 的资本开支和融资成本高，客户合同期限必须覆盖 GPU 折旧。
- 如果 NVIDIA Rubin / GB300 供给改善，AMD 专用云的价格折扣可能扩大。

### 投资含义

可投资权重上，今天这条新闻提高了 AMD 生态链的观察优先级：

- **直接方向：AMD。** 关键跟踪 MI355X 出货、MI400 / MI455X 时间表、ROCm 生产 workload、客户案例和数据中心 GPU revenue。
- **AI cloud / NeoCloud：** TensorWave、CoreWeave、Nebius、IREN、Nscale、Lambda、Crusoe、Vultr、Together、RunPod。重点看电力容量、GPU fleet、客户长约、利用率和融资成本。
- **服务器和机架集成：** 支持 AMD Instinct 的整机、液冷、rack-scale networking、switch、DPU、存储路径。
- **开放互联和运行时：** UALink、Ultra Ethernet、ROCm、vLLM、SGLang、Kubernetes GPU scheduling、AI FinOps。
- **电力和机电：** 2GW 级容量对应高压接入、变压器、switchgear、UPS / BESS、液冷和 DCIM 订单。

未来三个月需要验证：MI355X 实际部署区域、GPU 数量、客户合约期限、是否出现公开性能基准、是否有大型企业从 NVIDIA 迁移到 TensorWave，和 TensorWave 的电力上电节奏。

## 2. DiffusionGemma：文本扩散生成把本地推理速度推到新的技术路径

### 新闻事实

2026-06-10，Google 发布 DiffusionGemma developer guide，NVIDIA 同日宣布对 DiffusionGemma 提供本地 GPU 加速支持。DiffusionGemma 建在 Gemma 4 backbone 上，是 26B Mixture-of-Experts 模型，推理时激活 3.8B 参数，使用离散文本扩散生成，生成和修正 256-token canvas。

关键数字：

- Google developer guide：GPU token generation 最高 4 倍加速。
- Google 给出 NVIDIA GeForce RTX 5090 上 700+ tokens/s、单张 NVIDIA H100 上 1000+ tokens/s。
- NVIDIA 给出单张 H100 1000 tokens/s、DGX Spark 150 tokens/s、DGX Station 最高 2000 tokens/s 的本地/工作站侧数字。
- 支持 Hugging Face Transformers、vLLM、Unsloth。
- Apache 2.0 开放权重。
- 目标 workload 包括 interactive chat、agentic loops、on-device assistants、inline editing、code infilling。

来源：

- Google Developers Blog：`https://developers.googleblog.com/diffusiongemma-the-developer-guide/`
- NVIDIA Blog：`https://blogs.nvidia.com/blog/rtx-ai-garage-local-gemma-diffusion/`
- Hugging Face model card：`https://huggingface.co/google/diffusiongemma-26B-A4B-it`

### 背景和技术前因

主流 LLM 推理长期受自回归 token-by-token 生成限制。单用户交互场景下，每生成一个 token 都要反复读权重、做注意力和采样，很多时候瓶颈在 memory bandwidth 和序列依赖，而 GPU tensor cores 没有充分吃满。

DiffusionGemma 的路线是把文本生成改成并行块生成：先用随机占位构造一块文本 canvas，再经过多轮 denoising，把高置信 token 和上下文一起收敛。这个过程让模型一次处理更大的并行工作量，瓶颈更偏 compute。对单用户本地推理、代码补全、agent tool loop、低延迟编辑器来说，这很重要。

### 为什么重要

第一，它给“推理需求会吞掉全部 AI infrastructure”增加了新的技术变量。过去讨论推理成本时，重点是更便宜的 GPU、更高 HBM、更好的 KV cache、更优 speculative decoding。DiffusionGemma 提示另一条路径：改变生成方式，让同一块本地 GPU 在低 batch、低延迟场景下产出更多 tokens。

第二，它对 AI PC 和工作站的意义高于训练集群。RTX 5090、RTX PRO、DGX Spark、DGX Station 被同时放进叙事，说明本地 AI 的体验瓶颈正在从“能不能跑”转向“是否足够快”。如果开发者把部分 coding、document editing、RAG、personal agent 放到本地，云端推理需求会被分流一部分，但本地 GPU、内存、SSD、NPU、开发工具链需求会增强。

第三，它会推动 inference runtime 的新一轮适配。vLLM、SGLang、Transformers、Unsloth、quantization kernel、NVFP4 / FP8 / INT4、scheduler、latency profiler 都要处理“块生成 + 自修正”的执行模式。运行时和可观测性会跟着调整指标：不再只看 tokens/s，也要看 block convergence、tail latency、错误修正轮数、上下文稳定性。

### 反对观点和瓶颈

Diffusion text model 的核心验证还没有结束：

- 长文本一致性、事实稳定性、工具调用格式稳定性，需要真实 agent workload 检验。
- 开放模型速度高，不等于复杂任务质量接近闭源 frontier model。
- 单用户速度提升明显，batch serving、企业多租户和高并发吞吐是否同样受益，还要看调度器和服务框架。
- 如果 denoising passes 增加，延迟优势可能被质量要求吃掉。
- 对 GPU 的 compute utilization 友好，也会提高功耗密度和散热压力。

### 投资含义

这条新闻提高了三类资产的权重：

- **本地 AI hardware：** NVIDIA RTX / RTX PRO / DGX Spark、工作站 OEM、高速内存、NVMe SSD、本地向量库、AI PC 生态。
- **推理运行时和 kernel：** vLLM、SGLang、Transformers、Unsloth、Triton、TensorRT-LLM、quantization、compiler、GPU profiler。
- **低延迟应用：** coding agent、IDE 插件、文档编辑、个人知识库、本地 RAG、隐私敏感企业部门。

需要继续验证：DiffusionGemma 在代码补全、长上下文、多轮 tool calls、中文任务、RAG 格式输出、函数调用和 batch serving 上的质量。若质量足够，推理成本模型要新增“文本扩散 / parallel decoding”情景；若质量只能服务辅助编辑，它仍然会强化本地 AI PC 和工作站路线。

## 3. 数据中心从建设狂潮进入 ratepayer、监管和信息战阶段

### 新闻事实

2026-06-10，德州州长 Greg Abbott 指示 Public Utility Commission of Texas 和 ERCOT 采取措施，保护居民用户免于承担数据中心扩张带来的电力基础设施成本。公开指令要求：

- PUC 要求数据中心 fully fund 服务其运营所需的 electric infrastructure costs，防止成本转嫁给居民 ratepayers。
- PUC 和 ERCOT 在 2026-07-17 前向州长办公室提交联合备忘录，提出进一步措施。
- PUC 在 2026-07-31 前启动降低居民 transmission costs 的行动。

同一天，OpenAI 发布报告，披露两组 likely originating from China 的 ChatGPT 账户被封禁。其中一个被命名为 Data Center Bandwagon，生成英文和中文社媒评论与图片，围绕 AI data center buildouts、家庭电价和地方影响塑造叙事；另一个被命名为 Tech and Tariffs，围绕美国关税和科技政策生成内容，并关联到针对 OpenAI 的虚假数据泄露叙事。OpenAI 表示未发现这些行动有 meaningful breakout beyond its own activity。

2026-06-11，Axios 报道国会议员正在抓住数据中心 backlash，相关议案从研究评估到更硬限制均有出现。地方层面，Nashville Zoo 旁边的数据中心反对也在过去 24 小时继续升温。

来源：

- Texas Governor press release：`https://gov.texas.gov/news/post/governor-abbott-directs-puc-and-ercot-to-shield-texans-from-data-center-infrastructure-costs`
- Texas Tribune：`https://www.texastribune.org/2026/06/10/texas-greg-abbott-data-centers-regulation-sales-tax/`
- OpenAI：`https://openai.com/index/prc-linked-influence-operations-ai-debates/`
- Axios：`https://www.axios.com/2026/06/11/data-centers-ai-congress-bresnahan-bill`

### 旧主题新增 delta

2026-06-07 的底稿已经覆盖纽约州 20MW 以上数据中心法案，主题是州级许可暂停、影响评估和 data center moratorium。今天的 delta 是德州。德州是美国最重要的数据中心、电力和大型 AI 工厂州之一，政策基调从招商引资走向“数据中心自付电力扩容成本、节水、透明和成本隔离”。这比纽约的政治信号更接近核心 AI infrastructure 地带。

OpenAI 的报告又把争议推向信息安全层：数据中心反对运动中有真实地方利益，也有外部 actor 测试如何放大电价、用水和社区冲突。这会让未来的数据中心审批更像关键基础设施审批，涉及 public affairs、cyber influence monitoring、社区补偿、电网成本分摊、能源采购和水资源约束。

### 为什么重要

第一，数据中心的“可上电 MW”已经成为 2026-2027 AI 产业链第一闸门。项目内电力接入行业研究判断：AI 园区的串联链路从 interconnection、高压开关站、主变、中压开关柜、UPS / BESS / 发电，到低压母线和 rack power shelf，任一段延迟都能把 GPU 变成未通电资产。

第二，政策风险会改变数据中心经济模型。过去 hyperscaler 和数据中心开发商能通过税收优惠、utility cost-sharing、长期电力合同和社区承诺加速项目。德州的新方向意味着大型数据中心要承担更多 upfront infrastructure cost，项目 IRR、租约价格、客户保证金、PPA、BESS 和现场发电配置都会变化。

第三，反对力量和信息战会增加审批周期不确定性。真实社区反对会围绕电价、噪音、空气、水、土地、税收优惠和就业质量展开；外部舆论行动会利用这些议题制造放大效应。数据中心运营商要把 public legitimacy 当成交付能力的一部分。

### 投资含义

今天这组消息提高了以下方向的权重：

- **电力接入和高压变电：** Eaton、Schneider、Siemens Energy、GE Vernova、ABB / Hitachi Energy、Powell、Hubbell、Hyundai Electric、Mitsubishi Electric、Virginia Transformer、Delta Star、SEL 等。
- **现场发电和储能：** gas turbine、fuel cell、BESS、grid-forming inverter、microgrid controller、demand response。数据中心自付基础设施后，bridge power 和 flexible load 会更有预算。
- **节水和冷却：** closed-loop liquid cooling、CDU、dry cooler、冷却液、水处理、漏液监控、热遥测。德州和亚利桑那这类地区的水约束会进入 RFP。
- **DCIM / EPMS / 能控：** 数据中心需要证明自身对电网和居民的影响，实时功率、负荷曲线、water usage、PUE、tokens-per-watt、demand response 能力会成为监管和社区沟通素材。
- **开发商分化：** 已有电力路径、能够自带电力、愿意承担 upgrade cost、能签长约客户的开发商权重提高；依赖税收优惠、utility 兜底和宽松许可的项目折现率上升。

### 风险和待验证点

- 德州指令是否转化为具体 PUC / ERCOT 规则，2026-07-17 和 2026-07-31 是两个观察节点。
- 立法层面是否取消或限制数据中心销售税优惠，税收节省变化会直接影响新项目现金流。
- 数据中心能否通过自备电、储能和 demand response 获得更快 interconnection。
- PRC-linked 影响行动规模目前有限，未来要看是否出现更复杂的跨平台协同。
- 国会层面法案通过率仍偏不确定，但地方和州级规则已经足以影响项目排队。

## 4. NextSilicon Arbel：RISC-V 控制平面开始争夺 AI/HPC 服务器 CPU 位置

### 新闻事实

2026-06-10，NextSilicon 宣布将 Arbel RISC-V core 产品化为 64-core 和 128-core enterprise-grade processor，面向 AI 和 HPC，目标早期可用时间为 2028 年初。公司称该路线来自 Arbel test chip 的客户和伙伴验证，公告配合 RISC-V Summit。

技术细节：

- Arbel 原本作为 Maverick-2 accelerator platform 内部控制 processor，用于处理 serial logic 和 data movement。
- 公司用 TSMC 5nm 制程制造了 standalone Arbel test chip。
- test chip 采用 10-wide instruction-issue pipeline、480-entry reorder buffer，最高每周期退休 16 条 scalar instructions。
- 配备 4 个 128-bit vector units，支持 AI inference 等 data-parallel workloads。
- test chip 时钟达到 2.5GHz。
- 生产处理器目标扩展到 64 / 128 performance cores，目标频率 3.4GHz，迁移到更先进制程。
- 支持 RVA23 compliance 和标准 Linux distributions。

来源：

- Business Wire：`https://www.businesswire.com/news/home/20260610101195/en/NextSilicon-to-Productize-Arbel-RISC-V-Core-Into-64-Core-Enterprise-Processor-for-AI-and-HPC`

### 背景和产业链位置

Arbel 把 RISC-V 带进这个叙事。agentic AI 的特点是多轮调用、工具执行、代码运行、RAG、sandbox、storage、network 和权限检查交织在一起。许多步骤无法完全并行化，需要主机 CPU 做低延迟、分支密集、系统调用密集的控制工作。NextSilicon 的说法是，agentic AI 会提高对更强 CPU 的要求。

第三，如果 Arbel 作为 Maverick accelerator host processor 成功，它会形成异构平台：RISC-V host + dataflow accelerator + HPC / AI workload。对主权 AI、HPC center、开源硬件和去授权锁定客户有吸引力。

## 5. Linux Foundation OpenSharing：agent skills、AI models 和非结构化数据开始进入开放交换协议

### 背景和前因后果

过去三个月，企业 agent 的协议层快速膨胀：MCP 负责工具接入，A2A 负责 agent 间通信，Agent Name Service 处理身份和发现，云厂和 SaaS 厂商各自推出 connector、marketplace、agent skill 和企业数据接口。问题也同步出现：企业数据在 Snowflake、Databricks、BigQuery、S3、Iceberg、Delta、on-prem object storage、CRM、ERP、文件系统之间分散，agent skill 和模型资产又开始被平台锁住。

OpenSharing 的切入点是资产交换，而非单次工具调用。它把 agent skills、AI models、unstructured data volumes 放到同一套开放共享框架里。若能落地，企业可以把“数据产品 + 模型 + agent skill”封装成可治理、可审计、可跨平台消费的资产。

### 为什么重要

第一，agent 进入生产后，价值同时来自模型调用、企业专有数据和技能的分发效率。销售 agent、理赔 agent、投研 agent、法务 agent、供应链 agent 都需要可靠访问外部和内部 data products。

第二，开放协议会改变数据平台竞争。Databricks 贡献该协议有战略含义：它希望 Delta Sharing 的成功路径扩展到 agentic AI 时代，并把 Iceberg recipients、on-prem providers、AI assets 纳入同一生态。Snowflake、Databricks、Google、AWS、Microsoft、MongoDB、Elastic、Confluent、Redis、向量数据库、数据目录和权限治理厂商都要回应。

第三，AI 资产会逐渐金融化和商品化。模型、工具、提示、评估、数据集、RAG 知识库、行业技能包都可能被计价、授权、审计和复用。OpenSharing 如果被大型数据供应商和 regulated industries 采用，会推动“agent skill marketplace”从应用商店样式走向数据基础设施样式。

### 投资含义

受益方向：

- **数据平台：** Databricks、Snowflake、Google BigQuery、Microsoft Fabric、AWS、MongoDB、Elastic、Confluent。

- **行业数据资产：** 金融、保险、医疗、地产、供应链数据提供商。
- **agent 应用平台：** 需要跨组织调技能、模型和数据的企业工作流平台。

风险是协议太多。MCP、A2A、OpenSharing、各云 marketplace、SaaS connector 和内部 API 都在争夺标准位置。OpenSharing 的关键在于从公告走向 GitHub spec、SDK、认证、权限模型、审计日志、计费和大型客户落地。

### 待验证点

### 反对观点和待验证点

这份报告由 New Relic 发布，天然有 observability 供应商视角。样本只有 200 人，且是美国 upper mid-market / enterprise 决策者。它说明企业感知和采购方向，但不能单独证明所有 AI coding 都在增加缺陷。

- AI coding 工具是否会原生加入更强测试、telemetry 和 policy，压缩第三方平台空间。
- 企业是否愿意为 AI code observability 单独付费，还是把它并入现有 APM / DevOps 套餐。
- Senior engineer rework 是否在模型和流程升级后下降。

这对 AMD 是加分项，但还不能把结论推得太远。ROCm 和 CUDA 的生态差距仍然会影响迁移；MI355X 的真实部署数量、客户合同期限、利用率和价格折扣都还要验证；如果 NVIDIA Rubin 和 GB300 供给改善，AMD 专用云可能需要给出更明显的性价比。可投资链条上，最直接当然是 AMD，其次是 AMD Instinct 服务器、液冷、网络、存储、GPU 调度、vLLM、SGLang、ROCm、开放互联、电力设备和数据中心运营商。未来几个月最值得盯的是 TensorWave 有没有披露 MI355X 的上电节奏、客户名单、生产 workload 指标，以及 Fireworks、Luma 这类客户是否愿意把更多推理和训练转到 AMD 云上。

第二条，Google 和 NVIDIA 推出 DiffusionGemma。它是基于 Gemma 4 backbone 的 26B Mixture-of-Experts 文本扩散模型，推理时激活3.8B参数，用离散文本扩散方式生成和修正256-token canvas。Google 给出的数字很醒目：在 RTX 5090 上可以超过700 tokens/s，在单张 H100 上超过1000 tokens/s。NVIDIA 也给出本地 GPU 和 DGX 工作站侧的加速支持，并且模型以 Apache 2.0 开放权重，支持 Hugging Face Transformers、vLLM 和 Unsloth。

这条新闻重要，因为它改变了文本生成的工程假设。主流大语言模型长期按 token 一个接一个生成，前一个 token 没出来，后一个 token 很难真正开始。这种自回归路径在单用户低延迟场景里容易被 memory bandwidth、序列依赖和 KV cache 限制住。DiffusionGemma 选择另一种方式：先把一段文本看成一块待修正的画布，再经过多轮 denoising，把不确定的 token 一步步收敛到更可靠的答案。这样 GPU 可以一次处理更多并行工作，瓶颈更偏向 compute，tensor cores 的利用率有机会提高。

如果它在质量上站得住脚，本地 AI 和低延迟推理的成本模型要重算。过去我们说推理需求会持续压迫云端 GPU，优化路线通常是更大的 batch、更好的 speculative decoding、更高 HBM、更强 cache 和更便宜的推理芯片。DiffusionGemma 加了一条路：改变生成方式，让单个用户、单张显卡、单个工作站也能获得很高 tokens/s。它尤其适合几个场景：IDE 里的代码补全和改写、文档 inline editing、本地 RAG、个人 agent、隐私敏感的企业助理，以及需要快速试错的 agent loop。

这也会推动运行时和开发工具链重新适配。vLLM、SGLang、Transformers、Unsloth、Triton、TensorRT-LLM、量化 kernel、GPU profiler 过去大多围绕自回归解码做优化。文本扩散模型需要看 block convergence、denoising passes、tail latency、格式稳定性、工具调用正确率和长文本一致性。只看 tokens/s 会不够，因为速度高但输出格式不稳，agent 调工具时仍然会失败。

投资上，短期受益最清楚的是 NVIDIA 的本地 GPU、RTX PRO、DGX Spark、工作站 OEM、AI PC、内存、SSD、推理 runtime 和低延迟应用层。长期要看这种路线会不会分流一部分云端推理需求。如果本地模型能完成代码补全、文档编辑、个人知识库和小型 agent loop，云端大模型会更多承担高难任务、长上下文和跨系统编排，本地设备则承担高频交互。风险也很明显：开放模型的速度不等于复杂任务质量，长文本一致性、事实稳定性、中文能力、函数调用、RAG 引用、batch serving 都还需要真实 benchmark。今天先把它当作推理技术路径的强信号，距离马上改写全部算力需求还需要更多验证。

第三条，是德州、国会和 OpenAI 同一天把 AI 数据中心带进了一个新阶段。德州州长 Greg Abbott 指示 Public Utility Commission of Texas 和 ERCOT 采取措施，要求数据中心 fully fund 服务其运营所需的电力基础设施成本，防止成本转嫁给居民用户。PUC 和 ERCOT 要在2026年7月17日前提交联合备忘录，PUC 还要在7月31日前启动降低居民 transmission costs 的行动。与此同时，OpenAI 披露了两组 likely originating from China 的影响行动，其中一个叫 Data Center Bandwagon，专门围绕 AI data center、家庭电价和地方影响生成英文与中文社媒内容。Axios 也报道国会议员开始抓住 data center backlash 推进相关议案。

这组新闻的核心，是 AI 数据中心的瓶颈从设备和融资扩展到社会许可。过去市场最关心的是谁拿到 GPU、谁签了 MW、谁有租户、谁能融资。现在要加上几个问题：居民电价由谁承担，输电扩容谁付钱，水资源怎么解释，地方社区能得到什么，外部舆论行动会不会放大真实矛盾，州政府和国会会不会把数据中心当成电网和国家安全问题来管理。

德州这个信号尤其重要。纽约州的数据中心法案已经说明蓝州监管会更强，但德州是美国 AI 数据中心、电力和能源开发的重要州。如果德州也要求大型数据中心把基础设施成本更清楚地内部化，项目经济模型会变。原来可以通过 utility cost-sharing、税收优惠和宽松许可推进的项目，现在要更多承担 upfront infrastructure cost。开发商要重新计算 IRR，租户要重新看租约价格和保证金，电力设备、BESS、现场发电、需求响应、节水冷却和 DCIM 预算都会上升。

这里面最值得投资人关注的是可上电 MW 的溢价会继续提高。AI 产业链表面上是模型和芯片，落地时是 interconnection、高压开关站、主变、中压开关柜、UPS、BESS、发电机、busbar、液冷、冷却塔、楼宇控制和实时能耗监控。谁能更快拿到电，谁能证明不让居民承担过多成本，谁能通过自备电和储能给电网提供弹性，谁就更可能拿到租户和融资。Eaton、Schneider、Siemens Energy、GE Vernova、ABB / Hitachi Energy、Powell、Hubbell、Hyundai Electric、Mitsubishi Electric、Vertiv、nVent、Quanta Services、EMCOR、Comfort Systems、燃气轮机、BESS、CDU、dry cooler、水处理和 EPMS 都在这条线上。

OpenAI 披露 PRC-linked influence operation 也不能轻描淡写。报告里说这些行动还没有形成 meaningful breakout，但方向很清楚：数据中心会成为外部 actor 试图放大美国内部矛盾的议题。真实社区反对和外部信息行动会交织在一起。数据中心公司以后需要 public affairs、社区补偿、透明电价、用水披露、舆情监测和网络安全能力。这个变化会提高头部开发商的门槛，也会让资金更偏向已经有电力路径、地方关系和合规能力的项目。

第四条，Linux Foundation 启动 OpenSharing。这项工作由 Databricks 贡献，目标是提供开放、vendor-neutral 的 AI asset 和 data exchange protocol，把 agent skills、AI models、unstructured data volumes 纳入共享协议，并扩展到 Delta Sharing 和 Apache Iceberg recipients。

企业 agent 现在有一个很现实的问题：模型可以调用工具，工具可以接数据，但每家公司内部的数据、模型、技能、权限和审计都分散在不同平台。MCP 解决的是工具接入的一部分，A2A 解决的是 agent 协作的一部分，OpenSharing 关注的是资产交换。以后一个销售 agent、理赔 agent、投研 agent、供应链 agent，价值可能来自一组可授权的数据产品、一个行业模型、几个经过验证的技能包和一套权限规则。OpenSharing 想把这些东西变成可跨平台消费、可治理、可审计的资产。

Databricks 把它贡献给 Linux Foundation，有明显战略含义。Delta Sharing 已经是 Databricks 生态的重要开放协议，现在它希望在 agentic AI 时代把 Delta、Iceberg、非结构化数据、模型和 skill 都纳入同一张网。受益方向包括 Databricks、Snowflake、Google BigQuery、Microsoft Fabric、AWS、MongoDB、Elastic、Confluent、MinIO、Pure Storage、Dell、NetApp、VAST Data、WEKA、数据目录、权限治理和行业数据资产。风险是协议太多，企业会担心 MCP、A2A、OpenSharing、云厂 marketplace 和 SaaS connector 各说各话。后面要看 GitHub spec、SDK、权限模型、签名、撤销、审计、计费，以及 Snowflake、AWS、Microsoft、Google 这类大平台是否加入。

第五条，New Relic 发布 2026 State of AI Coding report，把 AI coding 的后治理问题量化了。调查对象是200名美国 upper mid-market 和 enterprise 技术决策者。几个数字很直接：78% 报告 incidents 增加，86% 报告 senior staff 花更多时间修复代码，74% 表示过去12个月至少25%的 AI code 需要 significant rework，82% 在过去6个月经历过 AI-generated code 相关 production failure，96% 认为 observability 在 AI-generated code 场景里非常重要或极其重要。

昨天已经讲过 agent observability、model routing、MCP security 和代码治理，今天这条的新增价值在于给预算问题补上数字。AI coding 第一阶段卖的是速度，第二阶段企业会问谁来承担维护、故障、回滚、测试、日志、trace、权限和安全供应链成本。New Relic 把这个叫 agent debt。这个说法很贴切：代码初看清晰、能跑、交付快，但如果边界条件没测、telemetry 没埋、架构假设没人复核，上线后就会把债务转给 senior engineer、SRE 和安全团队。

这会改变企业采购。coding agent 的预算会从 developer productivity 延伸到 Datadog、Dynatrace、New Relic、Grafana、Splunk、Elastic、Sentry、GitHub、GitLab、Atlassian、JetBrains、Sourcegraph、Sonar、Snyk、Semgrep、Black Duck、LaunchDarkly、Harness、CI、canary、rollback 和 LLM eval。报告本身有供应商视角，样本也只有200人，不能单独证明全部 AI coding 都在制造缺陷。但它很有用，因为它说明企业决策者已经把 AI code 的事故、返工和观测预算放到同一张表里。

最后两条做快讯。NextSilicon 宣布把 Arbel RISC-V core 产品化为64核和128核 AI/HPC 企业处理器，目标早期可用时间是2028年初。它的收入窗口偏远，可投资性现在不高，但方向值得跟踪。AI 服务器越来越像异构系统，GPU、ASIC、CPU、DPU、PCIe / CXL、retimer、BMC、firmware、telemetry 和安全根都要协同。agentic AI 会增加工具调用、代码运行、sandbox、RAG、存储和网络编排，主机 CPU 和控制平面的价值会被重新讨论。公开公司里，Arm、AMD、Intel、NVIDIA Grace、Broadcom、Marvell、Astera、Synopsys、Cadence、Rambus、Microchip 和 Montage 都可以作为长期映射。

Anthropic 推出1.5亿美元 Claude Corps，计划训练1,000名 early-career fellows，并把他们派往美国非营利组织一年。AP 补充说项目覆盖400多家 host organizations，并提供1万美元 grant 和免费 Claude credits。这条新闻商业化信号弱，硬件拉动也弱，但它说明模型公司开始为社会采用层付费。很多非营利、教育和公共服务机构缺少 AI adoption 人才，Claude Corps 等于把培训、prompting、workflow redesign、change management 和 responsible use 打包成一套外部部署实验。短期只作为公共部门、公益 AI、培训服务和模型公司社会合法性的观察项。
