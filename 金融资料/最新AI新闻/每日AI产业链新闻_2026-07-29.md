### 4. MCP 2026-07-28 final：无状态协议的迁移成本

- **破坏性delta：** HTTP session、`Mcp-Session-Id`和initialize握手被移除；每个请求需自包含协议版本与能力。原有server/client状态管理假设需重做。
- **新能力：** `server/discover`降低预配置需求；`subscriptions/listen`支持长连接更新；MRTR `InputRequired`允许请求更多用户输入；list响应增加`ttlMs/cacheScope`。
- **弃用项：** Roots、Sampling、Logging、HTTP+SSE和DCR退场，JSON Schema升级至2020-12。
- **产业影响：** host、SDK、server、gateway和企业代理平台需要同时验证版本协商、缓存、发现、订阅重连和授权。迁移不同步可能表现为静默能力缺失、反复重试或错误的权限假设。
- **安全边界：** 规范要求用户理解并同意，协议本身无法证明或执行同意；discover扩大了可见server面，需身份、allowlist、签名和审计配合。
- **生态实证：** MCPApps扫描1,723个公开GitHub应用，blocking approval为37.2%，config、官方SDK、logging和enable/disable均明显更高。样本来自公开仓和静态声明，适合显示控制落差，不适合估算全体生产部署。
- **下游验证：** 官方SDK支持矩阵、旧版兼容桥、真实host/server互操作、断线恢复、proxy/cache行为和生产迁移事故。
- **不应重复：** MCP生态规模、既有安全事故和旧版transport机制只保留最短基线。

### 6. 开放推理栈：五种失效机制需要不同验收

| 失效 | 触发与表现 | 当前状态 | 最小验收 |
|---|---|---|---|
| FlashInfer route-map OOB | 每次launch多读1个int32；guard page fault；整模autotune崩 | 已合main，未进rc4 | memcheck、guard page、整模autotune、多GPU/shape |
| PyTorch AO MXFP8 partial tile | scale损坏、race、越界2,048 bytes | open PR | scale完整性、多seed、partial tile、B200之外硬件 |
| vLLM Gemma-4 expert LoRA | 无报错、expert delta全失效 | open PR | module级delta、端到端质量、未命中日志 |
| vLLM NaN rejection sampler | 全NaN→padding OOB→illegal memory | open PR | NaN注入、错误隔离、warmup与生产负载 |
| SGLang调度饥饿 | 长prefill使decode约24秒才获一次batch | open PR | 混合长短请求、P50/P99、公平性与吞吐 |

- **共同判断：** “进程启动”和“目标模型可答”不足以证明量化、LoRA、spec decode、调度和内核路径正确。每类路径都需专门的语义、内存和时延验收。
- **口播边界：** open PR表示已定位和提出修复，不能写成稳定版已解决。用户复现和作者硬件数据的证据等级高于猜测，仍低于跨环境独立复现。

### 7. 企业与GUI agent评测：路由、状态和答案要分开

- **Desktop-Delta：** 最佳状态变化exact match约65%，拖拽识别弱于点击；上下文有时改善decoy、有时拖累正常样本，说明过程顺序可能形成捷径。
- **WorkSurface-Bench：** gold工具约束下路由近乎满分，答案正确率仍只有56.1%—75.3%，说明取对源之后还存在聚合、推理和生成损失。
- **RSIBench-Data：** 自主研究agent继续搜索常从峰值回退，说明优化过程还需checkpoint选择和密封评估。
- **组合机制：** 生产验收至少分为观察状态、选择来源、执行动作、生成答案、验证结果、保存/回滚六层。单一end-to-end success会掩盖具体失败位置。
- **验证问题：** 是否使用真实权限和脏数据；任务长度、动作成本与人工接管；状态变化能否触发恢复；评分是否保留失败类型和最佳checkpoint。

### 8. GitHub供应链控制：从发现到发布与执行闸门

- **发布层：** npm在新包可安装前执行恶意软件扫描，正常约5分钟、峰值可达15分钟以上；结果可放行、暂扣或阻断。
- **声明层：** 双用途内容需`contentPolicy`和根目录`DISCLOSURE`，进入额外扫描/人工复核并强制2FA发布。
- **执行层：** GitHub Actions对疑似恶意公共仓库工作流设置写权限协作者批准。
- **消费层：** Dependabot接入OpenSSF malicious-packages，扩展到PyPI等生态。
- **真正新增：** agent依赖、skill和自动化工作流的供应链风险开始进入平台默认控制，不再只依赖用户自行审计。
- **边界和验证：** Actions控制只覆盖github.com公共仓库；私有仓库、GHES、误报漏报、攻击适应、人工复核SLA与申诉透明度未披露。
