## 今日新增主线

1. **Google 与 Blackstone 把 TPU 从 Google Cloud 内部能力拆成独立算力资产。** Blackstone 5 月 18 日宣布与 Google 成立美国合资公司，提供数据中心容量、运营、网络和 Google Cloud TPU 的 compute-as-a-service；Blackstone 初始股权承诺 50 亿美元，目标 2027 年上线首批 500MW 容量。核心变化是：TPU 不再只是 Google Cloud SKU，而开始像 GPU 云、数据中心、电力容量一样被资本化、项目化、长期合同化。

2. **NVIDIA Vera CPU 从路线图进入顶级实验室实物交付。** NVIDIA 5 月 18 日披露，Ian Buck 已把首批 Vera CPU 系统送到 Anthropic、OpenAI、SpaceXAI，并在 5 月 18 日送到 Oracle Cloud Infrastructure。Vera 的关键规格包括 88 个自研 Olympus cores、1.2TB/s 内存带宽、满载下单核性能快 50%；NVIDIA 明确把它定位为 agentic AI 的 CPU，用于 orchestration、tool calling、RL workloads、data analytics、agent sandboxing 和 long-context state management。

3. **Dell Technologies World 把“本地 AI factory”推成企业 agent 的主战场。** NVIDIA/Dell 披露：Dell AI Factory with NVIDIA 已有 5000 家企业客户；Vera Rubin NVL72 面向大规模 agentic inference 可把 cost-per-token 降到 Blackwell 的十分之一；Dell PowerEdge XE9880L/XE9885L/XE9882L 是首批基于 HGX Rubin NVL8 的 Dell 系统，支持每 rack 最高 144 GPUs、100% direct liquid-cooled compute nodes，并声称性能最高为 HGX B200 的 5.5 倍。Dell 同时发布 PowerRack、Deskside Agentic AI、面向 Google/OpenAI/Palantir/SpaceXAI 模型的本地部署支持。

4. **OpenAI 与 Dell 让 Codex 贴近企业内部数据和系统。** OpenAI 5 月 18 日公告，Codex 将连接 Dell AI Data Platform，使 Codex 更靠近企业内部 codebase、文档、业务系统、运营知识和团队流程；双方还将探索 Codex、ChatGPT Enterprise 和 API solutions 与 Dell AI Factory 的接口。这个增量是：coding agent 走出 IDE 和云端任务队列，开始进入企业本地治理数据层。

5. **Anthropic 收购 Stainless，抢的是 agent 连接层。** Anthropic 5 月 18 日宣布收购 SDK 和 MCP server tooling 公司 Stainless。Stainless 官方同步说明将停止 hosted Stainless products，包括 SDK generator，新 signup、project 和 SDK 不再开放。Anthropic 的关键叙事是：frontier AI 正从“回答问题的模型”转向“执行动作的 agents”，而 agent 的能力取决于它能触达哪些系统。

6. **Cursor Composer 2.5 发布，coding agent 的竞争进入“后训练与长任务行为”阶段。** Cursor 5 月 18 日发布 Composer 2.5，称其相对 Composer 2 在 intelligence 和 behavior 上有显著改善，尤其针对 long-horizon agentic tasks。重要性不在一个新 coding 模型本身，而在于 Cursor 正证明：在不更换底层大厂模型入口的情况下，面向真实 IDE 行为的 RL/post-training 可能形成产品差异。

7. **IBM Research/Hugging Face 发布 Open Agent Leaderboard，agent 评测从模型分数转向系统分数。** 5 月 18 日发布的 Open Agent Leaderboard 把 full agent system 作为评测对象，覆盖 SWE-Bench Verified、BrowseComp+、AppWorld、tau2-Bench Airline/Retail、tau2-Bench Telecom 等六类任务，并同时报告质量和成本。论文结论包括：agent architecture 可在同一模型内带来最高 12 个百分点差异，失败任务成本比成功任务高 20%-54%，open-weight models 在某些 agent 架构或任务上出现 “generality sinks”。

8. **CrossMPI 显示多模态 agent 的安全边界比文本 prompt injection 更脆弱。** Xidian University 等作者提交的 CrossMPI 论文显示，图像中的近不可见扰动可以改变大视觉语言模型对文本和视觉输入的联合解释。CSO 报道称，该方法在多个开源 LVLM 上平均攻击成功率 66.36%，比既有 baseline 高约 41 个百分点；SmoothVLM 可把若干场景攻击成功率降到 5% 以下，但没有一种测试防御能完全消除攻击。

9. **Musk v. OpenAI 诉讼结果移除一个资本市场不确定性，但暴露 AI 治理依赖少数人的现实。** 5 月 18 日陪审团一致认定 Musk 对 OpenAI、Sam Altman、Greg Brockman 和 Microsoft 的诉讼超过诉讼时效。AP 报道称，OpenAI 这家估值 8520 亿美元的公司仍在朝可能的大型 IPO 前进；Cornell 的 Sarah Kreps 认为，审判提醒人们 AI 的未来仍很大程度依赖极少数强势科技人物及其个人竞争。

## 创新性、前瞻性、超出想象的观点

- **算力将不再按“云厂商”分类，而按“资产组合”分类。** 企业会同时买 Google TPU 合资云、NVIDIA GPU neocloud、on-prem Dell AI Factory、主权 AI 机房和边缘 agent workstation。未来 CIO 买的不是云服务，而是可用 token 产能、延迟、治理边界、数据位置和长期电力成本。
- **agent 时代让 CPU 重新变成战略芯片。** 训练时代大家只盯 GPU；agent 时代大量时间花在工具调用、代码执行、数据库查询、沙盒、检索、状态管理和并发调度。Vera 的出现说明，GPU 利用率可能被 CPU、内存带宽和 agent runtime 拖住。
- **MCP/SDK/API 连接层会成为模型公司新的护城河。** Anthropic 收 Stainless 不是普通 devtools 收购，而是把 agent 从“会说话”推进到“能可靠调用世界”的基础层。谁掌握接口生成、MCP server tooling、权限、审计和开发者体验，谁就能决定 agent 真正能做多少事。
- **coding agent 的胜负越来越像自动驾驶：不是单次能力，而是长程行为。** Cursor Composer 2.5、Codex-on-Dell、Claude Code 和 Copilot CLI 的竞争点会从“能不能写对一段代码”转成“能不能在一天内稳定跑任务、低成本失败、留下可审计轨迹、适配企业权限”。
- **agent benchmark 必须把失败成本当作一等指标。** IBM/HF 的 20%-54% 失败成本溢价很关键：生产环境里，失败不是 0 分，而是烧钱、占队列、污染状态、拖慢人类审查。未来 agent 基础设施会有“快速失败”“低成本探索”“可恢复状态”设计。
- **多模态安全的难点从隐藏文字升级为隐藏扰动。** CrossMPI 的可怕之处是，即使文本被完全清洗，图像本身也可能改变模型的任务理解。未来浏览器 agent、文档 agent、视频巡检 agent、机器人 agent 都需要视觉输入防火墙。
- **AI 产业链正在从“最大模型”转向“最大可治理系统”。** Dell/NVIDIA/OpenAI/Anthropic/Google 的新增动作共同说明：谁能把模型、芯片、数据中心、电力、连接协议、企业数据、安全审计和本地部署串起来，谁才接近真正的生产入口。

## 新闻口播稿

今天的 AI 产业链，最重要的变化不是某一个模型分数刷新，而是整条基础设施开始重新分层。过去我们说 AI，第一反应是模型公司、GPU、HBM、CoWoS、液冷、电力和数据中心。但今天的新增信息把一个更清晰的框架摆出来：AI 正在从“谁的模型最强”，进入“谁能组织最大、最稳定、最低成本、最可治理的智能生产系统”。这个系统里面，芯片只是第一层，电力只是第二层，连接协议、企业数据、安全、agent runtime、CPU、内存、推理成本、失败成本，全都开始成为核心变量。

第一条主线，是 Google 和 Blackstone 的 TPU 合资云。5 月 18 日，Blackstone 宣布与 Google 成立一家新的美国公司，提供数据中心容量、运营、网络，以及 Google Cloud 的 Tensor Processing Units，也就是 TPU，作为 compute-as-a-service。关键数字非常硬：Blackstone 初始股权承诺 50 亿美元，目标是在 2027 年让首批 500MW 容量上线，并计划之后显著扩张。Google 会提供 TPU 硬件、软件和服务。新公司的 CEO 是 Benjamin Treynor Sloss，他在 Google 做了二十多年全球基础设施和运营。

这条新闻的创新点在于，它把 TPU 从 Google Cloud 的内部能力，变成了一个可以由私募资本融资、建设、运营、售卖的独立 AI 基础设施平台。过去企业想用 Google TPU，大体上是在 Google Cloud 的消费模型里买。现在，Google 和 Blackstone 等于承认：AI 算力已经大到不再只是 hyperscaler 云产品，而是一类需要金融工程、能源开发、数据中心运营、长期合同和芯片供应共同组织的基础设施资产。

这对 NVIDIA 不是直接替代，但对产业结构很重要。未来企业采购 AI 算力，可能不再问“我用哪一家云”，而会问“我的 agent 工作负载应该放在哪个容量组合里”：一部分用 NVIDIA GPU 云，一部分用 Google TPU 合资云，一部分用企业本地 Dell AI Factory，一部分放在主权 AI 机房，一部分放在边缘设备。AI compute 会像电力采购一样，从单一供应商模式走向 portfolio management。训练让 headlines 变得好看，推理让 invoices 变得真实。长期能不能便宜、稳定、合规地持续供应 token，会比一次 benchmark 更重要。

第二条主线，是 NVIDIA Vera CPU 真正进入顶级 AI 实验室。5 月 18 日，NVIDIA 披露，Ian Buck 已把首批 Vera CPU 系统交付到 Anthropic、OpenAI、SpaceXAI，并在周一交付到 Oracle Cloud Infrastructure。这个动作看起来像公关，但里面的技术信号很强。Vera 是 NVIDIA 第一颗 custom CPU，面向 agentic AI 设计，规格包括 88 个自研 Olympus cores、1.2TB/s 内存带宽、满载下单核性能快 50%。NVIDIA 列出的目标工作负载不是传统 CPU 的办公和数据库，而是 orchestration、tool calling、reinforcement learning workloads、data analytics、agent sandboxing 和 long-context state management。

这说明 agent 时代正在制造一个新的 CPU moment。训练时代大家几乎只盯 GPU，因为矩阵乘法是主战场。但 agent 不只是生成文字。一个真实 agent 要读文件、查数据库、跑 Python、调用 API、启动浏览器、执行测试、检索长上下文、维护状态、排队调度子任务、处理失败、再把结果喂回模型。GPU 负责模型前向计算，但这些周边动作大量落在 CPU、内存、I/O、网络和 runtime 上。NVIDIA 在博客里说得很直白：agents 不只跑在 GPU 上；每个 sandbox、每个 tool call、每个 orchestration layer、每个 long-context retrieval，都是 CPU work。

这件事对硬件投资框架很重要。过去大家把 AI 芯片想成“GPU 越多越好”。但如果 agent 工作负载越来越多，单纯堆 GPU 可能会被 CPU、内存带宽、数据库查询、代码沙盒和状态管理拖住。Vera 的出现说明，AI factory 的效率不只取决于每秒多少浮点运算，还取决于整个 agent 循环能不能少等待、少上下文切换、少排队、少失败。未来最贵的不是某一次模型推理，而是一个长程 agent 在几小时内反复试错、跑工具、查资料、生成代码、验证结果的总成本。

第三条主线，是 Dell Technologies World 上 NVIDIA 和 Dell 对企业 AI factory 的完整包装。NVIDIA 的报道给出几个非常夸张的数字：Dell AI Factory with NVIDIA 已经有 5000 家企业客户；全球 AI infrastructure spending 到 2030 年可能达到 3 到 4 万亿美元；token consumption 到 2030 年可能增长 3400%。Jensen Huang 在台上说，有用 AI 的时代已经到来，所以需求正在抛物线式上升；生产力从数月变数周、数周变数日、数日变数小时，这对生产力是大事，对计算需求则是巨大跃升。

硬件层面的新增也很明确。Dell PowerEdge XE9812 基于 NVIDIA Vera Rubin NVL72，面向大规模 agentic inference，声称 cost-per-token 可比 Blackwell 低 10 倍。Dell PowerEdge XE9880L、XE9885L、XE9882L 是首批基于 NVIDIA HGX Rubin NVL8 的 Dell 系统，每 rack 支持最高 144 个 GPU，计算节点 100% direct liquid-cooled，性能最高可达 HGX B200 的 5.5 倍。Dell 还发布 PowerRack，把 compute、networking、storage、thermal design、power management 和软件优化做成一个整体。

这说明 AI 服务器竞争已经从单卡、单机、单集群，进入 rack-scale、液冷、网络、数据平台和 token 成本的一体化竞争。企业不想自己买一堆 GPU、网卡、交换机、存储和冷却系统再慢慢集成。它们想要的是一个能把 agent 放进去跑、能连接内部数据、能做安全治理、能保护模型和数据、能控制成本的工厂。换句话说，企业 AI 的下一步不是“买模型”，而是“买一套能把模型变成工作流的生产线”。

第四条主线，是 OpenAI 和 Dell 的 Codex 合作。OpenAI 5 月 18 日公告说，Codex 会连接 Dell AI Data Platform。这个平台本来就用于企业在本地存储、组织和治理数据。通过合作，Codex 会更靠近内部 codebase、文档、业务系统、运营知识和团队流程。双方还会探索 Codex、ChatGPT Enterprise 和其他 API solutions 与 Dell AI Factory 的接口，用来准备数据、管理系统记录、运行测试、部署 AI 应用。

这条新闻的真正含义是：coding agent 不再只是 IDE 里的助手，也不只是云端任务队列里的一个代码生成器。它正在进入企业内部数据层。一个能真正干活的 coding agent，需要的不只是 repo 权限，还需要文档、issue、测试环境、CI、部署规则、业务系统、产品反馈、客户工单、运营指标。OpenAI 和 Dell 的合作，就是把 Codex 往企业本地治理数据和本地基础设施里插。对大企业来说，这比单纯“把代码发到云端让模型看”更容易通过安全、隐私、合规和数据主权审查。

这也解释了为什么 on-prem AI 又热起来。以前很多人以为 AI 会把一切推向云，因为最强模型和最强 GPU 都在云里。但 agent 进入生产之后，企业会重新在意数据在哪里、谁能看、日志怎么审、模型有没有泄露、执行动作能不能回滚、失败有没有证据。本地部署不是反云，而是企业在把最敏感、最核心、最需要治理的 agent 工作负载放回自己的控制边界里。云负责弹性和前沿模型，本地负责数据密度、治理和可控执行。

第五条主线，是 Anthropic 收购 Stainless。这条新闻表面是 devtools 收购，实际是 agent 连接层的争夺。Anthropic 5 月 18 日宣布收购 Stainless。Stainless 是 SDK、CLI 和 MCP server tooling 公司，从 2022 年成立以来一直做 API layer 工具，曾为 Anthropic 生成官方 SDK，也被很多公司用于生成 SDK、文档站、命令行工具和 MCP server。Stainless 官方说明，加入 Anthropic 后将停止 hosted Stainless products，包括 SDK generator；从当天起，新 signup、新 project 和新 SDK 不再开放。

为什么这很重要？因为 Anthropic 的说法非常清楚：frontier AI 正从“回答问题的模型”转向“执行动作的 agents”，而 agents 的能力取决于它们能连接到哪些系统。一个模型再聪明，如果没有稳定、类型清晰、权限可控、文档可靠、错误可恢复的工具接口，它就只能停留在聊天。MCP、SDK、API connectors、CLI，这些看起来很底层的东西，实际上决定 agent 能不能真的改 CRM、查财务系统、跑部署、签合同、审代码、发邮件、检索知识库。

所以 Anthropic 收购 Stainless，不是买一个 SDK 生成器，而是把模型层、协议层和工具生成层往一起合。未来 agent 平台的护城河可能不是“我的模型会多说几句话”，而是“我的 agent 能以最低摩擦连接最多系统，并且连接后可审计、可治理、可维护”。这也是为什么 MCP 这么关键。模型公司谁掌握连接层，谁就更容易成为企业 agent 的默认入口。

第六条主线，是 Cursor Composer 2.5。Cursor 5 月 18 日发布 Composer 2.5，称它相对 Composer 2 在 intelligence 和 behavior 上有 substantial improvement，特别是在 long-horizon agentic tasks 上。第三方报道提到，这个模型继续围绕 Cursor 自己的 coding agent 体验做优化，重点是更长任务、更可靠的指令跟随、更细致的工具选择和更稳定的多步骤执行。

这条新闻的价值，不是说 Composer 2.5 一定超过 Claude、Codex 或 Copilot，而是它说明 coding agent 的竞争正在从“底层模型多强”转向“产品内后训练和长任务行为多稳”。IDE 里的 agent 面对的任务很具体：理解仓库、改代码、运行测试、读错误、再修改、写提交说明、遵守团队风格、不要破坏无关文件。这种能力不完全等同于通用问答模型分数。Cursor 这样的产品可以通过真实使用轨迹、工具调用数据、失败样本、RL 和行为校准，训练出更适合自己工作流的 agent 行为。

未来 coding agent 会越来越像自动驾驶。最重要的不是某一秒转向有多漂亮，而是一整段路能不能稳定、少犯错、遇到异常能不能降级、能不能留下可审计轨迹。一个长程 coding agent 如果跑了三个小时，最后失败，不只是得了 0 分，它还烧了 token、占了队列、污染了分支、制造了人类审查成本。谁能把长期任务的失败率和失败成本降下来，谁就能真正进入企业生产。

第七条主线，是 IBM Research 和 Hugging Face 发布 Open Agent Leaderboard。这个榜单 5 月 18 日发布，核心思想是：评测 agent 不能只看模型，要看完整 agent system。它把 SWE-Bench Verified、BrowseComp+、AppWorld、tau2-Bench Airline/Retail、tau2-Bench Telecom 等六类任务统一起来，评测不同 agent 架构、不同模型、不同任务下的成功率和成本。论文设计是 5 个 agent architectures、5 个 backbone LLMs、6 个 benchmarks。

这里最有价值的不是谁排第一，而是几个结论。第一，同一个模型套上不同 agent 架构，结果可以相差最多 12 个百分点。第二，模型选择仍然是主导因素，但 agent architecture 已经明显影响结果。第三，在 4 个测试 benchmark 上，顶级 general agents 已经和高度定制的 domain-specific agents 没有显著差异。第四，失败任务比成功任务成本高 20% 到 54%。第五，一些 open-weight models 会出现 generality sinks，也就是在某些 agent 架构或任务上系统性塌陷，而不是均匀落后。

这对行业是一个很好的冷水提醒。我们不能再只问“哪个模型最聪明”，还要问“哪个 agent 系统最便宜地完成任务，最便宜地失败，最容易恢复，最容易审计，最容易复现”。企业部署 agent 的成本结构里，失败不是边角料，而是账单里的大头。未来的 agent 平台会越来越重视工具 shortlisting、状态管理、失败检测、任务切分、轨迹压缩、权限控制和恢复机制。模型是发动机，但 agent 系统是整辆车。

第八条主线，是 CrossMPI 多模态 prompt injection。Xidian University 等作者 5 月 15 日提交了一篇论文，CSO 在 5 月 18 日报道。它研究的是 image-only perturbation，也就是通过图像中近乎不可见的像素扰动，改变大视觉语言模型对视觉和文本输入的联合解释。论文称 CrossMPI 把优化目标从视觉 embedding space 转到模型 hidden state space，并发现最有效的攻击层不是最后输出层，而是视觉和文本信息融合的中间层。

这里的关键数字是，研究者在 MiniGPT4、BLIP-2、InstructBLIP、BLIVA、Qwen2.5-VL 等多个开源 LVLM 上测试，平均攻击成功率为 66.36%，比 baseline 高约 41 个百分点。防御方面，SmoothVLM 在若干场景可以把攻击成功率降到 5% 以下，JPEG compression 也有一定削弱效果，但没有一种测试防御能完全消除攻击。

这条线对未来 agent 非常重要。过去大家讨论 prompt injection，通常想到网页里的隐藏文字、文档里的恶意指令、邮件里的诱导语句。CrossMPI 提醒我们，未来多模态 agent 的风险不止文字。一个 agent 如果能看截图、读 PDF、处理图片、理解视频、控制网页或机器人，那么图像本身也可能成为攻击载体。即使你把文字 prompt 清洗得很干净，一张被微调过的图片也可能改变模型对任务的理解。未来浏览器 agent、文档 agent、财务票据 agent、视频巡检 agent、机器人 agent，都需要视觉输入防火墙。

第九条，是 Musk v. OpenAI 的诉讼结果。5 月 18 日，陪审团一致认定 Elon Musk 对 OpenAI、Sam Altman、Greg Brockman 和 Microsoft 的诉讼超过诉讼时效。AP 报道称，OpenAI 在赢得这场法律战后，仍朝着可能成为历史上最大 IPO 之一的方向前进，报道中提到 OpenAI 估值为 8520 亿美元。这件事不是技术突破，但它对 AI 产业链的融资和治理有影响。

它说明，前沿 AI 的资本路径还在继续集中。训练和推理需要巨额资本，资本又要求公司结构、收入、云合约、芯片供应、IPO 路径和治理稳定。OpenAI 少一个重大法律不确定性，对融资当然是利好。但另一方面，这场审判也暴露出一个事实：AI 的未来仍然很大程度被极少数人物、董事会、云合作方、模型公司和资本市场共同塑造。AI 治理不是抽象伦理讨论，而是公司章程、诉讼时效、融资结构、控制权、云合同和数据中心预算。

把今天这些线合在一起，最前瞻的叙事是：AI 行业的核心竞争正在从模型参数竞争，升级为系统组织竞争。Google 和 Blackstone 证明，custom silicon 可以被拆出来变成独立基础设施资产。NVIDIA Vera 证明，agent 时代让 CPU 和内存重新变成 AI factory 的关键。Dell 和 OpenAI 证明，企业 agent 必须贴近内部数据、系统和治理边界。Anthropic 和 Stainless 证明，连接层可能成为模型公司的新护城河。Cursor 和 IBM Research 证明，agent 的长期行为、系统架构、失败成本和评测标准，会决定真正可用性。CrossMPI 证明，多模态 agent 的安全边界还远远没有准备好。

所以接下来 48 小时要重点盯四件事。第一，Google I/O 是否会把 TPU、Gemini、Android、agentic coding 和 enterprise AI 打成一个更完整的系统叙事。第二，NVIDIA 在 Vera、Rubin、OpenShell、NeMoClaw、Confidential Computing 上是否继续把 agent infrastructure 变成标准栈。第三，Anthropic 收 Stainless 后，MCP 和 SDK 生态会不会出现平台锁定争议，以及 OpenAI、Google、Cursor、Microsoft 会如何反制。第四，多模态 agent 安全会不会从研究论文迅速进入企业采购和监管要求，因为一旦 agent 可以看屏幕和操作系统，输入安全就不再是文本过滤这么简单。

一句话总结今天：AI 的下一轮竞争，不是单纯更大的模型，而是更大的可治理智能工厂。模型负责思考，芯片负责计算，CPU 负责协调，连接层负责触达世界，企业数据负责上下文，安全系统负责边界，资本负责把这一切建成可以持续供电、持续扩容、持续赚钱的基础设施。真正的赢家，不一定是某一天跑分最高的公司，而是谁能把这些环节组织成稳定、低成本、可审计、可扩张的生产系统。
