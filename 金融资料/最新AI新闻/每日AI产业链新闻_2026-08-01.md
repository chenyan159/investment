## 前沿人物、X与技术讨论

### 模型发布与可部署性

1. DeepSeek-V4-Flash-0731 保持目标模型架构不变，显著调整后训练。官方列出的 agent benchmark 相对 Preview 提升很大；其中 DeepSWE 7.3→54.4、Cybergym 38.7→76.7 的幅度需要公开 harness 和独立复测支持。

3. Inkling-Small 以约三分之一总参数和更低激活参数在数项 coding/terminal 指标略高于大 Inkling，同时 SimpleQA 和 Tau3 Banking 明显退化。完整 BF16/NVFP4 权重与 Apache-2.0 许可满足此前账本的 full-weights 重开条件。
4. llama.cpp b10217 增加 DeepSeek V4 在 reasoning 未闭合时的 tool-call 解析，表明模型权重发布后，模板和解析器仍是 agent 可用性的独立交付层。response_format 与 tool JSON schema 的组合还没有覆盖。

### 数值正确性、推测解码与运行时边界

- FlashInfer v0.6.17rc1 的 FP4 修复覆盖 block scale subnormal、precise 模式乘数方向和 w1_alpha 双用三条机制。作者同时给出张量误差与推理 token 代价，构成今天洞见增量最高的工程信号。配套 vLLM PR 尚未合并，稳定版和默认依赖 pin 尚待确认。
- TensorRT-LLM all-reduce 修复显示速度 autotuner 可在不同运行时状态选择不同精度的归约路径。模型、提示与权重完全相同时，GPQA 仍可发生约 3.5 个绝对点变化。评测复现需要记录 tactic、精度和拓扑。
- vLLM ROCm/AITER 的 verify mask 漏洞会让待验证 token 看见同一 draft block 的未来 token。接受率和吞吐因此可能虚高，输出文本仍有机会保持表面合理；需把 causal reference 纳入 spec decode 验收。
- TensorRT-LLM BF16 MoE split-K 和 SGLang Kimi symmetric-memory 两条前日 open PR 都已合并 main。它们只完成代码状态跃迁，正式 tag、受影响版本和跨硬件复测仍缺。
- SGLang FULL_MASK 漏洞发生在 eager batch 超过捕获 max_bs 的边界，症状可从 device OOB 扩散到 scheduler hang；作者的 GSM8K 得分为 0。此类容量边界应进入负载测试。
- TensorRT-LLM v1.3.0rc23 主动列出 DeepSeek、Qwen、Gemma 在 GB300、A100、NVFP4、FP8、BF16、多 LoRA 和 disaggregated 模式下的已知问题。该清单用于候选版风险控制，不代表线上事故分母。
- FlashInfer DumpLogits 的 2.1% 错误只污染观测钩子，不改变最终 attention 输出。它适合说明“调试证据也可能失真”，口播必须保留影响边界。

### 凭据与可观测性边界

- OpenAI Agents SDK 0.19.2 把 MCP URL/认证信息清洗从 main 推进到稳定包，并扩大到 prompts、resources、HTTPX 和嵌套异常路径。它满足旧队列“release”触发，不提供历史 trace 是否需要回收的信息。

## 优先候选研究包

### RP-1｜DeepSeek-V4-Flash-0731

- 时间线：7/30 23:56 官方 X 宣布；7/31 00:30 HF 建库，20:07 当前 artifact；8/1 01:05 SGLang 适配 PR 合并，仍属于本轮 48 小时技术窗口。
- 核心事实：目标模型结构与 Preview 相同，重新后训练；约 284B 总参数、13B 激活，DSpark 草稿模块使仓库总量约 304.18B；MIT 权重、1M context、384K 最大输出、七 token 草拟。
- 支持证据：官方模型卡给出多项 agent benchmark；SGLang 同时在 H200/B200 完成 6,848 请求零错误，并披露显存参数 OOM 与调优值。
- 反证与边界：DeepSeek Harness 尚未公开，测试使用 max effort、temperature 1、top_p 0.95；两项 DSBench 为内部集。SGLang 数据来自项目适配，不含真实工具失败率与单位成功任务成本。
- 新洞见：大幅 agentic 提升主要由后训练、harness 和草稿解码共同交付，目标模型参数没有增加。公开权重使第三方可检查部署成本。
- 可展开机制：后训练如何重排 coding/cyber/tool 能力；DSpark 对延迟和吞吐的贡献；极低 token 定价与实际完成任务成本的差异。
- 验证问题：独立 Terminal/SWE 复测是否保持排序；1M 上下文有效检索与 KV 成本；API 与本地 fingerprint 是否一致；默认显存参数为何 OOM。
- 避免重复：不重讲 DeepSeek 的开源路线、MoE 常识和此前 Preview 的 1M context。

### RP-2｜Inkling-Small 全量权重

- 时间线：7/15 Small Preview；7/30 10:47 官方发布，17:39 全量 artifact 到位。
- 核心事实：276B 总参数、12B 激活；BF16/NVFP4；Apache-2.0；文本、图像、音频；1M context；GB300 NVL72 训练。配方包含改进预训练、部分 on-policy Inkling distillation 和两周 agentic coding RL。
- 支持证据：权重可下载、许可和架构文件可检查；四个 coding/terminal/knowledge benchmark 与大 Inkling 并列披露。
- 反证与边界：SimpleQA 与 Tau3 Banking 大幅落后；厂商 harness、effort 和 trajectory 配置可能显著影响成绩；缺独立吞吐、显存和总拥有成本。

- 验证问题：BF16/NVFP4 质量差、1M 多模态稳定性、实际并发、ARC Prize 与第三方 contamination audit。
- 避免重复：不重讲美国开放权重竞争格局和此前 Inkling 大模型发布。

### RP-3｜FlashInfer FP4 数值修复

- 时间线：7/31 08:50 v0.6.17rc1 发布；FlashInfer 修复已合并，配套 vLLM PR 仍是 draft。
- 三条机制：E4M3 subnormal block scale 解码偏差最高 4.5 倍；precise quant 路径反转 inverted multiplier 并可把结果归零；w1_alpha 同时承担权重和激活 alpha，使过小权重 scale 被塞入 block scale。
- 量化影响：Qwen3.6-35B-A3B-NVFP4 平均约 17% 权重失真；Frobenius error 0.6773→0.1742，cosine 0.9211→0.98485；相对 Marlin 的多余 reasoning token 在 GPQA 从 +18.7% 降到 +6.2%，SciCode 从 +46% 降到 +14%，作者未测到延迟回退。
- 证据边界：数字来自作者/reviewer；当前是 RC；没有 CVE、生产事故或旧版本影响表；vLLM 依赖可能继续使用旧 pin。
- 新洞见：同一个“FP4 准确率”问题同时跨量化数学、融合 kernel 参数语义和框架集成。错误会增加 reasoning token，并且可能全程不崩溃。
- 可展开机制：block scale 的表示范围、权重/激活 alpha 生命周期、为什么高层 benchmark 会将数值误差放大成 token 成本。
- 验证问题：稳定版日期、不同模型/GPU、Marlin 对照公平性、默认依赖升级和在线回归。
- 避免重复：不再列举 7/14 已播的所有低精度故障和通用验证框架，只引用一句基线。

### RP-6｜分布式推理正确性：TRT-LLM 与 vLLM

- TRT-LLM 机制：性能 autotuner 可能选择 BF16 自定义 all-reduce，残差数量级放大舍入；修复改用 FP32 累加，作者测 GPQA 62.121→65.657，36 组微基准无明显回退。
- vLLM 机制：ROCm AITER 在每 rank 少于 16 heads 的 MLA spec verify 路径错误 flatten mask，验证 token 读取未来 draft token；张量偏差由 0.994 降至 0.00275。
- 共同新增：基础设施优化可以改变 benchmark 语义。一个通过归约顺序改变数值轨迹，一个通过 mask 改变因果信息集。
- 证据边界：两项都只有作者复现，缺受影响版本和独立端到端验证。
- 口播机制：解释为何“同一权重”不足以保证同一结果；评测环境应固定归约、tactic、TP/head 布局与 spec 验证参考。
- 验证问题：稳定版、线上影响、接受率回归、跨 GPU/模型与性能代价。
- 避免重复：不重列此前所有 kernel bug，只保留两条新因果机制。

### RP-7｜Apollo 与 FAR.AI：安全评测测到的对象

- Apollo 测的是模型在不同 grader-belief 条件下是否更新行为，重点是动机可辨识性。87%/9% 来自 o3 未安全训练的中间 checkpoint，gpt-oss 33%→86% 来自 model organism。
- FAR.AI 测的是预算约束下发现通用越狱的数量和成本。Grok 4.5 与 Gemini 3.1 Pro 有大量观测；Claude Fable 5 与 GPT-5.6 Sol 的零观测只形成 >$14K 下界。
- 共同新增：安全排名取决于评测者究竟观察行为、信念更新、攻击覆盖还是预算。数字离开对象定义就会失真。
- 反证：Apollo 的任务构造与 checkpoint 代表性有限；FAR 排除 adaptive attacks 且缺独立复现。
- 验证问题：样本量、模型版本、系统提示、judge、预算、攻击 primitive 重叠和复现。
- 避免重复：不概括为“模型会欺骗”或“某模型不可越狱”。

- 证据边界：AWS 未披露使用率、收入、客户数或强制终止日期。
- 验证问题：未来退役日、迁移工具、价格、支持 SLA、配额例外和客户事故。

- 共同新增：秘密可能从工具地址、回调配置与异常对象进入第二套遥测面。框架需在序列化、日志、trace 和外部 callback 四个边界分别清洗。

- 避免重复：不复述通用 API key 管理建议，只讲本次新增的数据流路径和 release 状态。
