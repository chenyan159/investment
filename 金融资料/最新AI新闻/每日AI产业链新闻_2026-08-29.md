### 包 C｜大型企业软件工厂的单位经济

覆盖：Uber（03）、Blue Yonder（10）、AMD ROCm 10（29）、fal H3 Max（31）。

- 避免重复：Stripe 已播的 7,000 PR、30% PR 与 16-agent 编排只作一句基线。

### 包 D｜权限边界与文档供应链

覆盖：Claude Code 2.1.251（04）、llms.txt 依赖执行（30）。

- Claude Code 的五类补洞跨越文件系统、插件市场、settings、外部 workflow 与搜索工具；说明统一“允许/拒绝”结果仍可能在解析时、执行前与执行后被路径变化破坏。

- 共同机制：低信任文本通过工具权限转成代码或文件系统动作；控制需要 provenance、解析后 canonical path、执行前再次授权、依赖 pinning 和 package ownership 检查。

- 避免重复：不复述通用 prompt injection、secret 上传和昨日 restricted 模式。

### 包 E｜推理运行时：假成功、静默错误与跨请求污染

覆盖：vLLM（11—13）、SGLang（14—15）、PyTorch（16）、TensorRT-LLM SIGBUS（17）、llama.cpp（19—20）。

| 故障面 | 新事实 | 生产验收应增加的检查 |
|---|---|---|
| CUDA graphs 饱和崩溃 | 7—8 分钟后死，eager 存活；作业可 exit 0 | 预期请求数、窗口数、退出码、GPU kernel error 与尾部缺失 |
| recurrent state dtype | fp32 累加落 fp16 后 inf→NaN→重复 token | 长上下文、非有限值、跨 backend dtype 合约 |
| KV raw-bits | BF16/FP16 错配仍输出流畅文本 | 配置期 fail-fast、内容级 golden、backend/block-size 矩阵 |
| symmetric-memory deadlock | 健康检查 200，真实吞吐归零 | 真实 canary、queue age、token progress、注册超时 |
| cross-request logprob | 长度断言通过，内容来自另一请求 | request identity、内容 provenance、retraction 压力 |
| BF16 compiler fusion | eager 与 compiled 的 tie 语义分歧 | materialization 边界、gradient finite、低精度 differential |
| JIT workspace | mmap 后文件被另一 rank relink，SIGBUS | per-worker 工件、inode/lock、并发启动 |
| SSM 内存与 k-quant NaN | 固定 RSS 斜率；模型级 NaN 绕过算子测试 | 请求后状态回收、模型语料、硬件/量化组合 |

证据边界：多数为单报告、open issue/PR 或作者复现。它们适合形成“验收方法”联稿，不能估计总体事故率。稳定版、生产 trace、跨硬件复现和历史输出审计是下一阶段触发。
