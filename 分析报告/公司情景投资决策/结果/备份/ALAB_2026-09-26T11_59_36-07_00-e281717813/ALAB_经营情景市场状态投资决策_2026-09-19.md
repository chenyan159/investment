财务起点：截至2026-06-30的季度/半年，业绩公告2026-08-04、10-Q于08-05公开；2025年报于2026-02-20公开。法律普通股数为2026-07-31的173.485104百万股；奖励和权证清单截至06-30。研究未把9月19日当成新的已披露资产负债表日。2026全年及以后均为估计。[10-Q][S02]、[10-K][S03]

报价与短期价格比较采用每股未复权成交/收盘口径，模型从同一现有普通股单位出发；预测现金分配为0。未把不同拆股基准的历史价格接入回报，未来纯拆股只同步调整价格与股数、不产生经济回报。

## 一、真正要购买的经济权益：从连接器件到客户平台的收费权

客户支付给ALAB，是为了让昂贵计算设备稳定交换数据、缩短系统开发时间，并在特定拓扑中提高可用吞吐。架构选择和资格认证主要由云厂/平台商负责；ODM、分销商、线缆和系统厂可能下单、付款和收货。会计收入按控制权转移确认，并不等到客户所有机柜上电，因此备货增长与最终工作负载增长可以错位。公司目前只有一个报告分部，产品级收入、成本和利润不能从集团残差“识别”为披露事实。[10-K：Business、Revenue Recognition][S03]

本研究保留四个可加经济单元。Aries与Taurus分别调查，因缺少独立利润披露，在数值模型合并为信号调理；Scorpio P/X同理合并，但保留各自采用与替代机制。COSMOS是共享软件能力和硬件成交条件，没有独立、可核验的订阅利润池，不另外虚拟软件ARR。

| 模型单元 | 使用者、收费与价值来源 | 阶段、边界及最强替代 |
| --- | --- | --- |
| S：信号调理 | Aries恢复PCIe/CXL信号；Taurus支持以太网铜连接。按ALAB实际交付的芯片/模组收取净价 | Aries已有规模；Taurus新品与既有模组并存。模块含外购材料，不能把整缆售价再加一次；短距直连、Redriver、光学及端点集成可减少独立器件 |

普通股拥有Astera Labs及其并表子公司的剩余权益；本次未查得需要从上述四池分走利润的重大少数股东或合资分成。公司不拥有客户的GPU、云服务或整个协议生态，合作身份不构成独家收费权。已有技术、软件、现场支持及研发实验室共同投入，集团共享销售管理费仅扣一次。股权奖励、客户权证及租赁在第五节闭合，不能把企业价值直接视为173.5百万现有股票的全部财富。

决定采用的不是“AI带宽还会不会增长”，而是下代系统中ALAB仍有多少独立可采购位置、能获得多少净价，以及交付、支持和更新成本是多少。NVIDIA公开的ConnectX-8架构将48条PCIe Gen6及交换集成，特定拓扑不再需要独立交换；这构成P系列数量上限的反证，不能泛化成所有Scorpio被替代。Credo在2026-08-31宣布Toucan通过PCIe 6.x合规，这是竞争者进入资格阶段的证据，尚不证明其已经取得ALAB客户的大额份额。[NVIDIA架构原文及图1][S09]、[Credo合规公告][S10]

### 2.1 Amazon合同约束了哪些判断

2025年一个最终客户超过70%收入、前三大约86%；这不是2026年精确份额，也不能直接给匿名客户贴名。Amazon是已披露客户及权证持有人，足以证明合作关系，尚不足以把全部匿名终端收入精确归给Amazon。四个直接客户的分散不意味着终端预算分散。[10-K：Risk Factors][S03]

新权证于2026-02-05签署、02-10公开，最多3,262,299股、行权价142.82美元，期限至2033-02-05，可无现金行权。8-K的65亿美元对应相关采购付款的归属门槛；本次检查了8-K、权证Exhibit 4.1和交易协议Exhibit 10.1。交易协议序言又引用2022-10-06 Global Purchase Agreement，公开年报检索和针对性SEC检索未取到可核验的完整采购最低量/取消条款。因此：**未查得65亿美元最低采购承诺，不能据此确认backlog、take-or-pay、预付款或担保；也不能断言所有非公开商业安排都没有约束。**[8-K Item 1.01][S04]、[交易协议序言及Article I][S06]

权证定义保留了可识别条件：交换分两个先后阶段，新交换归属还依赖旧Scorpio条件满足；信号调理、光学使用不同起算日；产品金额和分期股数有删节。已知条件不能因为删节而被抹去。付款门槛不是付款保证，相关采购也已包含在产品收入路径内，不能再加65亿美元。[权证第2条与Vesting Event定义][S05]

客户自身有资金和真实需求：Amazon Q2 AWS收入422亿美元、营业利润166亿美元，集团TTM经营现金流1,614亿美元，但自由现金流为负76亿美元。AWS已于2025-12-02宣布Trn3 UltraServer一般可用，最多144颗Trainium3。它们支持客户项目存在和支付能力，同时不证明ALAB在每台系统的固定BOM或未来不可取消采购。[Amazon Q2原始公告][S11]、[AWS产品可用公告][S12]

## 三、业务路径：哪些成功是必需的，规模如何约束

**S信号调理：**现有认证和现场可靠性给Aries收费基础；Taurus更高带宽模组扩大每台收入，但降低集团毛利率。增长需要客户平台数×实际安装内容，不是PCIe速度翻倍就收入翻倍。基准到2033年度收入15.5亿美元、之后缓降：将Gen6/7/后继更新与独立器件被集成、短距直连及光学替代同时计入。突破行S仅19亿美元，低于乐观20亿美元，原因是更激进的光学替代，避免把旧池与新池各自最好端点相加。

**F交换：**P的资格/多端点功能提供通常扩张；X是主增量，需要领先客户连续部署、至少几个新平台复制，以及固件、集群稳定性和后继协议更新。基准2033的50亿美元不要求所有UALink、NVLink Fusion和以太网路线同时成为赢家，而要求至少两条可收费架构延续，并且不完全被客户内化。Scorpio 320-lane已出货及H2爬坡具有公司公告支持；性能主张对应特定通信机制，不能直接等同于客户全部训练效率提升。[320-lane公告][S07]

**M内存：**2026-09-15新Leo X/2 E/P送样。先通过工作负载验证，再有付费试点、批量复购和可复制运维；2027收入不意味着2027盈利。KV重用率低、压缩/重算更便宜或软件维护成本太大，都可能使技术可用但商业失败。Meta Vistara论文验证CXL有生产收益，同时用自研ASIC，说明行业采用不保证商用Leo份额。模型M包含CPU扩容和GPU fabric附加内存，不能套用狭义CXL控制器市场总额，更不能包含DRAM价值。[Leo公告及测试脚注][S08]、[Vistara论文第1—2、10—11页][S13]

**O光学/定制：**按组件资格→NPO量产→更高集成CPO排列。先组件收费可能很小、仍亏损，后续放大需要封装/耦合良率、热稳定性、返修率、供应合作和客户跨机架预算同时成立。公司50米线性光学演示是工程可行性证据，不是已确认的年销量；它还省略某些Retimer/DSP，从而蚕食S。基准2033 O=12亿美元，突破=50亿美元，不将完整光模块、交换硅与第三方制造收入重复加总。[线性光学演示][S18]

F净价范围应至少检验700—1,300美元/被覆盖XPU，突破高配置1,200—1,800美元；管理层每XPU目标不能当全行业均价。若客户只有250万被覆盖XPU而非500万，基准50亿美元无法靠1,000美元内容兑现。突破800万被覆盖XPU不是全球全部XPU，要求ALAB在足够大的非封闭/可合作平台中获取大量份额；按1,500美元交换内容是每颗3万美元计算器件假设的5%，有系统效率改善才可能获得这笔预算。3万美元只是比较尺度，不是预测芯片市场报价。

基准2033四池合计86亿美元，约等于Amazon当前TTM净物业设备投入1,690亿美元的5.1%（以经营现金流1,614亿减自由现金流−76亿直接计算）。两者年份不同，这只是预算量级检查；连接供应商若全靠一家客户获得如此大份额，证据负担很高，因此基准明确要求客户复制，不能仅用单一客户预算扩大支撑全部增长。50亿美元光学突破收入约为公司所谓“数百亿美元机会”的显著份额；要成立，需至少两家大规模客户及外部XPU侧销售，不能只在已有Scorpio内部转移收入。全球客户总预算允许这些量级，并不等于ALAB已赢得份额。

Fabless减少厂房负担，仍需合格晶圆、封测、板卡、固件与客户验收；年报列示有限供应来源及客户短期订单风险。没有公开的产品级良率、晶圆配额或新增光学产能承诺可独立证明2033规模。模型每年扣5%销售额CapEx及12%增量收入营运资本，并保留大量研发；如果必须自己建设光学大规模产线，5%CapEx就不足，需下调价值，而非仅提高产能假设。[10-K：Manufacturing、风险因素][S03]

### 3.2 四条连续路径及概率对象

用四条联合路径作为连续分布的离散近似：**受损25%、基准45%、乐观23%、突破7%**。对象是自当前信息集出发、经过2027/2029验证直到2033形成对应规模并延续到2040的完整经济路径，不是每年重新抽签的成功率，不是技术验证概率，也不是四种股价状态。分支代表值是工作代表点，不能证明等于真实条件均值；对其偏差用规模、成本和替代分布检验，不伪称统计置信度。

受损类包括恢复不足/架构受损，2033大致低于30亿美元；基准类为约30—105亿美元的持续商业化；乐观类为约105—170亿美元、更广客户与功能采用；突破类为约170亿美元以上并同时取得可持续利润。边界用于使工作分布互斥，价格不能决定分类；这些范围内仍可能存在本模型没有单独枚举的延迟和退出。巨大超尾部及清算尾部在敏感性中另检验，四点不是现实的有限全集。

为什么不是平均四分之一：已交付和Q3订单能见度让“已有业务完全失败”缺乏中心地位；但大客户集中、竞争进入、协议分歧又使七年跨代成功不能接近确定。基准和乐观合计68%，表示持续扩张更有根据；突破仅7%，因为光学资格、供应良率、多客户复制和长期经济利润是额外联合门槛。没有可用且同口径的统计基础率数据集可以支持个位数概率精度，工作概率合理范围大致为受损15%—40%、突破2%—15%，其余概率必须相容地补齐，不能独立取各自上端。

支持上调的证据是新增最终客户的连续大额收费和旧客户之外的收入占比，而非客户接洽数本身。支持下调的是同代净价下降、平台内化或新代际重复延期。本次预设两组完整替代分布：谨慎40/45/13/2，积极10/40/35/15。更新必须由新信息改变采用、规模、时间或持续性，不因为过了一个季度就自动把突破率调高。

### 5.1 资金起点与承诺

承诺不是全可撤销：最低软件/云等采购付款合计181.669百万，2026余下24.661、2027为66.189、2028为45.340、2029为30.437、2030为15.042；外包订单取消仍须支付已发生成本。租赁负债44.413百万、未折现未来租金54.304百万，另有未起租11.7百万。费用模型已覆盖工具、云服务、租金，不把全部租赁负债从企业价值再扣一遍。采购承诺不等于已获晶圆配额；普通贸易应付款在营运资本内处理。[10-Q：Note 7—8][S02]

四条参考路径无增发/借款/回购，期间现金分红为零。留存仅按3%税后现金收益积累，后续投资已经在经营现金中扣除，不依靠未来收购免费获得收入。未来如有大额并购，需要同时扣对价并检验新增收益；管理层资本配置倾向再投资，因此现金积累并不保证届时分红或获市场按1:1定价。

治理的经济后果：2026代理文件的2025现金奖金以收入和非GAAP营业利润率各占50%考核。这支持扩张与利润率目标，却没有同等直接约束股份报酬和营运资本；因此本模型不以非GAAP利润替代股东现金。管理层将现金优先用于研发和小型人才/技术收购，模型据此保留持续研发、零分红，且对未来大收购不免费计收益。[代理文件：Annual Cash Incentive Bonuses][S20]

### 5.3 现金公式、税与再投资

```
营业利润 = Σ(业务收入 × 业务毛利率 − 业务研发支持费用) − 共享费用
现金税 = max(营业利润,0) × 税率
经济FCFF = 营业利润 − 现金税 + 折旧摊销 − CapEx
           − Δ经营营运资本 − Δ最低运营现金 + 既有奖励摊销纠重加回
超额经济现金_t = 超额经济现金_(t−1) × 1.03 + 经济FCFF_t
```

Y1/Y2/Y3税率15%/18%/20%，此后21%；不资本化研发，不把同一研发再计CapEx。折旧2%销售额、CapEx 5%，新增经营营运资本为增量收入12%、最低运营现金增加为增量收入2%。营运资本起点用1.75×12%=0.210十亿美元的归一化占款锚，与6月底应收/库存/贸易负债数量级相容；1.75不是披露的历史年度收入。税损在受损代表路径没有成为生存决定因素，严重亏损压力不假设立即收到税退款。

5%CapEx中的约2%对应设备更新、验证及实验室维持，约3%对应成长准备；研发中大部分是每代必须继续支付的费用。本方法不额外加资本化“研发资产价值”。光学/内存成功前亏损和研发都已入账。长期固定资产、研发和营运资本同时变化，因此收入扩大不是没有投资的纯利润。

不能据此宣布所有更大机会都不值钱：如果本研究漏掉一个今天就值1,000美元/股的巨大新平台分支，替换现有99.46美元期望的一部分，需要约22.6%概率才能支持303.25；若该分支值1,500美元，约需14.5%。这只标示未覆盖机会需要多大规模/概率，**不把反求结果冒充真实概率**。现有公开客户、净价与量产证据不足以把此类极端扩张赋予这么高的概率。

最强支持现在参与的组合是：突破真实概率远高于7%，长期毛利接近管理层70%而非本研究较低组合、光学双端内容顺利付费，且权益资本成本接近9.5%。该组合下突破七年上端约713美元、年化约13%，12%标准可转为谨慎建议投资；若只要求8%且接受损失大部分本金，突破中心也勉强合格。因此**不能用“仍有亏损分支”否决所有高风险参与**，但今天证据并未证明投资者有能力锁定突破路径。

现金零分配及全部超额现金按账面计价对价值偏有利：若大额收购低效、留存被浪费或市场不认账，价值再降。相反，更高现金分配可以减少资金闲置，但必须从余额扣除；不能在期末现金保留不变的同时额外加分红。

## 附录：同一底稿的最小复算代码

以下Python仅需标准库。输入包括全部年度节点和费用/资本规则，可重建年度序列、今天价值与十二格；`results()`的上下端为参数包络。代码中的文件写出是可选运行输出，不代表需要另建正式报告。

```python
from pathlib import Path
import json, math, copy

# USD billion; share counts in billion. Years end on September 19.
PRICE=303.25
N0=(173.485104+1.693+9.180+0.375)/1000
X0=1.252958-.350
K=.115
NODES=[1,3,7,10,14]
P=[.25,.45,.23,.07]
CFG={
 '受损':dict(rev=[[.80,.85,.025,0],[.65,.65,.025,.005],[.50,.55,.025,.025],[.42,.42,.020,.020],[.35,.30,.015,.015]],gm0=[.65,.63,.50,.35],gm14=[.58,.55,.48,.35],rdv=[.15,.20,.35,.30],fixed=[.09,.12,.045,.06],fg=-.08,w=2.316175,g=-.02,roic=.15),
 '基准':dict(rev=[[1.10,1.30,.080,.020],[1.35,2.70,.300,.200],[1.55,5.00,.850,1.20],[1.50,6.00,1.10,1.60],[1.40,6.50,1.30,1.80]],gm0=[.72,.71,.65,.45],gm14=[.64,.65,.61,.54],rdv=[.14,.18,.25,.22],fixed=[.09,.10,.04,.09],fg=.04,w=5.578474,g=.025,roic=.25),
 '乐观':dict(rev=[[1.20,1.55,.100,.050],[1.60,3.65,.450,.400],[2.00,7.50,1.30,2.20],[2.10,9.50,1.70,3.20],[2.10,11.00,2.00,4.00]],gm0=[.73,.73,.66,.48],gm14=[.66,.68,.64,.57],rdv=[.14,.17,.24,.21],fixed=[.10,.12,.05,.11],fg=.06,w=5.578474,g=.03,roic=.28),
 '突破':dict(rev=[[1.20,1.65,.120,.030],[1.60,4.80,.700,.900],[1.90,12.00,2.00,5.00],[1.80,16.00,3.00,8.00],[1.60,20.00,4.00,11.00]],gm0=[.73,.74,.66,.46],gm14=[.64,.68,.63,.58],rdv=[.15,.18,.24,.22],fixed=[.11,.16,.07,.17],fg=.08,w=5.578474,g=.03,roic=.25)
}
def interp(y, nodes):
    if y<=1:return list(nodes[0])
    for j in range(1,len(NODES)):
        if y<=NODES[j]:
            f=(y-NODES[j-1])/(NODES[j]-NODES[j-1])
            return [a+(b-a)*f for a,b in zip(nodes[j-1],nodes[j])]
    raise ValueError(y)

def model(c,k=K,gdelta=0,gmshift=0,scale=1,delay=False):
    n=N0+c['w']/1000
    rows=[]; cash=X0; prior=1.75
    for y in range(1,15):
        rr=[v*scale for v in interp(max(1,y-1) if delay else y,c['rev'])]
        gm=[a+(b-a)*(y-1)/13+gmshift for a,b in zip(c['gm0'],c['gm14'])]
        rd=[rr[i]*c['rdv'][i]+c['fixed'][i]*(1+c['fg'])**(y-1) for i in range(4)]
        contribution=[rr[i]*gm[i]-rd[i] for i in range(4)]
        rev=sum(rr); shared=.07*rev+.05*(1.03**(y-1))
        ebit=sum(contribution)-shared
        taxrate=[.15,.18,.20][y-1] if y<=3 else .21
        tax=max(ebit,0)*taxrate
        da=.02*rev; capex=.05*rev; dnwc=.12*(rev-prior)
        dreserve=.02*(rev-prior)
        # Existing awards fully reserved in N0. Remove remaining expense once.
        legacy=[.320,.220,.060][y-1] if y<=3 else 0
        # Future new awards remain in operating cost as cash replacement.
        fcff=ebit-tax+da-capex-dnwc-dreserve+legacy
        startcash=cash
        cash=cash*1.03+fcff
        rows.append(dict(y=y,rr=rr,rev=rev,gm=gm,rd=rd,contribution=contribution,shared=shared,ebit=ebit,tax=tax,da=da,capex=capex,dnwc=dnwc,dreserve=dreserve,legacy=legacy,fcff=fcff,cash=cash,startcash=startcash))
        prior=rev
    g=c['g']+gdelta
    # Maintenance, replacement R&D is already in EBIT; terminal incremental
    # tangible/working/operating-cash investment uses g/ROIC for positive g.
    terminal=rows[-1]['ebit']*(1+g)*.79*(1-max(g,0)/c['roic'])/(k-g)
    values={}
    for t in [0,1,3,7]:
        pv=sum(x['fcff']/(1+k)**(x['y']-t) for x in rows if x['y']>t)
        tv=terminal/(1+k)**(14-t)
        cx=X0 if t==0 else rows[t-1]['cash']
        eq=pv+tv+cx
        values[t]=dict(ev=pv+tv,equity=eq,price=eq/n,cash=cx,shares=n,tvshare=tv/eq,total=eq/n/PRICE-1,cagr=(eq/n/PRICE)**(1/t)-1 if t else None)
    return dict(rows=rows,values=values,n=n,terminal=terminal)

def results():
    out={}
    for name,c in CFG.items():
        m=model(c)
        low=model(c,k=K+.02,gdelta=-.01)
        high=model(c,k=K-.02,gdelta=.01)
        m['range']={t:[low['values'][t]['price'],high['values'][t]['price']] for t in [0,1,3,7]}
        out[name]=m
    return out

def expectations(out,weights=P):
    return {t:sum(p*out[n]['values'][t]['price'] for p,n in zip(weights,CFG)) for t in [0,1,3,7]}

if __name__=='__main__':
    out=results()
    for name,m in out.items():
        print(name, 'VALUE', {t:round(v['price'],2) for t,v in m['values'].items()},'RANGE', {t:[round(x,2) for x in v] for t,v in m['range'].items()})
        print('NODE',[(x['y'],round(x['rev'],3),round(x['ebit'],3),round(x['fcff'],3),round(x['cash'],3)) for x in m['rows'] if x['y'] in NODES])
    print('WEIGHTED',expectations(out))
    Path(__file__).with_suffix('.json').write_text(json.dumps(out,ensure_ascii=False,indent=2),encoding='utf-8')
```
