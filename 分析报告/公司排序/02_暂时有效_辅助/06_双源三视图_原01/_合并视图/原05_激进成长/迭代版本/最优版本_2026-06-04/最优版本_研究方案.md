# 双源投资排序方案

## 1. 方案定位

本方案用于让独立研究员在不调用其他资料的情况下，基于已完成的评估报告和最新金融数据，生成可复核、可更新、可分层使用的投资排序。

排序目标不是只做一张万能榜，而是同时输出三类结果：

1. 基本面性价比排序：重视中期风险收益、确定性和下跌保护。
2. 激进成长排序：重视乐观情景、收入台阶和估值可承受度。
3. 财报事件与右尾弹性排序：重视近期重估、波动弹性、财报后证据和短期催化。

最终报告必须明确区分三张榜的用途，不能把短期涨幅最大、长期性价比最好、右尾弹性最强混成同一个结论。

## 2. 强制数据源范围

本方案只能使用以下两个数据源。

### 2.1 评估报告源

允许读取：

`D:\drive\Investment\基本面\分析报告\公司评估\结果\`

只允许读取该目录下的正式评估报告。评估报告用于抽取：

- 标的代码和标的名称。
- 所属分类。
- 评估报告日期。
- 已纳入的最新经营事实或财报日期，如报告中有明确披露。
- 悲观、基准、乐观、极度乐观四种情景。
- 未来收入、利润、自由现金流、毛利率、经营利润率等预测口径。
- 情景可信度、证据强度、主要瓶颈和主要反证。
- 订单、backlog、RPO、指引、已确认收入、客户认证、产能、交付、库存、应收、现金流等报告内明确事实。

### 2.2 日度金融数据源

允许读取：

`D:\drive\Investment\基本面\日度资料\每日金融数据\`

只允许读取该目录下的每日金融数据文件和同日补充字段校验文件。日度金融数据用于抽取：

- 最新价格和价格日期。
- 市值、EV、PE、Forward PE、P/S、EV/EBITDA。
- Call IV、Put IV 或可用的综合 IV。
- 交易货币、财报货币、股本、TTM 收入、TTM EPS、Forward EPS。
- 上市类型、ADR/ADS 标记、ADR 比例说明。
- 字段校验状态，例如市值、PE、Forward PE、P/S 是否为 `ok`、`warn`、`bad` 或缺失。
- 同一目录中历史日度文件提供的近 5、10、20 个交易日价格变化。

## 3. 禁止使用的资料

除第 2 节两个数据源外，禁止读取或引用任何其他资料，包括但不限于：

- `公司调研/`
- `行业调研/`
- `日度资料/最新AI新闻/`
- `日度资料/前沿访谈/`
- `特征量化/`
- Signals、回归、模型比较、历史排序结果、排序评估结果。
- `tmp/`、`data/`、`scripts/` 中的中间结果，除非只作为执行工具且不提供事实输入。
- 互联网网页、新闻、券商报告、社交媒体、外部数据库。
- 任何不在两个允许目录内的旧报告、备份报告或手工摘要。

若两个允许数据源没有提供某项事实，必须标记为缺失或低置信，不能从其他目录或外部资料补充。

## 4. 输出结果

排序结果写入：

`D:\drive\Investment\基本面\分析报告\投资排序\`

每轮至少输出两个文件：

- Markdown 排序报告：`双源投资排序_YYYY-MM-DD.md`
- CSV 评分卡：`双源投资排序_评分卡_YYYY-MM-DD.csv`

Markdown 报告必须包含：

- 本轮使用的数据日期。
- 数据源清单。
- 三张排序榜。
- 关键分项解释。
- 数据质量和缺失字段统计。
- 排序方法版本。
- 不适合直接比较的异常口径说明。

CSV 评分卡必须保留每个标的的原始抽取项、标准化分项、最终分数和排名，便于复算。

## 6. 资料抽取规则

### 6.1 评估报告抽取

优先从评估报告中抽取已经明确写出的四情景股价变化。如果报告只给出收入、利润或估值区间，没有直接给出股价变化，则按第 7 节转换规则计算。

评估报告中的证据等级按以下顺序归类：

1. 最高证据：官方量化订单、backlog、RPO、明确全年指引、已确认收入、已确认利润、已确认自由现金流。
2. 强证据：价格数量协议、客户锁量、合同负债、客户预付款、收入覆盖率、明确交付计划。
3. 中等证据：客户认证、设计导入、管理层定性指引、产能规划、pipeline、产品级收入线索。
4. 弱证据：产业链旁证、主题相关性、产品定位、未来可选性。
5. 最低证据：纯叙事、早期验证、商业化前期、无明确收入或无明确交付。

若评估报告中没有足够证据判断等级，则设置为中低证据，并降低确定性。

### 6.2 金融数据抽取

日度金融数据必须使用最新可用日期。若最新主文件和补充字段校验文件同日存在，必须同时读取。

字段处理规则：

- `ok` 字段可用于评分。
- `warn` 字段可用于评分，但必须降低数据质量分。
- `bad` 字段不得用于估值加分，只能作为风险备注。
- 缺失字段不得用其他来源补齐。
- 交易货币与财报货币不一致时，估值字段必须降权。
- ADR/ADS、比例不明、跨币种口径不清时，必须增加数据口径风险。

### 6.3 多日价格抽取

从同一日度金融数据目录内读取历史日度文件，计算：

- 近 5 个交易日收益。
- 近 10 个交易日收益。
- 近 20 个交易日收益。
- 近 20 个交易日市值变化。
- 近 20 个交易日 P/S、Forward PE 或 EV/EBITDA 的变化，字段可用时计算。

这些指标只能用于判断已涨幅、短期动量和重估程度，不能替代评估报告中的经营事实。

## 7. 情景转换规则

### 7.1 已有股价变化口径

若评估报告已给出悲观、基准、乐观、极度乐观四种情景下的股价变化，直接抽取并进行合理性检查：

- 极度乐观情景应高于乐观情景。
- 乐观情景应高于基准情景。
- 基准情景应高于悲观情景。
- 若不满足单调性，必须标记为 `scenario_order_warning`，并人工复核，不得静默修正。

### 7.2 没有股价变化口径

若报告没有明确股价变化，但有未来收入、利润和 FCF 情景，则按以下方法转换：

1. 用当前市值与当前收入、利润、FCF 形成当前估值基准。
2. 用未来情景收入、利润、FCF 估算未来估值承受度。
3. 对高估值、高 IV、弱现金流、低证据等级标的降低估值倍数扩张假设。
4. 对低估值、强现金流、强证据等级标的允许一定估值修复。
5. 输出四情景股价变化，并标记为 `derived_scenario_return`。

不得用外部同业倍数、市场共识、新闻或其他目录资料计算未来估值。

### 7.3 情景期望收益

基本面性价比榜使用偏稳健权重：

`fundamental_expected_return = 0.15 * ret_pessimistic + 0.45 * ret_base + 0.30 * ret_bull + 0.10 * ret_extreme`

激进成长榜使用偏进攻权重：

`aggressive_expected_return = 0.08 * ret_pessimistic + 0.25 * ret_base + 0.42 * ret_bull + 0.25 * ret_extreme`

财报事件与右尾弹性榜使用右尾权重，但必须扣除已大幅上涨后的追高风险：

`event_expected_return = 0.05 * ret_pessimistic + 0.15 * ret_base + 0.35 * ret_bull + 0.45 * ret_extreme`

## 8. 分项评分

所有分项先转为横截面百分位分。建议使用 0-100 分，并对极端值做 1% / 99% winsorize，避免单个异常值压扁全样本。

### 8.1 基本面性价比分项

| 分项 | 权重 | 说明 |
|---|---:|---|
| 情景期望收益 | 45% | 使用基本面性价比权重计算 |
| 基准确定性 | 15% | 评估报告可信度、证据等级、区间宽度 |
| 利润和 FCF 质量 | 15% | 利润率、现金流、营运资本、融资压力 |
| 估值支撑 | 10% | Forward PE、P/S、EV/EBITDA 与未来兑现匹配度 |
| 下跌保护 | 10% | 悲观情景、估值安全边际、现金流与资产负债表 |
| 数据质量 | 5% | 字段完整度、口径一致性、校验状态 |

基本面性价比分：

`fundamental_score = 45% * expected + 15% * certainty + 15% * profit_fcf + 10% * valuation + 10% * downside + 5% * data_quality`

### 8.2 激进成长分项

| 分项 | 权重 | 说明 |
|---|---:|---|
| 激进期望收益 | 35% | 使用激进权重计算 |
| 乐观情景弹性 | 20% | 乐观和极度乐观情景空间 |
| 收入台阶 | 15% | 未来收入增速、收入增量、已确认收入转化 |
| 需求直接性 | 10% | 评估报告中对需求、订单、客户、产能的直接证据 |
| 估值可承受度 | 10% | 高增长后估值是否仍可解释 |
| 证据和执行质量 | 10% | 订单、指引、交付、利润、现金流兑现 |

激进成长分：

`aggressive_score = 35% * aggressive_expected + 20% * upside_convexity + 15% * revenue_step + 10% * demand_directness + 10% * valuation_tolerance + 10% * execution_quality`

### 8.3 财报事件与右尾弹性分项

| 分项 | 权重 | 说明 |
|---|---:|---|
| 事件期望收益 | 25% | 使用右尾权重计算 |
| 近期重估动量 | 15% | 近 5、10、20 日价格表现 |
| IV 和交易弹性 | 15% | IV 水平、波动弹性、小中市值弹性 |
| 财报后证据状态 | 15% | 报告是否明确纳入最新财报、指引、订单或 backlog |
| 订单/指引边际变化 | 10% | 评估报告中明确描述的上修、订单、RPO 或转收入 |
| 已涨幅后剩余空间 | 10% | 情景空间扣除已涨幅后的剩余吸引力 |
| 数据确认度 | 5% | 价格、估值、IV 是否可用 |
| 追高风险惩罚 | -5% | 已涨幅过大、估值快速扩张、IV 过热 |

财报事件与右尾弹性分：

`event_score = 25% * event_expected + 15% * momentum + 15% * iv_elasticity + 15% * earnings_status + 10% * order_guide_delta + 10% * remaining_upside + 5% * data_quality - 5% * chase_risk`

该榜是短期进攻辅助榜，不代表基本面性价比最高。

## 9. 关键惩罚和护栏

### 9.1 数据质量惩罚

出现以下情况必须扣分：

- 市值、PE、Forward PE、P/S 或 EV/EBITDA 关键字段缺失。
- 补充字段校验为 `bad`。
- 交易货币与财报货币不一致且无法在允许数据源内解释。
- ADR/ADS 比例需确认。
- 价格日期与评估日期严重错配。
- IV 缺失且该标的被放入事件或激进排序前列。

### 9.2 估值透支惩罚

出现以下情况必须降低基本面性价比分和激进成长分：

- Forward PE 极高且利润增速无法解释。
- P/S 极高且未来收入增速不足以消化。
- EV/EBITDA 极高或为异常值，且现金流支撑不足。
- 当前价格已经大幅重估，但评估报告没有给出新的更高经营情景。

### 9.3 现金流和利润质量惩罚

出现以下情况必须降低确定性、利润 FCF 质量和下跌保护：

- 自由现金流为负或严重依赖营运资本改善。
- 收入增长主要来自低毛利 pass-through。
- 应收、库存、交付或客户验收成为核心瓶颈。
- 收入增长无法转化为利润率改善。
- 需要持续融资、摊薄或高资本开支支撑增长。

### 9.4 事件弹性护栏

高 IV、高主题、高极度乐观空间可以进入财报事件与右尾弹性榜，但不能自动进入基本面性价比榜前列。

若一个标的同时存在以下情况，应标记为 `high_tail_high_risk`：

- 极度乐观情景很高。
- 悲观情景明显为负。
- Forward PE、P/S 或 IV 处于高分位。
- 证据等级不足或现金流质量弱。

该标记不是排除项，但必须在报告中单独列示。

## 10. 排序流程

1. 读取评估报告目录，建立标的清单。
2. 读取最新日度金融数据和同日补充字段校验文件。
3. 对每个标的匹配评估报告和金融数据。
4. 抽取四情景、收入、利润、FCF、证据、瓶颈和反证。
5. 抽取价格、市值、估值、IV、口径校验和字段质量。
6. 从同一金融数据目录读取历史日度文件，计算近 5、10、20 日收益和估值重估。
7. 生成标准评分卡原始字段。
8. 对所有分项做 winsorize 和百分位标准化。
9. 分别计算基本面性价比分、激进成长分、财报事件与右尾弹性分。
10. 分别生成三张排名。
11. 检查前 30 名是否存在数据质量、口径异常或情景单调性问题。
12. 输出 Markdown 报告和 CSV 评分卡。

## 11. 报告结构

Markdown 报告建议使用以下结构：

1. 本轮结论。
2. 数据源和日期。
3. 基本面性价比前列排序。
4. 激进成长前列排序。
5. 财报事件与右尾弹性前列排序。
6. 三张榜重合和分歧。
7. 高弹性但高风险标的清单。
8. 数据质量异常和字段缺失。
9. 排序方法说明。
10. 后续复核清单。

每张榜至少列出：

- 排名。
- 标的代码。
- 标的名称。
- 分类。
- 分数。
- 价格。
- 市值。
- Forward PE。
- P/S。
- IV。
- 四情景股价变化。
- 核心分项。
- 主要理由。
- 主要风险。

## 12. 复核规则

输出前必须完成以下复核：

1. 是否只读取了两个允许数据源。
2. 是否有任何结论来自其他目录或外部信息。
3. 是否每个标的都有评估报告路径和金融数据路径。
4. 是否使用最新金融数据日期。
5. 是否存在关键估值字段为 `bad` 却被用于加分。
6. 是否将短期事件弹性误写成基本面确定性。
7. 是否将已大幅上涨误判为仍有同等剩余空间。
8. 是否对缺失字段做了明确标记。
9. 是否保留了完整 CSV 评分卡，方便独立复算。

## 13. 方法边界

本方案只能根据两个允许数据源进行排序，因此存在天然边界：

- 如果最新财报、订单或指引没有进入评估报告，本方案不能从外部补充，只能标记为待刷新。
- 如果日度金融数据缺少关键估值字段，本方案不能自行抓取外部行情，只能降低数据质量分。
- 如果评估报告没有给出清晰四情景，本方案可以做情景转换，但必须标记为推导口径。
- 如果短期涨幅来自两个允许源之外的新闻、政策、传闻或资金流，本方案只能通过价格、IV 和评估报告间接识别，不能直接引用原因。

因此，本方案适合做可复核的内部排序，不适合替代实时交易新闻监控。
